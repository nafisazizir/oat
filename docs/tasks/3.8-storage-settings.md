# 3.8 — Desktop storage settings (audio archive retention)
status: done
milestone: M3 · deps: 2.8, 2.6 · branch: task/3.8-storage-settings

## Goal
Control over the local audio archive (D-10): see how much space recordings use, choose a retention policy,
delete a meeting's audio, reveal files in Finder — never touching transcripts or notes.

## Context
SPEC §4 Audio archive, D-10, D-24 (multi-part recordings), D-28 (audio index never wiped, per-user DBs),
`@oat/audio` (OpusArchiveWriter, AudioRecordingStore, readMeetingRange), `@oat/local-store` (audio-index.sqlite),
`apps/desktop` (bridge contract, main store, settings UI location — add a Settings view in the desktop app if
none exists; another implementer is changing the meeting view (3.4) — keep separate).

## Scope
In:
- Settings → Storage (desktop): total size, per-meeting list (title, date, size, parts, status), sort by size/
  date; "Show in Finder" (shell.showItemInFolder on the meeting folder — path validated inside the audio root);
  "Delete audio" per meeting (confirm; marks rows `deleted`, removes files; transcript/notes untouched; never
  while recording that meeting).
- Retention policy: keep forever (default) / delete audio older than N days / cap total at N GB (oldest first);
  enforced by a main-process sweeper on launch + every 6 h + after each recording; never deletes the active
  recording or files < 1 h old; dry-run preview in the UI ("would free 1.2 GB").
- Meeting view hint (read-only badge "Audio deleted" / "Audio on another device") exposed via bridge for 3.7.
- Bridge channels validated + sender-checked; unit tests (policy math, sweeper safety, path traversal guard),
  desktop e2e (fixture recordings → storage list shows them → delete one → files gone, transcript still
  there → retention cap deletes oldest). Screenshots.
Out: playback UI (3.7).

## Design notes
(implementer + designer, 2026-11-15)

**Bridge (`packages/core/src/bridge-storage.ts`, spread into `bridgeContract`).** Invoke: `storage:list` →
`{totalBytes, meetings[], deletedMeetings, policy, lastSweep}`; `storage:delete-audio {meetingId}` →
`{deleted, freedBytes}` (`invalid_state` while that meeting records); `storage:show {meetingId}` →
`{shown}`; `storage:preview-policy {policy}` (dry run) → `{meetings, bytes, meetingIds, overCapAfter}`;
`storage:set-policy {policy}` → summary (saves, then sweeps); `storage:audio-status {meetingId}` →
`{status: available|recording|deleted|other-device|none, bytes, parts}` (the read-only hint for 3.7).
Push: `storage:changed {seq}` (delete, sweep that deleted, policy saved, recording ended). Requests are
strict objects; `meetingId` uses the archive's folder-name rule (no separators/dots); policies are a strict
discriminated union with bounds (1–3650 days, 0.1–10000 GB). **No path ever crosses the bridge** — the
renderer names a meeting, main resolves its folder. All handlers go through the existing sender check +
schema validation (`ipc.ts`).

**Main (`src/main/audio-storage.ts`, `src/main/retention.ts`; Electron-free, wired in `index.ts`).**
- Usage: rows from the audio index (D-28) grouped per meeting; sizes from `lstat` of each row's file (not
  the row's `bytes`, which is 0 while recording); `lastActivityAt` = max(row start + duration, file mtime).
  Parts = distinct parts with a file. Status: `recording` (the active meeting), `partial` (a partial row, or a
  crash-left `recording` row), else `complete`. Rows without files (deleted/failed) aren't listed; deleted
  meetings are counted. Titles come from the signed-in account's local store (`meeting → document.title`);
  meetings the account doesn't know (other accounts on this Mac, seeded/old) show "Untitled recording".
  ~~The list shows every meeting on this Mac~~ — superseded by D-30: only the signed-in account's meetings
  (see "Round 2").
- Delete (user or sweeper): per row, the file must be (lexically) `<userData>/audio/<meetingId>/(mic|system)
  [.n].opus`, the meeting folder must be a real directory whose realpath is inside the realpath of the audio
  root, and the file must `lstat` as a regular file (no symlinks followed). Then `unlink` and mark the row
  `deleted` with `bytes: 0` (rows stay: "Audio deleted" hint + D-24 part numbering). A row pointing anywhere
  else is left alone and logged (`deleted: false`). The folder is `rmdir`ed only if empty — unknown files
  (e.g. restored from a backup) stay. The transcript, the note and both SQLite files are never touched (the
  module never gets the local store, only a title lookup).
- Never while recording: `activeMeeting()` = `recording.busy ? recording.meetingId : null` (covers starting,
  recording, paused, stopping and files still closing). Checked on user delete (`invalid_state`) and again by
  the sweeper right before each meeting (a recording may start between plan and delete).
- Policy math (`planRetention`, pure, shared by the sweeper and the dry run): a meeting is deleted as a whole;
  `isProtected` = active, or audio activity < 1 h ago (also future mtimes: clock skew). Age: newest activity
  ≤ now − N days. Size cap (decimal GB, like Finder): total includes protected meetings; unprotected ones go
  oldest-first (start time, then id for ties) until total ≤ cap; `overCapAfter` tells the UI when the
  protected ones alone exceed it.
- Sweeper: on launch, every 6 h (`setInterval`, unref'd), after each recording (status → idle) and right after
  saving a policy. Deletes and sweeps are serialised (one promise queue). It never throws; failures are
  logged; the last result is kept.
- Policy storage: `<userData>/audio-retention.json` (temp file + rename, 0600), per account per Mac since
  round 2 (D-30); not synced (audio never leaves the Mac, D-10). An
  unreadable/invalid file means **keep forever** (never guess a deleting policy) and is logged.

**UI (designer).** Sidebar gets a "Settings" item (after "Show meeting widget"); Settings replaces the
meeting view (the recording keeps running; "Back to meeting" returns). Only `@oat/ui` + tokens:
```
┌ sidebar ┬ [← Back to meeting]  Settings ─────────────────────────────────┐
│ …       │ Storage                                                       │
│ Settings│ Meeting audio is saved only on this Mac… keeps the transcript │
│         │ ┌Card: [drive] 900 MB  Audio of 3 meetings · 1 with audio deleted┐
│         │ ┌Card Keep audio: [Limit total size to… ▾] [0.5] GB     [Save] ┐
│         │ │ Would free 600 MB now (1 meeting).                           │
│         │ │ Last cleanup Nov 15, 12:58 AM: freed 600 MB (1 meeting).     │
│         │ Recordings                                    [Newest first ▾]│
│         │ │ Meeting, Nov 15…  Nov 15, 2026 · 9 s  (Recording) 47 KB [📂][🗑]│
│         │ │ Untitled recording  Oct 26 · 30 min                600 MB [📂][🗑]│
└─────────┴───────────────────────────────────────────────────────────────┘
```
- Components: Card (sm), Select (policy kind, sort), Input + Label (amount), Button (ghost icon-sm row
  actions with `aria-label`/`title`, destructive confirm), Badge (Recording = destructive tone, Partial =
  outline), Dialog (delete confirm), Skeleton (loading). Sizes in tabular figures.
- States: loading skeleton; error line (role=alert); empty list ("No recordings on this Mac"); row being
  recorded (badge, delete disabled with a tooltip why, no length yet); invalid amount (`aria-invalid`, hint
  with the allowed range, Save disabled); dry run "Checking…" → "Would free X now (N meetings)." /
  "Nothing to delete right now." (+ "Still over the limit…" when protected audio alone exceeds the cap);
  Save enabled only when the form differs from the saved policy. Delete confirm states the size, that the
  transcript and notes stay, and that it can't be undone.
- Renderer reads are keyed (a stale dry run is never shown) and re-read on `storage:changed`.

**Meeting view hint (for 3.7).** Not rendered here (3.4 owns the meeting view): `storage:audio-status`
returns `deleted` (rows deleted, or files gone behind the app's back) / `other-device` (no rows on this Mac,
but the account's meeting has a start time) / `available` / `recording` / `none`.

**Tests.** Unit: 26 in `audio-storage.test.ts` + `retention.test.ts` (path guard incl. `..`, separators,
other meetings' files, non-archive names, relative paths; symlinked file and symlinked meeting folder never
followed; tampered rows pointing at the account DB are refused; unknown files and the folder kept; DB files
byte-identical after delete; active recording never deleted by user or sweeper; < 1 h and future mtimes
protected; plan/delete race skipped; serialised deletes; launch/6 h/recording schedule with fake timers;

`apps/desktop/e2e/storage.spec.ts` (1 test, ~25 s): seeds two synthetic recordings (sparse 300 MB / 150 MB

**Round 2 (review fixes, after merging `main` with 3.4 + D-30).**
- **D-30 account scope.** Audio-index migration 2 adds `audio_recording.user_id` (+ index); `RecordingArchive`
  stores the recording account (`RecordingService` `userId` option = signed-in user). Rows from before D-30
  stay `NULL` ("unknown") until the account whose local DB **owns** the meeting's note (`document.ownerId`)
  first scans them — then they're claimed; an account that merely has the note shared never claims them, and
  unclaimed rows only show in the aggregate. `AudioStorage` takes `currentUser()` (the signed-in user, once
  their database is the open one) and lists / deletes / reveals / sweeps **only that account's rows**; the
  rest is `otherAccounts {meetings, bytes}` → a dashed "Other accounts on this Mac · N meetings · X MB" row
  with no actions. Signed out: nothing listed, delete/set-policy `unauthorized`, sweep no-op. Policy + last
  sweep are per account: `audio-retention.json` = `{version: 2, accounts: {<userId>: {policy, lastSweep}}}`
  (anything else → keep forever). `index.ts` calls `storage.accountChanged()` after `sync.setUser` switches
  the open database (sweeps with that account's policy, refreshes the view). The size cap counts only the
  account's own audio.
- **Titles** clamped in main to `STORAGE_TITLE_MAX` (200, ellipsis, no split surrogate pair); list capped at
  `STORAGE_LIST_MAX` newest (+ `meetingCount`, "N older meetings are not listed"); preview ids capped too;
  unused `failed` status removed from the list schema.
- **Policy save** is disabled until the dry run of exactly the form's policy has loaded (Enter too); if it
  would delete ≥ 1 meeting a confirm dialog ("Delete the audio of N meetings? This policy removes X …
  Transcripts and notes stay. This can't be undone." → "Delete audio and save") comes first.
- **Settings writes** go through the same queue as deletes/sweeps (`#commit`): unique temp file
  (`.tmp-<uuid>`, removed on failure), rename, and only then the in-memory settings change — a failed save
  leaves the old policy live.
- **Optional items.** (a) `RecordingService.busyMeetingId` names the meeting from the first synchronous
  moment of `start()` (a resumed meeting included) through stop/file closing; storage uses it and re-checks
  it before every unlink and before `rmdir`. (b) The folder realpath check + `lstat` are repeated right
  before each unlink; the remaining same-user TOCTOU (no `unlinkat` in Node) is documented in the code.
  (c) `storage:delete-audio` returns `alreadyGone` (e.g. a sweep got there first): the dialog closes and the
  list reloads instead of showing an error. (d) done (see Titles).
- Tests added: 1000-char title parses; concurrent sweeps + saves (file and memory end on the last policy, no
  temp files); failed save never goes live; per-file active re-check; D-30 listing/aggregate/claiming,
  never touching other or unknown accounts' audio under any policy, per-account policy, signed-out, account
  switch sweep; audio-index v1 → v2 migration (old rows `userId: null`, filter, claim); recording rows carry
  the account and `busyMeetingId` is set synchronously on a resume. E2E seeds after sign-in (2 own, 1 other
  account, 1 unattributed), checks the aggregate row (no buttons, `alreadyGone` on a delete attempt, files
  untouched by the cap) and the policy confirm dialog (screenshot `storage-retention-confirm.png`).

**Not done / follow-ups.** `recoverRecordings` (2.8 crash repair) still isn't called at desktop startup (it
wasn't before this task either): a crash-left `recording` row shows as "Partial" and is deletable/sweepable
after 1 h, but its file isn't repaired. Storage channels don't require sign-in (the view is only reachable

## Review
(reviewer, 2026-11-15, diff `merge-base(main)..cc64a59`) — **changes**

Checked and fine: path guard (regex id + `dirname` check, archive-name regex, row's own meetingId), `lstat`
no-follow on files, realpath containment of the meeting folder, rows never pointing outside, unknown files /
non-empty folder kept, DB files untouched; size cap counts protected meetings and deletes oldest-first; age
uses newest activity; corrupt/unreadable policy → keep forever and a `forever` sweep never rewrites the file;
deletes + sweeps serialised and active/1 h re-checked per meeting; bridge requests strict + bounded, no paths
cross; delete disabled while recording + `invalid_state` server-side; screenshots match the design.

1. `packages/core/src/bridge-storage.ts:45` — `title: z.string().max(500)` but synced titles may be up to
   1000 chars (`packages/core/src/sync.ts:56`). One long title makes the `storage:list` response fail
   validation (`ipc.ts` → `internal`), so the whole Storage view is just an error. Fix: clamp in main
   (`audio-storage.ts:190`, e.g. first 200 chars) or allow 1000; add a test with a 1000-char title.
2. `apps/desktop/src/renderer/src/settings/storage-settings.tsx:182-213` — saving a policy that deletes now
   has no confirmation: one click (or Enter in the amount field) irreversibly deletes N meetings, and Enter
   inside the 250 ms debounce saves while the line still says "Checking…". Per-meeting delete has a dialog;
   bulk delete should too. Fix: Save stays disabled until the dry run for the current `policyKey` is loaded;
   if it would delete ≥1 meeting, open a confirm Dialog ("Delete audio of N meetings (X)? Transcripts and
   notes stay. Can't be undone.") before `storage:set-policy`.
3. `apps/desktop/src/main/audio-storage.ts:254-256, 317-318, 497` — `setPolicy`'s save runs outside the queue
   while a launch/interval sweep may be saving `lastSweep`; both write the same `${file}.tmp-${pid}` then
   rename. Interleaved: one `rename` hits ENOENT (setPolicy rejects though the new policy is live in memory)
   or the sweep's older snapshot lands last, so the policy silently reverts on restart. Fix: unique tmp name
   per write (e.g. `randomUUID()`), and persist the policy through `#serial` (then queue the sweep); only
   swap `#settings.policy` after the save succeeded.
4. Cross-account scope (`audio-storage.ts:174-208, 283-324`): the list, manual delete, "Show in Finder" and
   the per-Mac sweeper act on every account's audio in the shared root, so account A's retention policy
   deletes account B's recordings. The design notes argue it (same OS user, per-Mac archive) but it extends
   D-28/D-10 and isn't in `DECISIONS.md` (FACTORY §2 step 3). Fix: add a D-entry stating this, or scope
   delete/sweep to meetings the signed-in account knows (unknown ones kept unless the user deletes them).

Optional:
- a. `recording.meetingId` (`recording-service.ts:243`) is the previous transcript's meeting while `start()`
  awaits `finalized`/`beginMeeting`, so during that window `activeMeeting()` doesn't name a meeting being
  resumed; a sweep/delete can then `rmdir` its folder between the archive's `mkdir` and `open`. Expose the
  requested id while starting, and re-check `activeMeeting()` inside `#deleteMeeting` before each unlink/rmdir.
- b. The folder realpath check is once per meeting; per-file `unlink` then goes through the path again (a
  folder swapped for a symlink in between would be followed, archive names only). Same-user threat; note it.
- c. `DeleteDialog`: `deleted: false` because a sweep already removed it shows "Some files couldn't be
  deleted"; return/handle a "nothing to delete" case and close + reload.
- d. `storageMeetingSchema.status` has `failed`, never produced; `meetings.max(10_000)` has the same
  whole-list failure mode as #1.
