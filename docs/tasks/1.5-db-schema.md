# 1.5 — `packages/db`: Drizzle schema, migrations, seed
status: done
milestone: M1 · deps: 1.1, 1.10, 1.7 · branch: task/1.5-db-schema

## Goal
The Postgres source of truth (SPEC §6) as a Drizzle schema with migrations and a dev seed, running against the
compose Postgres (D-11).

## Context
SPEC §6 data model; `@oat/core` types (task 1.7) are the contract — schema enums/shapes must match them;
D-9/D-14 Better Auth (task 1.6 wires it): design tables so Better Auth can use them —
core auth tables `user`, `session`, `account`, `verification` (Better Auth's Drizzle shape) and its
organization plugin mapped onto our `workspace` / `membership` / `invite` via `modelName` + field mapping
(organization needs `name, slug, logo, metadata, createdAt`; member needs `id, organizationId, userId, role,
createdAt`; invitation needs `email, role, status, expiresAt, inviterId`). Add `kind: personal|team` to workspace.
pgvector + pg_trgm extensions exist in the compose DB (1.10). `@oat/testkit` gives per-run test DBs.

## Scope
In:
- `packages/db`: drizzle-orm + drizzle-kit + `postgres` (postgres.js) driver. Schema files per area
  (`auth.ts`, `workspace.ts`, `documents.ts`, `meetings.ts`, `ai.ts`, `integrations.ts`). All SPEC §6 tables.
  String IDs (uuid v7 or nanoid, decide + note), `created_at/updated_at` timestamps with tz,
  `document.version` int, `deleted_at` soft delete, FKs with sensible `on delete`, indexes for hot paths
  (document by workspace/folder/updated_at, segment by meeting/start_ms, membership by user), `chunk.embedding
  vector(1536)` with HNSW index (cosine), unique `share_token`.
- `createDb(url)` client factory; `migrate()` helper; drizzle-kit config; generated SQL migrations committed.
- Scripts: `db:generate`, `db:migrate`, `db:seed` (dev seed: demo user `demo@oat.local`, personal workspace,
  a team workspace, a few documents/folders, one meeting with segments from
  `fixtures/audio/standup-short.segments.json` if present), `db:studio`.
- Int tests: migrate a fresh test DB, insert/read each table, FK/unique constraints, vector insert + cosine
  query, enum values match `@oat/core`.
Also per D-19/D-20 (added after this file was written): `transcript_segment.id` client-generated stable text id;
`enhancement` gets `input_notes_json`, `status`, `idempotency_key` (unique), `started_at`, `completed_at`;
`chat_message.context_json`; `document.version` used for sync base-version checks; a server-side
`change_log`/sequence (bigserial per row change: table, id, workspace_id, seq) to back cursor pulls and SSE
invalidation (3.5) — schema only now. Folder rules per D-18.
Out: auth config (1.6), query/repository layer per feature (later tasks), desktop SQLite (2.6), FTS (3.6).

## Design notes
(implementer, 2026-11-14)

**Layout.** `packages/db/src/schema/{enums,columns,auth,workspace,documents,meetings,ai,integrations,sync}.ts`,
`client.ts` (`createDb(url, {max})` → Drizzle over postgres.js, close with `db.$client.end()`;
`migrate(url)`), `id.ts`, `auth-mapping.ts`, `seed.ts`, `rows.ts` (`XRow`/`NewXRow` types), CLIs in `src/cli/`.
Migrations in `packages/db/drizzle/`: `0000_extensions.sql` (custom: `create extension if not exists vector,
pg_trgm`, so Neon works too) + `0001_init.sql` (generated). Deps: drizzle-orm 0.45.4, drizzle-kit 0.31.11,
postgres (postgres.js) ^3.4.9 (stayed on 3.x: 4.0 is two weeks old, drizzle 0.45 is tested against 3.x),
better-auth ^1.7.12 as a devDependency (reference + compat test only).

**ID strategy.** UUIDv7 strings in `text` columns, generated in app code (`newId()` in `@oat/db/id`: Web
Crypto only, so desktop/renderer can import it). Why: time-ordered (B-tree locality, rough creation order),
generated offline on the desktop, and `text` because core treats ids as opaque and some aren't ours
(client segment ids, D-19). PG17 has no built-in `uuidv7()`, so there's no DB default: Drizzle's `$defaultFn`
fills it; raw SQL inserts must supply ids. `transcript_segment.id` has **no** default (client always supplies).
Better Auth: pass `advanced.database.generateId: () => newId()`. Tokens: `newToken()` = 24 random bytes
base64url (32 chars) — used for `invite.token`; share tokens (≥22 chars, enforced by a CHECK) are issued by
the share flow (5.3).

**Better Auth mapping** (`auth-mapping.ts` exports `organizationSchema`, plain data; usage snippet in its
doc comment). Core tables keep Better Auth's names/JS keys (`user`, `session`, `account`, `verification`),
snake_case columns. organization → `workspace`, member → `membership`, invitation → `invite`,
`organizationId` → `workspaceId`, session `activeOrganizationId` → `activeWorkspaceId` (no FK: short-lived,
validated by Better Auth, avoids an auth↔workspace FK cycle). Extra Better Auth columns kept: workspace
`slug` (unique; personal = `personal-<userId>`), `logo`, `metadata` (text); membership `id`; invite `status`
(`pending|accepted|rejected|canceled`), `inviterId`. Our additions have defaults so Better Auth inserts work:
`workspace.kind` (additionalField, default `team`), `invite.token` (`$defaultFn`), `invite.acceptedAt`
(nullable; CHECK: only when accepted). `workspace.createdBy` is NOT NULL → set it in the
`beforeCreateOrganization` hook (shown in the snippet). Roles are a pg enum, so Better Auth's comma-separated
multi-roles are rejected; `viewer` needs a custom Better Auth role in 1.6. `user.name` is nullable (core
contract) though Better Auth treats it as required — harmless. Better Auth's runtime schema check
(missing columns / required columns it doesn't write) runs in `auth-mapping.int.test.ts`, which does real
sign-up, createOrganization (team + personal), setActiveOrganization, createInvitation, acceptInvitation
against a migrated test DB. Note for 1.6: accepting an invitation requires `emailVerified`.

**Constraints / on delete.** Workspace children cascade (membership, invite, folder, document, template,
chunk, chat_thread, integration, change_log). Document children cascade (meeting → participant/segment,
enhancement, chunk, chat_thread). `folder.parent_id` cascades (subfolders go), `document.folder_id` set null
(docs fall back to root). `template_id` refs set null. User FKs: session/account/membership/invite.inviter/
chat_thread/integration cascade; **`workspace.created_by`, `folder.owner_id`, `document.owner_id` restrict** —
account deletion (later task) must delete the personal workspace and reassign/delete content first. CHECKs:
document `version >= 0`, `link` ⇒ share_token, share_token format; segment `0 <= start_ms <= end_ms`; chunk
segment range both-or-neither; chat_thread `scope = document` ⇔ `document_id` (mirrors core refine);
template `is_builtin` ⇔ `workspace_id is null`; enhancement `completed` ⇒ output + completed_at; folder not
its own parent. D-18 tree rules (private folder owner-only, no cross-workspace moves) stay in core permissions.

**Index choices.** document `(workspace_id, updated_at desc)`, `(folder_id, updated_at desc)`, `(owner_id)`;
folder `(workspace_id, parent_id)`; membership unique `(workspace_id, user_id)` + `(user_id)`;
transcript_segment `(meeting_id, start_ms)`; enhancement `(document_id, created_at desc)`; chunk HNSW
`vector_cosine_ops` + `(document_id)`, `(workspace_id)`; chat_thread `(user_id, workspace_id, updated_at
desc)`, `(document_id)`; chat_message `(thread_id, created_at)`; integration unique
`(workspace_id, user_id, provider)`; change_log `(workspace_id, seq)`; account unique `(provider_id,
account_id)`; FK-only lookups for session/account/verification/invite. Non-partial for now (trash views need
deleted rows); revisit with real query plans.

**Enums.** pg enums are built from the `@oat/core` tuples (can't drift; unit + int tests assert). Enums core
doesn't have yet live in `schema/enums.ts`: `INVITE_STATUSES`, `ENHANCEMENT_STATUSES`,
`INTEGRATION_PROVIDERS`, `CHANGE_OPS` — candidates to move into core when API tasks need them.

**Other choices.** SPEC `segment_range?` → `chunk.segment_start_ms/segment_end_ms` (recording-clock ms).
`participant` gets a surrogate `id`. All tables have `created_at`/`updated_at` timestamptz (`updated_at`
bumped by Drizzle `$onUpdate`; raw SQL must set it) except append-only `chunk`, `chat_message`, `change_log`.
`change_log`: see "D-22 detail" below. `chunk.embedding vector(EMBEDDING_DIMENSIONS)` with the constant from
`@oat/core/constants` (coordinator request; byte-identical to 4.1's file). `migrate()` takes a session
advisory lock so concurrent runs serialise. `db:seed` refuses non-loopback DBs unless
`OAT_SEED_ALLOW_REMOTE=1`; it inserts fixed-id rows with `on conflict do nothing`; transcript comes from
`fixtures/audio/standup-short.segments.json` if present (array or `{segments}` of
`{source,startMs,endMs,text,speakerLabel?,id?}`), else 4 built-in segments (the fixture is on main now: 8
segments).

**D-22 detail (change log, after review round 1).**
- Table: `change_log(seq bigserial pk, txid xid8 not null default pg_current_xact_id(), table_name,
  row_id, workspace_id, op upsert|delete, created_at)`, index `(workspace_id, txid, seq)`. `workspace_id` has
  **no FK**: a workspace's own delete and its cascade must still be loggable; old rows are pruned in 3.5.
- Writers: migration `0002_change_log_triggers.sql`. One `AFTER INSERT OR UPDATE OR DELETE FOR EACH ROW`
  trigger per synced table (`SYNCED_TABLES` in `schema/sync.ts`; a unit test checks the migration matches):
  workspace, membership, invite, folder, document, meeting, participant, transcript_segment, enhancement,
  template, chat_thread, chat_message. Not logged: auth tables, `integration` (server-only, credential-adjacent),
  `chunk` (derived, server-only). `oat_change_workspace(mode, row)` finds the workspace: `self` (workspace),
  `direct` (`workspace_id`), `document` (meeting, enhancement → document), `meeting` (participant, segment →
  meeting → document), `thread` (chat_message → chat_thread). Op: insert/update → `upsert` (soft delete is an
  upsert carrying `deleted_at`), delete → `delete`. An update that changes the workspace also logs `delete`
  in the old one.
- Rows with no workspace are skipped: built-in templates (`workspace_id null`; 3.5 needs another channel if
  clients cache built-ins) and children deleted by a cascade whose parent is already gone. The parent's own
  `delete` row covers them, so clients must delete a deleted document's meeting, segments and so on locally.
  The int test checks that a hard document delete logs exactly one row.
- Reader: `readChanges(db, workspaceIds, cursor, {limit=500})` → `{changes, cursor, hasMore}`. It returns
  rows with `txid < pg_snapshot_xmin(pg_current_snapshot())` and `(txid, seq) > cursor`, ordered by
  `(txid, seq)`. The cursor is opaque `"<txid>.<seq>"`. Why it can't skip: once a row with txid X is visible,
  every transaction below xmin has finished, so any row written later has a txid ≥ that xmin, which is > X.
  The int test uses two reserved connections: the early writer commits last, the reader returns nothing while
  it is open, then returns `early, late`. Cost: one long-running transaction anywhere in the cluster delays
  everyone's pulls, and the visibility horizon is cluster-wide. Keep transactions short; on Neon, use a
  direct connection for long jobs.
- Better Auth writes (membership, invite, workspace) are captured; the auth int test asserts it.
- For 3.5: membership and workspace changes that add a user to a new workspace are logged in *that*
  workspace, which the user doesn't pull yet. The per-user SSE channel needs to tell them (e.g. "your
  workspace list changed").

**Other changes after review round 1.**

  1.6 spreads it into `organization({...})`. The int test checks that `deleteOrganization` is refused and

- (a) User-deletion FK indexes: `workspace.created_by`, `folder.owner_id`, `invite.inviter_id`,
  `integration.user_id`, `meeting.template_id`, `enhancement.template_id`.
- (c) Seed resolves the demo user by `lower(email)` and the workspaces by slug, then uses those ids, so it
  works when `demo@oat.local` already signed up through auth (int test on a fresh DB).
- (e) Better Auth lower-cases emails (sign-up route, internal adapter create/update, magic link).
  `user_email_lower_uq` on `lower(email)` was still added; the int test checks a case-variant duplicate is
  rejected.
- (d, done) The concurrent-migrate test now runs three `migrate()` calls on a fresh DB.
- Migrations were regenerated from scratch (0000 extensions, 0001 init, 0002 triggers). Nothing is deployed.
  The dev `oat` DB was rebuilt with the new `db:reset` script (`pnpm --filter @oat/db db:reset [--seed]`:

**Notes for later tasks (review items not done here).**
- (b) For 3.5/2.6: `transcript_segment` (and any offline-created id) has a global text PK with client ids.
  Push upserts must authorize against the *existing* row, e.g. `on conflict (id) do update … where
  transcript_segment.meeting_id = excluded.meeting_id` plus a permission check on that meeting. Otherwise a
  client could overwrite another meeting's row by guessing its id. A composite `(meeting_id, id)` PK is the
  alternative if that is easier to enforce.
- (d) Prod migrate: the advisory lock is session-level, so run migrations over Neon's **direct** (unpooled)
  URL. Consider `lock_timeout`/`statement_timeout` for the lock wait (9.6).
- (f) 4.x retrieval: HNSW plus a `workspace_id` filter post-filters, so small workspaces can get too few
  hits. Use pgvector ≥ 0.8 `hnsw.iterative_scan = relaxed_order` (compose has 0.8.x) or per-workspace
  partial indexes if needed.

**Outside `packages/db`:** `packages/core/src/constants.ts` + export in `core/src/index.ts` (coordinator
request); catalog entries in `pnpm-workspace.yaml`; `.prettierignore` += `packages/db/drizzle/`
(drizzle-kit owns those files; formatting them would churn every `db:generate`); `docs/DEV.md` §Database
(db:* commands incl. `db:reset`). No turbo change needed (`test:int` already passes `DATABASE_URL`/`OAT_*`;
`db:*` scripts aren't turbo tasks). The main `oat` dev DB was reset, migrated and seeded with the

## Review
(reviewer, 2026-11-14; read task file + `git diff main...task/1.5-db-schema` only; tests not re-run)

**Verdict: `changes`** (both items small, no product-code redesign needed).

Checked and fine: all SPEC §6 tables/fields plus D-19 (client segment id, `document.version`, `change_log`)
and D-20 (`input_notes_json`, `status`, unique `idempotency_key`, `started_at`, `completed_at`,
`chat_message.context_json`); Better Auth core tables and organization mapping (modelName/fields, `canceled`
spelling, enum rejects multi-role, `viewer` in enum and flagged for 1.6, real sign-up/org/invite/accept flows
in `auth-mapping.int.test.ts`); all timestamps `timestamptz`; HNSW uses `vector_cosine_ops`, matching
`cosineDistance`/`<=>` in the test; requested hot-path indexes present; share_token unique + format CHECK;
soft delete has no unique constraints that collide with trashed rows (core permissions check `deletedAt`);
extensions `if not exists`; migrations run in drizzle's single transaction behind an advisory lock;
seed is fixed-id + `on conflict do nothing`; enum-vs-core assertions in unit and int tests.

1. `packages/db/src/schema/sync.ts:15` — a `bigserial` seq is assigned at insert, not at commit, so seqs commit
   out of order: a pull that has seen seq 101 sets its cursor there and never sees seq 100 from a transaction
   that commits later. A plain "seq > cursor" pull (and SSE replay-from-seq) silently loses changes. Fix now,
   while there are no writers: add `txid xid8 not null default pg_current_xact_id()` and document the read rule
   (serve only rows with `txid < pg_snapshot_xmin(pg_current_snapshot())`), or use a per-workspace counter
   bumped under a row lock in the writing transaction. Also record in the sync.ts doc comment (or a D-entry) how
   rows are written: AFTER-row triggers are recommended because Better Auth writes `membership`/`invite`
   through its own adapter and FK cascades (document → meeting → segments/chunks) never go through app code.
   Note that child tables (`transcript_segment`, `participant`, `enhancement`, `chat_message`) have no
   `workspace_id`, so the writer has to look it up.
2. `packages/db/src/auth-mapping.ts:6-15` (with `workspace.ts:27`, `documents.ts:44-46`) — deleting a workspace
   cascades to a hard delete of every document, transcript, enhancement and chunk, bypassing soft delete.
   Better Auth's organization plugin lets owners delete organizations by default, personal ones included. The
   documented 1.6 contract should set `disableOrganizationDeletion: true` (or add a `beforeDeleteOrganization`
   hook that refuses personal or non-empty workspaces) so one API call can't wipe a workspace.

Optional:
- a. User-deletion FK scans: no index on `folder.owner_id`, `workspace.created_by`, `invite.inviter_id`,
  `integration.user_id` (not leading), `meeting/enhancement.template_id`. Cheap to add now.
- b. `meetings.ts:45`: a global text PK with client-supplied ids means 3.x push upserts must authorize against
  the *existing* row (`on conflict (id) do update … where transcript_segment.meeting_id = excluded.meeting_id`).
  The same applies to every offline-created id. Consider a `(meeting_id, id)` PK, or at least a note for 3.5.
- c. `seed.ts:137` etc.: untargeted `onConflictDoNothing()`. If `demo@oat.local` already signed up through auth
  with another id, the user insert is skipped and the workspace insert fails on the FK. Look up the user by
  email or target `id`.
- d. `db.int.test.ts:62`: the concurrent-migrate check runs with nothing pending, so it doesn't exercise the lock.
  Run two `migrate()`s on a fresh DB. Prod migrate needs Neon's direct (unpooled) URL for the session lock,
  and the lock could use a timeout.
- e. `user.email` unique is case-sensitive and relies on Better Auth lowercasing. Consider a unique index on
  `lower(email)`.
- f. HNSW + `workspace_id` filter post-filters (small workspaces can get too few hits). Plan for
  `hnsw.iterative_scan` (pgvector ≥ 0.8) in 4.x.

### Re-review
(reviewer, 2026-11-14; `git diff 105781a..task/1.5-db-schema -- packages/db docs/DEV.md` against items 1–2 and D-22)

**Verdict: `approve`.**

- Item 1 is fixed. `0002_change_log_triggers.sql` puts AFTER INSERT/UPDATE/DELETE row triggers on all 12
  `SYNCED_TABLES`, and a unit test keeps the list and the migration in step. `integration`/`chunk`/auth tables
  are correctly left out. Workspace lookup: `direct`/`self` read OLD/NEW, so they work in cascades.
  Child tables look up their parent. During a cascade the parent is already gone, so the lookup returns NULL,
  the child row is skipped, and the parent's own `delete` row covers it (the 3.5 client must cascade
  locally). A move between workspaces logs a delete in the old one. Dropping the `change_log` → workspace FK
  is right. Better Auth writes are logged (asserted in `auth-mapping.int.test.ts`).
- Reader is correct. Every row with `txid < pg_snapshot_xmin(pg_current_snapshot())` belongs to a finished
  transaction, and any row written later gets a txid ≥ that xmin. So a `(txid, seq)` row-comparison cursor
  over `(workspace_id, txid, seq)` can't skip anything, pagination included. The cursor regex bounds both parts,
  values are bound parameters, and garbage input throws.
- The two-connection test does exercise out-of-order commit: `early` writes first, `late` commits first.
  The test shows the naive reader would see only `late`, `readChanges` returns nothing, and after `early`
  commits both come back in order.
- Item 2 is fixed: `organizationOptions.disableOrganizationDeletion: true`, with a test that a Better Auth
  delete is rejected and the row survives.
- `db:reset` checks that both the target and admin URLs are loopback, has no override, rejects
  `postgres`/`template*` and odd names, and quotes the database name. The `lower(email)` unique index is
  compatible with Better Auth, which writes and queries lower case.
- The optional items a, c, d and e from the first review are also fixed (FK indexes, seed reuses an existing
  demo user/workspace, fresh-DB concurrent migrate, case-insensitive email).

Notes for 3.5 / later (not blocking):
- xmin is cluster-wide, so a long or idle-in-transaction session anywhere stalls every pull. Set
  `idle_in_transaction_session_timeout` and alert on xmin age.
- `readChanges` returns ids for every row in the workspace. The pull must apply permissions (private docs,
  `invite` tokens) and turn "lost access" (visibility → private) into deletes.
- A user who joins a workspace needs a full fetch of it, because the global cursor is already past that
  workspace's history.
- The triggers run `to_jsonb(OLD/NEW)` over the whole row, so large `content_json` saves pay for that
  serialisation. Measure before optimising.
- `0001_init.sql` was rewritten after the dev DB was migrated. `db:reset` covers that (documented in
  DEV.md). This is fine only because 1.5 isn't on `main` yet.
- A localhost SSH tunnel to a remote DB would pass the loopback check (`db:reset`/`db:seed`). Consider also
  requiring the compose port.
