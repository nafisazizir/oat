# 3.4 — Meeting note view (desktop + web)
status: done
milestone: M3 · deps: 2.5, 2.6, 3.3 · branch: task/3.4-meeting-view

## Goal
The core screen: during and after a meeting, one view with the meeting header (title, time, attendees), my
notes editor, and a collapsible transcript panel — on desktop (live) and on web (synced).

## Context
SPEC §3 (Jot while transcribing), §4, D-20/D-26 (enhance on the doc), D-19/D-28 (desktop local store + sync),
`apps/desktop` (2.5 recording service + transcript panel; 2.6 local-store + SyncService; 1.8 bridge),
`apps/web` (document page with editor, enhance toolbar 4.4/4.5, chat panel 6.4, `?t=&seg=` reader,
`server/transcript.ts`), `@oat/editor`, `@oat/calendar` (CalendarEvent attendees), `@oat/ui`.

## Scope
In:
- Desktop: the recording view becomes a meeting note: header (editable title, start time, duration, attendees
  chips from calendar or manual add), `OatEditor` for my notes (stored in local-store `document.content_json`,
  synced by 2.6; autosave), transcript panel on the right (2.5 component) collapsible, resizable; "New meeting
  note" starts a meeting doc + recording; past meetings list in the desktop sidebar (from local store); open a
  past meeting → editor + stored transcript (read from local store).
- Web: document page for `kind: meeting` shows the same header + collapsible transcript panel (server
  segments, virtualised, me/them, click → jump target for future playback (3.7)); `?t=` reader integrates with
  this panel; participants editable (add/remove manual participants) via API with authz + deny markers.
- Shared components where sensible (`@oat/ui` or a new `packages/meeting-ui`) — avoid duplicating the
  transcript list between desktop and web.
- Tests: desktop e2e (fixture recording → type notes during recording → stop → notes + transcript persisted
  locally and synced to Postgres → open on web shows both); web e2e (meeting header, participants edit,
  transcript panel collapse/resize, deep link); screenshots desktop + web light/dark.
Out: audio playback (3.7), detection-triggered start (7.3), enhance UI changes (exist).

(implementer + designer, 2026-11-15)

- `@oat/meeting-ui` (new package, React, tokens only): `TranscriptList` (the 2.5 virtualised me/them bubble list,
  moved here so desktop and web share it: speaker/time headers, interims italic+muted, `follow` = live mode with
  "Jump to live", `focusId` = centre + ring a line, `onSelect` = click/Enter/Space on a line), `SidePanel`
  (collapsible + resizable right panel: left-edge `role=separator` handle, pointer drag via window listeners,
  ←/→ 16 px, Home/End, width per app in `localStorage`), `useStoredState` (localStorage-backed, hydration-safe),
  `ParticipantChips` (initials avatar, calendar icon for `source: calendar`, × remove, "+ Add attendee" popover with
  name + optional email, errors inline), `MeetingTime` ("Thu, Nov 12 · 3:04 PM · 30 min" / "In progress · 5 min"
  ticking / "Not recorded yet"), pure helpers in `format.ts`. Apps import `@oat/meeting-ui/styles.css` (only a
  Tailwind `@source`). Desktop `recording-view.ts` re-exports `startsGroup`/`isNearBottom` from it.
- States: transcript loading / empty ("No transcript yet", "Listening…", "Waiting for transcription" on desktop;
  "No transcript" / "Waiting for the transcript…" on web) / list; note loading / gone; save status
  (Saving… / Saved on this Mac / Couldn’t save — keeps trying); read-only notes (trashed, others' private) have
  no attendee controls and a read-only editor.

**Desktop (`apps/desktop`).**
- Main (`src/main/meeting-notes.ts`, Electron-free, unit-tested on a real `LocalStore`): list / get (by document or
  meeting id) / stored transcript / save (title, content) / add + remove manual participants, all on the signed-in
  user's local database; every write goes through the outbox and `sync.kick()` (2.6 carries it to Postgres).
  "Editable" locally = not trashed and (mine or shared with the workspace): the cache doesn't know my role, so a
  viewer's edit is refused by the server and parked (D-28), never lost. Notes without a meeting row (made on the
  web) get attendees on the web for now. Content isn't schema-validated in main (the server does on push).
- Bridge: new channels in `packages/core/src/bridge-meetings.ts` (spread into `bridgeContract`; own module so it
  merges cleanly): `meetings:list`, `meeting:get`, `meeting:transcript`, `meeting:save`, `meeting:add-participant`,
  `meeting:remove-participant`, subscribe `meetings:changed {seq}`. Main broadcasts `meetings:changed` (coalesced
  250 ms) when a recording creates/ends a note (`MeetingPersistence.onChange`), a title or attendee changes, or a
  sync run finishes (`lastSyncedAt` moved — pulled changes). Content autosaves don't announce (no echo).
- Renderer: `SignedInShell` (main-window) owns the open note + the dev input choice; "New meeting note" (sidebar)
  = `recording:start` → the new note opens as soon as it is in the list (setState-during-render on
  `activeMeetingId`). Recording bar: idle on a recorded note it says "Continue recording" (same meeting, a new
  part, D-24); elsewhere "Start recording" (new note). `MeetingView`: note column (max-w-3xl) + `SidePanel`
  transcript (default 340 px, 260–560). Transcript = stored finals ∪ live segments of that meeting
  (`mergeTranscripts`, live wins per id); while recording it isn't refetched (live has everything new).
  `NoteAutosave` (400 ms debounce, one write at a time, failed patches kept and retried, flush on leave). Reloads
  (`meetings:changed`) replace the editor's content/title only when not dirty and different from what this view
  last saw (`sameDocumentContent`, ignores key order/block ids) — my own saves coming back normalised from the
  server never move the cursor. `[contenteditable]` is text-selectable in the window CSS.
- Desktop dark mode follows `prefers-color-scheme` (unchanged); evidence uses `emulateMedia`.

**Web (`apps/web`).**
- API (`src/server/meeting.ts`, routes under `app/api/documents/[id]/{meeting,participants[/participantId]}`):
  `GET …/meeting[?transcript=1]` (readers: times, attendees, transcript), `POST …/participants {name, email?}` →
  201 (editors; creates the meeting row once — `ON CONFLICT (document_id) DO NOTHING` + `FOR UPDATE`; email
  lower-cased, empty → null, name falls back to the email; max 300 per meeting), `DELETE
  …/participants/:participantId` → 204. Authz via `getDocument` (unreadable = 404) + `access.edit`
  (`canEditDocument`: viewers, trash → 403); another note's attendee id = 404. `denies(...)` markers for all three
  in `meeting.int.test.ts` (6 tests); `entrypoints.int.test.ts` covers anonymous refusal automatically.
- Page: `/d/[id]` loads the meeting side in parallel with the document (`loadDocumentMeeting`: null for
  pages/folders/unreadable). A meeting note renders `MeetingNote` (client): `DocumentEditor` gets a new `meta`
  slot under the title for the header (`MeetingTime` in UTC until hydrated, then local; `ParticipantChips` via
  `meetingApi`), transcript in a sticky `SidePanel` (≥ lg, 280–600 px, default 360) or a 24 rem section under the
  note (< lg). Open/closed and width remembered per browser. `?t=&seg=` (6.4 links) opens the panel (even if
  remembered closed) and centres + rings that line (`focusedLine`); clicking a line sets `?t=&seg=` with
  `history.replaceState` (no server round trip; the 3.7 playback hook). The 6.4 `TranscriptReader` is no longer
  used for meeting notes (the assistant passes `transcript=null` for them); it can be deleted once 6.4's fixes
  have landed. Recorded-but-not-ended (< 6 h) notes poll `GET …/meeting?transcript=1` every 5 s (watching a live
  meeting on the web until 3.5's SSE). `server/transcript.ts` got `transcriptLines(db, meetingId)` (shared query).
- `assistant.spec.ts`: two selectors moved from `transcript-reader li[data-focused]` to `transcript-panel
  [data-focused]`.

**e2e.** Web `meeting.spec.ts` (3): header/duration/calendar chip, add + remove attendee (persisted), keyboard
and drag resize (persisted), collapse (persisted) + reopen, click line → URL + focus survive reload; `?t=705`

notes, attendee, transcript → attendee added on the web reaches the desktop after a sync; relaunch → past note

## Review

**Reviewer, 2026-11-15 — verdict: `changes`** (diff `main...task/3.4-meeting-view` + task file + screenshots)

Checked and fine: participants API authz (`getDocument` 404 / `access.edit` 403, another note's attendee 404,
meeting row scoped to the doc, deny markers present); attendee emails never reach link viewers (`sharing.ts`
untouched, API actors carry no share token); new bridge channels go through `createBridge` (sender check +
request/response zod); `TranscriptList` is one virtualised component shared by desktop and web; separator has
←/→/Home/End + aria-value*, close buttons labelled; sticky web panel and < lg stacking look right in the
screenshots. Server push already re-checks participant/meeting edit rights.

1. **Desktop typing silently overwrites remote edits (D-19 "never silent overwrite").**
   `apps/desktop/src/renderer/src/meetings/meeting-view.tsx:220-230` ignores a reloaded note while autosave is
   dirty, then `apps/desktop/src/main/meeting-notes.ts:142` writes the editor's whole `contentJson` over the
   local row. If a pull applied a web edit R in between (no outbox row was pending, the keystrokes were still in
   the 400 ms debounce), the local row now carries R's `version`; `takePushBatch` sends `baseVersion: d.version`
   (`packages/local-store/src/store.ts:574`) so the server accepts and R is lost with no conflicted copy. Shared
   notes edited on web + desktop during a meeting hit this. Fix: `meeting:save` carries the base the editor was
   built on (`updatedAt` of the loaded note / last save response, or the doc `version`); main compares with the
   local row and on mismatch keeps the newer row and saves the renderer's content as a "conflicted copy" (reuse
   the D-19 path) or returns a conflict so the view reloads. Unit test: pull between `queue` and `flush`.
2. **"Continue recording" loses the meeting clock after a relaunch (D-24).** 3.4 exposes Continue on every
   recorded note (`recording-controls.tsx:233`, `meeting-view.tsx:92`), but the part offset comes only from the
   in-memory `#meetingEnds` (`apps/desktop/src/main/recording-service.ts:313`). After a restart (or on a note
   recorded on another Mac) `offsetMs = 0`: part 2's audio row gets `offset_ms 0` and its segments restart at
   0:00, interleaving with part 1. Fix: when the map has no entry, derive the offset from persisted data
   (max `offset_ms + duration_ms` of the meeting's `audio_recording` rows, and max stored segment `endMs`);
   add a test with a fresh `RecordingService` on an existing meeting. Also only offer Continue when
   `note.editable` (trashed / view-only notes would record into a note the server refuses — parked forever).
3. **Keystrokes can be lost on quit / window close, and failed saves don't retry.** The only flush is the React
   unmount cleanup (`meeting-view.tsx:209-215`), which doesn't run when the window/page unloads, so up to
   400 ms of typing before Cmd-Q / closing the window is dropped. And after a failed write the patch is kept but
   nothing retries until the next keystroke (`note-autosave.ts:78-81`) while the UI says "keeps trying"
   (`meeting-view.tsx:354`). Fix: flush on `pagehide`/`beforeunload` (the invoke is dispatched before unload;
   or have main ask the window to flush in `before-quit`), and schedule a backoff retry in `NoteAutosave` on
   error (unit-tested).

Optional:
- Web live polling re-downloads the whole transcript (≤ 5000 lines) every 5 s, and `now` is frozen at mount
  so a long-open tab polls past the 6 h cap (`apps/web/src/components/meeting/meeting-note.tsx:96-111`);
  consider `?after=<startMs>` and re-evaluating the cap.
- Resuming a meeting keeps the old `meeting.ended_at` (`meeting-persistence.ts:69` returns early), so the web
  shows it as ended and doesn't poll while part 2 records; clear `endedAt` on resume.
- `OatEditor` builds its placeholder once, so the live/not-live placeholder switch (`meeting-view.tsx:299`)
  never applies.
- Ignore `onChange` when `!editable` (`meeting-view.tsx:302`): an id-repair emit on a view-only note would
  show "Couldn't save".
- `apps/web/src/server/shell.ts:176`: the old `loadDocumentTranscript` JSDoc now sits above
  `loadDocumentMeeting`'s.
- Collapse toggles could carry `aria-expanded`; the "Ask about this note" button overlapping the panel bottom
  (already noted) is visible in `web-meeting-*.png`.

**Review round 1 — fixes (implementer, 2026-11-15, after merging main @ 9ae4bf5 = 3.5).**
1. *No silent overwrite.* `meeting:save` now carries `base` (title + notes the editor was built on;
   `NoteAutosave` keeps it: initial note → each saved patch merged in → a reload adopted while clean). Main
   (`MeetingNotes.save`) compares it with the stored row (`sameDocumentContent`, normalised title): if a pull moved
   the row, the row is left alone and my text becomes a conflicted copy through 3.5's path — new public
   `LocalStore.saveConflictedCopy(of, owner, text)` shares `#insertConflictedCopy` with the push-conflict path
   (`conflictOf`/device/time, listed in 3.5's Conflicted copies panel, comparable/resolvable on web + desktop).
   The save answers `conflict`, the view shows a banner and adopts the newer note on the announced reload. My own
   save coming back normalised (key order, block ids) is not a conflict. Tests: pull between queue and flush →
   copy, row untouched, next save on the new base is normal; normalised echo → no copy; `NoteAutosave` base/
   rebase/conflict; local-store copy shape.
2. *Continue after relaunch (D-24).* `RecordingService` derives the offset when it has no in-memory end:
   max(`offset_ms + duration_ms` of the meeting's audio parts, `MeetingPersistence.meetingEndMs` = latest stored
   segment end). Resume clears `ended_at` (in progress again; the web polls). "Continue recording" only when the
   note is editable and its audio is on this Mac (`MeetingNote.recordedHere`, from the audio index); otherwise the
   bar says why and starts a new note; main refuses `recording:start {meetingId}` for such notes too
   (`cannotContinue`). Tests: fresh service on an existing meeting → part 2 offsets ≥ part 1 end, segments after
   it, `ended_at` cleared then set; `cannotContinue` cases.
3. *Flush + retry.* Renderer flushes every open note's autosave on `pagehide` and on main's `notes:flush`
   (answers `notes:flushed`); quit (`quitGracefully`) waits for that (≤ 1 s, `NotesFlush`) and for a running
   recording's shutdown, holding further quit requests meanwhile. Failed writes retry by themselves with backoff
   (1 s → 30 s), no retry after dispose. Tests: `notes-flush.test.ts` (ack/timeout/no window), autosave backoff;
   desktop e2e types and quits immediately → text present after relaunch.
Optional, done: web live polling fetches `?after=<last startMs>` and appends (`appendLines`, unit + int test),
re-checks the in-progress cap on every poll and stops once `ended_at` is set; resume clears `ended_at`; constant
editor placeholder; view-only notes never save; `shell.ts` doc comment; `aria-expanded` on the transcript
toggles. Not done: moving "Ask about this note" off the panel (6.4's component).
Out of scope touched in this round: `packages/local-store/src/store.ts` (conflicted-copy helper shared with 3.5's
path), `packages/core/src/bridge.ts` (+`meetingSendChannels`).
