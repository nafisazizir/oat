# 5.5 — Authz audit: every route and server action covered
status: done
milestone: M5 · deps: 5.3 · branch: task/5.5-authz-audit

## Goal
Prove that every way into the server enforces permissions: each API route and each server action has at least
one deny-case test, all go through `@oat/core` checks, and the coverage check in CI makes it impossible to add
an untested entry point.

## Context
D-18, D-25 (route-coverage test `apps/web/src/server/authz-coverage.test.ts`, `denies('<METHOD> <route>')`
markers, public-route entries), FACTORY §3, SPEC §6 read rule. Known debt from 5.3: server actions
`switchWorkspace`, `updateWorkspace`, `declineInvite` lack deny tests; Better Auth plugin endpoints (desktop
code exchange, calendar link, org endpoints) are covered only indirectly.

## Scope
In:
- Extend the coverage check to server actions (`'use server'` files): every exported action must have a
  `deniesAction('<name>')` marker in a test or an explicit "no-auth needed" entry with a reason.
- Add missing deny tests (the 3 above + anything the audit finds).
- Audit pass (write findings in Design notes as a table: entry point → auth required → permission check →
  test): all `app/api/**` routes, server actions, Better Auth endpoints exposed via the catch-all (list which are
  disabled/blocked, which are allowed and why), the `share/[token]` page, desktop bridge-invoked APIs. Fix any
  gap found (small fixes in-task; larger ones → new PLAN items).
- Shared helper(s) if patterns repeat (e.g. `withSession`, `loadPermissionContext` usage enforced by lint rule
  or test).
Out: new features.

## Design notes

### What the gate is now (three layers)
1. **Static coverage** (`apps/web/src/server/api/authz-coverage.test.ts`, unit, CI `test`). 5.3 already
   enumerated route handlers *and* `'use server'` exports (keys `'<METHOD> /<route>'`,
   `'action <module>#<export>'`) — so instead of a second `deniesAction()` helper the one marker
   `denies('action …#name')` covers actions (deviation from the scope wording, same semantics). Enumeration
   moved to `api/authz-enumerate.ts` and the reasoned registries to `api/authz-registry.ts` so the runtime
   test below shares them. `KNOWN_GAPS` is **gone**; `TESTED_ELSEWHERE` is empty (all member actions now have
   deny tests of the action itself, not only of `@oat/auth`).
2. **Runtime, every entry point** (`apps/web/src/server/entrypoints.int.test.ts`, CI `test:int`): imports
   every non-PUBLIC route module and action module the enumerator finds and calls it anonymously → route
   handlers must answer 401, actions must redirect to `/sign-in` before doing anything. A new route/action is
   covered automatically the moment it exists (that's the "shared helper enforced by test": rather than a lint
   rule for `apiRoute`/`requireSession`, the behaviour itself is asserted). Next's request APIs are stubbed
   (`next/headers|cache|navigation`), `getAuth`/`getDb` point at the harness — the actions run unchanged.
   Then signed-in deny cases for all 11 non-self-scoped actions, each with a happy-path control.
3. **Better Auth catch-all inventory** (`packages/auth/src/endpoints.test.ts`, unit): pins every HTTP route
   Better Auth registers (58 method+path keys) as `served` (with the reason it is safe), `disabled`
   (`DISABLED_AUTH_PATHS` → `disabledPaths`, 404 before any handler), `blocked` (our before-hook 404) or
   `route` (404'd by the web catch-all). A Better Auth upgrade/plugin that adds or renames a route fails CI
   until it's classified. Deny cases for served ones: `members.int.test.ts` (new block "deny cases (5.5)"),
   `desktop.int.test.ts`, `google-calendar.int.test.ts`, `auth.int.test.ts`.

**Better Auth catch-all** (`/api/auth/*`, full list with reasons in `packages/auth/src/endpoints.test.ts`)
- Served, public by design: `sign-in/magic-link` (rate-limited per IP + per email), `sign-in/social`
  (calendar provider refused), `callback/:id`, `desktop/token` (one-time code + PKCE), `get-session`, `ok`,
  `error`, `reset-password/:token` (inert: no reset can be requested).
- Served, self-scoped: `sign-out`, `list-sessions`, `revoke-session(s)`, `revoke-other-sessions`,
  `list-accounts`, `link-social` (email must match; calendar via consent redirect only), `unlink-account`,
  `update-user` (name only), `desktop/code` (cookie session only).
- Served, workspace-scoped with Better Auth role checks (`access.ts` mirrors core) + our hooks:
  `organization/create`, `update`, `set-active`, `list`, `get-organization`, `get-full-organization`,
  `list-members`, `get-active-member(-role)`, `has-permission`, `invite-member`, `cancel-invitation`,
  `list-invitations` (owners/admins), `get-invitation`/`reject-invitation`/`accept-invitation` (recipient),
  `list-user-invitations` (own email). Soft-deleted workspaces 404 on every read path.
- Blocked (our hook, 404; one write path under row lock in `members.ts`): `organization/update-member-role`,
  `remove-member`, `leave`, `delete`.
- Disabled (`disabledPaths`, 404): `get-access-token`, `refresh-token`, `account-info`, `sign-in/email`,
  `sign-up/email`, `change-password`, `request-password-reset`, `reset-password`, `verify-password`,
  `change-email`, `delete-user`, `delete-user/callback`, `send-verification-email`, `verify-email`,
  `update-session`, `organization/check-slug`.
- Route-level 404: `GET magic-link/verify` (login CSRF; consumed only in-process by the same-origin POST).
- Server-only (no HTTP route): `addMember`, `setPassword`.

**Desktop main process** (`apps/desktop/src/main/api-client.ts`): calls only `POST /api/auth/desktop/token`,
`GET /api/auth/get-session` and `POST /api/auth/sign-out` with `Authorization: Bearer` (signed tokens only;
`bearer({ requireSignature: true })`). Bearer writes skip the CSRF origin check in `apiRoute` only when no
cookie is sent. Covered by desk + auth ("a signed bearer token authenticates; an unsigned one does not").
No sync/data API is called from desktop yet (D-19 sync lands later and will be enumerated by the gate).
