# 5.5 — Authz audit: every route and server action covered
status: in-progress
milestone: M5 · deps: 5.3 · branch: task/5.5-authz-audit

## Goal
Prove that every way into the server enforces permissions: each API route and each server action has at least
one deny-case test, all go through `@oat/core` checks, and the coverage check in CI makes it impossible to add
an untested entry point.

## Context
D-18, D-25 (route-coverage test `apps/web/src/server/authz-coverage.test.ts`, `denies('<METHOD> <route>')`
markers, public-route entries), FACTORY §3, SPEC §6 read rule. Known debt from 5.3: server actions
`switchWorkspace`, `updateWorkspace`, `declineInvite` lack deny tests; Better Auth plugin endpoints (desktop
code exchange, calendar link, org endpoints) are covered only indirectly.

## Scope
In:
- Extend the coverage check to server actions (`'use server'` files): every exported action must have a
  `deniesAction('<name>')` marker in a test or an explicit "no-auth needed" entry with a reason.
- Add missing deny tests (the 3 above + anything the audit finds).
- Audit pass (write findings in Design notes as a table: entry point → auth required → permission check →
  test): all `app/api/**` routes, server actions, Better Auth endpoints exposed via the catch-all (list which are
  disabled/blocked, which are allowed and why), the `share/[token]` page, desktop bridge-invoked APIs. Fix any
  gap found (small fixes in-task; larger ones → new PLAN items).
- Shared helper(s) if patterns repeat (e.g. `withSession`, `loadPermissionContext` usage enforced by lint rule
  or test).
Out: new features.

## Acceptance criteria
- [ ] Coverage check covers routes + server actions; all pass; audit table complete; gaps fixed or ticketed.
- [ ] `pnpm run ci` green.
