# 4.1 — `packages/ai` foundation + mock LLM
status: done
milestone: M4 · deps: 1.1, 1.10 · branch: task/4.1-ai-foundation

## Goal
All AI calls go through one provider factory that uses AI Gateway when a key is set and the containerised
OpenAI-compatible mock otherwise (D-3, D-11, D-13), with an in-process mock for unit tests.

## Context
SPEC §5 (AI via AI SDK + AI Gateway, `"provider/model"` strings), §7, D-3, D-11, D-13. Load the
`vercel:ai-sdk` and `vercel:ai-gateway` skills for current APIs (AI SDK version: check `pnpm view ai version`).
`tools/mocks` (1.10) has the provider plugin structure — add the `llm` provider there.

## Scope
In:
- `packages/ai`: `getModel(role)` / `getEmbeddingModel()` where role ∈ `enhance | chat | fast | embed`; model
  registry mapping roles → gateway model ids (Claude models for text — verify ids against the gateway model
  list when a key is set; config-overridable via env `AI_MODEL_<ROLE>`). Provider selection by env:
  `AI_GATEWAY_API_KEY` set → AI Gateway; else `AI_BASE_URL` (default `http://localhost:14010/llm/v1`) via
  OpenAI-compatible provider. `EMBEDDING_DIMENSIONS=1536` constant shared with db.
- In-process test helpers: `createMockModel({ responses | handler })` built on AI SDK test utilities
  (MockLanguageModel / simulateReadableStream) and a deterministic mock embedding model.
- `tools/mocks` `llm` provider: OpenAI-compatible `POST /llm/v1/chat/completions` (non-stream + SSE stream,
  tool calls passthrough not required yet), `response_format: json_schema` → returns **deterministic
  schema-valid JSON** generated from the schema (strings derived from input text so outputs are relevant-ish,
  e.g. pulls sentences from the prompt), `POST /llm/v1/embeddings` (deterministic hash-based unit vectors,
  similar text → similar vectors via token hashing so retrieval tests are meaningful), `GET /llm/v1/models`.
  Scenario hooks: header `x-mock-scenario: error|slow|empty` for resilience tests.
- Tests: unit (factory env selection, registry), mocks unit tests, int test: `generateText`, `streamText`,
  `generateObject` (zod schema) and `embed` against the running mocks container through the real provider path.
Out: prompts/templates (4.3), eval harness (4.2), chat (6.x).

## Acceptance criteria
- [ ] With only `.env.example` defaults, `generateObject` against the mock returns a schema-valid object.
- [ ] Streaming works end-to-end via the mock (SSE).
- [ ] Embeddings deterministic; cosine(sim text) > cosine(unrelated text) in a test.
- [ ] Setting `AI_GATEWAY_API_KEY` switches provider (unit-tested without network).
- [ ] Global gates green incl. `pnpm test:int`.

## Design notes
Implementer, 2026-11-14. Versions: `ai` 7.0.173, `@ai-sdk/openai-compatible` 3.0.92, `@ai-sdk/provider` 4.0.38,
`zod` 4.6.7 (pnpm catalog). `createGateway` comes from `ai` itself, so `@ai-sdk/gateway` is not a direct dependency.

**`packages/ai`**
- `models.ts`: roles `enhance | chat | fast | embed`; `DEFAULT_MODELS` = `anthropic/claude-sonnet-5.5` (enhance,
  chat), `anthropic/claude-haiku-5.5` (fast), `openai/text-embedding-3-small` (embed, 1536-d natively). Ids
  checked against the public AI Gateway catalog (`GET /v1/models`, metadata only, no key, no inference) on
  2026-11-14; re-check when a key is configured. `AI_MODEL_<ROLE>` overrides, blank = default, malformed
  (`no provider/`) throws. `EMBEDDING_DIMENSIONS = 1536` lives in **`@oat/core`** (`packages/core/src/constants.ts`) and is
  re-exported by `@oat/ai`; the db task imports it from `@oat/core` for `chunk.embedding` (no db → ai dep).
- `provider.ts`: `resolveAiBackend(env)` → `{kind:'gateway', auth:'api-key'}` when `AI_GATEWAY_API_KEY` is
  non-blank; `{kind:'gateway', auth:'oidc'}` when `VERCEL_OIDC_TOKEN` or `VERCEL` is set (the gateway provider
  resolves the OIDC token per request via `@vercel/oidc`; in Vercel Functions it arrives as a request header, so
  it can't be checked at resolve time — a missing token is a loud gateway auth error, not a fallback); optional
  `AI_GATEWAY_BASE_URL`. Else `mock` at `AI_BASE_URL` → `${MOCKS_URL}/llm/v1` → `http://localhost:14010/llm/v1`,
  except `NODE_ENV=production` with none of those set throws `AiConfigError` (explicit `AI_BASE_URL`/`MOCKS_URL`
  stays allowed, e.g. e2e against `next start`). `backend` holds no secret; the key lives only in the
  `createGateway` closure and the `getAi()` cache key is a sha256.
  `createAi({ env?, fetch? })` returns `{ backend, models, getModel(role), getEmbeddingModel() }`; mock mode uses
  `createOpenAICompatible({ name: 'oat-mock', supportsStructuredOutputs: true, includeUsage: true })` so
  structured output goes over `response_format: json_schema` exactly like a real structured-output provider.
  Top-level `getModel(role)` / `getEmbeddingModel()` use a `process.env` client memoised on the `AI_*` +
  `MOCKS_URL` values (rebuilt if they change). The same gateway ids are sent to the mock, so the mock request
  log shows which role made each call.
- `testing.ts` (`@oat/ai/testing`): `createMockModel({ responses | handler, chunkDelayInMs? })` on
  `MockLanguageModelV4` + `simulateReadableStream` (generate and stream share one call counter; stream =
  word deltas), `promptText(call)` for handlers, `createMockEmbeddingModel({ dimensions? })` using
  `hashEmbedding` — byte-identical copy of the mock server's algorithm (`hash-embedding.ts`; copied, not
  imported, so `@oat/ai` has no runtime dep on `@oat/mocks`; an int test asserts parity).
- Note: AI SDK 7 deprecates `generateObject` in favour of `generateText({ output: Output.object({ schema }) })`.
  Tests use `Output.object` throughout; the one `generateObject` case is the container acceptance test (AC #1).
  4.3+ should use `Output.object`.

**`tools/mocks` `llm` provider** (`src/providers/llm/`): `index.ts` (routes, scenarios), `json-schema.ts`
(schema → deterministic value), `text.ts` (sentence pool from user messages; system prompt is never quoted),
`embedding.ts` (feature hashing: words weight 1 + char trigrams 0.5/word, hashed sign, L2-normalised).
- Objects: required keys missing from `properties` (e.g. `z.record(z.enum([...]), …)`) are generated from
  `additionalProperties`; `minProperties` padding takes names from `propertyNames.enum/const`. `multipleOf`
  prefers 0 when in range and trims float noise.
- Chat: text = up to 3 sentences of the last user message; `json_schema` → schema-valid JSON (strings cycle
  through prompt sentences; `title/name/heading/...` keys get ≤6-word phrases; arrays default to 3 items within
  min/max; depth guard for recursive schemas; formats date-time/date/time/email/uri/uuid; `pattern`, `not`,
  `if/then` unsupported → may be violated); unsatisfiable schema → 400. `json_object` → `{ "text": … }`. SSE
  stream: role chunk, word deltas, finish chunk, optional usage chunk, `[DONE]`. Tools accepted, never called.
- Embeddings: string or string[] (≤2048), `dimensions` (default 1536), float/base64.
- Scenarios: `x-mock-scenario: error` (+ `x-mock-status`, 429 → `rate_limit_error`), `slow` (+
  `x-mock-delay-ms`, aborts early when the client disconnects), `empty`; `x-mock-chunk-delay-ms` paces SSE.
  Unknown scenario → 400. Documented in docs/DEV.md "The `llm` provider".

**Tests.** Unit: `models.test.ts`, `provider.test.ts` (env selection incl. parsing `.env.example`; gateway switch
verified with a recording `fetch` — request goes to `https://ai-gateway.vercel.sh/…` with `Bearer <key>`, no
network), `testing.test.ts`; mocks: `llm.test.ts` (HTTP via `app.request`), `json-schema.test.ts` (zod →
`toJSONSchema` draft-7 and 2020-12 → generate → `parse`), `embedding.test.ts`. Int (`provider.int.test.ts`):
in-process `startMocks()` through the real provider path — `generateText`, `streamText` (SSE, usage),
`generateObject` + `Output.object` (zod), determinism, `embed`/`embedMany` + cosine ordering, mock/in-process
embedding parity, scenarios (APICallError status, SDK retry, empty, abort on slow). A second suite runs
`generateObject` with the plain env defaults against the shared container. It **skips only** when the container
answers 404 for `/llm/v1/models` (image predates 4.1 → `pnpm dev:build`) or a real gateway is configured; an
unreachable mock fails the test (checked: `AI_BASE_URL=http://127.0.0.1:1/llm/v1` → `fetch failed`).

## Review
**Reviewer, 2026-11-14 — verdict: `changes`** (3 small fixes; everything else is solid).

Checked and OK: provider selection (`AI_GATEWAY_API_KEY` is the only path to a real backend; the key only ever
reaches `createGateway`; the mock path sends no `Authorization` — unit-tested; blank = unset via `trim()`);
`AI_BASE_URL` → `MOCKS_URL` → default precedence; default model ids exist in the live AI Gateway catalog
(re-checked today); override validation; SSE (role chunk, deltas, `finish_reason: stop` chunk, `choices: []`
usage chunk only with `include_usage`, `[DONE]`), non-stream `usage`/`finish_reason`; determinism; embeddings
L2-normalised (incl. empty text), server/in-process copies byte-identical; int tests go through
`createOpenAICompatible` over real HTTP to `startMocks()`; `Output.object` covered. Probed the schema generator
with 11 extra zod shapes × draft-7/2020-12 (discriminated unions, intersections, nullable objects, tuples,
`length`, url/email/uuid/datetime, `gt/lt`, `multipleOf`): all valid except #1. `pnpm --filter @oat/ai test`
(21), `test:int` (11 + 1 skipped), `@oat/mocks test` (48) green locally.

1. `tools/mocks/src/providers/llm/json-schema.ts:155-170` — `required` keys that are not in `properties` are
   never generated. `z.record(z.enum(['a','b']), z.string())` emits `{propertyNames:{enum:[a,b]},
   additionalProperties:{…}, required:['a','b']}` and the mock returns `{}` → schema-invalid (a plausible shape
   for enum-keyed sections). Fix: after the `properties` loop, generate every missing `required` key from
   `additionalProperties` (error if it is `false`); when padding to `minProperties`, take key names from
   `propertyNames.enum`/`const` if present. Add the case to `json-schema.test.ts`.
2. `packages/ai/src/models.ts:26` — `EMBEDDING_DIMENSIONS` should live in `@oat/core` (zero-dep domain
   package) and be re-exported by `@oat/ai`. As designed, `@oat/db` must depend on `@oat/ai` (AI SDK, providers)
   just to size `chunk.embedding`, and the retrieval code in `@oat/ai` (4.x/6.x) will want `@oat/db` → cycle.
   Move it now (add `@oat/core` as a dep of `@oat/ai`; keep the `models.test.ts` assertion), and update the
   design note that tells the db task where to import it from.
3. `packages/ai/src/provider.int.test.ts:195-216` — the env-defaults suite that proves acceptance #1 skips
   silently whenever the mock is unreachable, so `pnpm test:int` can be green forever without it ever running
   (int tests already require `pnpm dev:up`). Fix: skip only when the container answers but lacks `/llm`
   (HTTP 404 = image predates this task) with an explicit message; fail on connection errors. Verifier: rebuild
   the container from this branch (`pnpm dev:build`) and record a non-skipped run in *Evidence*.

Optional:
- `provider.ts:40-52` — on Vercel with no key (OIDC `VERCEL_OIDC_TOKEN` is the gateway's other auth path) this
  silently targets `localhost:14010`. Consider failing fast when `VERCEL_ENV`/`NODE_ENV=production` resolves to
  the default mock URL, or accepting OIDC (track for 9.x if not now).
- `provider.ts:19-20` — `AiClient.backend.apiKey` exposes the secret on a public, easily-logged object; drop or
  redact it (`hasKey: true`).
- `embedding.ts:9`, `hash-embedding.ts` header — refer to `testing.int.test.ts`; the parity test is in
  `provider.int.test.ts`.
- `json-schema.ts:255` — with no lower bound, `multipleOf` returns `m` even when `maximum < m` (throws although
  `0` fits); float `multipleOf` (0.1) can yield `0.30000000000000004`. Prefer `0` when in range.
- Use `Output.object` as the primary path in tests/docs (keep one `generateObject` case) to cut deprecation
  noise and steer 4.3.

**Resolution (implementer, 2026-11-14):** 1 fixed (+ propertyNames, tests incl. `z.record(z.enum)` and
`z.partialRecord`, draft-7/2020-12). 2 fixed (`@oat/core` constant, re-exported). 3 fixed (skip on 404 only, fail
on connection errors). Optional items all done: production guard + OIDC auth, no key on `backend`, stale
comments, `multipleOf` (0 preferred, float noise trimmed), `Output.object` as the primary test path.
