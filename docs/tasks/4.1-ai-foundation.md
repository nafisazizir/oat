# 4.1 — `packages/ai` foundation + mock LLM
status: in-progress
milestone: M4 · deps: 1.1, 1.10 · branch: task/4.1-ai-foundation

## Goal
All AI calls go through one provider factory that uses AI Gateway when a key is set and the containerised
OpenAI-compatible mock otherwise (D-3, D-11, D-13), with an in-process mock for unit tests.

## Context
SPEC §5 (AI via AI SDK + AI Gateway, `"provider/model"` strings), §7, D-3, D-11, D-13. Load the
`vercel:ai-sdk` and `vercel:ai-gateway` skills for current APIs (AI SDK version: check `pnpm view ai version`).
`tools/mocks` (1.10) has the provider plugin structure — add the `llm` provider there.

## Scope
In:
- `packages/ai`: `getModel(role)` / `getEmbeddingModel()` where role ∈ `enhance | chat | fast | embed`; model
  registry mapping roles → gateway model ids (Claude models for text — verify ids against the gateway model
  list when a key is set; config-overridable via env `AI_MODEL_<ROLE>`). Provider selection by env:
  `AI_GATEWAY_API_KEY` set → AI Gateway; else `AI_BASE_URL` (default `http://localhost:14010/llm/v1`) via
  OpenAI-compatible provider. `EMBEDDING_DIMENSIONS=1536` constant shared with db.
- In-process test helpers: `createMockModel({ responses | handler })` built on AI SDK test utilities
  (MockLanguageModel / simulateReadableStream) and a deterministic mock embedding model.
- `tools/mocks` `llm` provider: OpenAI-compatible `POST /llm/v1/chat/completions` (non-stream + SSE stream,
  tool calls passthrough not required yet), `response_format: json_schema` → returns **deterministic
  schema-valid JSON** generated from the schema (strings derived from input text so outputs are relevant-ish,
  e.g. pulls sentences from the prompt), `POST /llm/v1/embeddings` (deterministic hash-based unit vectors,
  similar text → similar vectors via token hashing so retrieval tests are meaningful), `GET /llm/v1/models`.
  Scenario hooks: header `x-mock-scenario: error|slow|empty` for resilience tests.
- Tests: unit (factory env selection, registry), mocks unit tests, int test: `generateText`, `streamText`,
  `generateObject` (zod schema) and `embed` against the running mocks container through the real provider path.
Out: prompts/templates (4.3), eval harness (4.2), chat (6.x).

## Acceptance criteria
- [ ] With only `.env.example` defaults, `generateObject` against the mock returns a schema-valid object.
- [ ] Streaming works end-to-end via the mock (SSE).
- [ ] Embeddings deterministic; cosine(sim text) > cosine(unrelated text) in a test.
- [ ] Setting `AI_GATEWAY_API_KEY` switches provider (unit-tested without network).
- [ ] Global gates green incl. `pnpm test:int`.
