# 1.10 — Containerised dev environment
status: in-progress
milestone: M1 · deps: 1.1 · branch: task/1.10-dev-env

## Goal
Make development fully offline and portable (D-11): one command brings up every external dependency in Docker,
with mocks standing in for every third-party API, so a new machine needs only Docker + Node + pnpm and no keys.

## Context
D-11 (services, ports, env rules), D-12, D-13. Other local projects on this machine already use 5432, 6379,
1025, 8025 — use exactly the D-11 ports. Compose project name `oat`.

## Scope
In:
- `docker-compose.yml` at repo root: `postgres` (pgvector/pgvector:pg17, db `oat`, user/pass `oat`/`oat`,
  init script enabling `vector` + `pg_trgm` extensions, volume), `redis` (redis:7-alpine), `mailpit`
  (axllent/mailpit), `oauth` (ghcr.io/navikt/mock-oauth2-server, configured with an issuer `google` that
  issues id_tokens with `email`, `email_verified`, `name`, `picture` claims; support non-interactive login
  for tests and interactive login form for humans), `mocks` (built from `tools/mocks/Dockerfile`). All with
  healthchecks so `docker compose up -d --wait` returns only when healthy. Pin image tags.
- `tools/mocks` (`@oat/mocks`): TypeScript Node service (Hono + @hono/node-server; `ws` for websockets later),
  plugin structure `src/providers/<name>.ts` each mounted under `/<name>` (e.g. `/llm`, `/stt`, `/notion`,
  `/gcal` — only register the skeleton + `GET /health` + an example provider now; real providers come in
  2.2/4.1/7.4/8.1). Request log ring-buffer at `GET /_requests` (handy for tests asserting calls were made),
  `POST /_reset`. Unit tests with Hono's `app.request()`. Dockerfile (node:24-alpine, multi-stage, small).
  Also runnable natively with `pnpm --filter @oat/mocks dev`.
- `packages/testkit` (`@oat/testkit`): `createTestDatabase()` → creates `oat_test_<random>` on the compose
  Postgres via admin URL, returns `{url, drop()}`; `mailpit` helper (list/get latest message for an address,
  extract first link); `waitFor` utility. Integration tests (`*.int.test.ts`) prove each helper works against
  the running stack.
- Root scripts: `dev:up` (copies `.env.example` → `.env` if missing, then `docker compose up -d --wait`),
  `dev:down`, `dev:reset` (down -v — dev data only), `dev:logs`, `dev:ps`. Use a tiny node script in
  `scripts/` rather than shell-isms so it works on Linux/macOS.
- `.env.example` with every var, defaults pointing at the containers (`DATABASE_URL`, `REDIS_URL`, `SMTP_*`,
  `OAUTH_GOOGLE_ISSUER`/client id/secret placeholders, `MOCKS_URL`, `AI_*`, `DEEPGRAM_*` left blank = use mock)
  with comments saying which real service each replaces.
- `docs/DEV.md`: prerequisites, "new machine in 3 commands", service/port table, how mocks work, how to
  switch a provider to the real thing with a key, troubleshooting (port clash, `dev:reset`).
Out: app code, DB schema (1.5), auth wiring (1.6), real provider mocks (later tasks), CI (1.2), web Dockerfile (1.9).

## Acceptance criteria
- [ ] From a clean state: `pnpm dev:up` exits 0 with all 5 services healthy (`pnpm dev:ps`).
- [ ] `curl localhost:14010/health` → 200 JSON; `curl localhost:18089/google/.well-known/openid-configuration`
      → 200; Postgres has `vector` + `pg_trgm`; `redis-cli -p 63790 ping` (or via container) → PONG.
- [ ] `pnpm test:int` passes: testkit creates+drops a DB, sends an email via SMTP and reads it via Mailpit API,
      mocks health/reset/_requests work.
- [ ] `pnpm dev:down && pnpm dev:up` is idempotent; `pnpm dev:reset` wipes volumes.
- [ ] No step needs network beyond pulling images / npm packages; no keys.
- [ ] Global gates green.

## Verification
```
pnpm install && pnpm dev:reset && pnpm dev:up && pnpm dev:ps
curl -sf localhost:14010/health && curl -sf localhost:18089/google/.well-known/openid-configuration | head -c 200
docker compose exec -T postgres psql -U oat -d oat -c "select extname from pg_extension"
docker compose exec -T redis redis-cli ping
pnpm typecheck && pnpm lint && pnpm test && pnpm test:int
```
