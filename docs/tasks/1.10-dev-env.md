# 1.10 — Containerised dev environment
status: done
milestone: M1 · deps: 1.1 · branch: task/1.10-dev-env

## Goal
Make development fully offline and portable (D-11): one command brings up every external dependency in Docker,
with mocks standing in for every third-party API, so a new machine needs only Docker + Node + pnpm and no keys.

## Context
D-11 (services, ports, env rules), D-12, D-13. Other local projects on this machine already use 5432, 6379,
1025, 8025 — use exactly the D-11 ports. Compose project name `oat`.

## Scope
In:
- `docker-compose.yml` at repo root: `postgres` (pgvector/pgvector:pg17, db `oat`, user/pass `oat`/`oat`,
  init script enabling `vector` + `pg_trgm` extensions, volume), `redis` (redis:7-alpine), `mailpit`
  (axllent/mailpit), `oauth` (ghcr.io/navikt/mock-oauth2-server, configured with an issuer `google` that
  issues id_tokens with `email`, `email_verified`, `name`, `picture` claims; support non-interactive login
  for tests and interactive login form for humans), `mocks` (built from `tools/mocks/Dockerfile`). All with
  healthchecks so `docker compose up -d --wait` returns only when healthy. Pin image tags.
- `tools/mocks` (`@oat/mocks`): TypeScript Node service (Hono + @hono/node-server; `ws` for websockets later),
  plugin structure `src/providers/<name>.ts` each mounted under `/<name>` (e.g. `/llm`, `/stt`, `/notion`,
  `/gcal` — only register the skeleton + `GET /health` + an example provider now; real providers come in
  2.2/4.1/7.4/8.1). Request log ring-buffer at `GET /_requests` (handy for tests asserting calls were made),
  `POST /_reset`. Unit tests with Hono's `app.request()`. Dockerfile (node:24-alpine, multi-stage, small).
  Also runnable natively with `pnpm --filter @oat/mocks dev`.
- `packages/testkit` (`@oat/testkit`): `createTestDatabase()` → creates `oat_test_<random>` on the compose
  Postgres via admin URL, returns `{url, drop()}`; `mailpit` helper (list/get latest message for an address,
  extract first link); `waitFor` utility. Integration tests (`*.int.test.ts`) prove each helper works against
  the running stack.
- Root scripts: `dev:up` (copies `.env.example` → `.env` if missing, then `docker compose up -d --wait`),
  `dev:down`, `dev:reset` (down -v — dev data only), `dev:logs`, `dev:ps`. Use a tiny node script in
  `scripts/` rather than shell-isms so it works on Linux/macOS.
- `.env.example` with every var, defaults pointing at the containers (`DATABASE_URL`, `REDIS_URL`, `SMTP_*`,
  `OAUTH_GOOGLE_ISSUER`/client id/secret placeholders, `MOCKS_URL`, `AI_*`, `DEEPGRAM_*` left blank = use mock)
  with comments saying which real service each replaces.
- `docs/DEV.md`: prerequisites, "new machine in 3 commands", service/port table, how mocks work, how to
  switch a provider to the real thing with a key, troubleshooting (port clash, `dev:reset`).
Out: app code, DB schema (1.5), auth wiring (1.6), real provider mocks (later tasks), CI (1.2), web Dockerfile (1.9).

## Design notes
Implementer, 2026-11-14.

**Layout.** `docker-compose.yml` (project `name: oat`), `docker/postgres/` + `docker/oauth/` (tiny derived
images), `tools/mocks` (`@oat/mocks`), `packages/testkit` (`@oat/testkit`), `scripts/dev.mjs`, `.env.example`,
`docs/DEV.md`.

**Choices + why**
- **Nothing bind-mounted from the repo.** The stack is shared by all worktrees and outlives the worktree that
  started it (this one is deleted after merge). Bind mounts would break on container restart once that path is
  gone, so the Postgres init SQL and the oauth config/login page are baked into `oat-postgres:dev` /
  `oat-oauth:dev` (FROM the pinned upstream images). `dev:up` builds them only if missing; `dev:build` (from main) rebuilds (review round 1).
- **Pinned tags:** `pgvector/pgvector:0.8.7-pg17` (PG 17.12), `redis:7.4.12-alpine`, `axllent/mailpit:v1.33.1`,
  `ghcr.io/navikt/mock-oauth2-server:7.0.0` (= `latest` digest today), `node:24.22.3-alpine`.
- **Ports** exactly D-11, bound to `127.0.0.1` only (no LAN exposure of a passwordless-ish dev DB).
- **Extensions in `template1` too**, so `createTestDatabase()` DBs get `vector` + `pg_trgm` with a plain
  `CREATE DATABASE` (no superuser `CREATE EXTENSION` per test DB).
- **Healthchecks:** postgres uses `pg_isready -h 127.0.0.1` (TCP) so the socket-only init-time server doesn't
  count as healthy; mailpit `/mailpit readyz`; oauth `wget /isalive`; mocks `wget /health`; redis `redis-cli ping`.
- **OAuth issuer `google`:** a `tokenCallbacks` mapping sets `sub`/`email` = login username and
  `email_verified: true`. Mapping claims win over login-form claims (verified), so a test can't spoof `email`,
  while `name`/`picture` come from the form. Custom offline login page (`docker/oauth/login.html`, no external
  fonts, our own markup): email + optional name/picture; JS fills defaults (name = local part, picture = SVG
  data-URI initial). Tests are non-interactive by POSTing `username` + `claims` to `/authorize` and following
  the 302 (see `packages/testkit/src/stack.int.test.ts`).
- **Mocks service:** Hono `createApp({providers, logCapacity})` → `{app, log, providers}`. Providers are
  factories (`() => {name, description, app, reset?}`) so each app instance has isolated state (unit tests).
  Names validated (lowercase, not `health`/`_requests`/`_reset`, no dupes). Logging middleware records provider
  calls only (not `/health`, `/_*`), reads the body via Hono's cached `c.req.text()` (providers can still
  `c.req.json()`; tested), redacts `authorization`/`x-api-key`/`api-key`/`cookie` values but keeps the scheme.
  Ring buffer default 500, ids monotonic across `_reset`, filters `provider`/`since`/`limit`. JSON 404/500.
  Only `example` provider (echo + counter + `/example/ws` echo) as the template for 2.2/4.1/7.4/8.1.
- **Mocks image:** esbuild bundle → single `main.js` (~244 kB with `ws`; `createRequire` banner + bufferutil/utf-8-validate external) in `node:24.22.3-alpine`, no `node_modules` in
  the runtime stage, `USER node`. Build installs with `pnpm install --frozen-lockfile --filter @oat/mocks`
  using the repo lockfile/catalog (root `.dockerignore` keeps context small). D-15 allows a build step for a
  package that runs under plain Node. Natively: `pnpm --filter @oat/mocks dev` (`tsx watch`), env
  `MOCKS_PORT` (default 14010) / `MOCKS_HOST` (default 127.0.0.1; 0.0.0.0 in the image). Named `MOCKS_*`
  rather than `PORT` so it never picks up another tool's `PORT`.
- **Root `pnpm dev` excludes `@oat/mocks`** (`turbo run dev --filter=!@oat/mocks`): the container already owns
  :14010, so the D-11 flow `dev:up && dev` would otherwise fail with EADDRINUSE.
- **Testkit:** `createTestDatabase()` → `{name, url, drop()}`; name `oat_test_<base36 ms>_<8 hex>` (safe identifier, encodes creation time),
  `drop()` = `DROP DATABASE … WITH (FORCE)`, idempotent. Admin URL = `OAT_DATABASE_ADMIN_URL` or
  `DATABASE_URL` with db `postgres`. `createMailpit()` → `listFor/get/latestFor/waitForLatest/delete`, plus
  `uniqueAddress()` and `extractFirstLink()` (first http(s) `href`, entities decoded, else first URL in text).
  No "delete all mail" helper on purpose: Mailpit is shared across parallel worktrees. `waitFor(fn)` polls
  until non-`undefined/null/false`, retries through throws, timeout error carries the last error as `cause`.
  Env readers default to the compose ports, so tests run without a `.env` (turbo passes env through).
- **Dev scripts:** `scripts/dev.mjs` (plain Node, `spawnSync('docker', ['compose', …])`), extra args
  forwarded (`pnpm dev:logs mocks`); `up` copies `.env.example` → `.env` if missing and prints `ps`.
- **New env vars:** `MAILPIT_URL` (added to turbo `passThroughEnv` for `test:int` + `dev`),
  `OAT_DATABASE_ADMIN_URL` (covered by `OAT_*`), `AI_GATEWAY_API_KEY/BASE_URL`, `DEEPGRAM_API_KEY/BASE_URL`
  (covered by `AI_*`/`DEEPGRAM_*`). `MOCKS_PORT`/`MOCKS_HOST` are only read by the mocks process itself.
- **Catalog additions:** `hono`, `@hono/node-server`, `esbuild`, `tsx`, `pg`, `@types/pg`, `nodemailer`,
  `@types/nodemailer`. `onlyBuiltDependencies: [esbuild]` in `pnpm-workspace.yaml` (its postinstall).

**Outside the listed scope (small, noted):** `eslint.config.js` node-globals block now also matches
`scripts/**` (no package lints root files today, so this only matters for a root `eslint .`); root `package.json`
`dev` script filter; `pnpm-workspace.yaml` `onlyBuiltDependencies`; extra `stack.int.test.ts` in testkit
(oauth login flow + redis PING smoke tests, no helper API added).

**Known limits / follow-ups:** stateful providers used via the *container* still share state across worktrees
(tests should use `startMocks()`; an `x-oat-mock-scope` header was not added). Compose still recreates a service
whose definition differs between checkouts, so compose/`docker/` changes should only be brought up from main.

## Review
**Reviewer, 2026-11-14, round 1 — verdict: `changes`.** Read the task file + `git diff main...task/1.10-dev-env`.
Acceptance criteria are met on paper (D-11 ports, 127.0.0.1-only binds, pinned tags, healthchecks, `.env`
git-ignored and docker-ignored, no real secrets, testkit names/drop/cleanup sound, turbo `MAILPIT_URL`
passthrough added). Three problems break the "parallel worktrees share one stack" promise or mislead readers:

1. **Any worktree's `dev:up` swaps the shared stack to its own checkout.** `scripts/dev.mjs:14` runs
   `up --build --remove-orphans`, so when worktree A (say 2.2, adds `stt`) and worktree B (4.1, adds `llm`) each
   run `dev:up`, the last one rebuilds `oat-mocks:dev` and recreates the container. The other worktree's
   provider int tests then 404, and every recreate (mocks/postgres/oauth) kills connections for runs already in
   progress. `--remove-orphans` likewise deletes services that only another branch defines. DEV.md:60 and :85
   present this as a feature. Fix: integration tests for a provider run the mocks **in process**. Add a helper
   (e.g. `startMocks()` in `@oat/mocks` or testkit that does `createApp()` + `serve({port: 0})` and returns
   `{url, log, close}`) and say in DEV.md that provider tests use it. The shared container serves `pnpm dev` and
   whatever is on `main`. Make `dev:up` stop passing `--build`/`--remove-orphans` by default, add an explicit
   `dev:build` (or `dev:up --build`) and document when to use it.
2. **The shipped int test resets the shared mocks globally.** `tools/mocks/src/mocks.int.test.ts:36` calls
   `POST /_reset` on every `pnpm test:int`, which wipes other worktrees' request logs and provider state in the
   middle of their runs. That goes against DEV.md's own advice to avoid `/_reset`. Fix: support a scoped reset,
   `POST /_reset?provider=<name>`, which drops only that provider's log entries and calls only its `reset()`
   (`tools/mocks/src/app.ts:97`, plus a `RequestLog.clear(provider?)`). The int test should use the scoped form;
   the unscoped reset stays for humans.
3. **Nothing loads the root `.env`, but DEV.md says it does.** DEV.md:111 says env vars from `.env.example`
   override the testkit defaults, and DEV.md:92 says to switch to real providers by editing `.env`. No code reads
   `.env`. Turbo `passThroughEnv` only forwards exported shell vars, and Next.js would read `apps/web/.env*`, not
   the root. Editing `.env` today changes nothing (only compose reads it, for interpolation it doesn't use).
   Fix: either load it for int tests (e.g. `process.loadEnvFile()` on the root `.env` when present, in
   `vitest.shared.ts` int mode) and note that apps must load the root `.env` (1.6/1.9), or reword DEV.md to
   "exported shell env overrides; root `.env` is consumed once apps wire it".

Optional:
- `MockProvider` has no way to do websockets. `stt` (2.2) will need `createNodeWebSocket({app})` from the root
  app and `injectWebSocket(server)` in `main.ts`. Consider changing the factory signature now to
  `(ctx: { upgradeWebSocket }) => MockProvider`. The logger records only the upgrade, not frames, which is fine.
- Stateful providers (notion/gcal) will share state across worktrees. An optional `x-oat-mock-scope` header
  that namespaces state and log entries would solve this cleanly, if in-process mocks (item 1) aren't enough.
- `createTestDatabase()` will run `CREATE DATABASE` against any host. Refuse a non-loopback admin URL unless
  `OAT_DATABASE_ADMIN_URL` is set explicitly, so `DATABASE_URL=<Neon>` in a shell can't touch prod.
- Agents may not run `dev:reset`, so leaked `oat_test_*` databases never go away. Add a small sweeper (drop
  `oat_test_*` older than N hours) or a `dev:clean-test-dbs` script.
- `tools/mocks/Dockerfile` doesn't copy `tsconfig.base.json`, which `tools/mocks/tsconfig.json` extends. esbuild
  warns and ignores it; copy the file to keep the bundle on the same TS settings.
- DEV.md troubleshooting: `lsof` is often missing on Linux. Mention `ss -ltnp`.
- mock-oauth2-server builds the issuer from the Host header. Once `web` runs in compose (1.9), it must reach
  oauth as `localhost:18089` (or set a fixed issuer), or `iss` won't match `OAUTH_GOOGLE_ISSUER`.

**Resolution, round 1 (implementer, 2026-11-14)** — all 3 required items + optional (a), (b), (c), (d), plus the
`ss` and oauth-issuer DEV.md notes:
1. `dev:up` = `up -d --wait` (no `--build`/`--remove-orphans`; compose builds local images only if missing).
   New `pnpm dev:build` = `up -d --wait --build`, documented as main-checkout-only. Verified: a second `dev:up`
   builds/recreates nothing (same container ids). New `startMocks({port=0, hostname})` in `@oat/mocks`
   (`src/server.ts`) → `{url, port, log, providers, close}`; `main.ts` uses it too. `mocks.int.test.ts` now tests
   `/_requests` + scoped reset against an in-process instance; the container gets a read-only smoke test
   (`/health`, `GET /_requests`). DEV.md "Container vs in-process" + "Shared stack rules".
2. `RequestLog.clear(provider?)`; `POST /_reset?provider=<name>` clears that provider's log entries + calls only
   its `reset()`, 404 for unknown names. No test calls the container's `/_reset`.
3. `vitest.shared.ts` int mode: `process.loadEnvFile(<root>/.env)` when it exists (shell vars win; verified by
   pointing `.env` `MOCKS_URL` at a dead port → container tests fail, `MOCKS_URL=… pnpm test:int` → pass). DEV.md
   says who reads root `.env` (int tests now; apps must load it in 1.6/1.9).
- (a) `MockProvider.websockets?: {path, handle(socket, req, url)}[]`, raw `ws` sockets via one
  `WebSocketServer({noServer})`; `createApp` returns `handleUpgrade`/`closeWebSockets`, `startMocks` wires
  `server.on('upgrade')`. Upgrades are logged (101/404). Chose plain `ws` over `@hono/node-ws` (its peer is
  `@hono/node-server@^1`, we're on v2). Tested: text + binary echo, unknown path rejected, close() terminates.
  Bundled image verified (separate `oat-mocks:verify` container): healthy, ws echo, scoped reset.
- (b) `assertLocalDatabase()`: create/drop/sweep refuse non-loopback hosts unless `OAT_TESTKIT_ALLOW_REMOTE_DB=1`.
- (c) `sweepStaleTestDatabases({olderThanMs=1h})` drops `oat_test_*` whose name-encoded timestamp is older;
  `createTestDatabase()` runs it once per process, best effort. Int test: leaked DB dropped, fresh one + `oat` kept.
- (d) mocks Dockerfile copies `tsconfig.base.json`.

created so far): `dev:reset && dev:up` exit 0, 5/5 healthy, `/health` 200, discovery 200, vector + pg_trgm,
