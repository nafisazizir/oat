# 3.9 — Desktop workspace switcher (meetings into team workspaces)
status: done
milestone: M3/M5 · deps: 9.2, 5.1, 2.6 · branch: task/3.9-desktop-workspaces

## Goal
Found by 9.4: the desktop records only into the personal workspace and notes can't move between workspaces
(D-18), so a team can't get a recorded meeting except via public link. Let the user choose the workspace on
desktop: a switcher (like web), new meeting notes go into the active workspace, and "Start notes" from calendar /
detection uses the active workspace (or a per-event remembered choice).

## Context
D-18 (no cross-workspace moves in v1 — keep), D-19/D-28 (per-user local DB holds all the user's workspaces' rows
it can read), D-30, `@oat/core` permissions (canCreateInWorkspace; viewers can't), desktop sidebar + meeting view,
web workspace switcher (1.6/5.1) for consistency.

## Scope
In:

  and Upcoming filtered/annotated by workspace; "New meeting note" + calendar/detection "Start notes" create in

- Meeting header shows the workspace; visibility defaults per D-18/D-25 (private by default; share dialog on web).

## Design notes
(implementer)

**Knowing my role on the desktop.** The local cache had workspaces without roles, so it couldn't tell whether new
notes may go to a team workspace. The sync protocol's workspace row now carries the pulling user's `role`
(`syncWorkspaceRowSchema.role`, nullable + default `null` for old rows) and `SYNC_PULL_SCOPE` is 3, so every
client re-pulls from the start once and gets roles. Server pull (`apps/web/src/server/sync/pull.ts`): workspace
rows carry `roleIn(actor.ctx, id)`; a `membership` change in the change log (role change, someone joining/leaving)
is mapped to "re-send workspace W", so a promotion/demotion reaches the desktop through the existing SSE → pull
path within seconds. Local store migration 4 adds `workspace.role`; `LocalStore.workspace(id)` added. No Postgres
migration.

**Main process** (`apps/desktop/src/main/workspaces.ts`, `Workspaces`): `snapshot()` = my workspaces (personal
first, then teams by name), each with `role` and `canCreate` (`canCreateInWorkspace` from `@oat/core` permissions
on a context built from the synced roles; a personal workspace with no role yet counts as mine), the `activeId`
and the `targetId` where new notes go: the active workspace when `canCreate`, else personal. The active workspace
is stored in the account's own local database (`sync_state` key `desktop.activeWorkspace`): one DB file per
account (D-28), so the choice is per account per Mac and survives relaunches; a workspace that disappears falls
back to personal. `newNoteWorkspace()` = `targetId`, or (fresh DB) waits for sync to learn the personal workspace
as before. `MeetingPersistence` ("New meeting note", detection "Start notes" → `recording:start`) and
`MeetingNotes.fromEvent` (calendar "Start notes", prompt banner, notification) take an optional
`newNoteWorkspace` and use it instead of the personal workspace. Notes still go in private and at the root, and
never move afterwards (D-18); the server re-checks create rights on every push. Bonus of knowing roles:
`MeetingNotes` marks notes in a workspace where I'm a viewer as view-only (instead of letting edits park).
Bridge: `workspaces:list`, `workspaces:set-active` (`bridge-meetings.ts`); windows reload on `meetings:changed`,
which already fires after every sync run and now on a switch.

**Renderer.** `WorkspaceSwitcher` at the top of the sidebar (dropdown like the web's: tile, name, "Personal
space" / role; check on the active one). When the active workspace is view-only, a hint under it: "You can view
X but not add notes to it. New notes go to Personal." The meeting list shows the active workspace's notes only
(empty state names the workspace); the recording-note auto-open still looks at all notes. "Upcoming" rows whose
note lives in another workspace say "· in <workspace>". The note header has a workspace badge (layers icon) before
the visibility badge. No per-event remembered workspace (the goal's "or"): the active workspace decides.

**Tests.** Unit: `workspaces.test.ts` (ordering, canCreate, persistence across instances, viewer fallback, role
change / left workspace, unknown roles, fresh DB wait; recording and calendar notes land in the target; viewer
notes view-only), renderer `workspaces-state.test.ts`, local-store role test. Int (`sync.int.test.ts`): a member's
recording into a team workspace is created private + theirs; a viewer's document/meeting/segment are rejected
(`forbidden`); after demotion new notes and more segments are rejected; pull rows carry roles and a role change
re-sends the row. Desktop e2e `apps/desktop/e2e/workspaces.spec.ts`: teams added in Postgres arrive by SSE with
roles; Design team (member) → list filtered → recording lands there (Postgres check); Board (viewer) → hint,
Upcoming "Start notes" lands in Personal, annotated; demotion follows, note becomes view-only; active workspace
survives a relaunch. Acceptance journey (`e2e/acceptance/journey.spec.ts`) new last step: the owner's desktop
gets the team workspace by sync, switches to it, records "Team retro"; the teammate can't open it while private;
the owner picks "Workspace" in the web share dialog; the teammate finds it in their team sidebar and opens it
(`GET /api/documents/:id` 200) — no link. The web half of 3.9 is covered there (no web product change was
needed); the teammate context now stays open until that step.

**Out of scope touched:** test fixtures in existing local-store/desktop unit tests gained `role` on workspace rows
(type change). 9.4's evidence files were regenerated by my local acceptance run and reverted (not part of 3.9).

## Review
**Reviewer (2026-11-15) — verdict: approve** (diff `main...task/3.9-desktop-workspaces` @ 886b1b1 + task file only).

Checked:
- **Server push authz (the important one):** unchanged and sufficient. A new document goes through
  `roleIn` (non-member → `not_found`) → live workspace → `canCreateInWorkspace` (viewer → `forbidden`), and is
  always inserted `visibility: 'private'`, `ownerId: actor` (D-25 default; the client can't choose). Updates
  reject a changed `workspaceId` ("can't move between workspaces", D-18). Meetings/segments need an editable
  document, so a demoted member's later segments are refused. The new int test pushes over HTTP as a member
  (ok, private, theirs), as a viewer (doc `forbidden`, meeting + segment rejected, nothing in Postgres) and after
  demotion (new doc + segment for the earlier note `forbidden`), with the `denies('POST /api/sync/push')` marker.
  Pre-existing outsider tests cover non-members (`not_found`).
- **Pull:** role comes from the server's `roleIn(actor.ctx, …)` for the puller; `membership` is in the change log
  (`membership_change_log` trigger), mapped to "re-send workspace W"; unreadable/deleted still skipped. Scope bump
  to 3 forces one full re-pull (`store.ts` resets the cursor on scope mismatch). Pull test checks owner/member/
  personal roles and that a demotion re-sends the row.
- **Desktop:** `canCreate` from `@oat/core` `canCreateInWorkspace` on synced roles; unknown team role → can't
  create (fails closed → personal). Revoked membership: the workspace drops out of `workspaceIds` →
  `#dropWorkspacesExcept` deletes its rows locally → snapshot falls back to personal. Active workspace lives in
  the account's own DB (`sync_state`, D-28) so it is per account and survives relaunch; `setActive` refuses ids
  not in the local store. Viewer notes are view-only locally. All creation paths (`MeetingPersistence`, the only
  create in `MeetingNotes.fromEvent`) use `newNoteWorkspace`; no other `personalWorkspace` callers remain.
- **D-30:** audio indexing/scoping untouched (still per recording account); no audio is synced. **D-18:** no move
  path added. **D-11:** no new external calls (e2e uses FileSource + calendar JSON; acceptance uses the existing
  mocks). **Clean room:** copy and UI are original; nothing from `research/granola/`.
- Acceptance journey step 9: owner records into the team workspace on desktop → teammate gets non-200 while
  private → owner shares "Workspace" (no link) → teammate finds it in the team tree and opens it (200). Meets the AC.
- Ran: desktop vitest (workspaces, renderer workspaces, meeting-notes, meeting-persistence) 24/24 pass;
  `@oat/local-store` test 79/79 pass; typecheck desktop/web/core/local-store clean; desktop lint clean. Did not run
  int/e2e/CI (implementer's run in this worktree; verifier's job).

Non-blocking notes (suggest `docs/IDEAS.md`, no change needed for 3.9):
1. Viewer fallback: a note recorded while a view-only workspace is active goes to Personal (correct) but the
   Meetings list stays filtered to the active workspace, so the new note is opened but not listed until the user
   switches. Consider listing it or a "saved to Personal" toast.
2. A team workspace whose role is still `null` (until the scope-3 re-pull lands) shows the viewer hint
   "You can view X but not add notes" — fails closed, transient, copy slightly inaccurate.
3. Demotion/removal during a recording: the server refuses further segments (parked, D-28) and removal deletes the
   local rows, but the recording UI doesn't say so. Pre-existing leave-workspace behaviour; out of 3.9's scope.
