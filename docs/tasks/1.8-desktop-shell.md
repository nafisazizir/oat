# 1.8 — `apps/desktop`: Electron shell, typed bridge, deep-link auth
status: in-progress
milestone: M1 · deps: 1.4, 1.6 · branch: task/1.8-desktop-shell

## Goal
The macOS desktop app skeleton everything desktop-side plugs into: hardened Electron + electron-vite, one
renderer bundle with route-per-window, a typed preload bridge, a small main-owned live-state store, and
sign-in via the browser + `oat://` deep link with the session token stored securely.

## Context
SPEC §5 (desktop), §8 (no secrets in renderer; cold start < 2 s), PLAN 1.8 text, D-5, D-8, D-15 (bundle
`@oat/*` in main/preload, don't externalise), `research/granola/bundle-map.md` (structure reference:
route-per-window, sender checks, hardened fuses, main-owned sequenced store). `@oat/ui`, `@oat/auth`
(1.6, bearer plugin), `apps/web` (sign-in pages). `@oat/audio/node` (SidecarSource — `OAT_AUDIO_BIN` must be
dev-only per 2.4 notes; packaged path later in 9.1).

## Scope
In:
- `apps/desktop` (`@oat/desktop`): electron-vite (main/preload/renderer), React renderer using `@oat/ui`
  styles/tokens; windows: `main` (app shell) and `widget` (small always-on-top in-meeting widget placeholder),
  both from one renderer bundle selecting UI by route.
- Security: contextIsolation, sandbox, no nodeIntegration, CSP, `setWindowOpenHandler` deny + open external
  links in browser, navigation guard, `@electron/fuses` hardening config for packaging (RunAsNode off,
  OnlyLoadAppFromAsar, cookie encryption on, etc.).
- Typed bridge: contract in `packages/core/src/bridge.ts` (zod schemas for invoke/send/subscribe channels);
  preload exposes `window.oat` generated from it; main registers handlers through one helper that validates
  payloads and checks the sender frame URL is our renderer; tests for the helper (reject foreign sender,
  invalid payload).
- Main-owned store: small sequenced state (auth status, recording status placeholder, active meeting id)
  broadcast to windows with seq numbers; renderer hook `useMainState()`.
- Auth: "Sign in" opens the system browser to `apps/web` `/desktop/sign-in?state=…` (add this page in
  apps/web: after sign-in it issues a one-time code and redirects to `oat://auth?code=…&state=…`); main
  exchanges the code for a bearer session token via an API route (add it), stores the token with
  `safeStorage` (Keychain-backed) in userData, never exposes it to the renderer; sign-out revokes. Register
  the `oat://` protocol (dev: `app.setAsDefaultProtocolClient` with dev args) + single-instance lock.
- API client in main (fetch with bearer token) used via bridge `invoke('api:me')` smoke.
- Tests: unit (bridge, store, deep-link parsing, state/CSRF check); Playwright `_electron.launch` e2e:
  app launches, main window renders shell, sign-in flow simulated by invoking the deep-link handler with a code
  obtained from the web API in-test (against compose stack + test DB), `api:me` returns the user, token not
  readable from renderer (`window.oat` has no token). Cold-start time measured and recorded.
Out: recording UI (2.5), SQLite (2.6), packaging/signing (9.1).

## Acceptance criteria
- [ ] `pnpm --filter @oat/desktop dev` opens the app; e2e passes headless-ish on macOS.
- [ ] Deep-link auth works end-to-end in the test; token stored via safeStorage; renderer cannot read it.
- [ ] Sender checks + payload validation enforced (tests).
- [ ] `pnpm run ci` green (add the desktop e2e to the ci e2e step).
