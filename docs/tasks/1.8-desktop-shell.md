# 1.8 — `apps/desktop`: Electron shell, typed bridge, deep-link auth
status: done
milestone: M1 · deps: 1.4, 1.6 · branch: task/1.8-desktop-shell

## Goal
The macOS desktop app skeleton everything desktop-side plugs into: hardened Electron + electron-vite, one
renderer bundle with route-per-window, a typed preload bridge, a small main-owned live-state store, and
sign-in via the browser + `oat://` deep link with the session token stored securely.

## Context
SPEC §5 (desktop), §8 (no secrets in renderer; cold start < 2 s), PLAN 1.8 text, D-5, D-8, D-15 (bundle
`@oat/*` in main/preload, don't externalise), `research/granola/bundle-map.md` (structure reference:
route-per-window, sender checks, hardened fuses, main-owned sequenced store). `@oat/ui`, `@oat/auth`
(1.6, bearer plugin), `apps/web` (sign-in pages). `@oat/audio/node` (SidecarSource — `OAT_AUDIO_BIN` must be
dev-only per 2.4 notes; packaged path later in 9.1).

## Scope
In:
- `apps/desktop` (`@oat/desktop`): electron-vite (main/preload/renderer), React renderer using `@oat/ui`
  styles/tokens; windows: `main` (app shell) and `widget` (small always-on-top in-meeting widget placeholder),
  both from one renderer bundle selecting UI by route.
- Security: contextIsolation, sandbox, no nodeIntegration, CSP, `setWindowOpenHandler` deny + open external
  links in browser, navigation guard, `@electron/fuses` hardening config for packaging (RunAsNode off,
  OnlyLoadAppFromAsar, cookie encryption on, etc.).
- Typed bridge: contract in `packages/core/src/bridge.ts` (zod schemas for invoke/send/subscribe channels);
  preload exposes `window.oat` generated from it; main registers handlers through one helper that validates
  payloads and checks the sender frame URL is our renderer; tests for the helper (reject foreign sender,
  invalid payload).
- Main-owned store: small sequenced state (auth status, recording status placeholder, active meeting id)
  broadcast to windows with seq numbers; renderer hook `useMainState()`.
- Auth: "Sign in" opens the system browser to `apps/web` `/desktop/sign-in?state=…` (add this page in
  apps/web: after sign-in it issues a one-time code and redirects to `oat://auth?code=…&state=…`); main
  exchanges the code for a bearer session token via an API route (add it), stores the token with
  `safeStorage` (Keychain-backed) in userData, never exposes it to the renderer; sign-out revokes. Register
  the `oat://` protocol (dev: `app.setAsDefaultProtocolClient` with dev args) + single-instance lock.
- API client in main (fetch with bearer token) used via bridge `invoke('api:me')` smoke.
- Tests: unit (bridge, store, deep-link parsing, state/CSRF check); Playwright `_electron.launch` e2e:
  app launches, main window renders shell, sign-in flow simulated by invoking the deep-link handler with a code
  obtained from the web API in-test (against compose stack + test DB), `api:me` returns the user, token not
  readable from renderer (`window.oat` has no token). Cold-start time measured and recorded.
Out: recording UI (2.5), SQLite (2.6), packaging/signing (9.1).

## Design notes
(implementer, 2026-11-14)

**Package and build.** New `apps/desktop` (`@oat/desktop`, productName "Oat"). Catalog: `electron ^45.3.2`
(45.3.2), `electron-vite ^6.0.0`, `@electron/fuses ^2.1.3`. Electron 45 has no postinstall: the binary is
downloaded on first use (`node_modules/electron/install.js`), so `onlyBuiltDependencies` is unchanged.
`electron.vite.config.ts`: main → `out/main/index.js` (ESM), preload → `out/preload/index.cjs` (CJS, one
self-contained file, as sandboxed preloads require), renderer (React + Tailwind via `@tailwindcss/vite`,
minified). `externalizeDeps: false` for main and preload (D-15: `@oat/*` are TS source; everything is
bundled, only `electron` + Node built-ins stay external).

**Windows / renderer.** One renderer bundle; the hash selects the window (`#/main`, `#/widget`), each
window's UI is a lazy chunk. Main window: hidden-inset title bar with a drag region, centred account card
(states: restoring skeleton, signed out, signing in, signed in), footer with version + cold start. Widget:
frameless always-on-top `panel` (320×136, visible on all spaces) showing the recording placeholder + account
from the shared store; opened from the main window ("Show meeting widget", signed in only). All from
`@oat/ui` (Card, Button, Input, Label, Skeleton) and tokens; theme follows the OS (`.dark`).
- The built renderer is served from the privileged standard scheme **`app://oat/`** (`protocol.handle`; path
  resolution in `renderer-files.ts` refuses traversal, encoded NUL/backslash, other hosts) so it has a real
  origin for the CSP and the sender check; no `file://`.

**Security.**
- `webPreferences`: `contextIsolation`, `sandbox`, no `nodeIntegration` (incl. workers), `webSecurity`, no
  webview tag, no drag-drop navigation, devtools only in dev (or `OAT_DEVTOOLS=1`).
- `web-contents-created` hardening: `setWindowOpenHandler` → deny, and http(s) without credentials → system
  browser; `will-navigate` outside our origins → blocked (http(s) → browser); `will-redirect` likewise;
  `will-attach-webview` blocked. Permission request/check handlers deny everything (capture is the sidecar's).
- CSP (`security.ts`), as a response header. Builds: `default-src 'none'; script-src 'self'; style-src 'self'
  'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; base-uri 'none';
  form-action 'none'; frame-ancestors 'none'; object-src 'none'`. Dev (via `onHeadersReceived`, dev-server
  responses only) adds inline scripts (React refresh preamble) and `ws://localhost:*` (HMR).
- Fuses (`src/build/fuses.ts`: `OAT_FUSES` + `applyFuses()` for 9.1's after-pack hook,
  `strictlyRequireAllFuses`): RunAsNode off, NODE_OPTIONS off, `--inspect` args off, cookie encryption on,
  embedded asar integrity on, only-load-from-asar on, file-protocol extra privileges off, browser-specific
  V8 snapshot off, Wasm trap handlers on (default). Not applied in dev/e2e (stock binary; Playwright needs
  the inspector).
- `OAT_AUDIO_BIN` dev-only: `src/main/sidecar.ts` `sidecarLocateOptions()` strips it when packaged (pass the
  result to `@oat/audio/node` `locateSidecarBinary` / `@oat/calendar`; first used by 2.5). Likewise every
  desktop env override (`OAT_WEB_URL`, `OAT_USER_DATA_DIR`, `OAT_E2E`) is ignored when packaged (`config.ts`):
  nothing in the environment may point a released app's bearer token at another server.

**Typed bridge.** Contract `packages/core/src/bridge.ts` (exported from `@oat/core` and `@oat/core/bridge`):
`bridgeContract.{invoke,send,subscribe}` with zod schemas; derived types (`InvokeChannel`, `InvokeArgs`,
`InvokeResult`, `OatBridge`…), `bridgeChannels`, shared shapes (`MainState`, `DesktopUser`, `AppInfo`).
Channels: invoke `app:info`, `state:get`, `auth:sign-in`, `auth:cancel-sign-in`, `auth:complete-from-link`,
`auth:sign-out`, `api:me`, `window:open-widget`, `window:close-widget`; send `app:rendered`,
`shell:open-external`; subscribe `state:changed`.
- Preload (`src/preload/index.ts`) exposes `window.oat = { version, platform, invoke, send, subscribe }`,
  refusing any channel not in the contract before IPC; no `ipcRenderer`, no Node, no token.
- Main: `createBridge({ ipcMain, isTrustedSender, log })` (`src/main/ipc.ts`) is the only registration path.
  Per call: the sender must be a **main frame** (`senderFrame.parent === null`) whose URL origin is
  `app://oat` (or the dev-server origin in dev; `originOf` builds `app:` origins by hand because Node's
  `URL#origin` is `"null"` for non-special schemes), else `forbidden`; the payload is parsed with the channel
  schema (wrong type, missing, oversized, extra args, payload on a no-payload channel → `invalid_payload`);
  the handler's response is parsed too (unknown fields stripped, invalid → `internal`); a thrown
  `BridgeError(code)` → that code; anything else → `internal` with a generic message (details only in the
  main log). Invoke results are values (`{ok,value}|{ok:false,error:{code,message}}`), not rejections,
  because Electron flattens thrown errors. Pushes are parsed before `webContents.send` and only go to
  windows whose main frame is trusted. The renderer's `call()` unwraps into `BridgeCallError`.

**Main-owned store.** `MainStore` (`src/main/store.ts`): `{ auth, recording: {status}, activeMeetingId }`,
immutable updates, schema-checked, `seq` +1 per change (no-op updates don't bump), every change pushed as a
full snapshot on `state:changed`. Volatile: fresh each launch; auth starts `restoring`. Renderer:
`createMainStateClient` subscribes **before** calling `state:get` and keeps the higher `seq`, so an
overtaking push or a stale reply can't roll a window back; `useMainState()` via `useSyncExternalStore`.

**Deep-link auth** (shared protocol in `packages/auth/src/desktop-link.ts`, dependency-free so main bundles
it without Better Auth): an authorization code with PKCE (RFC 7636 S256).
1. Main: `state` + `verifier` (32 random bytes, base64url, 43 chars), memory only, one pending sign-in,
   10-minute timeout. Opens `${web}/desktop/sign-in?state&challenge` with `shell.openExternal`.
2. Web page `apps/web/src/app/(auth)/desktop/sign-in/page.tsx`: invalid params → "This link is incomplete";
   signed out → `/sign-in?next=<this page>` (both sign-in methods come back); signed in → shows the account
   and "Continue to the app" (`desktop-handoff.tsx`) → `POST /api/auth/desktop/code` (cookie session; Better
   Auth's origin check refuses cross-site) → `{ redirectUrl: "oat://auth?code&state" }` →
   `window.location`. Then "Back to the app" with "Open Oat again" and "Copy link for the app". "Use a
   different account" signs out and returns via sign-in. No-index, `Referrer-Policy: same-origin`.
3. Main receives the link (macOS `open-url`, queued until ready; `second-instance` argv on Windows/Linux; or
   pasted into the app's fallback field → `auth:complete-from-link`, same path). `parseDesktopDeepLink`
   accepts only `oat://auth?code=<43>&state=<43>` (no other host/path/port/credentials/fragment, no repeated
   params). No pending sign-in, expired, or `state` mismatch (constant-time compare) → **ignored** (logged):
   a forged link neither signs in nor cancels the real attempt. A match consumes the pending sign-in, then
   `POST /api/auth/desktop/token {code, verifier}` (Node `fetch`, not `net.fetch`, so the response cookie
   never lands in Electron's cookie jar; `redirect: 'error'`, 10 s timeout).
4. Server: the code row is deleted atomically (`DELETE … RETURNING`, so a race redeems it once), must be
   unexpired, and S256(verifier) must equal the stored challenge (constant time) → a **new** session
   (`internalAdapter.createSession`, so the personal-workspace session hook applies) → `setSessionCookie` →
   the bearer plugin's `set-auth-token` header carries the signed token; body `{user}`. Every failure is the
   same 400 `invalid_grant`.
5. Token + user saved with `safeStorage` (`TokenStore`, `<userData>/session.bin`, encrypted JSON, temp file +
   rename, 0600; if OS encryption is unavailable nothing is written and the session lasts until quit). Only
   the user goes into `MainStore`. Launch: stored session → signed in immediately (fast, offline-friendly),
   then `get-session` in the background; 401 → cleared + "Your session ended". `api:me` → bearer
   `GET /api/auth/get-session` → `{ user, activeWorkspaceId }`. Sign-out: bearer `POST /api/auth/sign-out`
   (revokes only the desktop session; offline → local sign-out anyway) + delete the file.
- Dev builds call themselves "Oat Dev" (`app.setName`): own userData and Keychain key ("Oat Dev Safe
  Storage"), never the release's. The single-instance lock lives in userData, so a test profile doesn't
  collide with a running dev app.
- `oat://` registration: packaged → `setAsDefaultProtocolClient('oat')` (Info.plist in 9.1); dev → Electron
  binary + app path, removed again on `will-quit`; `OAT_E2E=1` or `OAT_REGISTER_PROTOCOL=0` → never.

**`packages/auth` changes (why needed).** Creating the desktop session and its signed token has to happen
inside Better Auth (session hooks, cookie signing, `set-auth-token`), which means a plugin registered in
`createAuth`. New `src/desktop.ts` (`desktopAuth({ db })`, endpoints `/desktop/code` and `/desktop/token`,
served by the existing `/api/auth/[...all]` route, so no new Next route file was needed) and
`src/desktop-link.ts` (shared, dependency-free); `server.ts` registers the plugin before `bearer`; `index.ts`
exports. Codes live in `verification` as `desktop-code:<SHA-256>` (value `{userId, challenge}`), 2-minute TTL,
never in plain text. No schema change.

**Cold start.** Main logs and exposes (`app:info`) `process.uptime()` when the main window's first render
arrives (`app:rendered`, sent after the first frame). The e2e asserts < 2000 ms; measured **486 ms** (built
app, Playwright launch; `docs/tasks/evidence/1.8/cold-start.json`), ~600 ms with the Vite dev server.

## Review

### Reviewer (2026-11-14): **changes**
Read: task file + `git diff main...task/1.8-desktop-shell` (security focus). Tests not re-run (verifier's job).

Findings:
1. **Consent-phishing via the web hand-off page → account takeover** —
   `apps/web/src/app/(auth)/desktop/sign-in/page.tsx:52-71`, `desktop-handoff.tsx:61-101`. Anyone can craft
   `/desktop/sign-in?state=S&challenge=S256(attackerVerifier)` and send it to a signed-in victim. The page says
   "The app on this computer will use this account", one click mints a code for the **victim's** account bound
   to the attacker's challenge, and the "Didn't open?" panel then invites the victim to copy the
   `oat://auth?code=…` link. A victim talked into pasting that link to the attacker (support chat, "paste the
   link here") hands over a code the attacker can redeem with their verifier within 2 min → a full session in
   the victim's account. (The reverse — pasting an attacker's link into the victim's app — is already blocked:
   unknown `state` is ignored and the code is bound to the attacker's challenge.) Fix (minimal): on the page,
   above "Continue to the app", state plainly "Only continue if you just chose Sign in in the Oat app on this
   computer. Never share the link this page gives you — Oat will never ask for it."; repeat a one-line warning
   next to "Copy link for the app" (or require that warning to be acknowledged before the copy button shows).
   Add an assertion for the warning text to `apps/web/e2e/desktop-sign-in.spec.ts`. (Stronger option for later,
   not required now: show a short check value derived from `state` in both the app and the page.)
2. **DevTools can be enabled in packaged builds via environment** — `apps/desktop/src/main/windows.ts:41`
   (`process.env.OAT_DEVTOOLS === '1'`) is read unconditionally, contradicting the design note that every env
   override is ignored when packaged (`config.ts`). DevTools on a release renderer gives full use of
   `window.oat` (incl. `auth:complete-from-link`, `api:me`) to anyone who can launch the app with an env var,
   and undercuts the fuses (NODE_OPTIONS / `--inspect` off). Fix: move it into `DesktopConfig` (`devTools`,
   forced `false` when `isPackaged`), pass it to `createWindowFactory`, and add a `config.test.ts` case.

Checked and OK: contextIsolation/sandbox/nodeIntegration off/webSecurity/webviewTag off; prod CSP
(`default-src 'none'`, `connect-src 'self'`, no inline script; dev loosening only for dev-server responses);
permission request + check handlers deny all on the default session (windows use it); window-open deny +
http(s)-only external; will-navigate/will-redirect/will-attach-webview guards; `app://` resolver (scheme/host
pinned, decode + NUL/backslash reject, normalize + `relative` containment); fuses (RunAsNode, NODE_OPTIONS,
inspect off, asar integrity + only-asar, cookie encryption, strict); single-instance lock + `open-url` queue +
`second-instance` argv; bridge (main-frame + exact origin check, no passthrough, preload channel allow-list,
request/response/push zod parsing, errors as codes); PKCE S256 + 43-char CSPRNG values, constant-time state
compare, pending consumed before exchange; server code hashed at rest, 2-min TTL, atomic `DELETE … RETURNING`
single use, bound to user + challenge, wrong verifier burns it, uniform `invalid_grant`; code endpoint needs a
session + Better Auth origin check (cross-site 403 covered by web e2e); new per-desktop session, bearer sign-out
revokes it; token never in renderer/state/URL/logs (logs carry no code or URL); Node `fetch` with
`redirect: 'error'`; safeStorage never falls back to plaintext; packaged config ignores env (except #2).

Optional (non-blocking):
- `auth.ts:88` `beginSignIn` while already signed in replaces `#token` on success without revoking the old
  server session; either refuse when signed in or revoke the previous token after a successful exchange.
- `token-store.ts:53` on Linux, `isEncryptionAvailable()` can be true with the `basic_text` backend; when
  Linux matters, also require `safeStorage.getSelectedStorageBackend() !== 'basic_text'`.
- `/desktop/code` also accepts a bearer session (bearer plugin); harmless (same user), but restricting it to
  cookie sessions would match the documented "signed-in browser" intent.

### Resolution (implementer, 2026-11-14)
Merged current `main` first (clean).
1. **Code phishing.** The copy-link fallback is development-only on both sides.
   - Web: `desktopDevHandoff(env)` (`apps/web/src/lib/env.ts`) is `NODE_ENV !== 'production' &&
     OAT_DESKTOP_DEV_HANDOFF !== '0'`; the env schema refuses `OAT_DESKTOP_DEV_HANDOFF=1` in production. The
     page passes it as `devFallback`; without it, the "Back to the app" panel has only "Open Oat again".
     The button now reads "Copy link for the app (dev)".
   - Every build shows, above "Continue to the app": "Only continue if you just chose Sign in in the Oat app
     on this computer. Never share this link or code." and, after continuing, "Never share this link. Oat
     will never ask for it."
   - App: `AppInfo.packaged`; the paste field ("Dev build: …") renders only when unpackaged, and main refuses
     `auth:complete-from-link` with `forbidden` unless `DesktopConfig.allowDevHandoff` (false when packaged).
   - Device/app name: not shown. Everything the page knows about the requester comes from the URL, which an
     attacker crafts, so a name there would be spoofable and give false reassurance. The page names "the Oat
     app on this computer" instead. (The reviewer's check-value idea remains a later option.)
   - Tests: `env.test.ts` (dev on, `0` off, production off even with `1`, `1` refused in production);
     web e2e runs its server with `OAT_DESKTOP_DEV_HANDOFF=0` (what production forces, since web e2e only runs
     `next dev`) and asserts the warning, the never-share line, "Open Oat again", and **no** copy button;
     the desktop e2e (dev server default) asserts the warning, the copy button and the app's paste field.
2. **DevTools.** `DesktopConfig.devTools` = dev server or `OAT_DEVTOOLS=1`, forced `false` when packaged;
   passed to `createWindowFactory` (no more `process.env` read there). `config.test.ts` covers it.

Optional, all done:
- Re-sign-in revokes the previous server session after a successful exchange (best effort; unit test).
- `TokenStore` treats Linux `basic_text` as unavailable (memory only; unit test with `platform: 'linux'`).
- `/desktop/code` refuses a request with an `Authorization` header (403; int test): browser cookie sessions only.
