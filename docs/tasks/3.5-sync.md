In:

  row equals a sent hash → adopt server version as base, keep the entry, no conflicted copy. Property test.

  side-by-side, "Keep this" / "Keep other" / merge manually; resolving deletes the copy). Server stores the

  participants and segments even if their change_log rows predate the cursor.

  returns quickly with a "lagging" hint; monitor long txns in a dev log.

  the desktop sidebar.
- Tests: property tests (multi-device: desktop A + desktop B + web edits with random network faults → converge,
  conflicted copies only for real concurrent content edits), SSE int (authz: events only for readable
  workspaces; replay), backfill int (share a meeting note → teammate desktop gets transcript), e2e desktop:

## Design notes
(implementer, 2026-11-14)

**Protocol (`@oat/core/sync`).** Push envelope gains `device: {name}`; a document create may carry
`conflictOf`. Pulled document rows gain `conflictOfId/conflictDevice/conflictAt` (defaults null);
`SYNC_PULL_SCOPE` → 2 (clients re-pull once). Pull may say `lagging: true`. New: `syncBackfillResponseSchema`,
`syncEventSchema` `{seq, tables, ids, workspaces?}`, `syncConflictResolveSchema`, `documentContentKey()`
(normalized title + canonical body, the hash input), `documentLines()` / `diffLines()` (compare views,
shared by web and desktop).

**Lost acks — two halves.** (1) Client (the task's design): every document push records
`sha256(documentContentKey)` in local `doc_sent` (≤ 20 per doc, cleared on `ok`); a `conflict` whose server
row matches is our own landed write → adopt its version, keep the entry (pushed again on the new base), no
copy. (2) Server: the property test found the other half — lost ack, then someone edits, then the client
re-sends the *unchanged* text → still a "conflict" (server row isn't ours any more), making a copy of text
the server already had. So every sync-push write leaves a receipt (`sync_receipt(document_id, content_key,
version)`, last 20 per doc, migration 0011); a stale-base push whose text has a receipt is answered `ok` with
the current row. Both are needed: disabling either fails the property tests (checked). Known edge: a user
who deliberately reverts to a text they pushed earlier while another device edited gets the other device's
version (the reverted text is in history, not lost-as-new).

**Conflicted copies.** Columns `document.conflict_of_id` (FK set null) / `conflict_device` / `conflict_at`
(migration 0011). Push create with `conflictOf` links only to an original the pusher can read in the same
workspace (else a plain page: no existence leak), device = push `device.name` ("Another device" if absent).
Sync `delete` of a document: ok if unknown (idempotent), trash (version+1, `canDeleteDocument`) if it is a
conflicted copy, `unsupported` otherwise. Resolution: desktop does it locally (`LocalStore.resolveConflict`:
keep copy = ordinary edit of the original on its current version — conflicts again rather than overwrite —
plus delete of the copy; works offline); web via `GET/POST /api/sync/conflicts/:id` (`keep`, optional
`baseVersion` → 409 if the original moved; keep copy needs edit rights on the original; copy trashed). The
title suffix " (conflicted copy)" is stripped when the copy is kept.

**Backfill.** Local queue `backfill(document_id, after)`: a *meeting* document inserted by a pull after the
initial full pull (state `pull.initial` set while a pull from `null` pages) is queued; the engine, after
pulling, calls `GET /api/sync/backfill?document=&after=` (meeting + participants first page, then final
segments by id, 500/page) and applies pages like pulled rows (pending local edits win, no echo); 403/404
drops the entry. Server: same read rule as pulls, unreadable = 404.

**SSE (`GET /api/sync/events`, `server/sync/events.ts`).** Per connection: poll `readChanges` over the
user's workspaces every 1 s (same D-22 visibility rule); emit `id: <cursor>` `event: change` with distinct
table names and the ids of affected *documents the user can read now* (segment/participant/meeting →
document); unreadable changes add only their table name (timing metadata, workspace members only). Start:
`Last-Event-ID`/`?lastEventId=` cursor (replay) or `headCursor()` + a `ready` event carrying it. Memberships
re-read every 10 s → `{workspaces: true}`. Heartbeat 15 s, `retry: 2000`, stream ends after 270 s
(`maxDuration` 300). Trade-off: one indexed query/s per connection — fine at personal scale; a shared poller
or LISTEN/NOTIFY can replace it (follow-up).
Desktop: `SyncEventsClient` (main; fetch stream with the bearer, own SSE parser, Last-Event-ID, backoff
1 s → 30 s, 45 s idle watchdog, 401 stops); every `ready`/`change` → `SyncEngine.notify()` (pull after
150 ms, resets backoff). Engine interval 60 s = backstop. Web: `useSyncEvents()` in `AppShell`
(EventSource; debounced `router.refresh()`, skipped for this tab's own saves within 5 s and while hidden;
re-dispatches `oat:sync-change` for components that want finer reactions).

**xmin stalls.** `createDb({timeouts})` sets `statement_timeout` / `idle_in_transaction_session_timeout` as
connection params; web pool uses `sessionTimeoutsFromEnv()` (30 s / 15 s defaults, env overrides,
documented in `.env.example`). `hasHeldBackChanges()` → pull `lagging`; engine retries 2 s doubling (capped
by interval). `longTransactions()` (pg_stat_activity, no query text) logged ≤ every 30 s when lagging.
Indexing worker pool not changed (out of scope; follow-up).

**Desktop-local FTS5 (PLAN 3.6 desktop part).** Local migration 2: `document_fts(title, body)` and
`segment_fts(text)`, `tokenize='trigram remove_diacritics 1'`, rowid = base rowid, kept by triggers (body =
`json_tree` text nodes), backfilled for existing rows. `LocalStore.search()`: words ≥ 3 chars ANDed,
trashed notes excluded, snippets (64 trigram tokens) with \u0001/\u0002 markers rendered as `<mark>` (no
HTML). Bridge `search:query`; sidebar `LocalSearch` box (re-runs after every sync). `onOpen` is a prop for
the notes view (3.4) to wire; until then hits are read-only.

**Desktop UI.** Bridge: `search:query`, `conflicts:list|get|resolve`. Sidebar: `LocalSearch`,
`ConflictsPanel` (only while there are copies; compare dialog with highlighted differing lines). Separate
files under `src/renderer/src/sync/`; `main-window.tsx` only mounts them.

**Review round 1 — fixes (implementer, 2026-11-15).** Where the notes above differ, this wins.
1. **SSE limits.** Connects rate-limited per user (`apiRateLimiter`, 30/min, `sync-events:<user>` → 429 +
   `Retry-After`); at most 5 concurrent streams per user per process (`StreamRegistry`, 429 past it, slot
   freed when the stream ends). Web tabs close their `EventSource` while hidden and reopen on `visible`,
   resuming from the last event id (`?lastEventId=`; the browser's own reconnects send `Last-Event-ID`).
   Int tests: cap + release, connect rate limit.
2. **`readableDocuments`** selects only the access columns (id, workspace, owner, visibility, share
   token, deleted) — documents directly, meetings/segments/participants through one join each; never
   `content_json`/`content_md`.
3. **Backfill best-effort (D-28).** 401 still fails the run (sign-out path); other 4xx (gone, unreadable,
   stale token) drop the entry; network/408/429 stop backfilling for this run (no strike); 5xx or an
   unexpected error give the entry a strike and move it to the back of the queue (local `backfill.attempts`,
   dropped after 5) and stop for this run. The run itself never fails because of backfill. Engine test.
Optional, done: the poll `sleep()` removes its abort listener when the timer fires; memberships are
re-read every 2 s **and** before naming ids of each page with changes (a removed member gets no ids;
int test); a membership change moves the cursor to the new set's current end (no history replay through
the stream, clients re-pull); the session is re-checked every 30 s (revoked → stream ends; int test).
**Deploy note (9.6):** the timeouts travel as startup parameters (`connection` in postgres.js); Neon's
pooled (PgBouncer) endpoint may reject or ignore them — check before the first deploy, fall back to
`ALTER ROLE <app role> SET statement_timeout = …, idle_in_transaction_session_timeout = …`.
Not done (follow-ups): web "Keep this copy" sends the copy's *saved* text — an unsaved edit in the copy's
editor is flushed on unmount and refused (403, the copy is trashed); the editor needs a flush hook (3.4
area). Desktop "Keep this copy" on an original the user can't edit any more: the local edit is parked and
the copy trashed (text survives in the trash + the parked row); the local store has no roles to refuse it
up front.

## Review
**Reviewer, 2026-11-15 — verdict: `changes`** (diff `merge-base(main)..task/3.5-sync` @171ca90 + this file).

Findings (fix these):
1. **SSE has no per-user limit** — `apps/web/src/server/sync/api.ts:76-85`, `server/sync/events.ts:111`.
   Each stream costs ≥1 query/s (+ `loadActor` every 10 s) for 270 s and reconnects forever; any number
   can be opened per user, and every web tab keeps one open even while hidden
   (`components/app-shell/use-sync-events.ts:85`). Fix: rate-limit connects with the existing
   `apiRateLimiter` (e.g. 30/min/user) and cap concurrent streams per user per process (e.g. 5 → 429);
   close the `EventSource` while the tab is hidden and reopen on `visible` (Last-Event-ID / a refresh
   covers the gap). Add a deny/limit test.
2. **`readableDocuments` loads whole document rows** — `server/sync/events.ts:101-104` `select()` pulls
   `content_json`/`content_md` of every changed document, every poll, in every stream: while someone types
   (autosave ~1/s) each member's each stream reads the full body each second. Fix: select only the columns
   `canReadDocument` needs (id, workspaceId, ownerId, visibility, deletedAt, shareToken); ideally resolve
   segment/participant → meeting → document in one joined query.
3. **A failing backfill entry fails every sync run** — `packages/local-store/src/sync-engine.ts:284,312-325`.
   Any error other than 403/404 (400 from a stale/unknown `after` token, a persistent 5xx for one
   document) is rethrown after push + pull succeeded → status `error`, exponential backoff, on every run
   forever, and the head entry blocks the rest of the queue (D-28: nothing may block the queue). Fix:
   backfill best-effort — drop (or park with an attempt count) on non-retryable 4xx (not 401/408/429); on
   network/5xx stop backfilling for this run without failing it; engine test for both.

Optional:
- `events.ts:117-129` `sleep()` leaves one abort listener per poll on `stop.signal` (~270 per stream);
  remove it when the timer fires.
- After removal from a workspace, up to 10 s of events still carry that workspace's readable doc ids
  (stale actor, ids only); reload the actor before resolving ids when a page has changes.
- Timeouts are sent as startup parameters (`packages/db/src/client.ts:62-79`): check against Neon's pooled
  (PgBouncer) endpoint before 9.x deploys — it may reject or drop them; `ALTER ROLE … SET` is the fallback.
- A zero-workspace stream (`headCursor` null) that joins a workspace replays its whole history in a tight
  loop; on a membership change the cursor could jump to the head (clients re-pull anyway).
- Session revocation isn't re-checked during a stream (≤ 270 s, ids only) — could ride the 10 s check.
- Web "Keep this" resolves with the copy's *saved* content; flush a pending editor save first. Desktop
  "Keep this" after losing edit rights on the original parks the edit and trashes the copy (text survives
  only in trash + the parked local row); consider refusing locally when the original is read-only.

Checked and fine: event payloads are table names + readable document ids only (re-checked per page with
`canReadDocument`), replay cursor validated; no dedicated DB connection per stream (shared pool, autocommit
queries, cleanup via `request.signal` + `cancel()`, heartbeat 15 s, 270 s cap); backfill = same read rule,
unreadable → 404, meeting subtree only; conflicts API checks read on copy, edit on original, delete on copy,
`FOR UPDATE` + `baseVersion` 409; `conflictOf` linked only to a readable original in the same workspace;
`sync_receipt` bounded (20/doc, FK cascade), only consulted after `requireEditable`, answers `ok` without
writing (no spoofing gain); lost-ack property tests mirror the server rules and assert no copy for
never-concurrent texts + nothing lost; timeouts only on the web pool (migrate, indexer worker untouched;
enhance/chat transactions are short); FTS5 input is split into words, `"` stripped, each quoted (no MATCH
syntax injection); snippets rendered as text.
