## Goal
Finish D-19 sync so desktop and web stay consistent: conflicted copies shown and resolvable, near-real-time
updates via an SSE invalidation channel, full data for newly shared notes, and robustness against the issues
found in earlier reviews.

## Scope
In:
- Lost-ack false conflicts: client records a hash of each pushed document's content; on 409 where the server
  row equals a sent hash → adopt server version as base, keep the entry, no conflicted copy. Property test.
- Conflicted copies: UX on desktop + web (banner on the copy "Conflicted copy from <device/time>", compare
  side-by-side, "Keep this" / "Keep other" / merge manually; resolving deletes the copy). Server stores the
  device name on pushes.
- SSE invalidation: `GET /api/sync/events` (session/bearer) emits `{seq, tables, ids}` for workspaces the user
  can read (from change_log, with `Last-Event-ID` replay), heartbeat, reconnect; desktop subscribes and pulls
  on events; poll backstop every 60 s. Web pages can use it to refresh the tree/current doc (sidebar live
  update when another tab/device edits).
- Subtree backfill: when a client first sees a document (new access or initial sync), pull its meeting,
  participants and segments even if their change_log rows predate the cursor.
- xmin stalls: set `idle_in_transaction_session_timeout` + `statement_timeout` for app connections; pull
  returns quickly with a "lagging" hint; monitor long txns in a dev log.
- Desktop-local FTS5 search (PLAN 3.6 desktop part) over notes + segments in local-store with a search box in
  the desktop sidebar.
- Tests: property tests (multi-device: desktop A + desktop B + web edits with random network faults → converge,
  conflicted copies only for real concurrent content edits), SSE int (authz: events only for readable
  workspaces; replay), backfill int (share a meeting note → teammate desktop gets transcript), e2e desktop:
  edit on web → desktop updates within a few seconds via SSE.
