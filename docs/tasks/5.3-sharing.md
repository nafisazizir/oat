# 5.3 + 5.4 — Document sharing + public read-only viewer
status: done
milestone: M5 · deps: 3.3, 1.7, 3.2 · branch: task/5.3-sharing

## Goal
Share a note with the workspace or via an anyone-with-link read-only page, from a share dialog; the public
viewer renders safely with no app chrome and no data beyond the document.

## Context
SPEC §4 Sharing, §6 (`visibility`, `share_token`), D-18 (re-enabling link rotates token; tokens ≥ 22 chars
base64url; private folder rules), `@oat/core` (canShareDocument, shouldRotateShareToken, link token compare),
`@oat/editor` (read-only rendering / generateHTML with the same schema — sanitised), `apps/web` (`share/[token]`
layout from 1.4, documents API from 3.3).

## Scope
In:
- Share dialog on the document page: visibility (Private / Workspace / Anyone with the link), copy link,
  "transcript visible to link viewers?" toggle (default off — SPEC: transcript stays private unless chosen;
  store as a document setting), who-can-access summary; server actions/API with `assertCan`.
- Token: generated with crypto (≥ 128-bit, base64url), rotated when re-enabling link; disabling clears it.
- `share/[token]`: server-rendered read-only view (title, enhanced notes, meeting meta; transcript only if
  toggled), `noindex`, no auth required, rate-limited, 404 for invalid/disabled/trashed, no workspace/user
  data beyond author display name; Open Graph metadata minimal. Render via the editor schema to HTML on the
  server with an allowlist sanitiser; CSP headers for the route.
- 5.5 groundwork: an "authz coverage" test that enumerates every `app/api/**/route.ts` and asserts each has a
  deny-case test (simple registry) — fail CI if a route lacks one.
- Tests: int (visibility changes authz, token rotation, disabled link 404, trashed 404, link viewer can't
  reach any API), e2e: share via link → open in a fresh context (no cookies) → content visible, edit
  impossible; disable → 404. Screenshots.

## Acceptance criteria
- [ ] Public link works logged-out; disabling/rotating behaves; no data leaks (tests).
- [ ] Route-coverage test in CI; `pnpm run ci` green.

## Design notes
(implementer + designer, 2026-11-14)

### Pieces
```
document page header ──► ShareDialog (components/document/share-dialog.tsx)
   GET/PATCH /api/documents/[id]/share ──► server/sharing.ts getSharing/updateSharing
        load row → canReadDocument (else 404) → assertCan('shareDocument') (403)
        → D-18 private-folder check (409 private_folder) → token rule → UPDATE … version+1
/share/[token] ──► proxy.ts → lib/share-guard.ts (rate limit, CSP nonce, headers, strip cookies)
               ──► app/share/[token]/page.tsx → loadSharedDocument(db, token)
                     shape check → row by share_token → canReadDocument(anonymous ctx + token)
                     → renderDocumentHtml (@oat/editor/html) + meeting meta (+ transcript if opted in)
```

### Decisions (worth a DECISIONS.md entry — orchestrator's file, not in my scope)
- **Settings API**: `GET/PATCH /api/documents/:id/share` (`{ visibility?, shareTranscript?, rotateLink? }`),
  not a server action, so the desktop app can use it too. Any reader of the document can GET the settings
  (incl. the link path — a link only grants read, which they already have); only `shareDocument` may PATCH.
- **Tokens**: 24 CSPRNG bytes → 32 base64url chars (192 bits; core needs ≥ 22 chars). Entering `link`
  always issues a new token (`shouldRotateShareToken`), leaving `link` sets it to `null`, `rotateLink`
  ("Reset link") replaces it. Sharing changes never bump `version` (see "Content version" below).
- **D-18**: a document inside a private folder can't become workspace/link (409 `private_folder`); the dialog
  disables those options and says why. Moves into a private folder (3.3 code) already force `private`; the
  stale token they leave is inert (core only honours tokens while visibility is `link`, and re-entering
  `link` rotates).
- **Transcript toggle**: new column `document.share_transcript boolean not null default false`
  (migration `0005_document_share_transcript`; renumber to 0006 when 3.6's `0005_search` lands first). Shown in the dialog only for meetings shared by link.
  Public view shows final segments only, max 5000, ordered by `start_ms`; speaker = `speaker_label`, else
  the author's display name for `mic`, "Others" for `system`.
- **Public resolver** (`loadSharedDocument`): anonymous permission context on purpose (the viewer's own
  session never matters; the proxy also strips `cookie`/`authorization` before the page runs). Returns
  only title, kind, sanitised HTML, updatedAt, author *display name* (never the email / local part; `null`
  if unset), meeting start/end, transcript-or-null. Malformed tokens never hit the DB. Unknown, disabled,
  reset and trashed links are all the same 404 (`share/[token]/not-found.tsx`). Restoring a trashed link
  document makes its (unchanged) link work again.
- **Server HTML** (`@oat/editor/html`): `validateDoc` → `@tiptap/static-renderer` (editor's own extensions,
  no DOM) → `sanitize-html` allowlist (only tags/attrs the schema renders; http/https/mailto/tel links,
  forced `rel="noopener noreferrer nofollow" target=_blank`; disabled task checkboxes; block ids and mention
  ids dropped — mentions keep only `@Name`). Output goes inside `.oat-editor`, so editor styles (incl.
  `data-origin="ai"` colouring) apply and no editor JS ships to link viewers. New deps (catalog):
  `@tiptap/static-renderer`, `sanitize-html`, `@types/sanitize-html`.
- **Proxy** (`/share/:path*` added to the matcher; Node runtime): fixed windows of 120 req/min per client
  IP and 600 req/min per token (`@oat/auth/rate-limit`: Redis when `REDIS_URL`, keys hashed; else memory;
  fails open like sign-in) → 429 + `Retry-After`. Client IP (`clientIp`): with `TRUST_PROXY_HEADERS` on
  (default: only when `VERCEL` is set) `x-vercel-forwarded-for` → `x-real-ip` → first XFF hop; otherwise the
  *last* XFF hop (Next.js writes the socket address there when absent; an appending reverse proxy puts its
  peer last) — a client-chosen first hop never picks the bucket. Documented in `.env.example`; CSP `script-src 'self' 'nonce-…' 'strict-dynamic' 'sha256-<root theme script>'`
  (+ `'unsafe-eval'`/`ws:` in dev only), `style-src 'self' 'unsafe-inline'` (UI primitives set inline
  styles; sanitised document HTML can't carry `style`), `upgrade-insecure-requests` only over https, `object-src 'none'`,
  `base-uri 'none'`, `frame-ancestors 'none'`; plus `Referrer-Policy: no-referrer` (the token is in the
  URL), `X-Robots-Tag: noindex, nofollow`, `X-Frame-Options: DENY`, `nosniff`, `no-store`. Page metadata:
  robots noindex/nofollow/nocache, `referrer: no-referrer`, OG = title only.
- **Authz coverage (D-25; 5.5 groundwork)**: `src/server/api/authz-coverage.test.ts` (unit, `test` step),
  fail-closed. Enumerates (a) every `route.(ts|tsx|js|jsx|mjs|mts|cjs|cts)` anywhere under `src/app`, key
  `'<METHOD> /<path under app>'`, failing on `export *` or a route file with no recognised method; and
  (b) **server actions** — decided to cover them, since they are POST endpoints too: every export of a
  `'use server'` module under `src`, key `'action <module>#<export>'`; an inline `'use server'` elsewhere
  fails (actions must live in modules so they can be enumerated). Each handler needs a
  `denies('<key>')` marker (`src/server/api/authz-markers.ts`, dependency-free; only calls in statement
  position count, comments are ignored) in a `*.int.test.ts`, or a reasoned registry entry: `PUBLIC`
  (health, Better Auth, magic-link redeem), `SELF_SCOPED` (no resource id; the module must call
  `getSession(`/`requireSession(` — calendar upcoming/disconnect, create team workspace), `TESTED_ELSEWHERE`
  (member/invite actions → titles in `packages/auth/src/members.int.test.ts`, verified to exist), or
  `KNOWN_GAPS` (debt for 5.5, never to grow: `switchWorkspace` non-member, `updateWorkspace` non-admin,
  `declineInvite` wrong recipient). Stale/duplicate entries fail. Markers added to the 3.3 documents/
  folders and 4.3 templates deny tests. Bypass cases have their own tests (extensions, nested `app/`
  paths, `export *`, comment-only exports, inline `'use server'`, commented markers).
  **Merge note**: `GET /api/search` (3.6) needs `denies('GET /api/search')` in its int test when merged.
- **Content version**: sharing writes (visibility, token, transcript toggle) don't bump `document.version`
  — that's the optimistic-concurrency/sync-conflict version (D-19), and a visibility flip must never 409 an
  unsynced desktop edit into a conflicted copy. Other devices still see the change through the
  `change_log` trigger (D-22). (Small deviation from D-19's "every accepted write bumps the version";
  worth a line in D-19/D-25.)

### UI (designer)
- **Share button**: `outline` `sm` button with `Share2` icon at the right end of the document header row
  (badges · edited · save status · **Share**). Hidden in the trash.
- **Dialog** (`sm:max-w-md`): title "Share"; description = live who-can-access sentence ("Only you can open
  this." / "Everyone in Acme can open this." / "…, and anyone with the link can view it."). "General access"
  fieldset of three radio cards (native `input[type=radio]`, `sr-only`, the label is the card): icon tile
  (`bg-muted`, `bg-primary` when selected) + label + one-line detail (Private: "Only you"/"Only <owner>";
  Workspace: "Everyone in <ws> (N members)" or "Your personal workspace (only you)"; Link: "Workspace access,
  plus a read-only web page…"), check icon on the selected card. Changes apply immediately (no Save), the
  fieldset is disabled while a request is in flight.
- **Link row** (only for `link`): `InputGroup` with the full URL (mono, read-only, selects on focus) + Copy
  (clipboard → toast "Link copied"), then "View only. Not listed in search engines." and a ghost
  "Reset link" (toast: old link no longer works).
- **Transcript toggle** (meetings shared by link only): bordered row, label "Show transcript to link
  viewers", `Switch`, helper text that follows the state. Default off.
- **States**: loading = three skeleton cards; load error = destructive text; no permission = disabled cards
  + note "Only the owner or a workspace admin can change who has access."; private folder = Workspace/Link
  disabled + note "This is in a private folder. Move it out of the folder to share it."
- After a change: `router.refresh()` updates the visibility badge and sidebar section; the editor's autosave
  is unaffected (no version bump).
- **Public viewer** (`share/layout.tsx` from 1.4, unchanged chrome: wordmark, "Read-only", theme, "Try
  Oat"; no sidebar): `PageContainer` → badge ("Meeting notes"/"Page") + date · duration, h1 title, "Shared by
  <name> · Updated <date>", the note in `.oat-editor`, then (opt-in) a "Transcript" section: `mm:ss` mono
  offset column + speaker + text. 404: `EmptyState` with link icon "This link isn’t available". Tokens only.

### Known limitation
- A share 404 is rendered by Next.js's error-recovery path (`notFound()` before the shell flushes → error
  shell + client render, status 404). In `next dev`, React then warns "Encountered a script tag…" about the
  root layout's inline theme script (root layout is out of scope). Harmless in production; e2e filters
  exactly that message for share 404s (and the 1.4 screenshot spec's signed-out block allows console
  errors). Fix later by moving the theme script out of the React tree (e.g. `next/script`
  `beforeInteractive`) — a root-layout change.
- Without `REDIS_URL` the in-memory limiter is per instance; its map only evicts expired windows (bounded
  by request rate × 60 s). Self-hosting with untrusted headers and *no* reverse proxy lets a client choose
  its own XFF (the proxy can't read the socket); put a proxy in front or set `TRUST_PROXY_HEADERS`
  accordingly.
- e2e runs under `next dev`; the production CSP (no `unsafe-eval`) isn't exercised in a browser yet.

## Review
Reviewer, 2026-11-14 — **changes** (one item; everything else checked out).

Checked and OK: public resolver returns only title/kind/sanitised HTML/updatedAt/author display name (no
email fallback)/meeting times/opt-in final transcript — no ids, workspace, folder, attendees; RSC payload
carries only rendered strings. Token lookup is equality on the unique `share_token` (shape-checked first,
then constant-time `tokensMatch` via anonymous ctx); trashed/disabled/reset/private-after-move all 404 alike.
XSS: probed `renderDocumentHtml`/`sanitizeDocumentHtml` with mention label `<img onerror>`, callout emoji
`"><script>`, code language `x" onmouseover=`, highlight colour attr, `java\tscript:`, `data:`, entity-encoded
`javascript:` hrefs, bad `origin` — all rejected by `validateDoc`, escaped, or stripped (mention/block ids
dropped). CSP: nonce + `strict-dynamic` + sha256 for the theme script, no `unsafe-inline`/`unsafe-eval` in
script-src in prod. Cookies/Authorization stripped via middleware override; `no-store`, `no-referrer`,
noindex, DENY framing. Share authz uses `assertCan('shareDocument')` inside the tree lock + row lock; D-18
private-folder 409; rotation on entering link / reset, cleared on leave. Unit tests re-run: coverage+proxy
16/16, html 18/18.

Must fix:
1. `apps/web/src/server/api/authz-coverage.test.ts:53-57,38-49` — the D-25 gate fails open: it only scans
   `app/api/**/route.ts`, so a handler in `route.js`/`.tsx`/`.mts`, or any `route.*` outside `app/api`
   (Next allows route handlers anywhere under `app/`), is never enumerated; and `export * from '…'` in a route
   module yields no methods, so it passes silently. Fix: walk all of `src/app` for `/route\.(ts|tsx|js|mjs|mts)$/`
   (keep the key spelled as the path under `app/`), and fail when a route file contains `export *` or yields
   zero recognised methods. Add cases for these to the `exportedMethods`/walker tests.

Optional:
- `lib/share-guard.ts:41-44` keys on the leftmost `x-forwarded-for`. Fine on Vercel (it overwrites XFF), but
  client-spoofable behind any appending proxy (e.g. the compose `app` profile); prefer `x-real-ip` /
  `x-vercel-forwarded-for` first, or a trusted-hop setting. Without `REDIS_URL` the memory limiter's map can
  grow unbounded within a window under spoofed IPs (cleanup only removes expired keys).
- `denyMarkers()` also counts `denies(…)` inside comments/skipped tests; consider matching only call
  statements (`^\s*denies\(`).
- e2e runs under `next dev` only; the production CSP (no `unsafe-eval`, `upgrade-insecure-requests`) is never
  exercised in a browser. One `next build && next start` check of `/share/<token>` (hydration, theme menu, no
  CSP violations) would close that; note `upgrade-insecure-requests` will break plain-http self-hosting.
- `style-src 'unsafe-inline'` is acceptable (document HTML can't carry `style`), but worth a comment in D-25.
- Sharing changes bump `version`, so once desktop sync (D-19) lands a toggle will 409 a concurrent unsynced
  desktop edit into a conflicted copy; consider excluding sharing-only fields from the content version later.
