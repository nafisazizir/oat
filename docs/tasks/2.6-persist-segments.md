# 2.6 — Desktop SQLite cache + outbox → API → Postgres
status: in-progress
milestone: M2 · deps: 1.5, 1.6, 1.8, 2.5 · branch: task/2.6-persist-segments

## Goal
Transcript segments (and the meeting/document rows they belong to) are persisted locally the moment they're
final and reliably reach Postgres via the D-19 sync mechanism — the first real slice of desktop sync.

## Context
D-19 (trigger-driven outbox, version acks, disposable cache, single writer WAL), D-22 (server change_log),
SPEC §6, `research/granola/storage-sync.md` (reference). `@oat/db` (server schema, readChanges), `@oat/core`
permissions, `apps/web` route-handler conventions + bearer auth from 1.6/1.8.

## Scope
In:
- `packages/local-store` (`@oat/local-store`): SQLite via `better-sqlite3` (Electron rebuild handled in
  apps/desktop with `@electron/rebuild` or use `node:sqlite` if adequate — decide + note), schema version table,
  migrations, wipe-and-resync on corruption/too-new/failed migration, WAL, single writer; tables mirroring the
  synced server tables needed now (workspace, document, meeting, participant, transcript_segment,
  audio_recording [local-only]) + `outbox(version, table, row_id, op)` filled by triggers + `sync_state`.
- Push: `POST /api/sync/push` (apps/web): batch of outbox entries with row payloads + base versions; server
  validates (zod), authorises per row via `@oat/core`, upserts (segments: insert-or-replace by id within the
  same meeting only), returns acked versions + per-row conflicts (409 semantics per row). Client deletes acked
  outbox rows; retries with backoff; idempotent.
- Pull (minimal now, full in 3.5): `GET /api/sync/pull?cursor=` using `readChanges` filtered to workspaces the
  user can read, returns rows; client applies in one tx with "applying remote" flag (no echo).
- Desktop wiring: RecordingService writes finals + meeting/doc rows to local-store; SyncService runs push on
  change + interval, exposes status via bridge.
- Tests: local-store unit (triggers, migrations, wipe), API int (authz deny cases, idempotent replays,
  cross-meeting id spoofing rejected), property-style test: random sequences of local writes + network
  failures → server converges to the same final segments with no duplicates.
Out: conflict-copy UX + SSE (3.5).

## Acceptance criteria
- [ ] Fixture recording in desktop e2e → segments in Postgres (query in test) with matching ids/text.
- [ ] Offline (API down) → outbox grows; back online → drains; no dupes.
- [ ] `pnpm run ci` green.
