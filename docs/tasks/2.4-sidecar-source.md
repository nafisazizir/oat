# 2.4 — `SidecarSource` + recording state machine
status: done
milestone: M2 · deps: 2.1, 2.3 · branch: task/2.4-sidecar-source

## Goal
The Node side of capture: spawn `oat-audio`, parse its framed stdout into `AudioFrame`s, control it over
stdin, and a recording state machine (idle → starting → recording ⇄ paused → stopping → idle, + error) that
the desktop main process will drive — testable entirely with the sidecar's `--synthetic` mode and FileSource.

## Context
SPEC §3, §8 (never silently stop; surface errors), D-8, D-16 (`native/oat-audio/PROTOCOL.md`), D-17.
`@oat/audio` (2.1): `AudioSource`, `AudioFrame`, FileSource. `native/oat-audio/scripts/check-frames.mjs`
(reference parser/validator — port to TS, keep it the contract).

## Scope
In:
- `@oat/audio/node` entry (Node-only, not imported by renderer code): `SidecarSource implements AudioSource`
  — locate binary (env `OAT_AUDIO_BIN`, dev path `native/oat-audio/.build/release/oat-audio`, packaged path
  later), spawn with args (sources, sample rate, `--synthetic` for tests, `--no-aec`), streaming frame parser
  (handles partial chunks, validates protocol version via `oat-audio version`), stdin commands, events
  (started/stopped/paused/resumed/error/device_changed/level/overrun/aec_unavailable) mapped to typed
  `AudioEvent`s, crash handling (unexpected exit → error event with stderr tail; optional auto-restart policy
  with backoff, keeping the shared clock continuous via an offset), graceful stop with timeout → SIGTERM → SIGKILL.
- `RecordingController` (pure TS state machine, source-agnostic): commands start/pause/resume/stop, emits
  state changes + frames + levels + errors; guards invalid transitions; tracks elapsed time; fans frames out
  to subscribers (STT, archive writer) without one slow subscriber blocking others (bounded per-subscriber
  queues with drop/overrun accounting).
- Tests: parser unit tests (chunk boundaries, bad magic/version, truncated frames); state machine tests;
  int test (`*.int.test.ts`, skipped automatically if the sidecar binary isn't built or not macOS) running
  `oat-audio capture --synthetic` for 2 s via SidecarSource → frame counts/timestamps match; pause/resume;
  stop; killing the child mid-run surfaces an error and (with restart policy) recovers.
- A `pnpm --filter @oat/audio build:sidecar` script that runs `swift build -c release` in native/oat-audio.
Out: Electron wiring (1.8/2.5), STT hookup (2.6), Opus archive (2.8). Never run non-synthetic capture.

## Acceptance criteria

- [ ] Crash/restart and graceful-stop behaviours covered by tests.

## Design notes
(implementer)

**Files** (all in `packages/audio/src`):
- `sidecar-protocol.ts` — TS port of `check-frames.mjs`: `FrameParser` (Uint8Array/DataView, no Node APIs; copies
  payloads so Node Buffer pools are never aliased; error offsets are absolute in the stream; a failed parser stays
  failed), `validateFrames` (same checks/messages/summary), plus `toAudioFrame` / `toAudioEvent` (snake → camel,
  `t_us + offsetUs → tUs`, unknown types and per-source events without a source → `undefined`), `encodeFrame`,
  `decodePcm`. **Contract test:** `sidecar-protocol.test.ts` imports `check-frames.mjs` and requires identical
  `{errors, summary}` and parse errors on valid and broken streams; the int test does the same on real sidecar output.
- `sidecar-source.ts` — `SidecarSource implements AudioSource`, `locateSidecarBinary` (`OAT_AUDIO_BIN` → must exist;
  `<resourcesPath>/oat-audio` for the packaged app (9.1 finalises); dev `native/oat-audio/.build/release/oat-audio`),
  `readSidecarVersion`, `captureArgs`, `SidecarError`.
- `source-emitter.ts` — the listener fan-out + throttled `listener_error` announcement, extracted from FileSource so
  both sources share it (FileSource behaviour unchanged, its 27 tests pass untouched).
- `recording-controller.ts` — `RecordingController` (pure TS, exported from `@oat/audio`).
- `node.ts` — the `@oat/audio/node` entry (SidecarSource + protocol + everything from `@oat/audio`); explicit
  `"./node"` export in package.json. `@oat/audio` itself stays renderer-safe.
- `testing/fake-sidecar.ts` — scriptable protocol-1 fake (run with `process.execPath`, configured by `FAKE_SIDECAR`
  JSON: crash, crash-once, garbage, ignore stop / SIGTERM, wrong protocol, no `started`, exit before start), so the
  failure paths are unit-tested on any OS without the Swift binary.

**SidecarSource behaviour**
- Start: locate binary → `oat-audio version` (refuse protocol ≠ 1) → spawn `capture …` → wait for `started`
  (`startTimeoutMs`, default 10 s). The first frame must be `started` with protocol 1 and the configured sample
  rate, else protocol error. Start failures reject `start()` with the reason + stderr tail; `whenStopped()` then
  resolves with reason `error` and no events are emitted (same as FileSource).
- Pause/resume: `state` flips synchronously and the command goes to stdin; the sidecar's `paused`/`resumed` events
  are forwarded as the authoritative pause point (audio captured before the command may still arrive until
  `paused`). Documented in the `AudioSource.pause()` doc comment. Duplicate announcements are suppressed.
- Never silent: exit without a `stopped` frame → `error` event (`sidecar_exited`, message has exit code/signal and
  last stderr lines); protocol violation → child SIGKILLed → `sidecar_protocol_error`. Without restart policy the
  error is `fatal: true` and `stopped` (reason `error`) follows. New Node-side codes live in
  `SIDECAR_HOST_ERROR_CODES` (types.ts), kept apart from `SIDECAR_ERROR_CODES` so the PROTOCOL.md drift test is
  unaffected.
- Restart policy (`restart: true | {maxRestarts 3, initialDelayMs 250, factor 2, maxDelayMs 5000, resetAfterMs 30 s}`,
  off by default): crash → non-fatal error "restarting in N ms (attempt k/max)" → respawn after backoff. The session
  keeps one `started`; the new process's clock is shifted by `offsetUs = max(wall time since capture origin,
  last tUs + 1)` so timestamps stay continuous and strictly increasing per source and the outage is a forward gap.
  A pause is re-applied to the new process. After `maxRestarts` consecutive failures → fatal error + `stopped`.
- Graceful stop: `{"cmd":"stop"}` + stdin EOF → wait `stopTimeoutMs` (5 s; the sidecar itself gives a stalled
  reader ≤ 3 s) → non-fatal `sidecar_stop_timeout` + SIGTERM → wait `killTimeoutMs` (2 s) → SIGKILL. `stopped`
  always follows; `stop()` resolves only after the process has exited (no orphans; tests check the pid is gone).
- `stopped.samples` = samples delivered by earlier (crashed) processes + the final process's own count (equals
  the sidecar's figure for a single process — asserted in the int test).

**RecordingController**: `idle → starting → recording ⇄ paused → stopping → idle`, plus `error`.
`createSource()` is called per recording (sources can't restart). Invalid commands throw `RecordingStateError`
without side effects. Start failure → `error` (`start_failed`); source ending by itself with
`duration`/`end_of_input` → `idle`, with any other reason → `error` (`unexpected_stop`). `error` is left by
`start()` (retry) or `stop()` (acknowledge → `idle`). Every source `error` event (fatal or not) is surfaced via
`onError`; levels via `onLevel`; all events via `onEvent`. `elapsedMs` counts only recording time (injectable
clock). `subscribe(consumer, {maxQueuedFrames=400, sources, onOverrun})`: each subscriber has its own bounded
queue and async pump (started on a microtask, so all subscribers get a frame queued before any consumer runs); when
full the subscriber's oldest frame is dropped and counted (`stats.dropped`, `droppedSamples`, `onOverrun`); a
throwing consumer → non-fatal `subscriber_error`, delivery continues; `drained()` for shutdown/tests.

**Not done / for later tasks:** Electron wiring + packaged binary path (1.8/2.5/9.1); the dev path is resolved
from `import.meta.url`, so a bundled main process should pass `binary` explicitly.

## Review
**Verdict: `changes`** (reviewer, 2026-11-14; read task file + `git diff main...task/2.4-sidecar-source`;
`pnpm --filter @oat/audio test` → 144/144 pass; int tests not run by the reviewer).

Overall solid: no shell anywhere (`spawn`/`execFile` with arg arrays), frame payloads are copies, `close` (not `exit`)
drains stdout before exit handling, stop escalation stop+EOF → SIGTERM → SIGKILL with timers cleared, no restart on
intentional stop, backoff capped, offset keeps per-source `tUs` strictly increasing, orphan safety via stdin EOF
(PROTOCOL.md), controller transitions/concurrent stop-during-start handled, per-subscriber drop accounting correct
and the slow-subscriber test is meaningful.

1. **Audio leaks while paused after a restart** — `sidecar-source.ts:497-499` + `:503-508`. A sidecar respawned
   while the session is paused starts unpaused; the `pause` command is only sent when its `started` arrives, and every
   audio frame it emits before processing that command is forwarded (`#onFrame` never checks `#state`). That is audio
   captured *after* the user paused, delivered to STT/archive. The fake hides it (first frame ≥ 50 ms after start;
   `sidecar-source.test.ts:200`). Fix: while `#state === 'paused'`, drop (don't count in `delivered`) audio from a
   restarted child until that child's own `paused` event arrives — or simply defer the respawn until `resume()`
   (nothing needs to capture while paused). Regression test: fake option that emits one audio frame immediately
   after `started`.
2. **`FrameParser` retains a view of the caller's chunk** — `sidecar-protocol.ts:58` + `:95`. When the buffer is
   empty and the chunk holds only a partial frame (`off === 0`), `#buf` stays a view of the caller's memory; if the
   caller reuses that buffer before the next `push`, the stream is corrupted. Reproduced: push 10 header bytes from a
   reused `Uint8Array`, overwrite it, push the rest → `ProtocolError: unknown frame kind`. Contradicts the module's
   "never aliases" contract (public export of `@oat/audio/node`). Fix: `this.#buf = off === 0 ? (buf === bytes ?
   bytes.slice() : buf) : buf.slice(off)`; add a test next to `sidecar-protocol.test.ts:118` for the pending tail.

Optional:
- `sidecar-protocol.ts:58` concat-per-chunk is O(n²) for a large payload arriving in many chunks (16 MiB / 64 KiB →
  ~2 GiB copied); collect chunks and copy once when the frame completes. Real frames are KiB, so low priority.
- `sidecar-source.ts:609` concurrent `stop()` calls each run the escalation → duplicate `sidecar_stop_timeout`
  events / signals; memoize the terminate promise per child.
- `sidecar-source.ts:124` `OAT_AUDIO_BIN` is honoured in a packaged app too, letting the environment pick a binary
  that inherits Oat's mic/screen TCC grant; restrict to dev (`!app.isPackaged`) in 1.8/9.1.
- `sidecar-source.ts:348-354` `stop()` during start waits up to `startTimeoutMs` (10 s, e.g. a TCC prompt) before
  terminating; could kill the starting child directly.
- `sidecar-source.ts:441` `stderrPartial` is unbounded for a newline-less stderr stream; cap it.
- `sidecar-source.ts:593` with `durationSeconds` + restart, each respawn gets the full `--duration` again.
- `recording-controller.ts:259` one `AudioFrame` (same `pcm`) is shared by all subscribers; document "treat as
  read-only".

**Resolution** (implementer, after merging current `main`):

1. Fixed by **dropping** audio rather than deferring the respawn: a process that starts while the session is
   paused is `muted`, and its audio is discarded (not counted in `delivered`; subtracted from its own
   `stopped.samples`) until its own `paused` event arrives. Why drop: it covers every ordering, including
   `pause()` landing while a respawned process is spawned but has not yet sent `started`, which deferring the
   respawn alone would not cover. It also keeps the restart path in one place and makes resume instant. The fake
   has a new option, `audioRightAfterStarted` (one frame per source written before stdin is read). The regression
   test `drops audio a sidecar respawned during a pause …` fails without the fix and passes with it.
2. Fixed: `FrameParser` keeps pending bytes only as copies, in a list of chunks that is joined once when a frame
   can complete, so it never aliases caller memory. New tests reuse and overwrite the pushed buffer before the next
   push, at cuts of 3, 10, 14, 20 and 21 bytes, plus a 37-byte scratch buffer across many pushes. All 6 fail on the
   old parser.

Optional items:
- Done: copying is now linear (chunk list; test feeds a 2 MiB payload in 1 KiB chunks).
- Done: concurrent `stop()` calls share one promise and one escalation per process (test checks there is a
  single `sidecar_stop_timeout`).
- Done: `stop()` during start sends SIGTERM to the not-yet-started process at once. `start()` then resolves with
  no events, the same as FileSource (test uses `noStarted` with a 10 s start timeout and stops in < 2 s).
- Done: the stderr partial line is capped at 4 KiB.
- Done: a restart with `durationSeconds` captures only the remainder, measured by audio delivered so far; if
  nothing is left the session finishes with `duration` (test included).
- Done: `FrameConsumer` docs say frames are shared and read-only.
- Deferred to 1.8 / 9.1: restricting `OAT_AUDIO_BIN` to dev (`!app.isPackaged`).
