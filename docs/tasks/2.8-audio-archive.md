# 2.8 — Local audio archive (Ogg Opus)

status: done
milestone: M2 · deps: 2.4 · branch: task/2.8-audio-archive

## Goal

Every recording is archived locally per meeting and source as Ogg Opus, written incrementally so a crash
keeps everything up to the last flush (D-10, SPEC §6), on the same clock as transcript segments.

## Context

SPEC §4 Audio archive, §6 desktop-only `audio_recording`, D-10, D-17 (archive backfill later in 2.9),
`@oat/audio` (AudioFrame, events incl. overrun/format_changed, RecordingController from 2.4).

## Scope

In:

- `@oat/audio/node` `OpusArchiveWriter`: per source, mono 16 kHz → Opus (~24 kbps, 20 ms frames) in Ogg pages,
  flushed at least every ~1–2 s (fsync policy documented); correct granule positions; gaps (overrun/pause)
  handled so archive time stays aligned with the recording clock (insert silence or record a gap map — pick
  and justify; playback seek must map segment `startMs` → file offset correctly).
  Encoder: a WASM/pure-JS Opus encoder (no native addon; must run in Electron main and Node tests).
- Recovery: on startup, scan `partial` recordings, repair/truncate to the last complete Ogg page, mark
  `partial`/`complete`, compute duration.
- `audio_recording` metadata store interface (implemented with SQLite in 2.6/desktop; an in-memory impl here)
  - paths `<base>/audio/<meeting_id>/{mic,system}.opus` (base injectable; desktop uses
    `~/Library/Application Support/Oat`).
- Decoder/reader for tests and for 2.9 backfill (`readOpusRange(path, startMs, endMs)` → PCM).
- Tests: FileSource fixture → writer → decode → duration within 1 frame, cross-correlation with source PCM
  high; kill mid-write (truncate file at random byte) → recovery yields a playable prefix; pause/overrun gaps
  keep alignment; ~20 MB/hour budget check (size per minute).
  Out: playback UI (3.7), retention settings (3.8), backfill (2.9).

- [ ] Crash recovery test passes; alignment test passes.

## Design notes

(implementer, 2026-11-14)

**Modules** (`packages/audio/src`): `ogg.ts` (RFC 3533 pages: build/parse/CRC/packet reassembly, pure),
`ogg-opus.ts` (RFC 7845 OpusHead/OpusTags, TOC durations, pure), `opus-archive.ts` (`OpusArchiveWriter`),
`opus-reader.ts` (`inspectOggOpus`, `probeOpusFile`, `opusSeekPage`/`opusSeekOffset`, `decodeOggOpus`,
`readOpusRange(path, startMs, endMs)` → PCM), `archive-recovery.ts` (`repairOpusFile`, `recoverRecordings`),
`audio-recording.ts` (`AudioRecording` row incl. `part`/`offsetMs`, `AudioRecordingStore` interface,
`InMemoryAudioRecordingStore`, pure part helpers `meetingParts`/`nextPart`/`locateMeetingTime`/`nextPartAfter`;
exported from `@oat/audio`), `recording-archive.ts` (`RecordingArchive` = RecordingController subscriber,
`ArchiveError`, `audioArchivePath`, `defaultOatDataDir`), `meeting-audio.ts` (`readMeetingRange`,
`meetingSeek`). Everything file/codec-related is exported from `@oat/audio/node` only.

**Encoder: `libopus-wasm` 0.4.1** (MIT wrapper; libopus 1.6.1, BSD-3 — both permissive). Single-file ESM with
the WASM inlined: no native addon, no `locateFile`, no network; works in Node ≥ 22 and Electron main (ESM or
bundled). Encoder + decoder + PLC in one package, published 2026-09 (actively maintained). Rejected: `opusscript`
(MIT, but libopus 1.4 and last release 2023), `@evan/opus` (2024, unmaintained), `opus-encdec` (2022),
`@discordjs/opus` (native addon). Ogg muxing/demuxing is our own (~200 lines), so no container dependency.
Deterministic: same input → same bytes (checked).

**Encoding:** mono, source rate (16 kHz), `Application.Audio`, 24 kbps VBR, **DTX on**, 20 ms packets,
complexity 10 (default). Pre-skip = encoder lookahead (104 samples @16 kHz = 312 @48 kHz). Granule of each
page = 48 kHz samples decoded through its last packet; the EOS page's granule is trimmed to
`preSkip + samples×3`, so decoders (ours, ffmpeg, Core Audio) output exactly the archived sample count.
`OAT_ORIGIN_US`, `OAT_SOURCE`, `OAT_MEETING_ID`, `OAT_PART`, `OAT_OFFSET_MS` go into OpusTags. DTX: low-activity stretches (room tone /
noise floor) become 1–2-byte packets decoded as comfort noise; it cut the fixture archive from 19.9 to
12.1 MB/h with waveform correlation unchanged (0.997).

**Timeline / gap strategy: insert silence** (not a gap map). File sample 0 = the recording's `started` `tUs`
(`originUs`); every frame is placed at `round((tUs − originUs) × rate / 1e6)`. A forward jump (overrun drops,
sidecar pause/resume, device switch, leading delay before a source's first frame) is filled with digital
silence; an overlap (tUs before the archive end, e.g. host-clock resync after drift) drops the overlapping
samples; ±2 samples count as contiguous (µs rounding). Why: segment `startMs` (recording clock) maps to file
time 1:1, so seek = granule `preSkip + startMs×48` → bisect pages (`opusSeekPage`, 80 ms pre-roll per RFC 7845)
with no side table, and standard players (3.7 uses Chromium's `<audio>`) seek correctly. Mic and system files
share the origin, so they stay mutually aligned too. Cost of silence is tiny: zero frames are encoded until the
encoder emits the same packet twice (steady state), then that packet is repeated verbatim — no CPU for long
pauses (30 s gap ≈ 7 KB; 1 h gap ≈ 0.8 MB and ~20 ms CPU). Gaps > 24 h are refused as a clock bug.
FileSource pauses don't move its timeline (nothing was missed), so they add no silence — consistent with its
segment times. If the archive's own subscriber queue overflows (it lags >60 s), dropped frames become silence
at the right place (`RecordingArchive.droppedFrames`).

**Flush / fsync policy:** packets accumulate into a page that is appended when it holds `pageMs` of audio
(default **1 s**), on `flush()` (RecordingArchive calls it on `paused`), and on `close()`. App crash ⇒ lose
≤ ~1 s. `fdatasync` after the header pages, every **5 s** of captured audio (`fsyncMs`; inserted silence
doesn't count, so a long gap doesn't trigger hundreds of syncs), on `flush()` and on `close()` ⇒ power loss /
kernel panic loses ≤ ~5 s — best effort on macOS: `fdatasync` there flushes to the drive but not its
write cache (`F_FULLFSYNC` would; Node has no API for it, and it costs ~10–50 ms per call). Writes are serialised in the background; `write()` returns
immediately unless >256 KB is backlogged (backpressure), and the first I/O error fails later calls. File opened
`wx` (never overwrites an archive). Row is inserted (`recording`) _before_ the file is created, so a crash
never leaves an untracked file.

**Multi-part meetings (D-24):** each recording session is a part. `RecordingArchive` takes `offsetMs` (where
the session starts on the meeting clock — supplied by the caller, the same origin transcript segments use) and
picks `part = nextPart(store.list({ meetingId }))` (mic and system share it). Files: `<source>.opus` for part 1,
`<source>.<n>.opus` after; an unexpected existing file is never overwritten (`wx`) — that source moves to the
next free number. Rows carry `part` + `offsetMs`. `locateMeetingTime(rows, source, meetingMs)` (pure, renderer
safe) → (part, file ms); `meetingSeek` adds the byte offset; `readMeetingRange(store, meetingId, source, from,
to)` decodes across parts with silence between sessions and returns the `covered` spans. No silence padding
between sessions.

**Failures:** a file that cannot be created → row `failed` (new status; SPEC §6 lists
recording/complete/partial/deleted — orchestrator: add `failed` there), one `ArchiveError`
(`archive_open_failed`), other source unaffected. A disk error while writing (ENOSPC/EIO, or surfacing at
close) is caught in `#onFrame`/`#flush`/finish, reported **once** per source as `ArchiveError`
(`archive_write_failed`, with `source`, `recordingId`, `path`, `cause`); that writer is abandoned and its file
repaired in place → row `partial` with everything written before the failure. The other source and the
recording continue; RecordingController never sees a `subscriber_error`. If even the repair fails the row stays
`recording` for startup recovery. Writer file I/O is injectable (`openFile`) for tests.

**Recovery:** at startup (before any recording) `recoverRecordings(store)` repairs only `recording` rows (left
by a crash); `partial` rows were repaired already and are never touched again. The Ogg parser resyncs like
libogg: a corrupt page (bad CRC) in the middle is skipped to the next CRC-valid `OggS` page and recorded as a
hole; the file is not rewritten there and every later page is kept. The reader places each page by its granule
minus its packets' durations, so audio after a hole stays at its true time (the hole decodes as silence). Only a
tail with no further valid page is truncated, after the last page that ends a packet; that page gets EOS (CRC
rewritten), then `fdatasync`. A file already a clean EOS stream with no holes (closed, row update lost) →
`complete`; anything truncated, EOS-added or with holes → `partial`. Missing file → `partial`, 0 bytes; headers
torn → left as is, `partial`, 0 ms. `skipIds` protects a running recording.

**Licences:** `THIRD_PARTY_NOTICES.md` (repo root) reproduces libopus 1.6.1 `COPYING` verbatim (BSD-3,
Xiph.Org et al., plus the patent-licence pointers) and the `libopus-wasm` MIT notice. **PLAN 9.1 (desktop
packaging) must ship this file inside the app bundle** — BSD-3 clause 2 requires the notice in binary
distributions.

**Measured size** (`pnpm --filter @oat/audio test`, logged): fixture speech (one-on-one.wav, −70 dBFS noise
floor) **12.1 MB per meeting-hour for mic + system**; worst case white noise **10.1 MB/h per source**
(≈ 20 MB/h both). Budget ~20 MB/h met.

**Known limits / follow-ups:** (1) `readOpusRange`/`decodeOggOpus` read the whole file and allocate the whole
range (~10 MB per source-hour on disk, 2 h of 16 kHz PCM ≈ 230 MB); 2.9 should decode in chunks. (2)
`writeSilence` runs synchronously (~20 ms per hour of gap); a very long in-session gap could instead close the
part and start a new one. (3) Electron bundling: `libopus-wasm`'s generated module uses `import.meta.url` /
`createRequire` — keep main ESM or externalise the package. (4) Desktop must pass `app.getPath('userData')` as
`baseDir`, the meeting-clock `offsetMs`, and call `recoverRecordings` on startup (2.6/desktop wiring). (5)
Frames lost from the archive queue right before `stopped` are not padded, so a duration can be slightly short.

## Review

(reviewer, 2026-11-14, on `2827f35`) **Verdict: changes.**

Verified OK: Ogg framing (CRC poly/init, lacing incl. 255-multiples, ≤255 segments, sequence numbers), RFC 7845
headers (BOS OpusHead page alone, OpusTags on its own page, header granule 0, audio on a fresh page), pre-skip =
lookahead × 3 = 312, page granule = 48 kHz samples through the last packet, EOS granule trimmed to `preSkip +
samples×3` and never below the previous page; seek bisect + 80 ms pre-roll; DTX packets are 1-byte TOC packets
with 20 ms durations, so granules/seek are unaffected (checked: 1-byte packet decodes to 320 samples); silence
repetition keeps the encoder delay consistent; writes/fdatasync are async (`FileHandle`, libuv pool); memory
bounded while recording (≤1 page + ≤256 KB backlog + 3000-frame queue); encode measured 0.11 ms/frame (≈1 % of
main thread for 2 sources), WASM cold start ≈5 ms; meeting-id regex blocks traversal; `libopus-wasm` wrapper LICENSE
is MIT. `pnpm --filter @oat/audio test` 188/188 green.

Must fix:

1. **D-24 multi-part not implemented** — `recording-archive.ts:20-28,128-163`, `audio-recording.ts:17-31`,
   `opus-archive.ts:181` (`wx`). A second session of the same meeting hits EEXIST and loses all its audio (rows
   `deleted`). Fix: `AudioRecording` gets `part` (≥1) and `offsetMs` (session start on the meeting clock, passed in
   by the caller — the same origin transcript segments use, not derived from wall clock); `audioArchivePath(…, part)`
   → `{source}.opus` for part 1, `{source}.<n>.opus` after; RecordingArchive picks next part from
   `store.list({ meetingId })` (and retries on EEXIST); add `OAT_PART`/`OAT_OFFSET_MS` tags; a meeting-level reader
   (`readMeetingRange(store, meetingId, source, startMs, endMs)` mapping meeting ms → (part, ms − offsetMs), gaps
   between parts as silence or explicit holes) + a `(part, offset)` seek helper for 3.7. Tests: two sessions →
   two parts, read across the boundary lands at the right meeting time. Drop "known limit (1)".
2. **I/O failure mid-recording floods errors** — `recording-archive.ts:169-174` with `opus-archive.ts:219-220,
   338-341`: after the first write error (disk full, EIO) every frame's `write()` rejects, so RecordingController
   emits `subscriber_error` ~100×/s for the rest of the meeting. Fix: catch in `#onFrame`, report once via
   `onError`, abandon that writer (row stays `recording` → recovery, or repair + `partial` at finish), keep the
   other source going. Add a test with an injected ENOSPC.
3. **Recovery can destroy good audio** — `archive-recovery.ts:54-65,111`, `ogg.ts:128-167`: parsing stops at the
   first bad CRC and repair truncates everything after it, and `recoverRecordings` re-repairs every `partial` row
   on every startup — so one corrupt page in an old partial file irreversibly cuts the rest of the meeting. Fix:
   only repair `recording` rows (a `partial` row is already repaired; leave it); on a mid-file bad page resync to
   the next valid `OggS` page of the stream (libogg-style) in both parser and reader, and only truncate a tail
   that contains no further valid page. Test: corrupt one byte in page 3 of 10 → pages 4-10 kept and decodable.
4. **libopus BSD-3 notice missing** — `node_modules/libopus-wasm/THIRD_PARTY_NOTICES.md` only links upstream; the
   generated WASM module carries no copyright text. BSD-3 cl. 2 requires reproducing the notice in binary
   distributions. Fix: add libopus's `COPYING` (Xiph.Org et al.) to a repo notices file (e.g.
   `packages/audio/THIRD_PARTY_NOTICES.md`), and a desktop-packaging follow-up to ship it.

Optional:

- `fdatasync` on macOS is not `F_FULLFSYNC`; the "power loss loses ≤5 s" claim is best-effort — say so in the docs.
- `writeSilence` is synchronous (~20 ms per hour of gap, 24 h ≈ 0.5 s main-thread stall + ~19 MB queued at once);
  with D-24, cap in-session padding (e.g. >30 min gap → close part, start a new one).
- `decodeOggOpus` allocates the whole range (2 h at 16 kHz ≈ 230 MB) and `readOpusRange` reads the whole file;
  2.9 should decode in chunks.
- Electron bundling: libopus-wasm's generated module uses `import.meta.url`/`createRequire`; keep main ESM or
  externalise the package (note for desktop wiring).
- Frames lost to the archive queue right before `stopped` are not padded, so duration can be slightly short.
- `deleted` doubles as "never created"; a distinct `failed` status would read better in 3.8.
