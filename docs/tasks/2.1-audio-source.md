# 2.1 — `AudioSource` interface + `FileSource` + fixtures
status: done
milestone: M2 · deps: 1.1 · branch: task/2.1-audio-source

## Goal
The abstraction that makes capture testable without a microphone: one `AudioSource` interface for live
(sidecar) and file-based audio, plus realistic two-voice meeting fixtures.

## Context
SPEC §3, §5 (AudioSource), §6 (shared clock with segments), FACTORY §4, D-8. Frame format must match the
sidecar's wire protocol: `native/oat-audio/PROTOCOL.md` (task 2.3, may be merged already — if not, the
model is: frames tagged `source: 'mic'|'system'`, `tUs` microseconds on one shared clock, PCM s16le mono 16 kHz).

## Scope
In:
- New package `packages/audio` (`@oat/audio`): types `AudioFrame {source, tUs, pcm: Int16Array, sampleRate}`,
  `AudioEvent`, `AudioSource` (start/stop/pause/resume, `frames()` async iterable or event emitter — pick and
  justify; must support backpressure-free fan-out to STT + archive writer), `FileSource` (reads a 2-channel
  WAV where L=mic, R=system, or two mono WAVs; speeds `realtime` | `fast` | factor; resamples to 16 kHz mono
  if needed; emits ~20 ms frames per source with correct timestamps; pause/resume honoured).
  WAV parse/write utilities (no native deps). Level/RMS helper.
- Fixture generator `packages/audio/scripts/make-fixtures.ts`: uses macOS `say` (two different voices for
  me/them) + `afconvert` to build short scripted meetings from a JSON script (`fixtures/audio/<name>.json`:
  list of `{speaker: me|them, text, gapMs}`); output `fixtures/audio/<name>.wav` (2-ch 16 kHz s16) and a
  `<name>.segments.json` with ground-truth `{source, startMs, endMs, text}` (used by FakeSttProvider in 2.2
  and evals later). Generate and commit 2–3 fixtures: `standup-short` (~30 s), `one-on-one` (~60–90 s),
  `silence-gap` (with a 10 s silence to test resilience). Keep each WAV < 3 MB. Script must no-op gracefully
  on non-macOS (fixtures are committed).
- Tests: WAV round-trip, FileSource timing (fast mode), frame sizes, pause/resume, ground-truth alignment.
Out: SidecarSource (2.4), STT (2.2), Opus (2.8).

## Acceptance criteria
- [ ] FileSource on `standup-short.wav` in `fast` mode emits frames for both sources whose total duration
      matches the file within 1 frame; timestamps monotonic per source; same clock across sources.
- [ ] `realtime` mode takes ~real time (test with a 1 s slice).
- [ ] Fixtures + ground-truth JSON committed; regenerating is deterministic in text/timings.
- [ ] Global gates green.

## Design notes
(implementer, 2026-11-14)

**Package layout** — `packages/audio` (`@oat/audio`), same shape as the other packages (`exports` →
`src/*.ts`, `tsc` typecheck, `vitest`). Extra: `@types/node` devDep (from the existing catalog entry; no
catalog changes), `erasableSyntaxOnly` so `scripts/*.ts` run under Node's type stripping, and a package
`turbo.json` adding `$TURBO_ROOT$/fixtures/audio/**` to `test` inputs so fixture changes bust the cache.
- `types.ts` — `AudioSourceKind` (`mic`|`system`), `AudioFrame {source, tUs, pcm: Int16Array, sampleRate}`,
  `AudioEvent` union, `AudioSource`, `AudioStopReason`. Events mirror PROTOCOL.md (protocol 1) 1:1 in
  camelCase: `started{sampleRate,frameMs,sources}`, `stopped{reason,samples}`, `paused`, `resumed`,
  `error{source?,code,message,fatal}`, `device_changed`, `level{rmsDb,peakDb}` — so 2.4's parser is a
  pure field mapping (`t_us`→`tUs`, source `0/1`→`mic/system`). `stopped.reason` adds `end_of_input`.
- `emitter.ts` — `Fanout<T>` (tiny sync emitter, no `node:events`) and `framesOf(source)`.
- `file-source.ts` — `FileSource`. `wav.ts` — decode/encode. `resample.ts` — windowed-sinc resampler +
  downmix. `level.ts` — `measureLevel`, `toDbfs`, `LevelMeter`. `index.ts` has no Node-only imports
  (`node:fs` is imported lazily only for path inputs), so the renderer can import types/utilities.

**Push listeners, not an async iterable (the pick the scope asked for).** `onFrame(l)`/`onEvent(l)` return an
unsubscribe; listeners run synchronously in registration order. Why: live capture cannot be slowed down, so
backpressure is meaningless; an async iterator is single-consumer and pull-based, so fan-out to STT ×2 +
archive writer + meters would need a tee with per-consumer buffers anyway, and a slow consumer would pace the
others. With push, every consumer gets each frame immediately and owns its own buffering (the STT 120 s replay
ring of D-17, the Opus writer of D-10). For consumers that prefer pull, `framesOf(source, {sources})` wraps one
subscription in an unbounded-queue async iterator that ends at `stopped` (tested with a slow reader). A
throwing listener does not starve the others and never escapes: it goes to `onError` (default
`console.error`), and FileSource announces it as a non-fatal `listener_error` event (see the review response).
Frames never share buffers (`slice`, not `subarray`), so consumers can retain them without copying.

**Lifecycle** — `idle → start() → running ⇄ pause()/resume() → stopped`. `started` is always first,
`stopped` always last, nothing after it (listeners are cleared). `whenStopped()` resolves with the `stopped`
event however the session ended (also `reason: 'error'` if loading fails, without emitting anything; `stop()`
before `start()` resolves `command` and emits nothing). Not restartable. `pause()` takes effect at the next
frame boundary: the mic+system pair for one instant is delivered together.

**FileSource clock** — `tUs` = position in the file (sample-count based, `round(sample·1e6/16000)`), so it
lines up with the fixture ground truth and a `startMs` slice starts at `startMs`. Mic and system frames for
the same slice carry identical `tUs`. Deliberate difference from the sidecar: the timeline does **not**
jump across a pause (nothing was missed in a file); consumers must use `paused`/`resumed` events, never
timestamp gaps, to detect pauses — the sidecar's jumps are therefore also safe for them.

**Pacing** — `realtime` (default) delivers a frame when its last sample "would have been captured"
(`anchor + frameEnd/speed`, computed from an anchor, so no drift; pause shifts the anchor). Numeric speed =
multiple of real time. `fast` = no waiting, but yields to the event loop every 1 s of audio so
`stop()/pause()` from outside still work. Default `frameMs` 20 (task asked ~20 ms; the sidecar default is
50 — configurable 20–100, same range as the sidecar). Last frame of a source may be shorter. Level events every 250 ms of audio per
source (like the sidecar; `levelIntervalMs: 0` disables).

**Inputs** — `{stereo}` (2-ch WAV, L = mic, R = system; other channel counts rejected) or `{mic?, system?}`
(mono WAVs, multi-channel downmixed, at least one, may differ in rate/length — each source just ends when
its input ends). Path, `file:` URL or bytes. Any WAV rate → 16 kHz via windowed-sinc (Blackman, 16 zero
crossings; tested: 1 kHz tone survives 8/22.05/44.1/48 kHz → 16 kHz, 11 kHz@48k does not alias). WAV reader
handles 8/16/24/32-bit PCM, 32/64-bit float, WAVE_FORMAT_EXTENSIBLE, odd-sized unknown chunks (afconvert's
`FLLR`, `LIST`) and bogus streaming data sizes. Writer: 16-bit PCM.

**Fixtures** — `packages/audio/scripts/make-fixtures.ts` (`pnpm --filter @oat/audio fixtures`,
`fixtures:check`). Script format `fixtures/audio/<name>.json` = `[{speaker, text, gapMs}]`; `gapMs` = pause
after the previous line ends (negative = talk over it; used once in one-on-one). Voices: `Samantha` (US
female) = me/mic, `Daniel` (UK male) = them/system, fixed rate 180 wpm (`say`'s default follows a user
setting, so it is pinned). Each line: `say → AIFF → afconvert LEI16@16000 mono → decodeWav` (dogfoods our
reader) → edges trimmed at |s| ≤ 100 so ground-truth ranges are the voiced span. Channels get a deterministic
seeded noise floor (≈ −70 dBFS RMS, peak ≈ 30) so "silence" is not digital zero. `--check` regenerates in
memory and compares: segments identical and WAV bytes identical on this machine (other macOS versions may
render voices differently — the check reports that). No-op with exit 0 on non-macOS / missing tools.
Scripts are our own text.

| fixture | length | WAV bytes | segments |
|---|---|---|---|
| `standup-short` | 33.6 s | 2,148,004 | 8 |
| `one-on-one` | 44.9 s | 2,870,616 | 11 (one overlap) |
| `silence-gap` | 26.6 s | 1,700,320 | 4 (10 s both-silent gap) |

**Scope conflict, resolved by the size cap:** a 2-ch 16 kHz s16 WAV is 64 KB/s, so "< 3 MB" caps a fixture at
~46 s; "one-on-one ~60–90 s" is impossible at that format. I kept the format + cap and made one-on-one 44.9 s.
If a longer fixture is needed later, options are two mono files per fixture or LFS — orchestrator's call.

**Tests (60, `pnpm --filter @oat/audio test`, ~3 s)** — WAV round-trip + format variants + errors; resampler
accuracy/anti-aliasing/DC; levels + `LevelMeter`; `Fanout` isolation; FileSource on `standup-short` fast:
exact PCM per channel, coverage within one frame, 320-sample frames, contiguous strictly-increasing `tUs`,
identical clocks across sources, distinct buffers, started/stopped/level events; realtime 1 s slice
(≈1000 ms, clock starts at 5 000 000 µs), per-frame lateness, speed ×4; pause/resume in fast and realtime
(no frames while paused, wall time extended, no audio lost); `stop()` mid-stream, from a listener, while
paused, before start; double start; mono inputs at 48 k/16 k with different lengths; `frameMs`; bad inputs;
fan-out + unsubscribe + `framesOf` slow reader. Fixture tests: format, < 3 MB, length, ground truth vs
script, speech exactly inside segments (voiced at both edges, noise-floor-only elsewhere), and the FileSource
frame containing each segment start is voiced while the previous frame is not; silence-gap shows ≥ 9.5 s of
both-source quiet level windows.

## Review

**Reviewer, 2026-11-14 — verdict: `changes`** (diff `main...task/2.1-audio-source` + task file + 2.3 PROTOCOL.md;
`pnpm --filter @oat/audio test` 60/60 locally).

1. **A throwing listener crashes the process, so "isolation" fails in practice** — `packages/audio/src/emitter.ts:30-33`.
   Re-throwing from `queueMicrotask` becomes an `uncaughtException` in Node/Electron main. Reproduced: a
   `FileSource` (fast, standup-short) with one `onFrame` listener that throws on frame 10 → the process exits 1
   before `whenStopped()` resolves, so the healthy listener never finishes. In 2.4, a bug in a level meter
   would kill the recording (and STT + archive with it). Fix: catch and report without letting it escape as an
   uncaught error. Give `Fanout` an `onError` hook (default `console.error`, or `globalThis.reportError` where it
   exists and does not exit) and have `FileSource` also emit a non-fatal `error` event (`code: 'listener_error'`,
   `fatal: false`). Update the test at `emitter.test.ts:25-38` and add a FileSource test where one listener
   throws and the session still reaches `stopped` with every frame delivered to the other listener.
2. **`AudioEvent` is missing the protocol's `overrun` event** — `packages/audio/src/types.ts:47-88`. PROTOCOL.md
   (protocol 1) defines `overrun {stage: 'capture'|'output', dropped_samples, dropped_ms}` per source. The design
   notes say the union mirrors the protocol 1:1. 2.4 needs this event so it can pass on dropped audio, and STT
   (D-17 replay ring) and the Opus archive (D-10, 2.8) must treat it as a visible gap instead of guessing from
   `tUs` jumps. Fix: add `{type:'overrun'; tUs; source; stage: 'capture'|'output'; droppedSamples; droppedMs}`
   and note in the `AudioFrame.tUs` doc that gaps come from overrun, pause/resume or a device switch.

Checked and fine: WAV chunk walk (odd sizes padded, unknown/`FLLR`/`LIST` skipped, 0/0xFFFFFFFF data sizes
clamped, EXTENSIBLE via SubFormat, 8/24/32-bit PCM + 32/64-bit float conversions correct); resampler (Blackman
window correct at the centre and edges, cutoff 0.95 × lower Nyquist, unity DC through per-output weight
normalisation, kernel truncated at the ends without dimming, output length/alignment correct); realtime pacing
is anchored to `performance.now()` (no cumulative drift, a stall catches up, pause shifts the anchor);
pause/resume/stop races (stop while paused, stop from a listener, stop during load or before start, double
start) behave as documented; frames are `slice`d copies. Fixture ground truth spot-checked with RMS on all
three WAVs: 20 ms before each start and after each end is at the noise floor (≈ −70 dBFS, peak ≤ 30 more than
10 samples before the start), the first and last 20 ms are voiced, and the other channel is at the floor
except in the one scripted overlap. Boundaries are accurate to the 1 ms rounding. Push listeners
plus `framesOf` are the right choice for fan-out to STT ×2, the archive writer and the 2.4 controller.

Optional:
- `file-source.ts:202-215`: a numeric `speed` large enough that `waitMs` is never > 0.5 ms never yields (no
  pause/stop until the end). Apply the `yieldEvery` check to numeric speeds too.
- `types.ts:47-54`: add optional `aec?: boolean` / `synthetic?: boolean` to `started` so 2.4 can show whether
  echo cancellation is on (D-17).
- `FileSource` accepts `frameMs` 10–100 but the sidecar accepts 20–100; consider matching. An option to
  advance the clock across a pause (like the sidecar) would let 2.4/2.8 tests exercise gap handling.
- The whole file is decoded and resampled in memory, synchronously in `#load` (≈ 100 taps per output sample
  at 48 kHz). That is fine for fixtures but slow for hour-long recordings: say so in the doc comment.
- `wav.ts:66-69`: when a `data` chunk declared as 0 comes before `fmt `, the walker continues into the
  audio bytes. That is harmless and rare: break when the data chunk is open-ended.

**Implementer response, 2026-11-14 (commit e4dafd4; merged `main` first, so the final 2.3 PROTOCOL.md applies):**
1. Fixed. `Fanout(onError?)` sends listener errors to `onError` (default `logListenerError` → `console.error`).
   A throwing `onError` is logged too, and nothing is re-thrown or deferred. `FileSource` takes an
   `onListenerError` option and announces each failure as a non-fatal `error` event `{code: 'listener_error',
   source?}`. The announcement is throttled to one per second, and the next one includes how many were
   suppressed. It is delivered only after the current delivery has reached every listener, so `started`
   still comes first. It is never sent after `stopped`, and a listener that throws on the announcement
   itself is only logged, so there is no recursion. Tests: Fanout (`queueMicrotask` is never called, the
   default console path, a throwing handler); FileSource on standup-short where one frame listener throws
   from frame 10 on → reaches `stopped`/`end_of_input`, the healthy listener gets every sample, exactly one
   announcement (`tUs` 100 000, `system`); an event listener that throws on every event → no recursion,
   `started` first, `stopped` last.
2. Fixed and extended to the final protocol. Added `overrun {source, stage, droppedSamples, droppedMs}` and
   `format_changed {source, deviceSampleRate, previousDeviceSampleRate, channels}`. `started` now has optional
   `protocol`, `version`, `synthetic`, `aec`. Added `SIDECAR_ERROR_CODES` (all 14 codes, including
   `tap_format`, `tap_buffer_invalid`, `mic_buffer_invalid`, `aec_unavailable`) and `LISTENER_ERROR`;
   `code` is typed `KnownAudioErrorCode | (string & {})` so unknown codes still fit. Added the
   `AUDIO_EVENT_TYPES` const, and a compile-time check that it covers the union. The `AudioFrame.tUs` doc
   now says gaps come from overrun, pause/resume or a device switch. New `src/protocol.test.ts` parses
   `native/oat-audio/PROTOCOL.md`. It checks: the event table's types = `AUDIO_EVENT_TYPES`; each type's
   fields (camelCased) = the fields of a compiler-checked example of that union member; the error-code
   paragraph = `SIDECAR_ERROR_CODES`; the doc's stop reasons ⊆ `AudioStopReason`. PROTOCOL.md was added to the
   package's turbo `test` inputs.
Optional items taken: the yield check now applies at every speed, so external pause/stop lands mid-file at
`speed: 1e6` (tested). `frameMs` is now 20–100 like the sidecar. The doc comment says input is loaded whole
and in memory. The WAV walker stops at an open-ended `data` chunk (tested). Not taken: an option to advance
the clock across a pause. 2.4/2.8 can test gap handling with `overrun` once SidecarSource exists; FileSource
never drops audio, so it never emits `overrun` (documented).
