# 7.1 — Calendar: EventKit via sidecar + `CalendarSource`
status: done
milestone: M7 · deps: 2.3 · branch: task/7.1-calendar

## Goal
Know what meetings are coming up: read macOS calendars via the sidecar (EventKit), normalise into one
`CalendarEvent` shape shared with Google Calendar (7.4), and expose upcoming events — all testable with a
fixture source; the real permission prompt is a human checkpoint.

## Context
SPEC §4 Calendar, D-21 (calendar names the meeting: in progress or starting within 90 s, started ≤ 15 min ago;
"meeting starting" notification ~1 min before events with attendees), `research/granola/detection.md`
(behaviour reference: EventKit is change-notification driven, window −24 h…+14 d), PLAN 7.1 text,
`native/oat-audio` (CLI structure, PROTOCOL.md, Swift Testing), `@oat/audio/node` SidecarSource (spawn
patterns), `@oat/core` types.

## Scope
In:
- Sidecar commands (same binary, new subcommands; protocol doc section): `calendar status` (JSON auth status,
  never prompts), `calendar request-access` (prompts — human only), `calendar events --from --to` (JSON lines
  of normalised events: id, calendarId/title/colour, title, start, end, allDay, location, url, conference URL
  extracted from notes/location/url (Zoom/Meet/Teams patterns), attendees {name, email, status, isSelf,
  isOrganizer}, recurrence id), `calendar watch` (emits a line on EKEventStoreChanged; debounced). Swift
  tests with an injectable event-store protocol + fixture events (no real EventKit access in tests).
  `--fixture <file.json>` mode serving events from JSON so Node tests and the desktop can run without
  permissions.
- `packages/core`: `CalendarEvent` zod type + pure helpers: `currentMeetingFor(events, now)` (D-21 overlap
  rule), `upcoming(events, now, horizon)`, `startingSoon(events, now)` (attendees + ~1 min), conference-link
  detection shared util; exhaustive tests incl. all-day, overlapping, declined, cancelled, timezone edges.
- `packages/calendar` (`@oat/calendar`, Node): `CalendarSource` interface; `SidecarCalendarSource` (spawns
  sidecar subcommands; watch → refresh) and `FixtureCalendarSource`; cache + change events.
- Fixtures `fixtures/calendar/*.json` (a realistic week, written by us).
Out: UI list (desktop 2.5/3.4 will render), Google (7.4), detection (7.2), auto-create notes (7.3).
**Never run `calendar request-access` or non-fixture `calendar events`** — they'd prompt for permission.
`calendar status` is safe (no prompt).

## Design notes

Implementer, 2026-11-14 (branch `task/7.1-calendar`). Wire format and fixture format are specified in
`native/oat-audio/PROTOCOL.md` → _Calendar_; usage + human checkpoint steps in `native/oat-audio/README.md`.

**Data flow**

```
EventKit ──EKEvent──▶ EventKitCalendarStore ─┐                      (Swift, OatAudioCore/Calendar/)
fixture JSON ───────▶ FixtureCalendarStore ──┼─RawCalendarEvent─▶ CalendarNormalizer ─▶ JSON line
tests ──────────────▶ MockStore ─────────────┘   (protocol CalendarEventStore: authorization / events / observeChanges)
                                                                    │ stdout (JSON lines)
SidecarCalendarSource (execFile status/events, spawn watch) ◀───────┘          (@oat/calendar/node)
        │ CalendarSource interface (FixtureCalendarSource implements it too, in-memory)
        ▼
CalendarCache: window −24 h…+14 d, watch → coalesced refresh, 10-min safety refresh, onChange/onAccess/onError
        │ CalendarEvent[]  (zod schema in @oat/core)
        ▼
@oat/core pure helpers: currentMeetingFor (D-21) · upcoming · startingSoon · nextStartingSoonAt · detectConferenceLink
```

**Sidecar (`oat-audio calendar …`)** — same binary, JSON lines, `protocol` unchanged (capture untouched).
- `status` uses only the static `EKEventStore.authorizationStatus(for:)` (no store instance) → never prompts.
  `events`/`watch` check authorization first and exit **77** without full access instead of touching data.
  `request-access` is the only prompting path (`requestFullAccessToEvents`, macOS 14 API); it rejects
  `--fixture` so there is no "safe-looking" variant of it.
- Normalisation is in Swift (one place, next to EventKit) against an EventKit-shaped `RawCalendarEvent`; the
  EKEvent → Raw mapping is the only untested code (it needs real EventKit). Rules: ids unique per occurrence
  (`eventkit:<eventIdentifier>/<original occurrence ISO>` for recurring, since EventKit shares
  `eventIdentifier` across occurrences), `recurrenceId` = series id, `icalUid` for cross-source dedupe (7.4);
  all-day → midnights in the store zone + `allDayStart/End` day strings (EventKit's 23:59:59 end → next
  midnight); rooms/resources dropped; organizer flagged or prepended; delegated → declined. Notes are not
  emitted (privacy / size) — only the extracted conference link.
- `--fixture` re-reads the file on each `events` and `watch` follows it (kqueue file source, re-opens after
  atomic replace), so Node tests exercise the real binary's whole path incl. watch with no permissions. The
  fixture's `timeZone` makes all-day/day-argument output independent of the machine's zone.
- `watch` debounce: trailing 500 ms default, capped at 4× after the first change of a burst (`Debouncer`,
  generation-guarded so a cancelled/superseded fire is dropped). Stops on stdin EOF like `capture`.
- `Info.plist` embedded into the executable (`-sectcreate __TEXT __info_plist`, path from
  `Context.packageDirectory`) with `NSCalendarsFullAccessUsageDescription`/`NSCalendarsUsageDescription` (after review also
  `NSMicrophoneUsageDescription`/`NSAudioCaptureUsageDescription`, so capture keeps purpose strings):
  a bare CLI asking for calendar access without them is killed by TCC, which would sink the human checkpoint.
  No `CFBundleIdentifier`, so TCC attribution for capture is unchanged. Verified with
  `otool -X -s __TEXT __info_plist`.

**Conference links** — one rule set implemented twice (Swift for the sidecar, TS in core for Google 7.4 and
anything else) with **shared cases** `fixtures/calendar/conference-links.json` (22 cases) run by both test
suites: url → location → notes, earliest match in a field, Zoom (`*.zoom.us`/`zoomgov.com` `/j|s|w|my|wc/join/`),
Meet (`xxx-xxxx-xxx`, `lookup/…`), Teams (`teams.microsoft.com|teams.live.com|teams.cloud.microsoft`
`/l/meetup-join|meet/`), stop at whitespace/`<>"'`, trim trailing `.,;:!?)]}*`; lookalike hosts rejected.

**Core helpers (choices beyond D-21's text)**
- `currentMeetingFor`: candidates = timed, not cancelled, not self-declined, in progress or starting ≤ 90 s,
  started ≤ 15 min ago (both bounds inclusive; ended events excluded even inside the window). Ties: meeting-like
  (other attendees or a join link) beats solo blocks, then **latest start** (the one being joined — handles
  back-to-back and "focus block overlapping a sync"), then id; independent of input order.
- `startingSoon(events, now, lead = 60 s)`: start ∈ [now, now+lead]; eligible = timed, attending, titled, ≥ 1
  attendee who isn't self. `nextStartingSoonAt` gives a scheduler its next wake-up (for 7.2/desktop).
- `upcoming(events, now, horizon, {includeAllDay, includeNotAttending})`: end > now && start < now+horizon.
- Schema refinements: `end ≥ start`, all-day ⇔ day strings set, conference url ⇔ provider.

**`@oat/calendar`** — `.` is platform-neutral (interface, `CalendarCache`, `FixtureCalendarSource`, JSONL
parsing); `./node` adds `SidecarCalendarSource` (reuses `locateSidecarBinary`/`SidecarError` from
`@oat/audio/node` — same binary, same lookup). `CalendarCache`: refreshes never overlap (one queued
follow-up), emits only on real change (fingerprint), keeps last good events on errors, no access → clears
events/stops watch but keeps re-checking `status()` on the periodic refresh (picks up a later grant); a dead
watch is re-established with backoff 5 s ×2 … 5 min (reset after 60 s of healthy watching), followed by a
refresh. Watch child: EOF → SIGTERM → SIGKILL escalation like `SidecarSource`.

**Tests** — Swift: 36 new (normaliser incl. all-day/DST/zones, attendees, ids, JSON shape; fixture parsing
and errors; runner incl. "unauthorized never reads"; CLI; debouncer; file watch incl. atomic replace;
shared link cases). Core: calendar.test.ts (schema, shared link cases, D-21 boundaries at 90 s / 15 min,
back-to-back, overlapping, ties, DST fall-back, all-day/Tokyo zone, declined/cancelled). `@oat/calendar`: 31
unit (cache incl. coalescing, access changes, backoff with fake timers; sidecar source against a Node fake:
args, exit 77, bad output, watch lifecycle/escalation) + 6 int against the **real binary in fixture mode**
(status without fixture is the only non-fixture call — read-only).

**Not done / follow-ups**
- Human checkpoint (FACTORY §7, for the orchestrator to log under _Waiting on human_): run
  `native/oat-audio/.build/release/oat-audio calendar request-access` and grant; then `calendar status` →
  `full_access`; `calendar events | head`; `calendar watch` while adding an event in Calendar.app (expect one
  `changed`). Check recurring ids, attendee emails and a Teams/Zoom invite's `conferenceUrl` look right.
  **Also re-run the real-capture checkpoint** (`oat-audio capture --duration 10 | node scripts/check-frames.mjs`
  with a call playing): the binary now embeds an `Info.plist` (mic / system-audio / calendar purpose strings),
  which may change how TCC treats mic and system-audio access for the bare sidecar.
- No calendar list / per-calendar selection command yet (Granola has one); add with the settings UI.
- Fixture dates are fixed (week of 16 Nov 2026); a "shift to today" option would help desktop dev (2.5/3.4).
- No agent ran `request-access`, non-fixture `events`/`watch`, or non-synthetic `capture`.

## Review

Reviewer, 2026-11-14 — **changes** (small; the design is otherwise sound).

Re-ran (safe commands only): `swift build -c release` + `swift test` (88/21 pass), `calendar status` →
`not_determined`/`prompted:false`, fixture `events` (16 lines), `@oat/calendar` unit 31 + int 6, core
`calendar.test.ts` 49 — all pass. `codesign -dv`: `Identifier=oat-audio` (unchanged by the plist), `Info.plist=not bound`.

Must fix:
1. `native/oat-audio/Sources/oat-audio/Info.plist:4-11` — the embedded plist is justified (EventKit's in-process
   purpose-string check reads `Bundle.main`, which for the sidecar is the sidecar's own `__info_plist`, not
   Electron's, unless the binary sits in `Contents/MacOS`), and it does not change TCC *attribution* (responsible
   process is spawn-based; no `CFBundleIdentifier`, signing identifier still `oat-audio`). But the binary now
   *has* an Info.plist that lacks `NSMicrophoneUsageDescription` / `NSAudioCaptureUsageDescription`; any
   in-process/tccd purpose-string check that previously fell through for an unbundled binary may now refuse or
   abort mic / system-audio capture (the real-capture checkpoint has not run yet, so it would go unnoticed).
   Fix: add both keys (same wording as the app will use) and add "re-run real `capture` after this build" to the
   human checkpoint list in Design notes → Not done.
2. `native/oat-audio/README.md:56-58` and `:92-95` — packaging notes omit the hardened-runtime entitlement
   `com.apple.security.personal-information.calendars`; without it a signed, hardened Oat/sidecar is silently
   denied Calendars. Fix: list it next to `device.audio-input` and in the Calendar section's 9.1 note.
3. `packages/calendar/src/cache.ts:229-239` with `:175-191` — the re-watch backoff stalls: the timer only calls
   `refresh()`; if that refresh fails (status/fetch error, e.g. the sidecar crashing again) no watch starts and
   nothing re-arms the timer, so recovery waits for the 10-min interval (never, with `refreshIntervalMs: 0`),
   contradicting "backoff 5 s ×2 … 5 min". Fix: after the rewatch-triggered refresh, if `#running && canRead &&
   !#watch && !#watching`, call `#scheduleRewatch()` again; add a fake-timer test with a failing fetch.

Checked, no issue: `requestFullAccessToEvents` + `.fullAccess`/`.writeOnly` mapping (legacy `.authorized` aliases
`.fullAccess`); `status` uses the static query only; `events`/`watch` gate on auth → exit 77; store lifetime
(`withExtendedLifetime`, Task capture); `EKEventStoreChanged` with `queue: nil` is fine because `Debouncer` is
locked and main run loop runs. D-21 rule: instants only (DST-safe), all-day excluded, cancelled/self-declined
excluded, bounds inclusive, ended events dropped, deterministic ties. Link regexes: no nested ambiguous
quantifiers (`[a-z0-9-]+\.` repetitions are dot-delimited; tails are single greedy classes) → linear, no ReDoS;
lookalike/userinfo hosts rejected. `@oat/calendar` → `@oat/audio/node` only from `./node` (neutral entry clean) —
acceptable for "same binary, same lookup". Tests exercise real behaviour (shared link cases in both languages,
real binary in fixture mode, watch via file edits); int test never reaches EventKit except read-only `status`.

Optional:
- `EventKitCalendarStore.swift:47` — prime the store before observing (`_ = store.calendars(for: .event)`) so
  the daemon connection exists and `EKEventStoreChanged` is delivered to a store that never fetched; confirm in
  the watch checkpoint.
- `EventKitCalendarStore.hex` — `CGColor.converted(to: sRGB…)` would drop the AppKit link from `OatAudioCore`.
- `nextStartingSoonAt` returns `now` repeatedly while an event is inside the lead window; document that callers
  must track already-notified ids (7.2).
- HTML-escaped `&amp;` inside notes URLs is kept verbatim in `conferenceUrl`; decode if 7.4 descriptions are HTML.
- `#watchDied` uses `Date.now()` rather than the injected clock (stable-watch reset untestable with `now`).
