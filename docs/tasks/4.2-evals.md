# 4.2 — Eval harness + fixture meetings
status: done
milestone: M4 · deps: 4.1 · branch: task/4.2-evals

## Goal
A repeatable way to tell whether AI changes (enhancement now, chat later) got better or worse, runnable offline
against the mock (structural tier) and with a real model when a key is set (quality tier) — D-13.

## Context
SPEC §7 (Evals), FACTORY §3 (`pnpm --filter @oat/ai eval` must not regress vs main), D-13, D-20 (enhancement
output model: sections → blocks with origin; templates = title/description/ordered sections). `@oat/ai`
(getModel, mock models, Output.object). `fixtures/audio/*.segments.json` (3 short meetings with ground truth).
`research/granola/enhance-chat.md` (behaviour reference only — no prompts copied).

## Scope
In:
- `packages/ai/evals/`: fixture meetings (≥ 5, synthetic, written by us): each `{ meta (title, attendees,
  started_at), template id, myNotes (Markdown, rough), transcript segments (source, startMs, endMs, text),
  expectations }`. Reuse the 3 audio fixtures' ground truth as transcripts for 3 of them; write 2 longer
  text-only ones (sales discovery, interview). Expectations are *properties*, not golden text: must-mention
  facts/decisions/action items (with owner), must-not-hallucinate list (names/numbers not in transcript),
  my-notes coverage (every user note line represented, origin=me), section headings from template present,
  length bounds.
- Harness: `pnpm --filter @oat/ai eval [--suite enhance] [--model real|mock] [--json out.json]`: runs a
  pluggable `task(fixture) → output` (enhance task stub for now: a placeholder function in packages/ai that 4.4
  will replace — keep the interface), scores with
  - structural checks (schema valid, headings, origin marking, length) — always;
  - property checks via deterministic string/regex matching where possible;
  - LLM-as-judge checks (grounding, coverage) only in `--model real` (skipped with a clear notice otherwise),
  writes a results table + JSON; compares to a committed baseline `evals/baseline.json` and exits non-zero on
  regression beyond a tolerance. `eval:baseline` script to update it.
- Unit tests for scorers.
Out: real enhancement prompt (4.4), chat evals (6.5).

## Acceptance criteria
- [ ] `pnpm --filter @oat/ai eval` runs offline against the mock and prints a table; structural tier passes
      for the stub; baseline committed; regression detection proven by a test.
- [ ] Quality tier is cleanly skipped without a key.
- [ ] Global gates green.

**Fixtures** (TS modules so expectations can be RegExps; all content written for Oat, names invented):
`one-on-one`, `standup`, `silence-gap` import `fixtures/audio/*.segments.json` directly (validated with zod, so
they stay in sync with the audio ground truth); `sales-discovery` (30 segments, dense figures/names/dates) and
`interview` (26 segments; strengths vs gaps, salary never discussed) are text-only with timings from `timed()`.
Each has rough Markdown notes, attendees with roles, 2–12 `mustMention` (8 action items with owners), 3–4
`mustNotMention` traps (wrong %/amounts/months/day names, invented titles/metrics/pay), and word bounds.
`fixtures.test.ts` guards the fixtures themselves: every expected pattern is satisfiable from notes+transcript,
owners are attendees or named, and no "hallucination" pattern matches **notes + transcript + the rendered meta**
(`renderMeta` plus ISO / en-US / en-GB full, medium, short and weekday forms of the meeting date).

**Modes (D-13).** `--model mock` (default): each fixture gets an in-process `createMockModel` answering with
`extractiveDraft` JSON, so the real path (prompt → structured output → zod → scorers) runs offline,
deterministically, without `startMocks()`/compose. Judge tier skipped with a printed notice. `--model real`:
only when `resolveAiBackend()` says gateway (`AI_GATEWAY_API_KEY` or Vercel OIDC); task uses
`getModel('enhance')` at temperature 0, judge uses `getModel('judge')`; a notice warns if both resolve to the
same model id (self-grading). Without a key it prints a notice, runs the mock and exits 0 ("cleanly skipped");
`eval:baseline --model real` without a key exits 2 and writes nothing. `evals/run.ts` loads the repo-root
`.env` if present (shell vars win).

**Gating.** Exit 1 on any structural failure or task/judge error (absolute — independent of the baseline,
and in every run of `--runs N`), or on a baseline regression:
- *mock*: per check, `score < baseline − 0.01` (deterministic; a missing fixture/check is a regression).
- *real*: `baseline.real[suite]` stores `{model, judgeModel, runs, overall, fixtures}` with **tier means**
  (property, judge) per fixture and suite-wide; compared with tolerance 0.1 (`tier:<name>` regressions, fixture
  `all` = overall). If the run's task or judge model id differs from the recorded pair → "not compared"
  (reason printed), no failure. `--runs N` (1–20) averages check scores over N runs; a check passes only if
  it passed every run. Single property checks move in 0/0.5/1 steps and `judge:coverage` in 1/n steps, so
  only aggregates are gated with a real model.

`--tolerance` overrides; `eval:baseline` (= `--update-baseline`) rewrites only the mode + suites that ran and
refuses while the structural tier fails. `--json <file>` (relative to `INIT_CWD`) dumps results + comparison.
`--verbose` lists every non-passing check. Exit 2 = usage error.

**Mock draft and baseline.** `extractiveDraft`: template headings in order; my note lines verbatim
(`origin: me`) in the first section; ≥5-word transcript segments as `ai` items over the sections in meeting
order (250-word cap). It exercises the whole output contract: a segment where the speaker commits ("I'll …")
becomes a `task` with `owner` = the speaker (mic = me; system = the other attendee when there is exactly one);
a multi-sentence segment becomes a bullet with its later sentences as nested `children`. Mock baseline:
structural 20/20 (length moved to property), property mean 0.80. Baseline diff vs round 0: only
`one-on-one mention:oncall-cover` 0.5 → 1 — the draft's "I'll ask Priya…" task now carries `owner: Morgan`,
which the owner check reads. Fixture pattern fixes (below) changed no mock score. These numbers measure the
mock draft + scorers, not prompt quality (the mock never reads the prompt); prompt quality is only measurable
with `--model real` — when 4.4 lands, whoever has a key should run `eval:baseline --model real` (ideally
`--runs 3`) to record a real baseline.

## Review
Reviewer, 2026-11-14 — **changes**.

Ran `pnpm --filter @oat/ai eval` → 25/25 structural, property 0.77, 0 regressions, PASS, exit 0. Mock tier,
fixtures, scorers, exit codes (0/1/2) and the clean-room fixtures are solid. Problems are in the real/quality
tier, which is the only tier that can catch a bad 4.4 prompt (the mock never reads the prompt):

1. **Judge = task model.** `src/evals/cli.ts:27` judges with role `chat`, and `src/models.ts:14-15` defaults
   `enhance` and `chat` to the same model → self-grading bias. Fix: add a `judge` role (`AI_MODEL_JUDGE`)
   defaulting to a different model than `enhance`; record the judge model id in results; warn when equal.
2. **Real baseline not keyed by model.** `src/evals/baseline.ts:14-18` keys by mode only; the model id
   (`runner.ts:50`) is dropped, so switching `AI_MODEL_ENHANCE` compares against another model's scores.
   Fix: store `{enhanceModel, judgeModel}` with the real table (or key by them) and report "not compared"
   on mismatch.
3. **Real-mode gate will be flaky.** `baseline.ts:106` compares per check; property checks are 0/0.5/1 and
   `judge:coverage` moves in 1/8 = 0.125 steps, both > the 0.1 real tolerance, and the task call has no
   temperature (`enhance.ts:110`, `EnhanceOptions` can't pass one). `length` is structural, so one long
   output hard-fails (`enhance-scorers.ts:181-192`, `runner.ts:59`). Fix: in real mode compare aggregates
   (per-fixture tier mean, or suite mean per tier) with the tolerance, optionally `--runs N` averaging; make
   `length` a property check (hard-fail only schema/headings/origin/notes-coverage).
4. **Judge can't verify what it is told to verify.** `enhance-judge.ts:29-34` gives the judge notes +
   transcript but no meta (title, date, attendees, who is "me"), and `formatTranscript` (`enhance.ts:80`)
   labels every non-mic speaker "Others" — yet the judge prompt (`:64-66`) demands owners/names match
   "exactly". Correct attributions ("Tomás sets up the Arjun call", "Morgan asks Priya", full names) will be
   flagged. Fix: include a meta block in `sources()` and explain the `Others` label.
5. **Hallucination traps fire on meta-grounded facts.** `sales-discovery.ts:206` forbids "November" (meeting
   date 2026-11-13 is in the prompt); `silence-gap.ts:39` `\b\d{2,}\b` fires on "2026"/"14:00".
   `fixtures.test.ts:38-42` checks only the transcript. Fix: run the "never forbids" guard against
   notes + transcript + rendered meta (date, month, weekday, names) and narrow those patterns.
6. **Schema contract has no nesting.** `enhance.ts:21-38`: flat `paragraph|bullet|task` maps to TipTap
   (paragraph / bulletList / taskList) but not to nested lists, which meeting notes rely on. Changing it in
   4.4 resets the mock baseline and contract. Fix: add optional `children: Block[]` now (and optionally
   `owner`/`due` on `task`, which would also make owner scoring robust instead of regex-in-text).

Optional: `wrong-clinic-count` (`sales-discovery.ts:196`) flags "17 clinics" (14 + 3, a fair inference);
`wrong-budget` misses 3-digit/k amounts ("$400k"); `stakeholders` needs literal "CFO" (synonym "chief
financial officer" fails). `eval:baseline --model real` without a key silently rewrites the *mock*
baseline — prefer exit 2. No `maxOutputTokens` on task/judge calls (cost bound). D-20 says origin is set
during conversion: 4.4 should derive it by note-line match (as the scorer does) rather than trust the model.
Reviewers should treat any `baseline.json` score decrease in a diff as a gate change needing justification.
