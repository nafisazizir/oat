# 3.3 — Documents & folders: API, sidebar tree, document page
status: done
milestone: M3 · deps: 1.6, 1.7, 3.1, 1.5 · branch: task/3.3-documents

## Goal
Real documents in the web app: create/read/update/soft-delete/restore/move pages and meeting notes, folders,
a live sidebar tree, and the document page using `@oat/editor` — every route authorised via `@oat/core`.

## Context
SPEC §4 Workspace/Editor, §6; D-4, D-18 (folder rules, decideMove*/visibilityForNewItem), D-19 (document
`version` = sync base version), D-22 (change_log via triggers — nothing to write by hand). `@oat/db` schema,
`@oat/core` permissions (`assertCan`, ForbiddenError), `@oat/editor` (`OatEditor`, `validateDoc`,
`ensureBlockIds`; SSR-safe), `apps/web` shell (`src/server/shell.ts` loader is where real data replaces mocks;
1.6 session in `(app)/layout.tsx`).

## Scope
In:
- `apps/web/src/server/documents.ts` (+ folders): data-access functions taking a session context; every
  function loads the resource, builds a PermissionContext, calls `assertCan`/`decideMove*`. Server Actions or
  route handlers (`/api/documents…`) — pick one consistently (route handlers are needed anyway for desktop
  sync in 3.5; prefer a typed route-handler API + thin server actions for forms). Zod-validated input;
  `validateDoc` on every content write; `content_md` derived later (3.2) — leave nullable + TODO hook.
- Optimistic concurrency: updates carry `baseVersion`; mismatch → 409 with server copy (3.5 builds the
  conflicted-copy UX; here return 409 and show a "this note changed elsewhere — reload" toast).
- Sidebar: real tree (Shared = workspace-visibility docs/folders, Private = user's private), create page /
  folder, rename inline, move via drag-and-drop or "Move to…" dialog (respect D-18 incl. private conversion
  confirm), trash (soft-deleted) view with restore + permanent delete (owner/admin only per permissions).
- Document page `/d/[docId]`: title + `OatEditor`, debounced autosave (≤ 1 s) with saving/saved/error state,
  read-only for viewers, 404 vs 403 handled without leaking existence of private docs (return 404).
- `getShellData()` uses real data.
- Tests: int tests for every API route incl. deny cases (anon, non-member, viewer write, private doc of
  another member → 404, cross-workspace move), 409 on stale version; Playwright e2e: sign in (magic link
  helper), create page, type with slash menu, reload → content persisted, move into private folder, trash +
  restore. Screenshots → `docs/tasks/evidence/3.3/`.
Out: Markdown derivation (3.2 provides; wire in a follow-up), meeting view (3.4), sharing dialog (5.3),
search (3.6), desktop sync (3.5).

## Design notes
(implementer + designer, 2026-11-14)

### Layers
```
route file (app/api/**/route.ts, 1 line) ─► createApi(deps) handlers (src/server/api/handlers.ts)
   apiRoute(): CSRF check → session (Better Auth: cookie or Bearer) → Actor (userId + @oat/core ctx)
   → zod input → data layer (src/server/documents.ts, folders.ts): load row → @oat/core check → write
server pages/layout ─► src/server/shell.ts (getShellData, loadDocumentPage, recent lists) ─► same data layer
client ─► src/lib/api-client.ts (fetch) ─► same routes; then router.refresh() re-renders the shell
```
- **Route handlers for everything, no server actions**: the desktop (3.5) needs the HTTP API anyway, so the
  web UI uses exactly the same routes. Mutations from the UI are `fetch` + `router.refresh()`
  (`refresh()` from `next/cache` only works inside server actions).
- `createApi(deps)` takes `{ db(), getSession(headers), allowedOrigins() }`; `src/server/api/index.ts` binds
  it to `getDb`/`getAuth` (lazy, so `next build` needs no env). Int tests bind it to a throwaway DB and an
  in-process `createAuth` with a capturing mailer, and call the handlers exactly as Next does.
- **Permissions**: every function loads the row(s) and calls `@oat/core` (`canReadDocument`/`canReadFolder`
  → 404, `assertCan('editDocument' | 'deleteDocument' | 'createInWorkspace' | 'createInFolder' |
  'editFolder' | 'deleteFolder')`, `assertCanMoveDocument`/`assertCanMoveFolder` → their `setVisibility`
  is applied in the same write). List queries pre-filter in SQL (`visibility <> 'private' or owner = me`)
  and then filter through `canReadDocument`, so core stays the rule. `access: { edit, delete }` on every
  item is computed by core too; the UI only uses it to hide actions.
- **Content writes**: `validateDoc` (400 `invalid_content`) → `ensureBlockIds` → `content_md =
  toMarkdown(json)` (3.2 is merged, so derived Markdown is wired in now, not a TODO). New docs start from
  `emptyDoc()` (the DB default `{type:'doc',content:[]}` doesn't pass `validateDoc`).
- **Versions (D-19)**: every accepted document write (title/content, move, trash, restore, visibility change
  from a folder move) bumps `version`. Updates require `baseVersion`; the check is in the UPDATE
  (`where id = ? and version = ?`), so two racing writers can't both win (int test fires 3 in parallel →
  one 200, two 409). Folders have no version column; nothing written by hand to `change_log` (D-22).

### API (`/api`, JSON; shapes in `src/lib/api-types.ts`)
| Route | Body / query | Result |
|---|---|---|
| `GET /documents?workspaceId=…[&trash=1]` | | `DocumentSummary[]` readable live (or trashed) docs |
| `POST /documents` | `{ workspaceId, folderId?, kind?, title?, visibility?: private\|workspace, contentJson? }` | 201 `DocumentDetail` |
| `GET /documents/:id` | | `DocumentDetail` (incl. trashed, if readable) |
| `PATCH /documents/:id` | `{ baseVersion, title?, contentJson? }` | `DocumentDetail` · 409 `stale_version` + `document` (server copy) |
| `DELETE /documents/:id[?permanent=1]` | | trash (idempotent) → `DocumentDetail`; permanent → 204, 409 `not_in_trash` unless trashed |
| `POST /documents/:id/move` | `{ folderId \| null, makePrivate? }` | `DocumentDetail` · 422 `confirm_private` |
| `POST /documents/:id/restore` | | `DocumentDetail` (back in its folder, or root if the folder was deleted) |
| `GET /folders?workspaceId=…` | | `FolderSummary[]` (workspace folders + my private ones) |
| `POST /folders` | `{ workspaceId, parentId?, name, visibility? }` | 201 `FolderSummary` |
| `PATCH /folders/:id` | `{ name }` | `FolderSummary` |
| `DELETE /folders/:id` | | `{ trashedDocumentIds }` |
| `POST /folders/:id/move` | `{ parentId \| null, makePrivate? }` | `FolderSummary` · 400 cycle · 422 `confirm_private` |

Errors are `{ error: { code, message } }`: 401 no session · 404 unknown **or unreadable** (another member's
private doc/folder, non-member's workspace) · 403 readable but not allowed (viewer write, member trashing
someone else's shared doc, cross-workspace move/create, `cross_site`) · 400 bad input (strict zod objects,
JSON content-type required, 4 MB cap) · 409/422 as above. Decisions:
- **Visibility on create**: default = the parent folder's visibility, else `private`; `visibilityForNewItem`
  forces `private` inside a private folder. `link` can't be set here (sharing is 5.3).
- **Private conversion (D-18) is confirmed, not silent**: a move that `decideMove*` says makes the item
  private returns 422 `confirm_private` unless `makePrivate: true`. A folder moved into a private folder
  makes its whole subtree private (the actor owns all of it, or core refuses).
- **Folders have no trash**: deleting a folder deletes it and its subfolders and trashes every live document
  inside (one transaction). Refused (403) unless the actor may delete every subfolder and every document
  in it, so nobody trashes items they couldn't delete one by one. Restored docs land at the root.
- **Viewers** get 403 on create before any folder lookup (they can't create anywhere), so a viewer probing a
  private folder id learns nothing either.
- **CSRF**: cookie-authenticated writes need `Origin` ∈ {`BETTER_AUTH_URL`, trusted origins} (or
  `Sec-Fetch-Site: same-origin` when Origin is absent/`null`); no Origin at all → 403. `Authorization:
  Bearer` (desktop) skips it (no ambient credentials).
- **No new indexes** (`packages/db` untouched): tree lists use `document_workspace_updated_idx` /
  `folder_workspace_parent_idx`; the subtree CTE walks `parent_id` (fine at sidebar scale; a
  `folder(parent_id)` index is a cheap follow-up if trees get big).

### UI
```
┌ Sidebar ─────────────────────────┐┌ /d/[id] (document) ─────────────────────────────────┐
│ [P] Docs Team ⇕                  ││ [🔒 Private] [👁 View only] Edited 15 Nov  ✓ Saved   │
│ ✎ New note   ⌕ Search   ⌂ Home   ││ Launch plan                 ← textarea, serif 3xl   │
│ SHARED                        +  ││ ┌ OatEditor (slash menu, bubble toolbar) ─────────┐ │
│  📁 Handbook             ⌄  …    ││ │ Goals …                                         │ │
│     📄 Onboarding 🔒        …    ││ └─────────────────────────────────────────────────┘ │
│ PRIVATE                       +  │└─────────────────────────────────────────────────────┘
│  📂 Drafts               ⌄  …    │  trashed: red banner "This page is in the trash."
│     📄 Roadmap              …    │           [Restore] [Delete forever], read-only
│  📝 Standup (meeting)       …    │  folder:  title + "New page" + contents list / empty state
│ 🗑 Trash  2 · Templates · Settings│
└──────────────────────────────────┘
```
- **Tree** (`page-tree.tsx`): Shared = top-level items with workspace/link visibility, Private = mine; a
  folder lists all its readable children (a private page inside a shared folder shows there with a lock).
  Items whose folder the user can't see become top-level, so nothing readable is unreachable. Rendered
  flat (depth-indented rows) so shadcn's `group/menu-item` hover actions don't bleed into nested rows.
  Folders first, then creation order. Folders expand/collapse (chevron); ancestors of the open page are
  always expanded. Shared is hidden in a personal workspace unless it has items. Viewers see no "+"/menus.
- **Row "…" menu**: Rename (inline input: Enter/blur saves, Esc cancels; focus kept off the menu trigger),
  Move to…, New page/folder inside (folders), Move to trash / Delete folder. Section "+" → New page / New
  folder (a new folder opens straight into inline rename).
- **Move**: drag a row onto a folder (HTML5 DnD; the section label = top level, only within the same
  area since changing visibility is sharing, 5.3) or **Move to…** (searchable `CommandDialog` of the root +
  folders I can add to, minus the item's own subtree; private folders marked with a lock). Moving a
  non-private item into a private folder opens a confirm dialog ("Make “X” private? … Workspace members
  lose access") → `makePrivate: true`. The client mirrors D-18 to ask before the request (no failing
  round-trip); the server's 403/422 remain the authority and are handled too.
- **Trash**: sidebar footer item with a count opens a dialog: title (links to the read-only page), deleted
  date, Restore, and a trash icon that turns into "Delete forever" (second click). Trashing from the menu
  toasts with Undo. Folder delete always confirms.
- **Document page** (`document-editor.tsx`): title textarea (`field-sizing: content`, Enter → editor) +
  `OatEditor`. New empty pages focus the title. Badges: visibility, "View only" for viewers. Read-only when
  `!access.edit` or trashed. Content/title are local state from first render, so `router.refresh()` (after a
  title save, to update sidebar/breadcrumbs/tab title) never overwrites typing.
- **Autosave** (`use-autosave.ts`): edits merge into one pending patch; debounce 400 ms, max wait 1 s; one
  request in flight, newer edits queue. States: Saving… / ✓ Saved / "Couldn’t save · Retry" (network or 5xx
  retried every 4 s, edits kept) / "Changed elsewhere · Reload" on 409 (saving stops; persistent toast
  "This note changed elsewhere" with Reload; 3.5 adds conflicted copies). Flushes on tab hide and unmount
  (`keepalive` when < 60 KB), `beforeunload` warns while unsaved. Same-tab changes from the sidebar
  (rename/move/restore bump the version) are announced with a window event so the open editor adopts the
  new version instead of hitting a spurious 409.
- **404 vs 403**: `/d/[id]` renders the not-found page for anything unreadable (another member's private
  page looks exactly like a missing one; e2e checks with a second user, also via the API). The HTTP status
  is 200 because the shell has streamed before the page calls `notFound()` (Next behaviour with
  `loading.tsx`); the API returns a real 404.
- **Home**: Recent notes (meeting notes, newest edit first) and Jump back in (pages) from the DB; "New note"
  creates a meeting note in Private and opens it. ⌘K lists the real tree. Breadcrumbs: workspace ›
  Private/Shared (by the top-most visible ancestor) › folders › page; trashed → workspace › Trash › page;
  a doc outside the active workspace's tree → "Page".
- Components (all `@oat/ui`): sidebar (Group/Label/Action, Menu/Item/Button/Action, Input), dropdown-menu,
  command (CommandDialog), dialog, button, badge; lucide icons. Tokens only (`tokens-only.test.ts` passes).

### Fixes for review 1 (2026-11-14)
Merged `main` first (no conflicts; nothing in `apps/web` had changed there).
1. **False 409 on a sidebar rename after a body edit.**
   - Shared rule `canRebase(patch, base, server)` (`src/lib/json-equal.ts`, unit-tested): a patch made
     on `base` may be re-sent on the server's newer version when every field it writes is still unchanged
     on the server (content compared ignoring key order, since `jsonb` reorders keys).
   - Sidebar rename: sends the newest version this tab has seen (a version map fed by the
     `oat:document-changed` event, which autosave now fires after every save, plus moves and restores).
     On a 409 it re-sends once on the server's version if the server title is still the one the user saw.
     A real concurrent rename still shows "This page was renamed elsewhere".
   - Autosave: same rule on 409 (at most 3 rebases in a row), so a rename racing an in-flight body save
     doesn't put the editor into conflict. Only a real concurrent change to the same field stops saving.
   - e2e: edit the body → rename from the sidebar → no failed request (console guard), the editor
     adopts the title and keeps saving, and a reload shows both. Second e2e: body edited via the API
     (tree still on v0) → sidebar rename re-sends and succeeds. The conflict e2e now uses a real
     body/body conflict.
2. **Concurrent structural writes.** `lockTree(tx, workspaceId)` = `pg_advisory_xact_lock(hashtext(
   'oat:tree:' || workspace_id))` at the start of `moveFolder`, `deleteFolder`, `moveDocument` and of
   create-into-a-folder (`createFolder`/`createDocument` with a parent). Rows are re-read under the lock;
   the cycle check, `decideMove*` and the subtree-ownership check all run inside that transaction. The parent
   of a create and the target of a document move are also read `FOR UPDATE`. New int tests (5 rounds each):
   A→B ∥ B→A → exactly one 200 and one 400, one folder still at the root; move-into-private ∥ another member
   creating a page in the subtree → either the move is refused (page stays shared) or the create is a 404,
   never a page swept private. With `lockTree` disabled both tests fail; with it they pass.
3. Non-blocking notes, all done:
   - The autosave retry timer is cleared on unmount, so there are no timed retries once the editor is gone.
   - `beforeunload` still warns while edits are unsaved, including ones kept after a conflict, but not
     after the user clicks Reload (`discard()`). The e2e records dialogs and fails if one appears; I checked
     it fails with `discard()` removed.
   - Cross-workspace folders are the same 404 as unknown ones: create into one, and move a document or
     folder into one. Int tests updated from 403 to 404.
   - Folder delete refusals use the generic 403 text, so they don't hint at hidden children.
   - The Origin check is skipped only for `Authorization: Bearer` requests **without** a `cookie` header.
     Int test: a cookie request with a forged bearer and a foreign Origin gets 403.
   - `moveDocument` runs in a transaction, so a folder deleted mid-move is a 404, not an FK 500.
   - A trashed page shows an "In trash" badge instead of "View only".
   - A folder from a non-active workspace lists its own children, and the visibility badge names the item's
     own workspace.
   - Not done: buffering of chunked bodies with no `content-length` before the 4 MB check (Next/Vercel cap
     bodies upstream; noted for 9.x hardening). Also not changed: the product call that a member's private
     page inside a shared folder blocks an admin's folder delete. It stays as designed: refused, generic 403.

## Review

### Review 1 (reviewer, 2026-11-14) — verdict: **changes**

Read: task file, `git diff main...task/3.3-documents`, `@oat/core` permissions, D-4/18/19/22/23, SPEC §4/§6,
screenshots (move-confirm-private, trash-dialog, conflict). Authz is solid: every route loads the row and asks
core; nothing trusts a body `workspaceId` for an existing resource (create checks folder ∈ workspace; moves
go through `decideMove*`, which denies cross-workspace; other members' private folders/docs are 404 on every
verb); list/trash/folder SQL pre-filters + `canRead*` hide others' private titles; trash/restore/permanent
use `deleteDocument`; `validateDoc` runs on create and update (restore/move don't write content); the
content UPDATE is atomic (`where version = $base`) and tested with 3 racers; CSRF origin check is sound
(bearer bypass needs a non-safelisted header → CORS preflight, which we never answer); `shareToken` and
`content_md` never reach the client; tree loader is 3 parallel queries, no N+1. Two real problems:

1. **Sidebar rename of a page 409s after any content edit** — `apps/web/src/components/app-shell/tree-actions.tsx:162-163`
   sends `baseVersion: node.version` from the shell tree, but content autosaves don't refresh the shell
   (`document-editor.tsx` only calls `router.refresh()` after title saves, and the `(app)` layout doesn't
   re-render on soft navigation). So: open a page, type in the body, rename it from the sidebar → "This page
   changed elsewhere" toast; it stays broken until a full reload. Fix: a title-only rename can't clobber
   content, so on `stale_version` retry once with `error.body.document.version` when the server copy's title
   still equals `node.title` (otherwise show the toast); and/or let an open editor for that id own the
   rename. Add an e2e/int check: edit body → rename from sidebar → succeeds and the editor keeps saving.
2. **Folder moves race (cycle + D-18 sweep)** — `apps/web/src/server/folders.ts:196-231`: the cycle check
   and the subtree-ownership check are read-then-write under READ COMMITTED with no lock. Two concurrent
   moves A→B and B→A both pass and create a cycle; neither folder is then a root nor an orphan, so both
   (and everything inside) disappear from the tree for good. Likewise a document created in the subtree
   between the read and the `update … set visibility='private'` gets swept private under someone else's
   private folder. Fix: serialise structural folder writes per workspace — e.g.
   `select pg_advisory_xact_lock(hashtext(${workspaceId}))` at the start of `moveFolder`/`deleteFolder`
   (and take `for share` on the parent folder row in `createDocument`/`createFolder`/`moveDocument`). Add a
   regression int test firing A→B and B→A in parallel (expect one 200, one 400, no cycle).

Optional (nits, not blocking):
- `use-autosave.ts:97,155-159`: the unmount flush can schedule a retry timer nobody clears (retries every
  4 s forever on a persistent 5xx); clear it once the hook is torn down / cap retries after unmount.
- In `conflict` state the kept `pending` patch makes `beforeunload` prompt when the user clicks the toast's
  "Reload" — either clear the warning on explicit Reload or keep it deliberately.
- `shell.ts:138-142` / `d/[docId]/page.tsx:55`: a folder in a non-active workspace renders as "empty"
  (children come from the active workspace's tree), and a doc from another workspace shows the active
  workspace's name in its visibility badge.
- `folders.ts:251-256`: the 403 messages reveal that a shared folder holds items the actor can't see; a
  member's private page in a shared folder also makes that folder undeletable even for admins (documented,
  but worth a product call).
- `route.ts:36`: skip the Origin check only when the session actually came from the bearer token (or no
  `cookie` header is present) — defence in depth; Better Auth falls back to the cookie on a bad bearer.
- `route.ts:90`: chunked bodies without `content-length` are fully buffered before the 4 MB check.
- `moveDocument` isn't transactional: a folder deleted between read and update → FK error → 500 (map to 404).
- Trashed page shows a "View only" badge to its owner (trash-dialog.png); say "In trash" instead.
