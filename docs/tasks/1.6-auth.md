# 1.6 — Better Auth: magic link + Google, workspaces
status: in-progress
milestone: M1 · deps: 1.5, 1.4 · branch: task/1.6-auth

## Goal
Sign-in that works fully offline in dev (D-11): email magic links delivered to Mailpit, Google OAuth via the
mock OIDC server, Better Auth organization plugin mapped onto our workspaces, and a personal workspace
created on sign-up. Real providers switch on with env only.

## Context
SPEC §4 Auth/Workspace, D-9/D-14, D-11, D-18. `packages/db` (1.5): Better Auth tables + `auth-mapping.ts`
(organization→workspace, member→membership, invitation→invite) and its Design notes for 1.6 (createdBy via
`beforeCreateOrganization`, verified email for invite accept, custom `viewer` role). `apps/web` (1.4) shell — see its Design notes for exactly where the session check goes (`(app)/layout.tsx`) and the `getShellData()` loader in `src/server/shell.ts` +
`(auth)/sign-in` UI. `@oat/core` permissions/roles. `@oat/testkit` Mailpit helpers. `docs/DEV.md` (OAuth mock
issuer `http://localhost:18089/google`, non-interactive login for tests). Load the `vercel:auth` skill only for
general guidance — we use Better Auth (not Clerk).

## Scope
In:
- `packages/auth` (`@oat/auth`) or `apps/web/lib/auth` (decide; desktop 1.8 will need the session-token
  exchange, so prefer a package): Better Auth server config — Drizzle adapter on `@oat/db`, `magicLink` plugin
  (nodemailer SMTP from env → Mailpit in dev; our own email template, plain + HTML), Google social provider
  pointed at `OAUTH_GOOGLE_ISSUER` (mock in dev; real Google when real client id/secret set — use genericOAuth
  if the built-in Google provider can't take a custom issuer), `organization` plugin with our mapping + roles
  owner/admin/member/viewer (access control matching `@oat/core` permissions), `bearer` plugin (desktop),
  secure cookie settings, `BETTER_AUTH_SECRET`/`BETTER_AUTH_URL` from env (dev defaults in `.env.example`).
- On user creation: create a personal workspace (`kind: personal`, owner membership) in the same transaction
  / hook; set as active.
- `apps/web`: route handler `/api/auth/[...all]`, sign-in page wired (email form → "check your email" state;
  "Continue with Google"), sign-out, `getSession()` server helper, middleware/proxy protecting `(app)` routes,
  workspace switcher shows the user's real workspaces (from DB), create-team-workspace dialog (minimal; full
  settings in 5.1).
- Email: `packages/email` or inside auth — React Email optional; must render without network.
- Tests: int tests (test DB + Mailpit + in-process or container oauth mock): magic-link sign-up creates user +
  personal workspace; second sign-in reuses; Google mock login creates/links account; session cookie works on
  a protected route; viewer role cannot create docs (permission hookup smoke). Playwright e2e in apps/web:
  sign in via magic link (read link from Mailpit API) and via Google mock (non-interactive form post), land on
  /home with the personal workspace in the switcher; screenshot to `docs/tasks/evidence/1.6/`.
Out: invites UI/email (5.2), desktop deep link (1.8), member management (5.x).

## Acceptance criteria
- [ ] Both sign-in methods work end-to-end against the compose stack with only `.env.example` defaults.
- [ ] Personal workspace auto-created exactly once per user.
- [ ] Protected routes redirect anonymous users to /sign-in.
- [ ] No external network; global gates + `test:int` + web e2e green.
