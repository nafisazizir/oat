mock OIDC server, Better Auth organization plugin mapped onto our workspaces, and a personal workspace
created on sign-up. Real providers switch on with env only.

## Design notes
(implementer, 2026-11-14)

**Where it lives.** New package `packages/auth` (`@oat/auth`), so desktop (1.8) can reuse the client and
token exchange. better-auth 1.7.25 (catalog `^1.7.12`); no new catalog entries (better-auth, nodemailer,
@types/nodemailer, tsx, zod were already there).
- `src/server.ts` `createAuth({ db, config, mailer? })` → `betterAuth(...)`; `type Auth`.
- `src/config.ts` `authConfigFromEnv(env)` (zod; errors name variables, never values; refuses the dev secret
  when `NODE_ENV=production`).
- `src/access.ts` statements + roles (shared by server and client). `src/email.ts` magic-link template
  (plain + HTML, inline styles, no template engine, no network) + nodemailer SMTP mailer.
- `src/workspaces.ts` `ensurePersonalWorkspace`, `findPersonalWorkspaceId`, `listUserWorkspaces` (with member
  counts, personal first), `pickActiveWorkspace`, `loadPermissionContext` (→ `@oat/core` context),
  `teamWorkspaceSlug`.
- `src/client.ts` (`@oat/auth/client`): framework-free `createOatAuthClient()` (magic link + organization
  client). `src/cookies.ts`: `getSessionCookie` for the proxy.

**Better Auth config.**
- Drizzle adapter on `@oat/db` schema with `transaction: true` (OAuth user + account and workspace + owner
  membership are atomic). `generateId: newId` (UUIDv7). `organizationOptions` from `auth-mapping.ts`
  (workspace/membership/invite mapping, `disableOrganizationDeletion`, D-22).
- **Magic link:** 15 min, single use (Better Auth consumes it atomically), token stored **hashed**. Mail goes
  through `SMTP_*` (Mailpit in dev).
- **Google:** the built-in provider hard-codes Google's endpoints, so Google is a `genericOAuth` provider with
  id `google` and `discoveryUrl = ${OAUTH_GOOGLE_ISSUER}/.well-known/openid-configuration`,
  `requireIdTokenVerification: true` (id_token checked against the discovered JWKS, issuer and nonce), PKCE.
  Same code path for the mock and for `https://accounts.google.com`. In 1.7.x generic providers use the core
  `sign-in/social` + `callback/:id` routes, so the redirect URI is `${BETTER_AUTH_URL}/api/auth/callback/google`
  (in DEV.md for the real switch). Discovery runs lazily on first use and is retried per request if the issuer
  was down.
- **Account linking:** Better Auth's default rule (provider says `email_verified` and the local user is
  verified), so Google links to an existing magic-link user. Int test covers it.
- **Organization plugin:** `ac` + roles owner/admin/member/viewer (`access.ts`): org update (owner/admin),
  org delete (owner; disabled anyway), member + invitation (owner/admin), `document` create/read/update
  (member), read (viewer), all (owner/admin). `access.test.ts` asserts each statement equals the matching
  `@oat/core` function for a team workspace, so they can't drift. Hooks: `beforeCreateOrganization` forces
  `kind: 'team'` and sets `createdBy` (personal workspaces are only made by `ensurePersonalWorkspace`, so a
  client can't create a second one); `beforeCreateInvitation` runs `@oat/core canInvite` (personal workspace,
  or a role above your own → 403); `beforeAddMember`/`beforeAcceptInvitation`/`beforeUpdateMemberRole`/
  `beforeRemoveMember` refuse personal workspaces. Role change/remove in team workspaces relies on Better
  Auth's AC and its owner protections for now; 5.x member management should go through core
  `canChangeRole`/`canRemoveMember` (owner count under a lock).
- **Bearer** with `requireSignature: true`: desktop sends the signed token from `set-auth-token`; an unsigned
  raw token is rejected (int test). **nextCookies** last (a no-op outside Next).
- Cookies: `httpOnly`, `sameSite=lax`, `__Secure-` prefix whenever `BETTER_AUTH_URL` is https. Sessions 30
  days, refreshed daily. `trustedOrigins = [BETTER_AUTH_URL, ...BETTER_AUTH_TRUSTED_ORIGINS]` (Better Auth
  checks Origin on cookie POSTs and validates `callbackURL`s against it). Telemetry off.

**Personal workspace, exactly once.** `databaseHooks.user.create.after` → `ensurePersonalWorkspace(db, userId)`:
one Drizzle transaction that inserts the workspace (`slug = personal-<userId>`, `kind personal`, name
"Personal") `on conflict (slug) do nothing`, then the owner membership `on conflict do nothing`. The unique
slug makes it idempotent and race-safe. Better Auth runs `create.after` hooks *after* its transaction commits,
so our own connection sees the user row (otherwise the FK insert would wait on Better Auth's open
transaction). `databaseHooks.session.create.before` sets `activeOrganizationId` to the personal workspace
when the session has none (and heals a missing one). Caveat for upgrades: that hook also uses our own
connection; if a future Better Auth created the session inside the user's transaction it would block, and the
int tests would hang/fail rather than pass silently. The app shell also heals a user with zero memberships.

**apps/web.**
- `src/server/db.ts` `getDb()` and `src/server/auth.ts` `getAuth()`: lazy singletons on `globalThis` (no env
  read or OIDC discovery during `next build`; one pool across dev HMR).
- `src/app/api/auth/[...all]/route.ts`: GET/POST → `getAuth().handler`.
- `src/server/session.ts`: `getSession()` (React `cache`; reads `headers()` first so a route becomes dynamic
  before env/DB are touched; `/templates` used to prerender) and `requireSession()` → `redirect('/sign-in')`.
- `src/proxy.ts` (Next 16 proxy): matcher `/home`, `/d/:path*`, `/settings`, `/templates`; no session cookie →
  `/sign-in?next=<path+query>`. Optimistic only; `(app)/layout.tsx` calls `requireSession()` first, so forged
  or expired cookies also end at sign-in (e2e). `proxy.test.ts` fails if a new `(app)` route isn't matched.
- `src/lib/redirect.ts` `safeNextPath` (rejects absolute URLs, `//host`, backslashes, `/sign-in` loops) and
  `signInPath`.
- Shell: `ShellData` gains `user` (`ShellUser`); `getShellData()` = session user + `listUserWorkspaces` +
  active workspace (the session's, else personal). The pure part `buildShellData` is unit-tested.
  **Documents are still the 1.4 mock** for every workspace (3.3 replaces those getters).
- Sign-in page (server): already signed in → redirect to `next`; Better Auth's `?error=` codes mapped to copy
  (`src/lib/sign-in-errors.ts`); in development the "Check your email" state links to Mailpit. Form (client):
  magic link → "Check your email" (address, 15-minute note, "Use a different email"); Google → provider
  redirect; pending spinners; errors in a live region. `callbackURL = next`, `errorCallbackURL = /sign-in`.
- Sidebar: the workspace switcher lists real workspaces ("Personal space" / "N members"). Switching calls the
  `switchWorkspace` server action (`setActiveOrganization`, membership checked by Better Auth, then
  `refresh()`). "Create workspace" opens `CreateWorkspaceDialog` (name only; zod-validated server action
  `createTeamWorkspace` → `createOrganization` with `teamWorkspaceSlug(name)` → set active). New footer
  `UserMenu` (avatar or initial, name, email, Sign out → `authClient.signOut()` → `/sign-in`). Tokens only.
- Env: `BETTER_AUTH_SECRET` (dev value in `.env.example`, refused in prod), `BETTER_AUTH_URL`,
  `BETTER_AUTH_TRUSTED_ORIGINS` in `.env.example` and the web env schema; turbo `dev`/`test:int` pass
  `BETTER_AUTH_*` through.

**Verdict: `changes`** (two real holes, both small fixes).

Checked and fine: magic link 15 min, hashed, consumed atomically, same response for new/existing emails (no
enumeration), `revokeUnprovenAccountAccess` on first magic-link sign-in of an unverified OAuth-created user
(pre-hijack covered); Google via genericOAuth verifies id_token against discovered JWKS + iss + aud + nonce,
PKCE on, state handled by core; linking needs provider `email_verified` **and** local `emailVerified`
(`requireLocalEmailVerified` default true); invite accept requires verified email (implied by custom
`generateId`); cookies httpOnly/lax/`__Secure-` on https; Better Auth origin check on cookie POSTs and
callbackURL validation (relative `//` rejected); server actions get Next's Origin check and call
`requireSession`; bearer `requireSignature: true`; dev secret refused when `NODE_ENV=production` (Vercel
previews included); email template escapes the only variable (`url`); access.ts ↔ core matrix incl. viewer;
personal-workspace insert is race-safe under concurrent sign-ins; `packages/db` `MIGRATIONS_FOLDER` change is
value-identical.

1. `apps/web/src/lib/redirect.ts:12-16` (used by `sign-in/page.tsx:22`) — **open redirect.** The raw-string
   checks run before URL normalisation, and the returned `url.pathname` is normalised: `safeNextPath('/.//evil.com')`
   (also `/a/..//evil.com`, `/%2e//evil.com`) returns `//evil.com` (verified with tsx). A signed-in user opening
   `/sign-in?next=/.//evil.com` gets `redirect('//evil.com')` → off-site. Fix: after building the result, reject
   it if it starts with `//` or `/\` (or re-run the raw checks on the normalised path); add these cases to
   `redirect.test.ts`.
2. `packages/db/src/auth-mapping.ts:33-38` + `packages/auth/src/server.ts:120-160` — **`kind` and personal slug
   are mutable via `POST /api/auth/organization/update`.** `kind` is `input: true`, so Better Auth's update body
   accepts it, and there is no `beforeUpdateOrganization`. An owner can flip their personal workspace to `team`
   and then invite into it (bypasses `canInvite`'s personal rule); any team admin can flip a team workspace to
   `personal`, after which `beforeRemoveMember`/`beforeUpdateMemberRole` refuse everything (admin can't be removed).
   Changing a personal workspace's `slug` makes `findPersonalWorkspaceId` miss it, so the next sign-in's
