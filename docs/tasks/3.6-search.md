# 3.6 — Full-text search (Postgres FTS + ⌘K)
status: done
milestone: M3 · deps: 3.3 · branch: task/3.6-search

## Goal
Find any note or transcript line fast: Postgres full-text search over titles, note Markdown and transcript
segments, permission-filtered, surfaced in the ⌘K palette and a search page. (Desktop-local FTS5 is part of
3.5/desktop sync work — out of scope here.)

## Context
SPEC §4 Search, PLAN 3.6, `@oat/db` (document.content_md from 3.3, transcript_segment, pg_trgm enabled),
`@oat/core` permissions (search must never return what the user can't read — filter in SQL by workspace
membership + visibility + ownership, then re-check), `apps/web` ⌘K palette + data seams.

## Scope
In:
- Migration: generated `tsvector` columns (weighted: title A, content_md B; segment text) with GIN indexes;
  `pg_trgm` index on title for fuzzy/prefix; `unaccent` if available (add extension in init script + migration).
- `searchDocuments(ctx, q, {limit, cursor})` and `searchSegments(...)`: websearch_to_tsquery, ranking
  (ts_rank_cd + recency boost), highlighted snippets (ts_headline, safe HTML: only <mark>), prefix fallback via
  trigram for short queries; SQL-level permission filter.
- `GET /api/search?q=` (session auth), ⌘K palette shows top results (notes + transcript hits with time) with
  keyboard nav; `/search?q=` page with tabs (Notes / Transcripts), empty/loading states.
- Tests: int tests with seeded docs across two users/workspaces: private docs of others never returned,
  snippet escaping (no HTML injection), ranking sanity, performance (10k docs < 100 ms on dev DB — record).
  e2e: type in ⌘K → open result. Screenshots.

## Design notes
**Data (migration `0006_search.sql`, hand-written via `drizzle-kit generate --custom`).**
- `unaccent` extension (also added to `docker/postgres/init/01-extensions.sql` → needs `pnpm dev:build` on main;
  the migration creates it anyway, so nothing breaks before that) and a text search config
  `public.oat_search` = english stemming with `unaccent` first (a config can back a generated column; calling
  `unaccent()` directly can't — it is only STABLE).
- `document.search_tsv` = title (weight A) ‖ `left(content_md, 256 KiB)` (weight B), GENERATED STORED, GIN
  index. The cap keeps a giant note below the 1 MB tsvector limit (otherwise the write would fail); text past
  it isn't searchable. `document_title_trgm_idx` (GIN `gin_trgm_ops`) on title.
- `transcript_segment.search_tsv` = text, GENERATED STORED, GIN index.
- The columns are deliberately **not** in the Drizzle schema: every `select()` would otherwise fetch them and
  `DocumentRow` would change. Drizzle diffs against its snapshot, not the DB, so `db:generate` stays clean
  ("No schema changes"); comments in `schema/documents.ts` / `meetings.ts` point at them.

**Queries (`packages/db/src/search.ts`: `searchDocuments`, `searchSegments`, `parseSearchQuery`,
`toSafeHighlight`).**
- Query plan: plain words → `to_tsquery('w1' & 'w2':*)` (last word is a prefix → results while typing; words
  are reduced to letters/digits, and everything goes in as bind parameters). Quotes, `-word` or `or` →
  `websearch_to_tsquery`. Empty/punctuation-only → no query.
- Title fallbacks via the trigram index: ≥ 3 chars → `ILIKE '%q%'` or `q <% title` (word similarity, typos);
  1–2 chars → word-prefix `ILIKE 'q%' / '% q%'`.
- Rank = `ts_rank_cd(tsv, q, 32)` (title A > body B) + title similarity (0.3·word_similarity, or 0.2 for a
  short-prefix hit) + recency `0.1·exp(-age/30 d)`; ties → newer, then id. Segments: rank + recency, then
  earlier in the meeting.
- Permission filter in SQL: live docs only; `exists(membership of user in d.workspace_id)` and
  `(owner = user or visibility <> 'private')` — exactly `canReadDocument` for live docs (share tokens never
  apply to search). Optional `workspaceIds` only narrows. The web layer re-checks every hit with
  `@oat/core` `canReadDocument` before returning it.
- Pagination: `limit` (≤ 50) + offset, fetched as limit+1 for `hasMore`. Rank order isn't keyset-friendly, so
  the API cursor is an opaque offset (`o40`, max 1000).
- Snippets: `ts_headline` runs only on the returned page (`top` CTE, input capped at 64 KiB) with private-use sentinels
  (U+E000/U+E001) as StartSel/StopSel; those characters are stripped from the source first, so content can't
  forge a highlight. `toSafeHighlight` escapes `& < > "` and turns sentinels into `<mark>`/`</mark>` (balanced).
  Body text is de-Markdowned for snippets (link targets, `> ` quote markers, `*_#~|[]` and backslashes).
  Notes: up to 2 fragments (≤ 18 words); title fully highlighted; segments ≤ 24 words.

**API (`apps/web/src/server/search.ts`).** `GET /api/search?q=&type=all|notes|transcripts&workspaceId=&limit=&cursor=`
via the shared `apiRoute` (session cookie or bearer, 401 otherwise). `workspaceId` must be one of the user's
(404 otherwise, same as other APIs). `type=all` returns both sections and refuses a cursor (page one type at a
time). Wire types + pure helpers in `src/lib/search.ts`. Route file binds `createSearchApi(apiDeps)` (same
pattern as templates), so `src/server/api/index.ts` is untouched.

**UI.**
- Highlights are never injected as HTML: `<Highlight>` splits the safe HTML on `<mark>` and renders text nodes
  (`highlightParts`, unit-tested), styled `bg-warning/30` (honey highlighter, token-only).
- ⌘K (`command-menu.tsx`): searches the active workspace (`type=all`, 5 each, 150 ms debounce, aborts stale
  requests, keeps previous results while loading). cmdk filtering is off; the palette ranks itself: local items
  (Go to, the tree's pages/folders, actions, theme) are scored with cmdk's `defaultFilter`; groups whose best
  score > 0.5 render *above* the server results (so "settings" ↵ still opens Settings and a page title ↵ opens
  it before results arrive), weaker fuzzy matches below them. Server Notes (title + 1-line snippet) and
  Transcripts (snippet, meeting title, `m:ss` time) follow, then "Search all results for “q”" → `/search`.
  Pages already among the note results aren't listed twice. The cursor moves to the top item whenever the
  query or fresh results change, so Enter opens the best hit; arrows/Enter are cmdk's. (cmdk's own group
  sorting was not usable: it looks groups up by `encodeURIComponent(heading)`, so "Go to" never moves.)
- `/search?q=&tab=notes|transcripts` (`(app)/search/page.tsx` + `components/search/search-view.tsx`): query
  box (syntax hint), Notes / Transcripts tabs with loaded counts (`20+`), rows with highlight, meta
  (Private/Shared · date; transcript: time, Me/Them or speaker label), "Load more" (cursor), states: idle
  empty state, skeleton while loading, per-tab "no match" empty state, error with retry. URL kept in sync with
  `history.replaceState` (no RSC round-trip per keystroke). Added to `sections` (breadcrumb "Search") and to
  the proxy matcher.
- Transcript hits link to `/d/<meetingDoc>?t=<seconds>`; nothing reads `t` yet (transcript panel 2.5 can).

**Tests.** `search.test.ts` (query parsing, escaping), `search.int.test.ts` (15: 4 users incl. a non-member and
a removed member, personal + team workspaces, private/workspace/link/trashed docs and meetings, interim

segments inserted via the e2e server's DB URL, which `web-server.ts` now writes to `e2e/.auth/database-url-<port>`).

**Touched outside the listed scope (small):** `apps/web/src/proxy.ts` (matcher + `/search`),
`apps/web/src/lib/navigation.ts` (`sections.search`), `apps/web/e2e/web-server.ts` + `e2e/paths.ts` (DB URL
file, evidence path), `apps/web/package.json` (`cmdk` for `defaultFilter`), schema comments in

## Review
**Reviewer (2026-11-14): changes** — one required fix; otherwise solid.

Checked and fine: SQL filter = `canReadDocument` for live docs except (1) — removed members (no row) and
non-members excluded, viewers read, others' `private` excluded, `workspace`/`link` readable by members only,
share tokens never apply, trash excluded (docs and meeting segments), `is_final` only; every value is a bind
parameter (no string splicing; `CONFIG` is a constant `sql.raw`); `escapeLike` escapes `\ % _`; prefix words are
`[\p{L}\p{N}]+` only; `websearch_to_tsquery` gets raw text safely. XSS: sentinels stripped from title/body/segment
*before* `ts_headline`, `toSafeHighlight` escapes *after* it, UI renders via `highlightParts` as React text (no
`dangerouslySetInnerHTML`). Query capped at 200 chars, limit ≤ 50, offset ≤ 1000. Migration: config-backed
generated column is immutable-correct, extension `IF NOT EXISTS`. ⌘K: strong local matches stay above server
results, cursor resets to top, empty-query view unchanged. `e2e/.auth/database-url` is git-ignored
(`apps/web/.gitignore:2`) and holds only the throwaway local test DB URL.

Required:
1. **Soft-deleted workspaces are not excluded in SQL** — `packages/db/src/search.ts:159` checks only
   `membership`; D-22 soft-deletes team workspaces (`workspace.deleted_at`) and `loadPermissionContext` skips
   them. The web re-check hides the rows, so nothing leaks via `/api/search`, but the SQL contract the file
   documents ("= `canReadDocument`") is false: `/api/search` without `workspaceId` returns short/empty pages
   with a `nextCursor` when a deleted workspace's docs outrank live ones, and any future caller without the
   re-check (AI tools, M4 chat) would leak deleted-workspace content. Fix: `exists (select 1 from membership mb
   join workspace w on w.id = mb.workspace_id and w.deleted_at is null where …)`; add a soft-deleted team
   workspace to `search.int.test.ts` (docs + segments, both with and without `workspaceIds`).

Optional:
- `apps/web/src/server/search.ts:51` emits `nextCursor` past `MAX_SEARCH_OFFSET` (e.g. `o1020`), which
  `decodeSearchCursor` then rejects with 400 → "Load more" errors after ~50 pages. Return `null` instead.
- `search.ts:234-238`: headlines run on `limit + 1` rows (the `hasMore` probe too), each over up to 256 KiB of
  regex-cleaned Markdown. Cap the snippet input (e.g. 32–64 KiB) and/or headline only `limit` rows.
- `0006_search.sql`: `ADD COLUMN … GENERATED STORED` rewrites `document`/`transcript_segment` under ACCESS
  EXCLUSIVE and the GIN indexes are built non-concurrently — fine pre-launch, note it for later migrations.
- `0002` change-log trigger's `to_jsonb(NEW)` now also serialises `search_tsv` on every document/segment
  write; consider passing only `id`/`workspace_id`/parent id there later.
- Concurrent `web-server.ts` runs in one checkout overwrite the same `database-url` file (per-port name).
- `docs/DEV.md`: add `unaccent` (already noted in the task).
