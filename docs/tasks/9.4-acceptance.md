## Goal
One script proves v1 works end to end on a clean machine with only Docker + Node + pnpm (D-11): sign up →
record a fixture meeting on desktop → transcript live → stop → post-meeting pipeline enhances → share via link →
teammate invited sees it → chat answers with citations → Notion (mock) receives the page → search finds it →
playback seeks. Runs in CI as its own step.

## Design notes
(implementer)

**Where.** New workspace package `@oat/acceptance` at `e2e/acceptance/` (`pnpm-workspace.yaml` gains `e2e/*`):
`journey.spec.ts` + its own `playwright.config.ts`. Script name `acceptance` (not `e2e`, so the existing `e2e`
CI step doesn't run it twice): `pnpm --filter @oat/desktop run build && playwright test`. It reuses the existing
helpers instead of copying them: apps/desktop `e2e/helpers.ts` (`launchApp`, `waitForSignInUrl`,
`deliverDeepLink`, `scaled`, `evidence`, `writeEvidence`), apps/web `e2e/auth-helpers.ts`, `e2e/fixtures.ts`
(`hydrationAware`), `e2e/paths.ts` (`mocksUrlFile`), and the same web server (`apps/web/e2e/web-server.ts`:
throwaway DB, in-process LLM/Notion/GCal mocks, index worker, this checkout's agents server) with its own
`OAT_NEXT_DIST_DIR=.next-acceptance`. The package's eslint config turns off the D-29 `no-restricted-imports`
rule (it forbids relative imports into `apps/`): this is test code importing the apps' test helpers, sitting
above every app. No product code touched.

**Journey** (one test, one `test.step` per phase; one owner, one stranger, one teammate; all mocks):
1. Sign up on the web (magic link via Mailpit) → `/home`.
2. Settings → Integrations: connect Notion (mock), target "Meeting notes", turn on auto-send.
3. Desktop: fresh profile, `OAT_AUDIO_SOURCE=file:standup-short`, `OAT_CALENDAR=off`, `OAT_DETECTION=off`,
   `OAT_END_GRACE_MS=0` (7.5: stopped meeting ends at once; harmless before 7.5 lands). Cold start read from
   `app:info`. "Sign in with your browser" → the *already signed-in* owner browser opens `/desktop/sign-in` →
   "Continue to the app" → `oat://` link delivered (no second magic link).
4. "New meeting note": recording starts; a MutationObserver times the first visible segment per voice vs the
   fixture's speech onset; I type a note line and rename the note; the fixture ends by itself (~33 s) →
   idle, "Continue recording"; transcript word recall vs ground truth ≥ 0.95 per voice.
5. `sync:now` drains to 0 ("All changes synced").
6. Pipeline: poll `GET /api/documents/:id/pipeline` until `completed`; steps `enhance/index/notion` all `ran`;
   web note shows "Post-meeting: done", content has `origin: ai` blocks and my line; the desktop pulls the
   enhanced note (`meeting:get` has `origin: ai`).
7. Notion mock: exactly one `POST /notion/v1/pages` with the title in the mock's request log; the "In Notion"
   link's mock view page contains the title and my note line.
8. Share: "Anyone with the link" → a cookie-less context reads `/share/<token>` (200, title, note, no editor).
9. Assistant (note panel): question → answer with citation chips (3), a transcript chip ready; clicking it
   lands on `?t=…&seg=…` with the focused segment in view.
10. Search: web ⌘K "staging" → a transcript hit titled with the note → opens `/d/<id>?t=…`; desktop local FTS
    "staging" lists the note.
11. Teammate: owner creates a team workspace, invites by email; teammate opens the invite link, signs up by
    magic link, accepts, lands in the team; opens the share link signed in → reads it; `GET /api/documents/:id`
    for the teammate is not 200 (the note stays the owner's).
12. Playback (desktop): player `paused`; `playback:open` → available; click a transcript line → `currentTime`
    within 100 ms of its `startMs`, line highlighted.
Finally: no browser console errors on any web page (owner, stranger, teammate).

Order differs slightly from the goal's list: chat and search run before the teammate step because creating a
team workspace switches the owner's active workspace (⌘K searches the active one).

**Fresh clone** (`scripts/acceptance-fresh.mjs`): `git clone --no-checkout <this repo>` into a temp dir +
`checkout --detach <HEAD sha>`, then `pnpm install --frozen-lockfile --prefer-offline`, `pnpm dev:up`,
`pnpm run ci --only acceptance` there with a scrubbed env (no `DATABASE_URL`/`OAT_*`/`AI_*`/… from the shell),
per-phase summary, clone removed (`--keep` to inspect, `--ref` for another commit). Uncommitted changes are
listed and excluded. Machine caches (pnpm store, Chromium, Electron zip, Docker images) are used, as on any set
up machine; documented in DEV.md.

**CI**: step `acceptance` after `e2e` (slow, macOS only, needs `stack`), own free `E2E_PORT`, same load-aware
`E2E_TIMEOUT_SCALE`. Linux CI reports `skip`.

**Findings (for the orchestrator to route; no product code changed here):**
0. *Bug (desktop, 3.7/3.8) — FIXED in this task:* the player could stay on "recording" after a meeting ended.
   Found by the fresh-clone run (stuck > 45 s every time there; local runs won the race). Cause: `index.ts`
   `onStatus('idle')` → `storage.recordingEnded()` → `storage:changed` fired as soon as the status flipped to
   idle, while `RecordingService.#finalize` was still closing the archive files (`#closing` → `busyMeetingId`
   set), so `playback:open` answered `recording`; finishing `#finalize` doesn't change the status, so nothing
   announced storage again. Fix (minimal, orchestrator-approved scope `apps/desktop/src/main`):
   `RecordingServiceOptions.onArchiveClosed(meetingId)`, called at the end of `#finalize` after `#closing` is
   cleared; `index.ts` calls `storage.recordingEnded()` (sizes, sweep, `storage:changed`) from there instead of
   at `idle` (`sync.recordingEnded()` stays at idle). Regression test `recording-service.test.ts` "9.4:
   archive-closed is announced after idle, once the files are closed and the meeting is not busy" — verified
   failing (timeout) with the call removed, passing with it. The acceptance journey now asserts the player
   becomes `paused` on its own after the fixture ends (`playableAfterStopMs`); the workaround is gone.
1. *Product gap — a recorded meeting can't reach a team workspace* (found here; follow-up is task 3.9). The desktop always records into the
   personal workspace (`meeting-persistence.ts` → `sync.personalWorkspace()`), personal workspaces have exactly
   one member, and documents never move between workspaces (1.7/D-18 `decideMoveDocument`: cross-workspace
   moves denied). So "teammate invited sees it" is only possible through the public link; a teammate can't see
   it in the team space, can't open `/d/<id>`, and team chat/search never include it. SPEC §2 ("read shared
   notes, collaborate in team spaces") suggests a "move/share to team workspace" (or choose the workspace when
   recording) is expected for v1. The journey asserts today's behaviour (link) and should be extended once this
   exists.
2. *Test-data note, not a bug:* the STT mock splits long utterances (e.g. "…the new tax | rates before we ship
   it."), so a two-word search like "tax rates" finds the note but no transcript line (FTS matches per
   segment). The journey searches one word ("staging"). Real Deepgram endpointing can split the same way; a
   phrase spanning two segments is unsearchable in transcripts — possible IDEAS item.
3. With the mock LLM the enhanced note quotes prompt scaffolding (`</oat:people>`, "Template: General" …) as
   text — expected mock behaviour (D-13), not a product issue.
