## Design notes
(designer + implementer, 2026-11-15)

### Onboarding (9.2)

> **Superseded layout (D-39, 2026-11-21).** Setup is now a dialog over the signed-in app, not a screen that
> replaces the shell: centred, fixed height (longer states scroll above the Back/Continue row), four clickable
> progress bars (dark = current, mid = done, faint = to do) in first runs and
> Settings re-runs alike. The Oat mark, the numbered step buttons, the intro line and "Signed in as …" are gone.
> There is no leave button: a click outside or Escape closes the dialog, which skips setup. A re-run from Settings closes back to Settings. The
> steps, permission states, test recording and guide below are unchanged. The sketch and "Flow" text that follow
> describe the original layout.

```
 title bar (oat.)
   Set up Oat                                           Set up later
   A minute now, so your first meeting just works.
   ▬▬▬▬▬▬  ▬▬▬▬▬▬  ▬▬▬▬▬▬  ▬▬▬▬▬▬     progress (done = primary/50, current = primary)
   ✓ Microphone  2 System audio  3 Calendar  4 Test recording   (buttons, aria-current="step")
   ┌ card ──────────────────────────────────────────────────────┐
   │ (icon) Step title (h2, focused on step change) [status pill] │
   │ What it's for, one paragraph (Me / Them chips)              │
   │ [Allow …] "macOS asks you to confirm…"                      │
   │   or ⚠ "Oat isn't allowed to use this" → [Open System Settings] │
   ├ muted footer ──────────────────────────────────────────────┤
   │ Back                              Skip for now | Continue   │
   └─────────────────────────────────────────────────────────────┘
   Signed in as …
```
- **Flow.** First sign-in of an account on this Mac (`<userData>/onboarding.json`, per account like D-30) → setup
  replaces the shell (sidebar hidden: one thing to do), opening at the first permission not yet allowed. Every step
  can be skipped; "Set up later" leaves for good (no guide). "Finish setup" → home with the **first-meeting guide**
  card (record · jot · stop → Oat writes it up), dismissed with "Got it" / ×. Settings → **Setup** lists the three
  states and "Open setup" re-runs it (title "Setup", "Close"; no guide afterwards).
- **States per permission step** (pure, `onboarding-steps.ts`, unit-tested): `done` (Allowed), `ask` (never asked /
  unknown → "Allow …"), `blocked` (denied / restricted; calendar also write-only / error → how-to + "Open System
  Settings"), `unsupported` (system audio below macOS 14.4: info callout, counts as done), `off` (no Mac calendar in
  this build). Google Calendar connected counts for the calendar step; "Connect Google Calendar" opens the web
  integrations page (`calendar:connect google`).
- **Nothing prompts by itself.** Status = `oat-audio permissions` (+ the calendar service's EventKit state), re-read
  on window focus (back from System Settings) and after a request. `permissions:request` asks macOS only while the
  state is `not_determined`/`unknown` (`canRequest`): microphone via Electron `systemPreferences.askForMediaAccess`
  (the app's grant, which the spawned sidecar inherits — sidecar README "Permissions & bundling"); system audio has
  no request API, so a 2 s `oat-audio capture --system` (stdout discarded) makes macOS ask; calendars via the
  existing `calendar:connect eventkit` → `calendar request-access`. Deep links (`PRIVACY_URLS`, chosen by main from
  the permission kind — the renderer can't pass a URL): `x-apple.systempreferences:com.apple.preference.security?`
  `Privacy_Microphone` / `Privacy_ScreenCapture` / `Privacy_Calendars`. e2e: `OAT_PERMISSIONS=fixture:` answers in
  memory; under `OAT_E2E=1` without a fixture every state is `unknown` and the sidecar is never run.
  `OAT_ONBOARDING` defaults to `off` under `OAT_E2E=1` so other suites (and 9.4's acceptance) start in the app.
- **Test recording** (`test-recording.ts`, Electron-free, unit-tested with FileSource + FakeSttProvider): the same
  source + STT the recording bar uses (`recording-setup`), 10 s, a meter + "Heard ✓" per voice (peak > −45 dBFS),
  the latest transcript line (`aria-live`), then a verdict (ok / mic silent / transcription down / no words /
  failed). Saves nothing (no meeting, no audio file — asserted in e2e); refused while a meeting records; a meeting
  start stops it first (one audio input at a time); sign-out stops it.
- **Components.** `@oat/ui` Button, Card, Skeleton; tokens only (me/them, success, warning, destructive, accent,
  muted). The step card is a `section` labelled by its h2; status pills share the recording bar's pill shape.
- **Bridge** (`packages/core/src/bridge-onboarding.ts`): `permissions:get|request|open-settings`,
  `onboarding:get|complete|dismiss-guide`, `onboarding:test-start|stop|get`; pushes `onboarding:test-state`,
  `permissions:changed`.

## Review

### Reviewer (2026-11-15) — verdict: **approve**

Read the task file + `git diff main...task/9.2-onboarding` (3960deb). `pnpm run ci --fast`: ok (format,
actionlint, typecheck, lint, test — incl. `bridge-onboarding` 3, `onboarding-store` 4, `test-recording` 6,
`permissions` 10, `onboarding-steps` 11). Full CI / e2e left to the verifier; no sidecar, prompt or capture run.

Checked and fine:
- **IPC / URL opening.** `permissions:open-settings` takes only `{ kind }` (strict zod enum, extra `url` rejected
  — unit-tested); main maps it through the constant `PRIVACY_URLS`. No new generic open-URL path; the existing
  `setWindowOpenHandler`/`will-navigate` keep `isSafeExternalUrl`. `onboarding:test-start` fixture names are
  regex-limited and `resolveInput` still refuses file replay in packaged builds.
- **No prompt without a click.** `permissions:get` runs only `oat-audio permissions` (non-prompting) or a fixture;
  `permissions:request` is the only path to `askForMediaAccess`, the 2 s `capture --system --duration 2` (stdout
  ignored, 60 s kill) and `calendar request-access`, each only while `canRequest` / `not_determined`. The renderer
  calls it only from "Allow" buttons; focus/`calendar:changed` refreshes call `permissions:get` only.
- **`OAT_E2E=1`.** `createPermissionSource` returns an in-memory `FixturePermissions` (all `unknown`) when no
  fixture is set — the sidecar is never run; e2e specs set `OAT_PERMISSIONS=fixture:`, `OAT_CALENDAR=fixture:`,
  `OAT_AUDIO_SOURCE=file:`; `shell.openExternal` stubbed. Packaged config is hard-wired to `sidecar`/`auto`.
- **Test recording saves nothing.** `TestRecording` only holds a source + STT streams in memory (no
  `RecordingService`, archive, `MeetingPersistence` or audio index); e2e asserts `meetings:list` empty and
  `<userData>/audio` empty. Mutual exclusion with `recording:start`/prompt start, stopped on sign-out and quit.
- **Per account.** `<userData>/onboarding.json` keyed by user id; unit test covers a second account; renderer
  re-fetches on `user.id` change. `onboarding:complete|dismiss-guide` require a signed-in user.
- **Tokens.** Only light `--success` changed (L 0.56 → 0.49); recomputed: 5.65:1 on `--background`, 5.3:1 on
  `--sidebar`, ~5.1:1 on its 12% tint, `--success-foreground` on it 5.7:1. `.dark` `--success` untouched. Editor
  checkbox uses `--input/--primary/--primary-foreground/--ring` only.
- **9.3b tickets** (checkbox target, anchored assistant toggle, header "More actions") done; web a11y known
  exception removed. Out-of-scope touches are listed in Design notes and are on-task. Clean room: no Granola
  strings/assets; copy is original. D-11: Google connect opens `config.webUrl`; STT goes to the mock in e2e.

Non-blocking notes (implementer may take or leave; none gate verify):
1. Calendar step: `calendarPermissionView('unknown')` shows "Allow calendars", but main requests only when
   `eventkit === 'not_determined'`, so a click while the state is still `unknown` (before the first EventKit
   read) does nothing visible. Either request on `unknown` too or show a loading state.
2. `AssistantToggleAnchor` claims the slot in `useEffect`, so the meeting note paints the fixed corner button for
   one frame before it moves into the column; `useLayoutEffect` would avoid the flicker.
3. Re-opening Setup from Settings shows the previous test's verdict (the main-side `TestRecording` snapshot is
   kept); harmless, but a reset on open would read cleaner.
4. The `config.e2e` → fixture guard in `createPermissionSource` (index.ts) has no direct unit test; it is covered
   only implicitly by every desktop e2e suite. Consider moving it into `permissions.ts` with a test.
