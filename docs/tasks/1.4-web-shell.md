status: done

## Goal
The web app skeleton every web feature plugs into: Next.js App Router with the Oat app layout (sidebar with
workspace switcher + page tree placeholder, content area), built on `@oat/ui`, with Playwright e2e wired up.

## Context
SPEC §4–5, D-6, D-15 (TS-source packages → `transpilePackages`). Use the `vercel:nextjs` skill for current
Next.js App Router guidance (verify current stable major with `pnpm view next version`). UI tokens/components
from `@oat/ui` (1.3) — do not invent colours. Research: `research/granola/bundle-map.md` (layout inspiration
only — single main window, sidebar + content; visual identity is ours).

## Scope
In:
- `apps/web` (`@oat/web`): Next.js (latest stable), React 19, Tailwind v4 via `@oat/ui/styles.css`,
  `transpilePackages: ['@oat/*']`, typed env module (zod) reading `.env` (D-11 vars; app must boot with only
  the `.env.example` defaults).
- Routes (placeholders with real layout, data mocked in-memory for now): `/` (redirect to `/home`),
  `(app)/home` (recent notes list empty state), `(app)/d/[docId]` (document page placeholder),
  `(app)/settings`, `(auth)/sign-in` (form UI only; wiring in 1.6), `share/[token]` (public layout, 5.4).
- App layout: collapsible sidebar (workspace switcher dropdown, "New note" button, search trigger, sections:
  Home / Shared / Private tree placeholder / Templates / Settings), top bar with breadcrumbs, content area;
  keyboard shortcut `⌘K` opens a command palette (shadcn Command) with a few nav actions; light/dark/system
  theme toggle (next-themes or equivalent, no flash).
- Empty, loading (`loading.tsx` skeletons) and error (`error.tsx`) states for app routes.
- `GET /api/health` → `{ ok: true, version }`.
- Playwright config in apps/web (`pnpm --filter @oat/web e2e`) starting `next dev` on port 3000; smoke tests:
  home renders, sidebar collapses, ⌘K palette navigates, theme toggles. Screenshots (light/dark) → 
  `docs/tasks/evidence/1.4/`.
Out: auth (1.6), DB access (1.5/3.3), Dockerfile (1.9), real document data.

## Design notes

### Stack and setup
- Next.js **16.4.6** (latest stable, `pnpm view next version`), React 19.3, Turbopack, `src/app` layout.
  New catalog entries: `next`, `@next/eslint-plugin-next` ^16.4.6, `@tailwindcss/postcss` ^4.3.5,
  `zod` ^4.6.7.
- `next.config.ts`: `transpilePackages: workspacePackages(manifest)`: every `@oat/*` key in
  `apps/web/package.json` deps/devDeps (D-15, `src/lib/workspace-packages.ts`, unit-tested against the real
  manifest), so adding `@oat/db` etc. as a dependency is enough. `typedRoutes: true`, `reactStrictMode`. It also **loads the repo-root `.env`** with
  `process.loadEnvFile` (shell vars win). In `next dev` only, a missing `.env` falls back to `.env.example`,
  so a fresh checkout boots; `next build`/`start` never read the example file.
- `src/lib/env.ts`: zod schema for every D-11 variable in `.env.example`. Blank keys → `undefined`.
  `serverEnv()` parses lazily on first use (so `next build` needs no `.env`); errors name the variables,
  never their values. `import 'server-only'` makes a client import a build error (vitest aliases
  `server-only` to its RSC empty module). `integrationModes()` = mock vs real per provider (key set → real). Settings ›
  Environment shows it, so the env is exercised at runtime.
- Tailwind v4 via `@tailwindcss/postcss`; `src/app/globals.css` only `@import '@oat/ui/styles.css'`.
  The plugin's `base` is `src/` so Tailwind scans/watches only app sources (not `.next/`,
  `test-results/`); @oat/ui is still scanned through its own `@source`. Fonts are bundled locally
  (11 `.woff2` in `.next/static/media`, no CDN).
- Lint: root rules + `@next/eslint-plugin-next` (recommended + core-web-vitals) + react-hooks.
  `eslint-config-next` is not used: it pulls eslint-plugin-react/import, which lag behind ESLint 10.
- `typecheck` = `next typegen && tsc` (typed routes). `next-env.d.ts` is generated, so it's gitignored
  (apps/web/.gitignore) and prettier-ignored.
- `apps/web/AGENTS.md` is written by `next dev` itself (Next 16 agent rules); committed so the tree stays
  clean, as the file asks.

### Theme: own provider, not next-themes
next-themes on React 19 renders a `<script>` from a component (the console error noted in 1.3). Instead:
- `src/lib/theme.ts` has an inline `themeScript` that the **root layout (a server component) puts in
  `<head>`**: it reads `localStorage['oat-theme']` (`light|dark|system`) and toggles `.dark` before first
  paint, so there is no flash. `<html suppressHydrationWarning>` covers the class difference.
- `ThemeProvider` (`src/components/theme-provider.tsx`) reads the preference and `prefers-color-scheme`
  with `useSyncExternalStore` (no setState-in-effect, no hydration mismatch: the server snapshot is
  `system`). It applies `.dark` with transitions disabled for one frame, follows OS changes live when on
  System, and syncs across tabs (`storage` event). Storage blocked → in-memory fallback.
- The @oat/ui `Toaster` gets an explicit `theme` prop from our hook (it otherwise calls next-themes'
  `useTheme`, which returns defaults without a provider). @oat/ui itself is unchanged.
- Desktop (Electron) can reuse the same two files later.

- Sidebar `collapsible="icon"`: collapses to an icon rail with tooltips. Toggle with the top-bar button,
  the rail, ⌘/Ctrl+B or the palette. The state persists in the `sidebar_state` cookie (written by

  a slim header (wordmark, "Read-only" badge, theme menu, "Try Oat") and a footer, with no sidebar.

### Data seam (for 1.6 / 3.3)
- `src/server/shell.ts` (`import 'server-only'`) is the **only** place mock data lives. It exports
  `getShellData()` (React `cache`, so layout + pages share one load per request) → `{ workspace,
  workspaces, documents }`, plus page getters `getDocument`, `listChildren`, `listRecentMeetings`,
  `listRecentPages`. All async, so callers already `await`.
- `src/lib/tree.ts`: the shared types (`ShellData`, `Workspace`, `DocumentNode`) and pure helpers
  (`findDocument`, `childrenOf`, `ancestorsOf`) that take the document list as an argument.
- `(app)/layout.tsx` awaits `getShellData()` (in parallel with `cookies()`) and passes it as
  `AppShell data` → `ShellDataProvider` (`src/components/app-shell/shell-data.tsx`). The sidebar
  (workspace switcher, Shared, Private tree), ⌘K pages and the top bar read it with `useShellData()`.
  `breadcrumbsFor(tree, pathname)` is pure and takes the tree. No client module imports data.
- **1.6 adds the session check at the top of `AppLayout` in `src/app/(app)/layout.tsx`**: resolve the
  session, `redirect('/sign-in')` if there is none, then pass the user/workspace to `getShellData`.
  Pages that load data get the same check through their getters.
- **3.3 replaces only the function bodies in `src/server/shell.ts`** with DB queries (same names and
  return shapes; 1.7 permission filtering goes in there too). Nothing in `components/` changes.
- Errors thrown there go to `global-error.tsx` (layout) or `(app)/error.tsx` (pages).

### States
- **Empty:** Home "Recent notes" shows a dashed panel with "No meeting notes yet", a New note button and a
  link to Getting started. Document pages show an "editor is on its way" panel. Folders list their
  children.
- **Loading:** `loading.tsx` skeletons for `(app)` (generic), `home` and `d/[docId]` (title + paragraph
  lines at the note measure). Data is in-memory, so they only flash; they exist for 1.5/3.3.
- **Error:** `(app)/error.tsx` shows an alert card with "Try again" (`reset`), "Go home" and the digest,
  inside the shell. In dev/test `/d/__error` throws to exercise it (a plain 404 in production).
- **Global error:** `src/app/global-error.tsx` catches anything thrown by the root or `(app)` layout
  (session/shell loading later). It has its own `<html>/<body>`, imports `globals.css`, uses tokens only,
  and offers "Try again" (`reset`), "Go home" (plain `<a>`, full reload) and the digest. Next renders it
  on the client, where React doesn't run `<script>`, so it sets the theme class from a
  `useSyncExternalStore` read rather than the head script. e2e checks it, including that it keeps dark mode.
- **Not found:** `(app)/not-found.tsx` (unknown doc, inside the shell) and a root `not-found.tsx`.
- **Placeholders:** "New note", the "+" on Private, switching to the team workspace, and the sign-in
  buttons show a toast or inline status ("coming soon", "arrives with task 1.6"). Nothing pretends to work.

### Playwright
- `playwright.config.ts`: always starts its own `next dev` (`reuseExistingServer: false`) on `E2E_PORT`
  (default 3000). For the server it forces `AI_GATEWAY_API_KEY=''`, `DEEPGRAM_API_KEY=''` and the mock
  OAuth issuer, so e2e never reaches real providers even if a local `.env` has keys (D-11).
- `e2e/fixtures.ts`: every test fails on any browser console error or page error (this catches hydration
  and React warnings). Opt out per test.
- `e2e/smoke.spec.ts` (13 tests): `/` redirects and home renders; the page loads once (no reload loop);
  the sidebar collapses, the cookie keeps it collapsed after reload, and ⌘B expands it; the page tree
  navigates and breadcrumbs are right; ⌘K opens, filters, navigates, and toggles closed; the theme goes
  light → dark → (reload, class present at first paint) → system follows emulated OS dark → palette
  "Light theme"; `/api/health`; Settings env badges; not-found; sign-in UI; the share layout; the error
  boundary; global-error (with dark theme kept). Sign-in now has a real `<h1>`.
- `e2e/screenshots.spec.ts` is opt-in (`pnpm --filter @oat/web e2e:screenshots`). It writes 26 PNGs
  (13 views × light/dark, incl. `global-error-*`) to `docs/tasks/evidence/1.4/` and hides the Next dev indicator.

### Notes / follow-ups
- **Dev reload loop (seen once):** in one stretch of runs `next dev` logged "Compiled in 0ms" after every
  request, and the browser did a full reload each time (an endless loop; ordinary assertions still
  passed between reloads). It went away and I couldn't reproduce it from a clean `.next` with or without
  the change below. Likeliest cause (reviewer, round 1): `pnpm typecheck` ran `next typegen` (rewrites
  `.next/types` and `next-env.d.ts`) while `next dev` was running, which Next picks up as a change;
  Tailwind already skips gitignored `.next/`. So avoid running `pnpm typecheck` for apps/web while its dev
  server is up. Mitigations kept:
  - Tailwind `base: src`, so it only asks the bundler to watch sources;
  - an explicit smoke test that counts page loads.
  If it comes back, start with `rm -rf apps/web/.next`.
- @oat/ui (not changed here): only some components carry `'use client'` (dialog, command, popover,
  select, tabs, label, … don't). Today they are only imported from client components or used without
  hooks in server components, which works. Adding `'use client'` to the hook/Radix ones in @oat/ui would
  make server-component imports safe by default.
- `next.config.ts` loads the root `.env` itself, so Next won't hot-reload edits to it: **restart
  `pnpm dev` after editing `.env`** (worth a line in DEV.md; not edited here, out of scope).
- CSP (later): the theme head script is static, so allow it by `sha256` hash, not nonces (nonces would
  make every route dynamic).
- `⌘` is shown in shortcut hints (macOS-first); Ctrl works too.
- Out of scope touched: root `.prettierignore` (+`next-env.d.ts`, a generated file Prettier can't be told
  to skip from `apps/web`); catalog entry `server-only` ^0.0.1.

### Round 1 · 2026-11-14 · reviewer · verdict: **changes**
Read: task file + `git diff main...task/1.4-web-shell`, screenshots (home light, palette dark, mobile sheet
dark: polished, token-only). Re-ran `pnpm --filter @oat/web typecheck lint test`: green (22 tests).
Checked and fine: server/client split (only interactive leaves are `'use client'`; `(app)/layout` reads the
sidebar cookie on the server), route groups, `(app)` loading/error/not-found placement (shell survives),
metadata title template + `robots: noindex` on share, async `params`, `typedRoutes`, health route `no-store`.
Theme: head script in a server layout + `suppressHydrationWarning` + `useSyncExternalStore` with a `system`
server snapshot has no FOUC and no hydration mismatch; console-error fixture would catch regressions.
Env: verified `process.loadEnvFile` never overrides shell vars, including empty strings (Node 26), so the
Playwright `AI_GATEWAY_API_KEY=''` override holds; `.env.example` holds only mock creds and the fallback is
dev-phase only, so it is safe. Playwright: own server, `reuseExistingServer: false` fails loudly on a busy
port rather than testing another worktree's code. No D-11 or clean-room problems.

Required:
1. `apps/web/next.config.ts:35`: `transpilePackages: ['@oat/ui']` is hand-maintained; D-15 requires every
   `@oat/*` dependency, and 1.5 (`@oat/db`/`@oat/core`) will silently depend on someone remembering. Fix:
   derive it from `package.json`, e.g.
   `Object.keys(pkg.dependencies).filter((n) => n.startsWith('@oat/'))` (globs aren't supported).
2. Data-loading seam for 1.6/3.3: client components read the in-memory store directly
   (`app-sidebar.tsx:59`, `command-menu.tsx:30`, `top-bar.tsx:72` → `navigation.ts:1`). With the DB, that
   data must come from the server, so 3.3 would have to restructure the shell. Fix: add a server-side
   loader (e.g. `src/lib/shell-data.ts` → `getShellData()` returning workspace, workspaces, page tree),
   call it in `(app)/layout.tsx`, pass it to `AppShell` and expose it via a small client context; make
   `breadcrumbsFor(pathname, tree)` pure. Then 1.6 adds the session check in that layout and 3.3 swaps
   only the loader body. Pages (`home`, `d/[docId]`) keep calling server-side getters, which is fine.
3. No `src/app/global-error.tsx`: anything thrown by `(app)/layout.tsx` (where 1.6/3.3 data loading will
   live, see 2) or root-level code falls through to Next's bare error page, since `(app)/error.tsx` only
   covers its children. Fix: add a minimal `global-error.tsx` (own `<html>/<body>`, token classes, reset +
   "Go home"), and an e2e check if it can be triggered cheaply.

Optional:
- `src/lib/env.ts`: add `import 'server-only'` (install the package) instead of relying on the comment.
- Sign-in has no `<h1>` (`(auth)/sign-in/page.tsx:13`, `CardTitle` is a div); render it as `h1`.
