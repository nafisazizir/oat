# 8.3 — Post-meeting pipeline (production wiring on eve, D-29)
status: done
milestone: M8 · deps: 8.1, 8.2 · branch: task/8.3-post-meeting-pipeline

## Goal
When a meeting ends, the pipeline runs durably: enhance (if not done) → index/action items → push to configured
integrations — visible to the user with status and errors, retryable, never duplicating work.

## Context
D-29 (eve, guardrails, `/jobs` contract, layering rule, revisit trigger), D-26 (enhance job), D-11, the 8.2 spike
in `agents/` (+ review notes in docs/tasks/8.2-eve-evaluation.md: services must move out of `apps/web`, lint ban,
replace the Better Auth instance used only to decrypt the Notion token), `@oat/integrations-notion`,
`@oat/indexing`, `apps/web` enhance service, auto-push setting (none yet — add per workspace integration).

## Scope
In:
- Layering: move enhance service, Notion push service and token decryption into packages (e.g.
  `packages/services` or into existing packages) used by both `apps/web` and `agents/`; ESLint rule banning
  imports from `apps/*` in packages/agents; behaviour unchanged (existing tests pass).
- Trigger: when a meeting ends (meeting `ended_at` set via desktop sync push or web "End meeting"), the web app
  authorises (owner/editor per D-29 contract) and calls `POST /jobs/post-meeting {meetingId, workspaceId}` with
  the service token; idempotent per meeting (a second call returns the existing run).
- Settings: per-workspace integration setting "Auto-send meeting notes to Notion" (off by default) + "Auto-enhance
  after meetings" (on by default; template = meeting's template or workspace default).
- Run visibility: `pipeline_run` table (our run log, D-29) — status per step, error, timestamps; meeting header
  shows "Post-meeting: enhancing… / done / failed — retry"; retry endpoint (authz + deny markers).
- Dev: `pnpm dev` starts the agents server (localhost only) alongside web + worker; compose `app` profile gets an
  `agents` service; docs/DEV.md updated.
- Tests: int (trigger authz; idempotency; auto-push off/on; failure + retry; agents server down → run queued as
  "waiting for pipeline" and retried by a backstop sweep), e2e (end a fixture meeting → status shows done →
  Notion mock received page when auto-send on). No network beyond localhost.
Out: other integrations (Slack etc.), auto-stop detection (7.5).

## Design notes

### Shape
```
desktop sync push (meeting.ended_at null → set)            meeting header "Retry" / POST /api/documents/:id/pipeline
        │ pushChanges → after commit: onMeetingEnded             │
        ▼ (after(): never delays the push)                       ▼
@oat/services/pipeline  requestPostMeeting / retryPostMeeting: canRead (else 404) + canEdit (else 403), meeting
        ended (else 409 meeting_not_ended) → INSERT pipeline_run ON CONFLICT (meeting_id) DO NOTHING (idempotent)
        → dispatchPipelineRun: claim (status=waiting & due → next_dispatch_at = now+30 s) → POST
        <OAT_AGENTS_URL>/jobs/post-meeting {pipelineRunId, attempt, meetingId, workspaceId} (Bearer token)
           ok → queued + workflow_run_id · unreachable/5xx/401 → stays waiting, backoff 5 s…5 min
           400/404/409 (job can never run) → failed
agents /jobs/post-meeting → loadMeeting (workspace check, D-29) → startPipelineWorkflow: row FOR UPDATE, same
        attempt + no workflow yet → start(postMeetingWorkflow) once (repeats get the same run id)
postMeetingWorkflow: load (current attempt?) → enhance → index → [pushDelayMs] → notion → finish
        each step: markPipelineStep (running, current_step) → work → recordPipelineStep (replaces same-step
        record) — all writes fenced on (id, attempt) and status queued|running; finish → completed|failed + message
backstop: agents schedule `post-meeting-sweep` (cron * * * * *, under `eve start`) + GET status of a waiting run
```

### Decisions (implementer)
- **Layering.** New package `@oat/services` (`packages/services`): `actor`, `errors` (ApiError), `documents`,
  `folders`, `tasks`, `templates`, `profile` (AI-profile half), `enhance/{service,broker,versions}`, `notion`,
  `json-equal`, `pipeline`, and the client-safe API shapes in `dto/*` (api-types, enhance, templates, tasks,
  profile, pipeline). `git mv`, imports rewritten, `import 'server-only'` dropped from the package (web keeps it on
  its re-export shims). `apps/web/src/server/{actor,documents,folders,notion,api/errors,tasks/service,
  templates/service,enhance/*}.ts` and `src/lib/{api-types,enhance,templates,profile,json-equal}.ts` are now
  one-line re-exports, so every web import (and 3.4's new `meeting.ts`) is unchanged and merges stayed trivial;
  `lib/tasks.ts` keeps the Next-typed `taskHref`/`groupByDocument`. Behaviour unchanged: all web unit/int/e2e
  suites pass untouched. The spike seam (`agents/src/post-meeting/web.ts`), the `@/*` path mapping and the vitest
  aliases are gone.
- **Lint rule** (root `eslint.config.js`, so every package config that extends it gets it):
  `no-restricted-imports` bans any specifier with an `apps/` path segment and `@oat/web|desktop[/*]`. (Dynamic
  `import()` isn't covered by that rule; nothing does it, and `@/` no longer resolves outside apps.)
- **Token decryption without Better Auth:** `@oat/auth` `secretConfigFromEnv`/`secretSourceFromEnv` rebuild the
  secret config Better Auth builds (`BETTER_AUTH_SECRETS` versioned keys + `BETTER_AUTH_SECRET` as legacy, else the
  plain secret). `SecretSource` became a structural `{ $context: PromiseLike<{ secretConfig }> }` (the auth instance
  still fits). Unit tests round-trip against a real `createAuth` instance, including rotation.
- **Run log = `pipeline_run`** (migration `0012_pipeline_run`, after main's 0011): one row per meeting (unique),
  `status` enum waiting|queued|running|completed|failed, `attempt`, `current_step`, `steps` jsonb, `error`
  (user-facing), `workflow_run_id`, `dispatch_attempts/dispatch_error/next_dispatch_at`, timestamps, `requested_by`.
  Server-only: no change_log trigger, not synced (the desktop can read the API later). The Redis run log of the
  spike is gone. Retry = same row, `attempt + 1`, steps cleared; a stale attempt can't write (fenced) and a
  finished attempt can't be reopened by a late replay.
- **Idempotency:** per meeting by the unique row (a second "meeting ended" or request returns it); per hand-over
  by the claim lease; per attempt on the agents side by `startPipelineWorkflow` (row lock; concurrent repeats →
  one `start()`, tested with 3 parallel calls); per step by the spike's idempotent bodies (keyed enhance,
  content-hashed indexing, `document_export` re-push) + same-step record replacement.
- **Trigger:** the sync push records meetings whose `ended_at` goes from unset to set (also a new row pushed
  already ended) and calls `onMeetingEnded(actor, id)` after the transaction commits, i.e. after the same push's
  segments landed; `apps/web` wires it to `requestPostMeeting` inside `after()`. The pushing user passed the
  edit check already; `requestPostMeeting` checks again (D-29). There is no web "End meeting" button on main
  (3.4 shipped the meeting view without one); the same function serves it when it lands, and the header's
  POST starts an ended meeting's run when none exists.
- **Acts as the note owner** (spike): enhance with the owner's profile/template, the owner's Notion connection
  and settings. The requester (owner or editor) is recorded in `requested_by`.
- **Settings:** "Auto-enhance after meetings" = `pipeline_setting(workspace_id, user_id, auto_enhance default
  true)`; "Auto-send meeting notes to Notion" = `integration.settings_json.autoPush` on the user's own Notion
  connection (off by default; added to the Notion settings schema so `patchSettings` keeps it, and a reconnect to
  the same Notion workspace keeps it). `GET/PUT /api/settings/pipeline` (member of the workspace, own settings
  only; auto-send without a connection → 409 `notion_not_connected`; written with a jsonb merge). UI: Settings →
  Integrations: an "After a meeting" card (auto-enhance) and a switch in the Notion card (auto-send).
  Template: the meeting's template, else the built-in default (there is no per-workspace default template yet).
  Auto-enhance off → the step is `skipped` ("auto-enhance off"); index and Notion still run.
- **Status UI** (`components/pipeline/pipeline-status.tsx`, one line in `document-editor.tsx`'s action row for
  meeting notes, so it shows in 3.4's meeting view too): badge "Post-meeting: waiting for the pipeline… /
  starting… / enhancing… / indexing… / sending to Notion… / done / failed" + "Retry" (editors). Polls every 2 s
  while live, every 15 s while there is no run. When the pipeline is (or was just) enhancing, it calls the new
  `useEnhancement().follow()`, which attaches the editor to that run (live preview, then the applied body)
  if it is generating or finished after the page loaded — so an open note doesn't autosave over the enhanced body.
- **Failure messages** are user-facing on the row (`Enhancing the notes failed. Try again.`, `Sending to Notion
  stayed blocked by another send…`); the raw error stays in the workflow record and logs. Internal hand-over
  errors are never shown (DTO `error` is null unless failed).
- **Agents down:** the run waits; the web retries on the next due status read; the agents' handler schedule
  sweeps due waiting runs every minute (`EVE_SCHEDULES_DISABLED` honoured on extra replicas). With no
  `OAT_AGENTS_TOKEN` on the web side the run waits for the agents' sweep (5 min re-check from the web).
- **Dev / compose:** `@oat/agents` `dev` script (`pnpm dev` → `eve dev --no-ui` on 127.0.0.1:3100, loads the root
  `.env`/`.env.example`, creates + migrates `oat_workflow` first). Compose `agents` service (profile `app`,
  `agents/Dockerfile`: deps → `agent:build` → `eve start` via `serve.ts` on Node's TS support; localhost forward of
  the mocks so Notion links keep the host's form; loopback-published :3100). The web service gets
  `OAT_AGENTS_URL=http://agents:3100`; both use a compose-only token (`OAT_AGENTS_COMPOSE_TOKEN`), since images run
  `NODE_ENV=production` where the `.env.example` dev token is refused. `turbo.json` passes `WORKFLOW_POSTGRES_*`
  and `EVE_*` through. eve's default ports clash (3000/2000), hence `OAT_AGENTS_PORT` (3100).
- **eve gotcha found:** a non-step helper in the workflow file that touches Node-only modules pulls them into the
  workflow bundle (`eve build` fails on `node:crypto` etc.); such helpers live in `src/post-meeting/track.ts`
  and are only called from `"use step"` bodies.

## Review

### Review 1 (reviewer, 2026-11-15) — verdict: `changes`
Read: task file + `git diff $(git merge-base main HEAD)..HEAD`. Ran `@oat/services` unit (4/4), `agents/src/layering.test.ts`
(2/2), `@oat/services` typecheck: green. Checked and OK: D-29 authz before `/jobs` (`canRead`→404, `canEdit`→403,
ended→409; deny markers on all 4 routes), `workspaceId` carried and re-checked by the agents (`loadMeeting`,
`startPipelineWorkflow`), constant-time current+previous token check, ≥32 chars, dev token refused in prod, agents
bound to 127.0.0.1 (compose: 0.0.0.0 in-container, published on loopback only); lint rule is real (root config,
every package extends it, test proves it); the services move is behaviour-identical (diff of every moved file vs
main shows only import paths + the 8.3 `autoPush` additions; no import cycles; `dto/*` imports are type-only and
client-safe); sync trigger fires only after commit, only on unset→set, only for editors (viewers are rejected by
`requireEditable`); runs act as the note owner with the owner's own Notion connection/switch for the note's
workspace and `sendToNotion` re-checks the owner's read access, so no one else's note or token is ever used;
hand-over claim/lease and per-attempt fencing (status + attempt on every agents write) hold under the races I
traced; compose `agents` runs as `node`, `.env*` excluded from the build context, no secrets in the image.

1. **Runs stuck in `queued`/`running` are never recovered and can't be retried.** `packages/services/src/pipeline.ts:308-312`
   + `:391-408` sweep only `waiting`; `retryPostMeeting` (`:267`) only re-arms `failed`. Ways in: the Workflow run
   is lost/cancelled (world DB wiped, eve upgrade — D-29's own revisit trigger), or `finishStep` fails on the
   success path (`agents/agent/lib/post-meeting.ts:75` is outside the `try`, so exhausted retries fail the workflow
   and leave the row `running` forever). The header then shows "enhancing…" indefinitely with no Retry.
   Fix: in the agents' `post-meeting-sweep`, also select `status in (queued, running)` with `updated_at` older than
   a threshold (e.g. 10 min; busy re-calls refresh `updated_at` every `busyRetryMs`) and ask the world
   (`getRun(workflowRunId).status`): `failed`/`cancelled`/not found → `finishPipelineRun(ref, failed, "The post-meeting
   steps stopped. Try again.")` (already fenced on attempt + live status); `completed` → mark completed; still
   running (e.g. a durable `pushDelayMs` sleep) → leave. Rows `queued` with no `workflow_run_id` → back to `waiting`.
   Add an int test (world run deleted / forced failure → swept to `failed` → Retry → attempt 2 completes).
2. **A resumed meeting never re-runs the pipeline.** The desktop resumes meetings (D-24,
   `apps/desktop/src/main/meeting-persistence.ts:70` sets `endedAt: null`, then a later end sets it again); the
   push hook fires correctly on the second unset→set, but `startOrReturn` (`pipeline.ts:243-249`) returns the
   existing completed run, and `ensureEnhanced` (`agents/src/post-meeting/steps.ts:85`) would skip "already
   enhanced" anyway. So the resumed part is never enhanced, indexed early, or re-sent to Notion — not "runs when the
   meeting genuinely ends". (Also: resuming while attempt 1 is still running enhances a partial transcript.)
   Fix: record the end being processed on the row (e.g. `pipeline_run.ended_at`); in `requestPostMeeting`, when
   `meeting.ended_at` is newer than the row's and the row is `completed`/`failed`, re-arm it like a retry
   (attempt+1, steps cleared, fenced on the old attempt); if it is still live, set a `rerun_requested` flag the
   finish step turns into a new attempt. In `ensureEnhanced`, treat "already enhanced" as a completed enhancement
   created at/after the meeting's `ended_at` (decide + note whether re-enhancing a resumed meeting is wanted; if
   not, still re-run index + Notion). Int test: end → completed → resume + end → attempt 2 runs.

Optional:
- `retryPostMeeting` on a `waiting` run clears `next_dispatch_at` (`pipeline.ts:296-301`), which also breaks a held
  hand-over lease and lets an editor bypass backoff by clicking; harmless (agents dedupe per attempt), but only
  clear it when no hand-over is in flight (e.g. `dispatch_error is not null`).
- `startPipelineWorkflow` calls eve `start()` inside the row-locked tx (`pipeline.ts:440`); if the commit then
  fails, a workflow runs while the row stays `waiting` (its writes are fenced off) and the sweep starts a second
  one. Idempotent steps make this safe; worth a comment.
- An owner who left the workspace makes enhance/Notion throw 404 → step retries → "…failed. Try again." which a
  retry can't fix; map `not_found` from the owner's access to a `skipped`/clear message.
- Meeting notes that ended before 8.3 (or whose run never got created) render no status and offer no "Run" even
  though `POST` supports it; the 15 s idle poll runs forever on every open meeting note.
- Root `engines` (Node ≥ 22.13) vs eve's ≥ 24 — already noted as follow-up.
