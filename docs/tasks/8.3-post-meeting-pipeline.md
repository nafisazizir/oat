# 8.3 — Post-meeting pipeline (production wiring on eve, D-29)
status: in-progress
milestone: M8 · deps: 8.1, 8.2 · branch: task/8.3-post-meeting-pipeline

## Goal
When a meeting ends, the pipeline runs durably: enhance (if not done) → index/action items → push to configured
integrations — visible to the user with status and errors, retryable, never duplicating work.

## Context
D-29 (eve, guardrails, `/jobs` contract, layering rule, revisit trigger), D-26 (enhance job), D-11, the 8.2 spike
in `agents/` (+ review notes in docs/tasks/8.2-eve-evaluation.md: services must move out of `apps/web`, lint ban,
replace the Better Auth instance used only to decrypt the Notion token), `@oat/integrations-notion`,
`@oat/indexing`, `apps/web` enhance service, auto-push setting (none yet — add per workspace integration).

## Scope
In:
- Layering: move enhance service, Notion push service and token decryption into packages (e.g.
  `packages/services` or into existing packages) used by both `apps/web` and `agents/`; ESLint rule banning
  imports from `apps/*` in packages/agents; behaviour unchanged (existing tests pass).
- Trigger: when a meeting ends (meeting `ended_at` set via desktop sync push or web "End meeting"), the web app
  authorises (owner/editor per D-29 contract) and calls `POST /jobs/post-meeting {meetingId, workspaceId}` with
  the service token; idempotent per meeting (a second call returns the existing run).
- Settings: per-workspace integration setting "Auto-send meeting notes to Notion" (off by default) + "Auto-enhance
  after meetings" (on by default; template = meeting's template or workspace default).
- Run visibility: `pipeline_run` table (our run log, D-29) — status per step, error, timestamps; meeting header
  shows "Post-meeting: enhancing… / done / failed — retry"; retry endpoint (authz + deny markers).
- Dev: `pnpm dev` starts the agents server (localhost only) alongside web + worker; compose `app` profile gets an
  `agents` service; docs/DEV.md updated.
- Tests: int (trigger authz; idempotency; auto-push off/on; failure + retry; agents server down → run queued as
  "waiting for pipeline" and retried by a backstop sweep), e2e (end a fixture meeting → status shows done →
  Notion mock received page when auto-send on). No network beyond localhost.
Out: other integrations (Slack etc.), auto-stop detection (7.5).

## Acceptance criteria
- [ ] Ending a meeting runs the pipeline durably with visible status + retry; layering rule enforced.
- [ ] `pnpm run ci` green.
