# 7.5 — Auto-stop + auto-enhance
status: done
milestone: M7 · deps: 4.4, 7.2, 7.3, 8.3 · branch: task/7.5-auto-stop-enhance

## Goal
Recording ends itself sensibly and notes appear without clicking: stop when the call is clearly over (or ask),
then the post-meeting pipeline (8.3) enhances automatically.

## Context
PLAN 7.5 text, D-21 (detection; `meetingEnded{prompted, recordingStartedDuringMeeting}` semantics from 7.2 review:
stop only when `recording && (recordingStartedDuringMeeting || prompted)`), D-24 (resume), D-26, D-29 + 8.3
(pipeline trigger on meeting end; "Auto-enhance after meetings" setting), `@oat/detection`, `@oat/calendar`,
desktop RecordingService + detection wiring (7.3).

## Scope
In:
- Auto-stop rules (pure, fixture-tested): never in the first 3 min; when the meeting app releases the mic and
  the calendar event's end is within ±5 min → stop automatically (with a 10 s "Stopping… Keep recording" undo
  toast); otherwise show "Meeting over? Stop recording / Keep going" prompt; a silence/inactivity fallback
  (both sources below level threshold for 10 min) → same prompt; never auto-stop in-person (mic-only) recordings
  unless user enabled it.
- Auto-enhance: after stop, if "Auto-enhance after meetings" is on and the transcript passes a minimum length
  (e.g. 60 s of speech), the 8.3 pipeline runs (it already triggers on end) — add a grace delay (60 s) during
  which "Continue recording" cancels the pipeline start; resuming within grace doesn't create a run.
- Settings: "Stop recording automatically when the meeting ends" (on by default) in desktop settings.
- Tests: rule fixtures (timelines with mic-apps + calendar + levels), desktop e2e with fixtures: call ends →
  auto-stop toast → stopped → pipeline status "enhancing → done" in the header; undo keeps recording.
Never real capture/mic-apps/EventKit.

## Design notes
(implementer, 2026-11-15)

**Shape.**
```
mic-apps ─► Detector (detect, D-21) ── meetingEnded / call span open·closed ─┐
calendar (CalendarService) ───────────────────────────────────────────────────┤
RecordingService snapshots (status, levels: only quiet↔loud changes) ─────────┼─► AutoStopService ─► AutoStopper
settings <userData>/auto-stop.json ───────────────────────────────────────────┘     (autoStop reducer + timer)
      actions: stopping → toast + notification │ stop → recording.stop() │ ask → "Meeting over?" │ cancel
recording.stop() → MeetingEndGrace.endMeeting (held 60 s) ─► MeetingPersistence.endMeeting (ended_at) ─► sync push
      ─► web onMeetingEnded → pipeline_run (8.3) ─► agents: enhance (skipped < 60 s speech) → index → Notion
meeting header: grace countdown ("Continue recording" / "Start now") → PipelineLine polls pipeline:get
```

**Rules (`packages/detection/src/auto-stop.ts`, pure, like `detect`).** Inputs: recording on/off (+ the note's
own calendar event), paused, levels (RMS dBFS), detect's `meetingEnded`, call span open/closed, calendar,
settings, keep/answered, tick. Actions: `stopping` (undo toast, `stopAt`), `stop`, `ask`, `cancel` (reason).
- Floor 3 min: an end inside it is kept and decided at the floor (unless the call came back).
- Counted ends: **strict** = the 7.2 contract `recording && (recordingStartedDuringMeeting || prompted)`;
  **loose** = the call overlaps the calendar event the recording's note was made from (notes started from
  "Upcoming" before joining: recording first, so the strict flags are false). Loose ends only ever **ask**.
  Anything else (FaceTime during an in-person recording, voice notes) is ignored — fixture
  `in-person-call-ignored.json`.
- (Review round 1) Every end waits a 30 s confirmation; a returning app = resumed; resumed calls carry their
  strictness + event; back-to-back = next meeting; the other side still talking → ask. See *Resolution*.
- Strict + an event ending within ±5 min of the release → auto-stop (toast, 10 s undo). Event = the prompt's,
  else the note's own, else an attended timed event overlapping the call (closest end). Otherwise ask.
- Silence: both sources ≤ −50 dBFS RMS for 10 min of recorded (not paused) time → ask; in-person (no call in
  this recording) + "Also stop in-person recordings" → toast + stop instead. "Keep going" restarts the clock;
  sound returning cancels a silence notice.
- Setting "Stop recording automatically…" off → the auto-stop case asks instead (asking is never destructive).
- Cancel reasons: undo, keep, meeting_resumed (call back during the toast), sound, recording_ended, settings,
  replaced (one notice at a time).
- 12 fixture timelines in `fixtures/auto-stop/` run detect + autoStop together on a virtual clock
  (`runAutoStopTimeline`; `stop` stops the recording for both reducers); edge cases in `auto-stop.test.ts`.
  `Detector.onState` added (the desktop needs the call span opening/closing).

**Grace period (decision: desktop-side, no server change).** The pipeline starts when the sync push sets
`meeting.ended_at` (8.3). `MeetingEndGrace` decorates the recording's `TranscriptPersistence`: `endMeeting` is
held for 60 s; `beginMeeting` of the same meeting within it ("Continue recording", D-24 resume) drops it, so the
end is never written and **no run is ever created** (no server-side cancel/delete of runs needed, nothing for
other clients to see). The end is written with the real stop time when the period runs out, on "Start now", when
another meeting starts, on quit (`quitGracefully`, after the recording shut down), on sign-out and on an account
change (while that account's database is still the open one; never into another account's database). During the
grace the note shows its end time locally (renderer overlay); the web sees the meeting as in progress for up to
60 s. Crash during the grace = the meeting stays open, same as a crash mid-recording (2.7's territory).

**Minimum transcript.** `@oat/services/pipeline` `MIN_AUTO_ENHANCE_SPEECH_MS = 60 s` + `speechMs` (union of segment
intervals, overlaps once). The agents' enhance step skips with `transcript too short` below it (index and Notion
still run, like "auto-enhance off"); `OAT_AUTO_ENHANCE_MIN_SPEECH_MS` overrides (agents int test 10 s, web/desktop
e2e 5 s: fixture transcripts are seconds long). "No output yet" was already the step's `already enhanced` skip.

**Desktop UI** (`@oat/ui` + tokens only).
```
┌ Meeting over?  Oat hasn't heard anything for a while…            [Keep going] [■ Stop recording] ┐ ← strip (ask)
│ recording bar                                                                                    │
│ [Private] Saved on this Mac  [⏱ Post-meeting steps in 9 s]  🎙 Continue recording   Start now    │ ← grace
│ [Private] Saved on this Mac  [✓ Post-meeting: done] / [⟳ Post-meeting: enhancing…] / failed Retry│ ← pipeline
│ …                                                                                                │
│            ┌──────────────────────────────────────────────────────────┐                         │
│            │ ⏱ Stopping the recording in 8 s   Your meeting ended.  [Keep recording] │ ← toast    │
│            └▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ (bar drains over the undo window) ─────┘                         │
```
- `auto-stop/auto-stop-notice.tsx`: `AutoStopQuestion` (role=alertdialog strip, same look as the 7.3 prompt
  banner) and `AutoStopToast` (role=status aria-live, popover card bottom-centre of the content column, countdown,
  draining bar — static under reduced motion). Native notifications mirror both ("Stopping the recording",
  "Meeting over?"; click → focus the window); e2e records them.
- `meetings/post-meeting.tsx`: `GraceLine` (badge countdown + "Continue recording" when continuable here, D-24 +
  "Start now") and `PipelineLine` (badge "Post-meeting: waiting… / starting… / enhancing… / indexing… / sending to
  Notion… / done / failed" + error + Retry for editors; "Not enhanced: the transcript is too short." when that
  step was skipped). Polls 2 s while live or a run is expected (≤ 2 min after the end), 15 s with no run, stops
  once finished; offline → nothing.
- Settings → Recording (`settings/recording-settings.tsx`): two switches, the second disabled while the first is
  off.
- Main: `auto-stop-service.ts`, `meeting-end-grace.ts`, `api-client.pipeline()` (bearer GET/POST
  `/api/documents/:id/pipeline`, only the header's fields kept), bridge `bridge-auto-stop.ts` (`autostop:*`,
  `grace:*`, `pipeline:get|retry`; push `autostop:changed`, `grace:changed`).
- Dev/e2e: `OAT_AUTO_STOP` (JSON timings), `OAT_END_GRACE_MS`, `OAT_DETECTION=file:<apps.json>`
  (`FileMicAppsSource`, polled 100 ms) — packaged builds ignore them. DEV.md updated.

**e2e** (`apps/desktop/e2e/auto-stop.spec.ts`, fixtures only: calendar JSON, mic-apps JSON file, FileSource):
(1) prompt → Start notes → Zoom leaves 4 min before the event's end → toast → stopped → grace → header
`running:enhance` → `completed` (recorded in `evidence/7.5/pipeline-statuses.json`), server run completed with
enhance `ran`; (2) "Keep recording" keeps recording past the undo window; manual stop → "Continue recording" in
the grace → same meeting records, after the would-be grace end the server meeting has no `ended_at` and no
`pipeline_run`; stop → "Start now" → the run appears; (3) silence-gap fixture (in-person) → "Meeting over?" (no
toast) → Keep going; Settings → Recording switches persist. The desktop suite slows the agents' mock LLM
(`OAT_E2E_AGENTS_AI_DELAY_MS=100`) so the header can be seen mid-run.

**Out-of-scope files touched (all small, needed):** `packages/core/src/bridge-auto-stop.ts` + `bridge.ts` (IPC
contract lives in core), `fixtures/auto-stop/*` (new), `agents/src/{env,env.test}.ts`,
`agents/src/post-meeting/{steps,post-meeting.int.test}.ts` (the min-transcript skip + its int case),
`docs/DEV.md`.

**Follow-ups.** The ask/toast is not shown in the widget window (native notification covers a hidden main window);
a crash during the grace period leaves the meeting open (as a crash mid-recording does today); the desktop
doesn't show the pipeline for meetings ended on another device until it syncs their `ended_at`.

## Review

Reviewer, 2026-11-15 — **changes** (three behavioural fixes; the reducer shape, UI and agents skip are sound).

Read only: task file + `git diff main...` + screenshots. Nothing run against capture / mic-apps / EventKit.
Checked OK: undo really cancels (`keep` → `cancel undo`, notice cleared, timer re-armed to nothing; a late click
gets "no longer on screen"); silence fallback −50 dBFS RMS on both sources for 10 min of unpaused time, one loud
frame resets it, asks by default — sane and non-destructive; in-person auto-stop default off (`inPerson: false`,
schema + reducer `!call && enabled && inPerson`); `OAT_AUTO_STOP` / `OAT_END_GRACE_MS` / `OAT_DETECTION=file:`
ignored when packaged (`config.ts` packaged branch returns `{}` / `undefined` / sidecar); `speechMs` interval
union is correct (overlaps once, zero-length dropped); screenshots (toast, question, grace, done, settings, both
themes) read well.

Must fix:
1. **A temporary mic drop near the event's end cuts a live meeting short.** `packages/detection/src/auto-stop.ts:252-258`
   only cancels the toast on `call: open`, which needs detect to re-qualify the app (`detect.ts:279-286`): ≥ 2 s,
   plus `minHoldMs` 15 s for Slack/WhatsApp/… (longer than the 10 s undo) unless an event is "current" — and
   `currentMeetingFor` only counts events started ≤ 15 min ago, so late in any meeting a returning **browser** call
   (Meet/Teams web) never becomes eligible and the stop always goes through. Triggers: apps that release the mic
   on mute, a Bluetooth headset/device switch, a browser audio-process restart (> 2 s gap) in the last 5 min or
   ≤ 5 min overrun. Fix: (a) treat any raw reappearance of one of the ended call's `appIds` (detect `presences`,
   not eligibility — expose it via `Detector.onState`) as resumed; (b) don't show the toast until the release has
   held for a confirmation period (e.g. 30 s), and don't auto-stop while system audio is loud in that window
   (others still talking = the call is live; ask instead). Fixtures: Slack huddle 20 s drop at the event end;
   Chrome/Meet drop at minute 55.
2. **After a resume the call's real end is ignored, so auto-stop silently turns off for that meeting.**
   `auto-stop.ts:262-266`: the reopened span has `recordingStartedDuringMeeting = false` and `prompted = false`
   (no prompts while recording), so `strict` is false; notes made from the event get only a loose "ask", other
   recordings never stop (`fixtures/auto-stop/call-resumes.json` stops manually at 1980000, which hides it).
   Back-to-back meetings in the same app hit the same path: A's toast is cancelled by B's call, A's note records
   all of B and never auto-stops (and B is never prompted). Fix: remember a strict end in the recording state and
   let the next `meetingEnded` inherit `strict` + the original event; don't count a reopen as `meeting_resumed`
   when the original event has ended and a different attended event is now current (let the stop proceed).
   Fixtures: resume then end at the event end → `stopping`; back-to-back A→B in Zoom with a 5 s gap.
3. **The grace period's pending end lives only in memory.** `apps/desktop/src/main/meeting-end-grace.ts:47,85-90`:
   a crash / force-quit / power loss / dead battery in the 60 s after a stop means `ended_at` is never written —
   the note stays "in progress" on the web forever and the pipeline never runs (before 7.5 the end was written at
   stop, so this is a regression, not "same as a crash mid-recording"). Also a normal quit inside the grace writes
   the end locally but nothing pushes it before exit (`index.ts:800-806`), so the run waits for the next launch.
   Fix: persist the pending end (`<userData>/grace-pending.json`: meetingId, endedAt, userId) and on start-up,
   once that account's store is open, write it (and re-arm if `dueAt` is still ahead); after the quit flush do a
   bounded (≤ 5 s) sync push. Unit-test the restart path.

Optional:
- `packages/services/src/pipeline.ts` `meetingSpeechMs`: filter `isFinal` for symmetry with the rest of the reads.
- `post-meeting.tsx:130`: a note with no run (never synced, old meeting, 404) polls `pipeline:get` every 15 s
  forever while open; stop after a few tries / on a non-`unavailable` error.
- Grace state shows two "Continue recording" buttons (recording bar + header line); keep one.
- `agents/src/env.ts`: `OAT_AUTO_ENHANCE_MIN_SPEECH_MS` is honoured in production too; refuse < 60 s with
  `NODE_ENV=production` like the jobs token.

### Resolution (implementer, 2026-11-15; main merged incl. 2.7 — `index.ts` / `meeting-view.tsx` conflicts resolved)
1. **Mic blips.** New `confirmMs` (30 s): an end is decided at `max(floor, release + 30 s)`, so nothing is shown
   for a drop shorter than that. The reducer now gets the raw meeting apps holding the mic (`apps` input = detect
   presences not gone, via `Detector.onState` → `DetectionService.onAppsChanged`): any reappearance of one of the
   call's apps — eligible or not — is a resume (pending end dropped / toast cancelled `meeting_resumed`). System
   audio above `speechDb` (−40 dBFS RMS) after the release (+2 s tail) → ask instead of stopping. Fixtures:
   `call-resumes.json` (mute / device switch, 8 s), `slack-huddle-drop.json` (messaging app, 20 s drop at the
   event end), `browser-drop-late.json` (Chrome/Meet restart at minute 55, never re-qualifies),
   `others-still-talking.json`.
2. **Resume semantics.** A resumed counted call is remembered (`recording.carry`: strictness, event, apps); its
   next end inherits both — whether detect reports it (`meetingEnded` of the reopened span, flags false) or the
   carried apps simply let go again (detect never re-qualified them: browsers late in a meeting). Not a resume:
   the app returns after the call's event ended while another attended event is current (back-to-back) — the
   first meeting's end proceeds. Fixtures: `call-resumes.json` (resume then end at the event end → stop; no
   manual stop any more), `call-resumes-during-toast.json`, `back-to-back.json` (Zoom A→B, 5 s gap). Known
   limit: B isn't prompted after A's note stops (detect's "no prompt while recording" made that presence
   `done`) — the user starts B from "Upcoming"; left as is (changing D-21's gate is a detection change).
3. **Durable grace.** `MeetingEndGrace` keeps every held end in `<userData>/grace-pending.json` (atomic replace,
   removed when empty). At launch they are *parked*; `accountOpened(storeUser)` (after each `sync.setUser`)
   writes the due ones and re-arms one still inside its period; an end due while another account's database is
   open is parked too (never written elsewhere, no longer dropped). "Continue recording" after a relaunch drops
   the held end. Quit inside the grace: the end is written, then a sync push for at most 5 s before exit.
   Tests: unit (crash → relaunch → ended once the account opens; relaunch inside the period re-arms the rest;
   parked across accounts; corrupt file) and e2e test 4 (SIGKILL inside the grace → relaunch → `ended_at` set
   and a `pipeline_run` created).
Optional, done: `meetingSpeechMs` reads finals only; `PipelineLine` stops polling after 4 idle reads (15 s) once
the "just ended" 2 min are over; one "Continue recording" (the recording bar's; the header line keeps the
countdown + "Start now"); `OAT_AUTO_ENHANCE_MIN_SPEECH_MS` below 60 s is ignored with `NODE_ENV=production`.
e2e timings now include `confirmMs: 2000` and `speechDb: 0` (the fixture keeps playing both voices after the
"call" ends).
