# 7.5 — Auto-stop + auto-enhance
status: todo
milestone: M7 · deps: 4.4, 7.2, 7.3, 8.3 · branch: task/7.5-auto-stop-enhance

## Goal
Recording ends itself sensibly and notes appear without clicking: stop when the call is clearly over (or ask),
then the post-meeting pipeline (8.3) enhances automatically.

## Context
PLAN 7.5 text, D-21 (detection; `meetingEnded{prompted, recordingStartedDuringMeeting}` semantics from 7.2 review:
stop only when `recording && (recordingStartedDuringMeeting || prompted)`), D-24 (resume), D-26, D-29 + 8.3
(pipeline trigger on meeting end; "Auto-enhance after meetings" setting), `@oat/detection`, `@oat/calendar`,
desktop RecordingService + detection wiring (7.3).

## Scope
In:
- Auto-stop rules (pure, fixture-tested): never in the first 3 min; when the meeting app releases the mic and
  the calendar event's end is within ±5 min → stop automatically (with a 10 s "Stopping… Keep recording" undo
  toast); otherwise show "Meeting over? Stop recording / Keep going" prompt; a silence/inactivity fallback
  (both sources below level threshold for 10 min) → same prompt; never auto-stop in-person (mic-only) recordings
  unless user enabled it.
- Auto-enhance: after stop, if "Auto-enhance after meetings" is on and the transcript passes a minimum length
  (e.g. 60 s of speech), the 8.3 pipeline runs (it already triggers on end) — add a grace delay (60 s) during
  which "Continue recording" cancels the pipeline start; resuming within grace doesn't create a run.
- Settings: "Stop recording automatically when the meeting ends" (on by default) in desktop settings.
- Tests: rule fixtures (timelines with mic-apps + calendar + levels), desktop e2e with fixtures: call ends →
  auto-stop toast → stopped → pipeline status "enhancing → done" in the header; undo keeps recording.
Never real capture/mic-apps/EventKit.

## Acceptance criteria
- [ ] Auto-stop + undo + prompt flows; grace-period auto-enhance; `pnpm run ci` green.
