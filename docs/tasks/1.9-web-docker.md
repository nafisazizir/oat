# 1.9 — `apps/web` Dockerfile + compose profile `app`
status: done
milestone: M1 · deps: 1.4, 1.10 · branch: task/1.9-web-docker

## Goal
Run the whole web app in containers alongside the dev stack (D-11) so a new machine can demo Oat with only
Docker, and so the prod image path is exercised early.

## Context
D-11 (compose profile `app`, port 3000), D-15 (TS-source packages → Next build transpiles them), `docker/`,
`tools/mocks/Dockerfile` (pattern for monorepo builds), `apps/web` (Next 16; env module; loads root `.env`),
`docs/DEV.md`. Note from 1.10 review: the mock OAuth issuer URL is `http://localhost:18089/google` from the
host; inside compose the web container must reach it as `http://oauth:8080/google` while browsers still use
localhost — handle issuer/host mismatch (e.g. mock-oauth2-server `hostname`/issuer config or a server-side
discovery URL override env).

## Scope
In:
- `apps/web/Dockerfile`: multi-stage (pnpm fetch/install with `--filter @oat/web...`, `next build` with
  `output: 'standalone'`, slim runtime `node:24-alpine`, non-root user, healthcheck on `/api/health`).
  `.dockerignore` tuned (no node_modules, .next, worktrees, research/raw, fixtures audio not needed).
- `docker-compose.yml` service `web` under profile `app`: depends on healthy postgres/redis/mailpit/oauth/mocks,
  env pointing at service hostnames, port 127.0.0.1:3000, runs DB migrations on start (separate one-shot
  `migrate` service under the same profile, or an entrypoint step — pick and justify).
- Root scripts: `dev:app` (= `docker compose --profile app up -d --wait`), documented in DEV.md.
- Verification that sign-in (once 1.6 lands) works through the container is out of scope here — just health +
  home page render + an API call that touches Postgres (e.g. extend `/api/health` with `db: ok`).
Out: Vercel (9.6).

## Design notes
(implementer, 2026-11-14)

**Image (`apps/web/Dockerfile`, context = repo root).** Stages: `base` (node:24.22.3-alpine + corepack) →
`manifests` (copies the context, extracts every `package.json` + lockfile + workspace file; its *output* only
changes when a manifest does, so the next `COPY --from=manifests` stays cached on source edits) →
`web-deps` (`pnpm install --frozen-lockfile --filter '@oat/web...'`, pnpm store as a BuildKit cache mount) →
`web-build` (root tsconfig/eslint/vitest configs that `apps/web/tsconfig.json` pulls in, `packages/`,
`apps/web/`, `next build`) → `web` (default/last target: `.next/standalone` + `.next/static` +
`docker/web/entrypoint.mjs`, `USER node`, `HOSTNAME=0.0.0.0`, `NEXT_TELEMETRY_DISABLED=1`, HEALTHCHECK on
`/api/health`). Standalone output is self-discovering: no hand-maintained list of workspace packages
(adding `@oat/auth` in 1.6 needs no Dockerfile change). Measured: `oat-web:dev` 296 MB (node:24.22.3-alpine
base alone is 238 MB in this Docker Desktop store; the app layer is ~45 MB). A source-only edit re-runs only
`next build` (install layer `CACHED`, checked with `--progress plain`).

**Migrations: separate one-shot `migrate` service** (same Dockerfile, target `migrate`, image
`oat-migrate:dev`, 279 MB), not an entrypoint step. Why: the runtime image stays free of migration code and
of `drizzle/` files Next doesn't trace; `web` uses `depends_on: migrate: service_completed_successfully`, so
a failed migration stops the start visibly instead of crash-looping web; multiple web replicas never race;
and it mirrors prod, where migrations are a deploy step (9.6). The image runs
`node packages/db/src/cli/migrate.ts` with Node 24's built-in type stripping (@oat/db is erasable-syntax TS
with `.ts` imports, `verbatimModuleSyntax`), prod deps only (`--prod --filter '@oat/db...'`), no tsx/esbuild.

**OAuth issuer / Host mismatch: in-container localhost forwards.** mock-oauth2-server derives `iss` and every
discovery endpoint from the Host header, so the server must call it by the same URL a browser uses. The web
entrypoint reads `OAT_LOCALHOST_FORWARDS=18089=oauth:8080,14010=mocks:14010` and forwards those loopback
ports (127.0.0.1 and ::1) to the services before importing Next's `server.js` in the same process. Result:
`OAUTH_GOOGLE_ISSUER=http://localhost:18089/google` works unchanged inside the container (issuer, token `iss`,
authorize/token/jwks endpoints all `localhost:18089`), so 1.6's discovery-based Google provider needs no
container-specific code and the browser redirect stays valid. Mocks get the same treatment because STT/LLM
URLs may be handed to the desktop app. Rejected: a socat sidecar sharing web's netns (breaks when web
restarts), pinning the issuer to `oauth:8080` (browser can't reach it), a server-side discovery override env
(app code for a dev-only problem), `host.docker.internal` (127.0.0.1-bound ports, Linux differences). Unset
in production: the entrypoint then only starts Next. **No existing compose service definition changed.**

**Compose (`docker-compose.yml`, profile `app`).** `migrate` + `web`; web depends on healthy
postgres/redis/mailpit/oauth/mocks + completed migrate, `127.0.0.1:3000:3000`, `init: true` (signals),
`restart: unless-stopped`, healthcheck on `/api/health`. Env is explicit in compose: server-to-server via
service names (postgres:5432, redis:6379, mailpit:1025/8025), browser-facing URLs via forwarded localhost;
provider keys and the Google issuer/client are interpolated from the root `.env` (default = mocks), so real
keys work as on the host. 1.6 must add its `BETTER_AUTH_*` env to the `web` service. `ci.mjs`'s stack check
uses the default profile, so it ignores these services.

**Health.** `/api/health` → `{ ok, version, db }`; `db` is a `select 1` through a lazily-created pool
(`src/server/db.ts`, kept on `globalThis` for dev reloads), 2 s timeout, HTTP 503 when not ok, failure reason
logged but never returned. Logic in `src/server/health.ts` with unit tests; e2e smoke updated to the new shape.

**Scripts.** `pnpm dev:app` = `compose --profile app build migrate web` then `up -d --wait web` (builds only
these two images, never the shared ones; compose recreates web only when its image/definition changed).
Added `pnpm dev:app:stop` (`rm --stop --force web migrate`) to free :3000 without touching the stack.
`dev.mjs` now accepts multi-step commands. DEV.md: new "Web app in Docker" section + commands, OAuth note,
`.env` readers, port 3000 troubleshooting.

**Outside the listed scope (strictly needed):**
- `packages/db/src/client.ts`: `MIGRATIONS_FOLDER` built with `path.join(dirname(fileURLToPath(import.meta.url)),
  '..', 'drizzle')` instead of `new URL('../drizzle', import.meta.url)` — Turbopack treats the latter as an
  asset reference and `next build` fails ("Can't resolve '../drizzle'") as soon as apps/web imports `@oat/db`.
  Same value at runtime; 1.6 would have hit this when wiring `@oat/auth` into the app.
- `apps/web/package.json` + lockfile: `@oat/db` dependency (health db check).
- `apps/web/e2e/smoke.spec.ts`: health assertion includes `db: 'ok'`.
- `eslint.config.js` + root `lint` script: `docker/**/*.{js,mjs}` gets Node globals and is linted
  (`eslint scripts docker`), so the entrypoint is checked in CI.
- `.dockerignore`: also drops playwright/test output, tsbuildinfo, Swift `.build`, fixture audio binaries.
