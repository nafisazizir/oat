# 6.4 — Chat UI: note side panel + global assistant
status: done
milestone: M6 · deps: 6.3 · branch: task/6.4-chat-ui

## Goal
Talk to your notes: a chat side panel on every note (scope = that note) and a global Assistant view (scope =
workspace), streaming answers with clickable citations that jump to the transcript moment or note block, and
safe approval of proposed edits.

## Context
SPEC §4 Assistant, §7, D-27, `apps/web/src/server/chat*.ts` + `/api/chat*` (6.2/6.3: UI message stream,
threads, proposals endpoint, citation markers `[[seg:<id>]]`/`[[block:<id>]]`, 6.4 UI notes in
docs/tasks/6.2-assistant.md Design notes), AI SDK UI (`useChat` from `@ai-sdk/react`; load `vercel:ai-sdk`
skill), `@oat/ui`, document page (3.3/4.4), search `?t=` deep links (3.6 noted nothing reads `t` yet — implement
it here for transcript segments).

## Scope
In:
- Note panel: toggle button on the document page; thread list for this note + new thread; message list with
  streaming, tool-activity indicators ("Searching meetings…"), markdown rendering (sanitised), citations
  rendered as chips → click scrolls/highlights the cited block in the editor or opens the transcript at the
  segment (`/d/<id>?t=<seconds>&seg=<id>`; implement the reader on the document page: scroll transcript/
  highlight). Proposals render as a diff card (document title + before/after, never only the model's
  summary) with Approve/Reject; 409 stale → show "note changed, re-run".
- Global `/assistant` page: workspace-scoped threads list + chat; same components.
- Empty/loading/error/rate-limited (429 with retryAfter) states; stop button (abort); keyboard: ⌘J opens panel.
- e2e with the mock tool loop: ask → streamed answer with citation chips → click chip → navigates/highlights;
  proposal approve flow; rate limit message (mock 429). Screenshots light/dark.
Out: voice input, custom assistants (IDEAS).

## Acceptance criteria
- [ ] Note panel + global page work against the mock; citations navigate; proposals require approval.
- [ ] `pnpm run ci` green.

## Design notes

**Layout (ASCII, ≥ lg).** The panel is a sticky column beside the note (below `lg` a full-height overlay); the
toggle is a floating pill bottom-right, ⌘J toggles (remembered per browser in `localStorage`, read after
hydration). `/assistant` = thread list column + centred chat (`max-w-content`).
```
┌ sidebar ┬──────────── note (PageContainer) ─────────────┬─ Ask about this note  ⟲ ＋ ✕ ┐
│ Home    │ Title                                         │        [ user question ]      │
│ Assist. │ Lakeside pilot starts on the first of March.  │ ✓ Searched meetings           │
│ …       │ ┌ Transcript ───────────────────────── ✕ ┐    │ Answer text … ① … ② … ③       │
│         │ │ 1:05 Them The pilot starts …  (focused) │    │ ┌ Suggested edit to <title> ┐ │
│         │ └─────────────────────────────────────────┘    │ │ − before   + after         │ │
│         │                                               │ │ [Approve] [Reject]         │ │
│         │                                               │ [ Ask about this note…   ↑/■ ] │
```
Components (`apps/web/src/components/assistant/`), all from `@oat/ui` (Button, Badge, DropdownMenu, Tooltip,
Skeleton) + tokens only (`bg-me/them`, `bg-selection`, `success/warning/destructive` tints):
- `document-assistant.tsx` — the document page wrapper: panel + toggle + ⌘J, transcript reader, block
  highlight, and the `OpenDocumentContext` bridge (`open-document.tsx`). The **only hook into the page/editor**:
  `page.tsx` wraps `<DocumentEditor>` in it (and reads `?t/seg/block`), and `DocumentEditor` calls
  `useRegisterOpenDocument(doc.id, { settle, replace })` (one call: autosave `settle`, and `adopt` + `setContent`
  for a server-written body). No other change to the editor (4.5 works there).
- `assistant-chat.tsx` — threads (`GET /api/chat/threads`, history dropdown in the panel / list on the page),
  new chat, loading/error states; `chat-session.tsx` — one conversation via `useChat` (`@ai-sdk/react` 4.0.177,
  matches `ai` 7.0.173; added to the catalog) + `DefaultChatTransport`; `chat-message.tsx` (tool activity rows,
  proposal cards in stream order); `answer.tsx` (Markdown + chips); `proposal-card.tsx`; `transcript-reader.tsx`.

**Streaming + persistence.** The transport sends only the new user message + `threadId` + scope + time zone
(the server ignores client history, D-27). The thread id is read from the `x-oat-thread-id` response header
(custom `fetch` in the transport), so the second question continues the thread. On `onFinish` the session
re-reads `GET /api/chat/threads/:id` until the streamed message id (= the server's `generateMessageId`) is
saved (the server persists in `onEnd`, after the client sees the end), then replaces messages with the saved
copies (metadata: citations, proposals with status) and takes the thread's `sources`. Stop = `useChat.stop()`
(the server saves the partial answer, 6.2). States: empty (suggestions), "Thinking…" while submitted, tool
rows (`Searching meetings…` → `Searched meetings`, failures), error alert; 429 → "Try again in N s" from
`retryAfter` (`describeChatError` reads the transport's `APICallError` body).

**Markdown, sanitised.** `src/lib/chat-markdown.ts`: markdown-it with `html: false` → our own allowlisted
tree (p, h3/h4, lists, quote, strong/em/s, code/pre, tables, br/hr, links) rendered as React elements — no
`dangerouslySetInnerHTML` anywhere in the chat. Links only http(s)/mailto/app-relative (`safeHref`, external
ones `target=_blank rel=noopener noreferrer nofollow`); images become their alt text. Citation markers are
swapped for private-use sentinels before parsing (typed sentinels are stripped first) and come back as `cite`
nodes; inside code they stay literal. Unit-tested (`chat-markdown.test.ts`).

**Citations → chips → navigation.** Chips are numbered per answer in order of first appearance. They resolve
through a new **`sources`** field on `GET /api/chat/threads/:id` (`ChatThreadDetail.sources`, server
`resolveSources` in `src/server/chat.ts`): `seg:<id>` → segment + meeting → document, `block:<id>` → looked up
only in documents the thread touched (its note, `documentId`s in stored tool calls/results, proposal targets —
never workspace-wide), and **every document re-checked with `canReadDocument` now** (live, readable); anything
else is absent → the chip renders "unavailable" (struck through) once the message is saved, "loading" while it
streams. Tooltip: title · m:ss · speaker + the cited text. Click (`useOpenCitation`): a block of the open note →
scroll + highlight in place (a `<style>` rule on `[data-id]`, no DOM mutation inside ProseMirror, so no
spurious autosave); a segment of the open note → `router.replace('/d/<id>?t=<s>&seg=<id>')` (panel stays);
anything else → `router.push` to `/d/<id>?t=&seg=` or `/d/<id>?block=<id>`.

**Transcript reader (`?t=` / `seg=`).** `page.tsx` parses `t`, `seg`, `block` (`parseDeepLink`, malformed values
dropped) and, for a meeting note with `t` or `seg`, loads the final transcript server-side (`src/server/
transcript.ts` `loadTranscript` → `getDocument` permission check; exposed as `loadDocumentTranscript` in
`shell.ts`). `TranscriptReader` shows it under the note with the focused line (the segment, else the line
spoken at `t`) centred and highlighted; ✕ removes the params. Search's transcript hits (3.6, `?t=` only) now land
on the right line too. The full meeting view (collapsible live transcript, header) stays task 3.4.

**Proposals.** Rendered from the saved message's `metadata.proposals` (server copy, plain text) where the
`updateDocument` tool part ran (a skeleton while the turn is still streaming). The card shows the target
note's **title** (from `sources.documents`, only if still readable) and **every change as before/after plain
text** (`<del>` / `+`, sr-only "Before/After"), with the model's summary below, labelled "Assistant's note" —
never the summary alone. Approve: if the target is the open note, `settle()` its autosave first (so the change is
checked against what the user sees); then `POST …/proposals/:id`; on success the editor gets the server copy
(`GET /api/documents/:id` → `replace`, version adopted — typing afterwards saves without a conflict); for other
notes a toast with "Open note". 409 `stale_version` → the thread re-read shows status `stale`: "The note changed
since this suggestion… Re-run" (re-asks the question that produced it); `failed` similar; `proposal_closed` →
refresh. Reject → `rejected`.

**Navigation.** `sections.assistant` (`/assistant`) in the sidebar (under Home, `data-testid=nav-assistant`),
the ⌘K "Go to" group and breadcrumbs (workspace › Assistant).

**Tests.** Unit: `chat-markdown.test.ts`, `transcript.test.ts`, `chat-client.test.ts`. Int (`chat.int.test.ts`):
thread `sources` resolve a segment and a block (title, speaker, startMs, text) and drop the block once its note
goes private to someone else (seg in a readable note stays). e2e `e2e/assistant.spec.ts` (mock tool loop
in-process; meetings/segments seeded in the e2e DB and indexed with `indexDocument` + the mock's own
`hashEmbedding`, so query and chunk vectors match): (1) ⌘J → ask → tool row → streamed answer with seg + block
chips → seg chip opens the reader at the cited line (in viewport, panel still open) → block chip highlights the
block in view → close/reopen + history dropdown restores the thread; (2) `mock:tool updateDocument` → card with
title + before/after → Approve → editor shows the change and keeps autosaving → second proposal, note edited →
Approve → `stale` + Re-run; (3) sidebar → `/assistant` → answer + thread list; mocked 429 → "Try again in 42 s";
chip → `/d/<id>?t=&seg=` (or `?block=`) with the focus shown; (4) Stop aborts. Tests (2)/(3) set
`allowConsoleErrors` (the browser logs the expected 409/429 as failed resources). The spec hides the dev-only
Next.js indicator, which sits over the composer's send/stop button. `E2E_SCREENSHOTS=1` writes
`docs/tasks/evidence/6.4/*-{light,dark}.png` (viewed: panel answer, transcript moment, proposal pending/stale,
assistant page, rate limit).

**Touched outside the listed paths (all small):** `src/server/chat.ts` (+`resolveSources`, `sources` on
`getThread`), `src/lib/chat-types.ts` (`ResolvedCitation`, `ChatSources`), `src/server/shell.ts`
(`loadDocumentTranscript`), new `src/server/transcript.ts`, `src/components/document/document-editor.tsx`

`apps/web/package.json` (`@ai-sdk/react`, `markdown-it`), `pnpm-workspace.yaml` catalog, lockfile.

**Follow-ups / notes for others.** 3.4 can grow `TranscriptReader` into the collapsible meeting transcript

## Review

**Reviewer (round 1) — verdict: `changes`.** Reviewed the task file + `git diff $(git merge-base main
task/6.4-chat-ui)..task/6.4-chat-ui` + screenshots in `evidence/6.4/` (all 12 viewed; states look right).

Checked and fine: markdown is `html: false` → allowlisted React tree, no `dangerouslySetInnerHTML`; `safeHref`
rejects `javascript:`/`//host`/`/\host` (markdown-it percent-encodes the backslash); chips resolve only via the
server's `sources`, built from stored (D-27-filtered) citation ids; `resolveSources` re-checks every document with
`canReadDocument` + `deletedAt` (actor carries no share token), blocks are searched only in documents the thread
touched and then filtered to readable ones, so no titles/snippets of unreadable notes leak; proposal card shows
the server's `before`/`after` (computed in `@oat/ai` `edit.ts`), title only if still readable; approve settles
autosave first, 409 → `stale` + Re-run, tested in e2e; `?t/seg/block` are regex-validated, used only for in-page
focus (no redirect sink); `loadTranscript` goes through `getDocument` (404 for unreadable), final segments only.

Must fix:
1. `apps/web/src/components/assistant/document-assistant.tsx:95,147` — a hard load of `/d/<id>?block=<id>`
   (reload after a block chip for another note, or a pasted link) seeds `highlight` in the `useState`
   initializer, so the `<style>` with `CSS.escape(...)` renders during SSR, where `CSS` is undefined →
   `ReferenceError` on the server (React falls back to client rendering with a logged error at best). Fix: render
   the `<style>` only after hydration (`hydrated && highlight`) or escape with a local helper (the id is already
   constrained by `parseDeepLink`); add an e2e that `page.goto`s a `?block=` URL with no console errors.
2. `apps/web/src/components/assistant/assistant-chat.tsx:147` (+ `ThreadList` :252) — `/assistant` lists note
   threads too ("About a note · …", `listThreads` without `documentId`), but continues any opened thread with
   the page's workspace scope → `POST /api/chat` returns 400 "This thread belongs to a different scope"
   (`server/chat.ts:461`). Fix: when the opened thread's `scope === 'document'`, give the session
   `{ kind: 'document', documentId: thread.documentId }` (or show it read-only with "Open note"); e2e: ask a
   follow-up in a note thread from `/assistant`.
3. `document-assistant.tsx:165-175` — panel focus management: closing (✕ or ⌘J) unmounts the focused `aside`
   and focus drops to `<body>`; below `lg` the panel is a full-screen `fixed` overlay with no Escape to close
   and no focus containment (Tab walks into the hidden page behind). Fix: on close return focus to the toggle /
   previously focused element; Escape closes; in overlay mode make it a modal (`role="dialog" aria-modal`, focus
   trap — e.g. the `@oat/ui` Sheet below `lg`).

Optional:
- `chat-session.tsx:239` — `aria-live="polite"` on the whole message list: VoiceOver ignores `aria-busy` and reads
  each streamed delta, and tool rows/"Thinking…" (`role=status`) announce twice. Prefer `role="log"` without live
  updates during streaming + one sr-only status ("Answer ready").
- `proposal-card.tsx:59-69` — text typed between `settle()` and `replace()` (two round-trips) is overwritten by
  `setContent`; make the editor read-only while approving, or skip `replace` if autosave is dirty.
- `resolveSources` reads full `contentJson` of up to 50 documents per `GET` thread, and `refresh` polls it up to
  30×; select only needed candidates / poll a cheaper endpoint.
- Chip numbers: `citationOrder` counts markers inside code spans, and `AssistantMessage` renders one `Answer`
  per text chunk (numbering restarts after a tool row), so numbers can skip or repeat.
- Deny-case coverage: no direct test that `loadTranscript` refuses an unreadable note, and the `sources` int test
  drops a block but not a segment of a note that became unreadable.
