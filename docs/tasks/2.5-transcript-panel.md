# 2.5 — Desktop recording + live transcript panel
status: done
milestone: M2 · deps: 1.8, 2.2, 2.4, 2.8 · branch: task/2.5-transcript-panel

## Goal
In the desktop app: start/pause/stop a recording, see live two-source transcript (me/them) with interim →
final updates, levels and status — wired through the real pipeline (SidecarSource or FileSource →
RecordingController → DeepgramProvider ×2 (mock in dev) + OpusArchiveWriter).

## Context
SPEC §3, §8 (latency, never silently stop), D-17, D-19 (stable segment ids; finals replace interims;
retraction = final with empty text), D-24. `@oat/audio` (RecordingController, SidecarSource, FileSource,
RecordingArchive), `@oat/stt` (DeepgramProvider; token via `getToken` → our API's STT grant endpoint — add
`POST /api/stt/token` in apps/web returning a short-lived token from the mocks grant endpoint in dev /
Deepgram in prod, session-authenticated), `apps/desktop` (1.8: bridge contract, main-owned store, windows).
UI tokens `--me/--them`.

## Scope
In:
- Main process `RecordingService`: owns the controller, STT streams per source, archive; exposes bridge
  channels: `recording:start {meetingId?, source: 'sidecar'|'file', fixture?}`, `pause`, `resume`, `stop`,
  subscription `recording:state` (state, elapsed, levels, per-source STT status, errors) and
  `transcript:segments` (batched deltas). Dev menu/env to use FileSource fixtures instead of the mic
  (`OAT_AUDIO_SOURCE=file:standup-short`) — the default in e2e.
- Renderer: recording bar (start/pause/stop, elapsed, level meters, STT status pill, error banner that never
  hides), transcript panel (virtualised list, me/them labels + colours, interim italic/muted then final,
  autoscroll with "jump to live" when the user scrolls up, timestamps), empty/loading/error states. Widget
  window shows compact status + stop.
- Tests: unit (segment store: interim/final/retraction merge by id; batching), Playwright `_electron` e2e with
  FileSource `standup-short` in fast/realtime + mock STT: segments for both sources appear, finals match
  ground-truth text closely (mock_fixture), pause/resume, stop → archive files exist. Screenshot evidence.
Out: persistence to SQLite/API (2.6), meeting note editor (3.4), playback (3.7).

## Design notes
(implementer + designer, 2026-11-14)

**Pipeline (main process, `apps/desktop/src/main/recording-service.ts`, Electron-free).**
`AudioSource` (SidecarSource | FileSource) → `RecordingController` → two independent bounded subscribers:
`RecordingArchive` (Opus parts under `<userData>/audio/<meeting>/`, D-10/D-24) and `SttPipe` (one
`SttStream` per source, opened on that source's first frame, D-17). STT being slow/down never delays capture
or the archive (separate queues; the STT queue holds ~30 s while the provider is being resolved).
- Status = controller state, except `stopping` while our stop waits for finals + closed files. When the
  source ends by itself (fixture end, crash) the session is finalized in the background (STT finish, archive
  close); `error` stays until `recording:stop` (Dismiss) or a new start.
- Stop: drain STT queue → streams that are `open`/`connecting` `finish()` (provider `finishTimeoutMs` 8 s),
  offline ones are `close()`d (their audio is in the archive; back-fill from it is later work) → archive
  rows returned (never paths).
- Clocks: segments arrive on the recording clock (frame `tUs`); the transcript uses the meeting clock =
  recording ms − `started.tUs` + session offset (0, or the end of the previous part of the same meeting
  this launch, D-24). `audio_recording` rows: `InMemoryAudioRecordingStore` until 2.6 (SQLite).
- Issues (capture/STT/archive) become user-facing messages (raw details only in the log), de-duplicated
  (`count`), max 20, cleared on next start. A source that can't even be created (no sidecar binary) is
  wrapped as a source whose `start()` rejects, so it goes through the same `error` path.
- Quit while recording: `before-quit` is deferred until `shutdown()` stopped gracefully.

**STT credentials (D-17).** `POST /api/stt/token` (apps/web, `src/server/stt-token.ts`, route
`src/app/api/stt/token/route.ts`): cookie (same-origin, CSRF guard as the documents API) or bearer session →
fresh grant from `resolveDeepgramEndpoints(env)` (`DEEPGRAM_API_KEY` → Deepgram with the key server-side;
else `${MOCKS_URL}/stt`), `ttl_seconds: 60`, never cached/shared → `{ accessToken, expiresIn, listenUrl }`.
Production without a key and a non-loopback mock → 503 `stt_unavailable` (as `@oat/ai`); grant failures →
503 (details only in logs). Desktop: `AuthController.sttGrant()` (bearer stays in main; 401 signs out) →
`SttCredentials` (cache until 10 s before expiry, shared in-flight request, `refresh` after a 401,
`listenUrl` must be `wss:` or loopback `ws:`). The websocket URL is the one the API names for its token, so
token issuer and endpoint can't disagree; if the API is unreachable at start, the default endpoint is used
(Deepgram packaged / env-resolved in dev) and `getToken` keeps retrying on every reconnect.
No new env vars on the web side (`DEEPGRAM_*`, `MOCKS_URL` already in `.env.example`).

**Inputs / dev switches (`config.ts`, `recording-setup.ts`; all ignored when packaged).**
`OAT_AUDIO_SOURCE` = `sidecar` (default) | `synthetic` (sidecar tone generator) | `file:<fixture>`
(FileSource, realtime, `fixtures/audio/<name>.wav`; the e2e default). `OAT_STT_URL` overrides the STT
websocket (e2e points it at a closed port). A fixture replay against a *loopback* endpoint adds the mock's
`mock_fixture/mock_channel/mock_offset_ms` so the transcript equals the ground truth; never packaged, never a
remote endpoint. The dev sidecar is looked up in the repo (`native/oat-audio/.build/release`), because
`@oat/audio`'s own dev path is relative to its source file, which bundling moves.

**Bridge (`packages/core/src/bridge.ts`).** invoke `recording:options`, `recording:start
{meetingId?, input?, fixture?}`, `recording:pause`, `recording:resume`, `recording:stop` → `{meetingId,
audio[]}`, `recording:get`, `transcript:get`; subscribe `recording:state` (snapshot: status, meeting, input,
startedAt, elapsedMs@elapsedAt, levels, per-source STT status, issues; status changes immediately, levels
throttled to 100 ms) and `transcript:segments` (batches every 50 ms, newest update per id, `seq` +1 per batch;
`transcript:get` flushes first so snapshot `seq` lines up). New bridge error code `invalid_state`.
`MainState.recording.status` now has the full status set and `activeMeetingId` is the recording's meeting.
Live segment type is `LiveSegment` (`@oat/core` already exports the synced `TranscriptSegment` row).
Renderer clients (`renderer/src/recording-state.ts`) subscribe before fetching: recording keeps the higher
`seq`; transcript holds batches until the snapshot, applies only newer ones, a new meeting starts at `seq` 1,
any gap reloads. Merge rules shared by main and windows (`src/shared/transcript.ts`): upsert by id, final
replaces interim and is never downgraded, empty final = retraction.

**UI (designer).** Signed in, the main window becomes: account sidebar (w-64, `bg-sidebar`; the 1.8 actions
kept) + meeting view:
```
┌ sidebar ─────┬───────────────────────────────────────────────────────────────┐
│ (R) name     │ [Pause][■ Stop] │ ● 0:10  Me ▬▬  Them ▬▬▬        (● Live) [Fixture ▾] │
│ email        │ ⚠ Transcription is offline — still recording   (banner, role=alert)    │
│ Check conn.  ├───────────────────────────────────────────────────────────────┤
│ Widget       │ Them 0:08                                                     │
│              │ (oat bubble, italic+muted while interim)                       │
│              │                                  Me 0:12                      │
│ Sign out     │                         (ink bubble)  [↓ Jump to live]        │
└──────────────┴───────────────────────────────────────────────────────────────┘
```
- Components only from `@oat/ui` (Button, Select) + tokens: `bg-me`/`text-me-foreground` (right) and
  `bg-them`/`text-them-foreground` (left) bubbles; meters are the voice colour tracks with the foreground
  fill; pill tones success / warning / destructive; elapsed in mono tabular figures.
- Transcript: `@tanstack/react-virtual` (new catalog dep `^3.14.24`) with measured rows; speaker + time header
  when the speaker changes or after 30 s; follows the live end while at the bottom; scrolling up stops
  following and shows "Jump to live".
- States: loading/starting spinner; empty ("No transcript yet" + what is transcribed); recording without
  segments ("Listening…"); STT down without segments ("Waiting for transcription", audio still saved).
  Issue banner lists the last 3 issues (time, message, ×count); it stays until the next start, heading
  calmer once the problem is over ("This recording had problems").
- Widget (320×136): status dot + label, elapsed, compact meters, STT pill, Stop; the bottom line shows the
  account, or a short issue line while recording with problems.
- Dev only: fixture/mic select in the bar when fixtures are available (never in a packaged app).

**Tests.** Desktop unit 131 (new: `shared/transcript`, `transcript-buffer`, `stt-credentials`,
`recording-service` (12, real FileSource + Opus archive + FakeSttProvider), `recording-setup`, renderer
`recording-state`, config/auth additions). Web: `stt-token.test.ts` (12), `stt-token.int.test.ts` (4).
E2E `apps/desktop/e2e/recording.spec.ts` (2): full fixture realtime with latency, interims, pause/resume,
widget, ground-truth comparison, jump-to-live, archive files; STT down via `OAT_STT_URL` → banner, empty
state, widget issue, recording continues, Stop from the widget, archive complete. The sidecar path is
covered by unit tests through the same `RecordingService` (injected sources); it was not run (only
`--synthetic` would be allowed).

**Out of scope / follow-ups.** `docs/DEV.md` should list `OAT_AUDIO_SOURCE` / `OAT_STT_URL` under "Desktop
app → Env" (not edited: outside this task's file scope). Rate limiting `POST /api/stt/token` per user is not
done (tokens are short-lived and scoped to our key). Back-fill of STT outages from the archive (D-17) and

## Review
(reviewer, 2026-11-14, round 1; read the task file, `git diff $(git merge-base main HEAD)..task/2.5-transcript-panel`,
and the PNGs in `evidence/2.5/`. Tests were not re-run.)

**Verdict: `changes`.** Both items are small.

These are fine: pipeline independence. Archive and STT have separate bounded queues, one `SttStream` per
source, and a fatal stream drops only its own writes. Every failure path ends up in `issues` with a
de-duplicated message and stays visible until the next start: token fetch (`token`, retried on every
reconnect), WS drop/stall (reconnect plus replay, `replay_overflow` with its time range), sidecar exit
(non-fatal restart, then fatal → `error`), archive ENOSPC/EACCES (named in the message, recording continues),
no provider (15 s timeout → fatal STT issue). Segment merge: upsert by id, finals never downgraded, an empty
final retracts, sort by `startMs`/source/id. The `@oat/stt` id lifecycle rules out an interim after its
final. Memory: a 2 h meeting is about 5k segments, sorted lazily once per 50 ms batch. The renderer
subscribes first, fetches the snapshot, holds batches and reloads on a seq gap, so a reload during recording
is safe. The list is virtualised with measured rows. The token route takes a cookie only with a same-origin
or allowed Origin, and a bearer only without a cookie. It requests a fresh 60 s grant for each call, sends
`no-store`, returns 503 in production when only a non-loopback mock is configured, and keeps the key
server-side. The token stays in main. `listenUrl` must be `wss:` or loopback `ws:`. The bridge
`meetingId`/fixture regexes prevent path traversal. Start requires a session. When packaged, the
`OAT_AUDIO_SOURCE`, `OAT_STT_URL`, synthetic and fixture switches are all ignored, and `mock_fixture` is only
sent to loopback in dev builds. The screenshots match the design. The live/finished views show me/them
bubbles, interims in italics, the banner and the widget issue line.

1. **Quit can exit before the archive is closed.** `recording-service.ts:367-373`: `shutdown()` returns at
   once when a user Stop is in flight. During `controller.stop()`, `#stopping` is true but
   `session.finalized` is still `undefined`, because it is set only when the source reaches `idle`. The app
   then calls `app.quit()` without the last finals and without closing the Ogg files. `index.ts:316` also
   skips the deferral when `status === 'idle'` while a self-ended session (fixture end, graceful sidecar
   stop) is still finalizing. Fix: keep `#stopPromise` in `stop()`. Have `shutdown()` await
   `#stopPromise ?? #session?.finalized`. Expose `busy` (status ≠ idle **or** finalize pending) and use it
   in `before-quit`. Add a unit test: start → stop() → shutdown() resolves only after the archive rows are
   `complete`.
2. **Sleep/wake is not surfaced (SPEC §8).** Nothing listens to `powerMonitor`. On lid-close the sidecar
   stops delivering audio, then the WS stalls and reconnects. The user sees no note that the meeting wasn't
   recorded during sleep. The wall-clock `elapsedMs` also keeps counting through sleep while the archive and
   transcript don't. Fix (main, `index.ts`): on `powerMonitor` `suspend`/`resume` while active, add a
   non-fatal `audio` issue such as "Your Mac slept for 12 min; nothing was recorded then". The simplest
   option is to pause on suspend and resume on resume, so elapsed and archive stay consistent. Cover it with
   a unit test through an injected power-event hook.

Optional:
- `RecordingService.start` (`recording-service.ts:236-240`): the state check happens before an `await`, so
  two concurrent starts (e.g. a future second caller) can both pass. Set a synchronous `#starting` flag. The
  UI disables Start while pending, so this can't happen today.
- `IssueBanner` (`recording-controls.tsx`): a fatal `archive` issue reads "Recording, with a hiccup" in the
  warning tone, and the STT-offline empty state still says "saved on this Mac". Treat fatal archive issues
  as severe and change that copy when the archive has failed.
- `SttCredentials` (`stt-credentials.ts:80-91`): a grant still in flight at sign-out repopulates the cache
  after `clear()`. Bump a generation counter in `clear()` and drop stale results.
- `TranscriptBuffer.push`: guard against a pending final being replaced by an interim with the same id, to
  match `TranscriptStore` (defence in depth; the provider never emits that).
- `transcript:get` failing leaves the panel on "Loading…" with no retry. Retry with backoff or show an error
  state.
- Rate limiting `/api/stt/token` is not needed now. A session can already stream for hours on one token, so
  the real control is a per-user STT budget/quota (track for M9). Splitting finals mid-sentence ("Great.
  See" / "you tomorrow.") is expected provider behaviour. Grouping by `speechFinal` could come later (3.x).
- `docs/DEV.md` env entries for `OAT_AUDIO_SOURCE`/`OAT_STT_URL` (already noted as a follow-up).

**Resolution, round 1 (implementer, 2026-11-14).** Merged current `main` (5.3, 3.6, 4.3; one conflict in
`apps/web/src/server/api/index.ts` → `apiDeps` + `sttToken`, and a leftover conflict in
`apps/web/src/lib/api-types.ts` fixed; error codes now include `private_folder`, `builtin_read_only` and
`stt_unavailable`).
1. Fixed. `stop()` keeps `#stopPromise` (a second stop or a quit gets the same promise, it no longer throws).
   `shutdown()` waits for an in-progress start, then awaits `#stopPromise ?? session.finalized`, and
   otherwise stops. New `busy` = status ≠ idle, a start in flight, or an ended session's files still closing
   (`#closing`). `before-quit` defers while `busy`, then quits. Tests: Stop then shutdown resolves only once
   both archive rows are `complete`; a session that ended by itself is busy until its files are closed; a
   second stop returns the same promise.
2. Fixed. `RecordingServiceOptions.power` (`powerMonitor` in `index.ts`). On `suspend` while recording, the
   recording pauses (controller pause, so STT finalizes and gets KeepAlives) and a non-fatal `audio` issue
   `system_sleep` appears: "Paused while your Mac was asleep." On `resume` the recording resumes and the same
   issue becomes "…asleep (N min); nothing was recorded then. Recording resumed.", and it stays visible.
   Elapsed time and the files don't include the sleep (paused). A recording paused by hand stays paused, and
   an idle app ignores sleep. Tests use a fake power emitter.
Optional, all done:
- Synchronous `#starting` guard: concurrent starts → `invalid_state` (tested).
- Fatal `archive` issues make the banner severe with the heading "Audio isn't being saved on this Mac". The
  message reads "…this audio is not being kept", and the STT-offline empty state no longer claims the audio
  is being saved.
- Sign-out while recording: `auth:sign-out` first runs `recording.shutdown()` when `busy`.
- `SttCredentials.clear()` bumps a generation counter, so a late grant can't refill the cache (tested).
- `TranscriptBuffer.push` never lets an interim replace a pending or sent final (tested).
- `transcript:get` failure: the view gets `failed: true` and shows "Couldn't load the transcript.
  Retrying…". Retries back off at 0.5 s, 1 s, 2 s, … up to 10 s (tested).
- `docs/DEV.md`: `OAT_AUDIO_SOURCE` / `OAT_STT_URL` and a short "Recording (2.5)" entry.
- CI route coverage: `denies('POST /api/stt/token')` on both deny-case int tests.
