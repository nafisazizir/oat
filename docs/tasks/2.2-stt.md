# 2.2 — `packages/stt`: SttProvider, Fake, Deepgram adapter + mock
status: done
milestone: M2 · deps: 2.1, 1.10 · branch: task/2.2-stt

## Goal
Live transcription behind one interface, with a deterministic fake for tests and a Deepgram streaming adapter
that works against the containerised Deepgram-compatible mock in dev (no key) and real Deepgram in prod.

## Context
SPEC §3.3, §5, §8 (latency < 1.5 s, never silently stop), D-11, D-17 (short-lived tokens, one stream per
source, ≥120 s replay buffer on reconnect), `research/granola/audio-path.md` (behaviour reference: per-source
WS, interim results, keep-alive, reconnect w/ replay). `@oat/audio` (2.1) frame types + fixtures with
ground-truth `*.segments.json`. `tools/mocks` provider structure + websocket hook + `startMocks()` (1.10).

## Scope
In:
- `packages/stt` (`@oat/stt`): `SttProvider` → `openStream({source, sampleRate, language?, keyterms?})` returning
  a `SttStream` (`write(frame)`, `finish()`, `close()`, events `segment` {source, startMs, endMs, text,
  isFinal, words?, confidence?}, `status` {connecting|open|reconnecting|closed|error}, `error`). Timestamps
  are on the recording clock (frame tUs), not the socket's.
- `FakeSttProvider`: driven by ground-truth segments (from fixture JSON or inline): emits interim
  partials as audio time passes each segment's midpoint and a final at its end; options for injected delays,
  disconnects, errors — for resilience tests.
- `DeepgramProvider`: WS to `DEEPGRAM_URL` (default `ws://localhost:14010/stt/v1/listen`), linear16 16 kHz
  mono, interim results, smart formatting, endpointing, keep-alive messages while paused/silent, auth via a
  `getToken()` callback (short-lived token per D-17; in dev the mock's grant endpoint), maps results →
  segments with correct offsets. Reconnect with exponential backoff; rolling replay buffer (≥120 s per
  stream, configurable) re-sent on reconnect with timestamp offset correction and de-dup of finals already
  emitted. `finish()` sends close-stream and waits for final results.
- Mocks `stt` provider in `tools/mocks`: Deepgram-compatible WS `/stt/v1/listen` (subset: query params,
  binary audio in, JSON `Results` messages with `is_final`, `speech_final`, `start`, `duration`, channel
  alternatives/words; `KeepAlive`, `CloseStream` handling), and `POST /stt/v1/auth/grant` → `{access_token,
  expires_in}`. Text: energy-based VAD finds speech regions; text comes from a deterministic sentence corpus,
  or from a fixture's ground truth when the dev-only query param `mock_fixture=<name>&mock_channel=mic|system`
  is present (never sent by production code paths — only tests/dev tools). Scenario params for
  `drop_after_ms`, `latency_ms`, `reject_auth`.
- Optional real-provider smoke test, skipped unless `DEEPGRAM_API_KEY` is set.
- Tests: unit (Fake behaviour, result mapping, replay-buffer math/de-dup), int via in-process `startMocks()`:
  stream `standup-short.wav` through FileSource (fast) → DeepgramProvider → mock: segments for both sources,
  monotonic, interim→final; forced disconnect mid-stream → reconnects, no lost finals, no duplicates;
  auth rejection surfaces an error status.
Out: wiring into desktop (2.4/2.6), web token endpoint (later with auth), diarization.

## Design notes
(implementer, 2026-11-14)

**Interface** (`packages/stt/src/types.ts`). `SttProvider.openStream({source, sampleRate, language?,
keyterms?})` → `SttStream` with `write(frame)`, `finish(): Promise<void>` (never rejects), `close()`,
`status` and `on('segment'|'status'|'error', fn) → unsubscribe` (sync `Fanout` from `@oat/audio`, no Node
`EventEmitter`). Segment = `{source, startMs, endMs, text, isFinal, speechFinal?, words?, confidence?}` on
the **recording clock** (frame `tUs`). Consumer rule: each new segment of a stream supersedes that stream's
previous interim; finals are immutable, ordered, non-overlapping. Status: `connecting` → `open` ⇄
`reconnecting` → `closed` | `error` (terminal). Errors `{code, message, fatal, status?, lostFromMs?,
lostToMs?}`; codes `auth`, `token`, `bad_request`, `connection`, `stall`, `protocol`, `replay_overflow`,
`finish_timeout`. Non-fatal errors are informational (the stream keeps going) so nothing stops silently.
`BaseSttStream` holds the shared event/status plumbing.

**FakeSttProvider** (`fake.ts`): ground truth (`parseGroundTruth` for fixture JSON) per source; interim with
the first half of the words when audio passes a segment's midpoint, final at its end; `finish()` finalizes
segments the audio started. Options: `latencyMs`, `connectDelayMs`, `disconnectAtMs`/`reconnectDelayMs`
(drop without loss), `errorAtMs`/`errorCode` (fatal), `failOpen` (e.g. `auth`).

**DeepgramProvider** (`deepgram.ts`). Node-only, uses `ws` (needed for an `Authorization` header and for
handshake HTTP status → `auth`/`bad_request`; WHATWG WebSocket exposes neither). Runs in Electron main.
- Query: `model=nova-3, encoding=linear16, sample_rate, channels=1, interim_results, smart_format,
  endpointing=300, mip_opt_out=true, language?, keyterm×n` (`buildListenUrl`).
- Auth: `getToken()` before every (re)connect → `{token, scheme}`; `Bearer` for grant tokens (D-17),
  `Token` for a raw key (smoke test only). `grantTokenSource({grantUrl, apiKey?})` calls
  `POST /v1/auth/grant`, caches until 5 s before expiry. A 401/403 is retried once with a fresh token
  (`authRetries`, default 1), then fatal `auth`; 400 is fatal `bad_request`; anything else reconnects.
- Resilience: `ReplayBuffer` keeps ≥ `replayBufferMs` (default 120 000) of frames by reference. A
  watermark `committedMs` = recording-clock end of the last `is_final` result (Deepgram results tile the
  audio, including empty finals in silence). On (re)open the stream sends every buffered frame from the one
  containing the watermark, then live frames. `SocketTimeline` maps socket seconds → recording ms per
  connection (anchor at first frame and at every discontinuity, e.g. pauses), so replayed audio keeps
  original timestamps. De-dup (`mapDeepgramResults`): results ending at/before the watermark are dropped;
  straddling ones lose words whose midpoint is before it (kept words clamped to it). Lost audio is
  detected from evictions (`ReplayBuffer.evictedEndUs` past the watermark), reported once as non-fatal
  `replay_overflow` with the range (D-17: back-fill from the archive later), so a pause jump in a live
  timeline is not misreported.
- Backoff: 500 ms × 2ⁿ, cap 10 s, ±20 % jitter, reset by the first server message on a connection;
  `maxAttempts` default ∞ (each failed attempt emits a non-fatal error). `KeepAlive` when no audio was sent
  for `keepAliveMs` (3 s); stall check redials when audio flows but the server is silent for 30 s.
  `finish()` sends `CloseStream` (or after the next open if disconnected; again after a drop) and resolves
  on the server's close 1000, or after `finishTimeoutMs` with `finish_timeout`.
- `extraQuery(ctx)` adds per-connection params; tests/dev tools only (mock fixture/scenario params).

**Env** (`deepgram-config.ts`, `resolveDeepgramEndpoints`). Deviation from the brief's `DEEPGRAM_URL`: the
repo already defines `DEEPGRAM_BASE_URL` + `DEEPGRAM_API_KEY` (1.10, `.env.example`, DEV.md "Switching a
provider"), so I reused them instead of adding a second, conflicting variable: base = `DEEPGRAM_BASE_URL` ||
(key ? `https://api.deepgram.com` : `${MOCKS_URL}/stt`); listen = base (http→ws) + `/v1/listen`, grant =
base + `/v1/auth/grant`. Default listen URL is exactly `ws://localhost:14010/stt/v1/listen`. Both vars were
already in turbo `passThroughEnv` (`DEEPGRAM_*`, `MOCKS_URL`), so turbo.json (root) is unchanged.

**Mock `stt` provider** (`tools/mocks/src/providers/stt.ts`). `POST /stt/v1/auth/grant`; `WS
/stt/v1/listen` with Deepgram `Results` (`is_final`, `speech_final`, `from_finalize`, `start`, `duration`,
`channel.alternatives[0].{transcript, confidence, words[{word, start, end, confidence,
punctuated_word}]}`), `Metadata` + close 1000 on `CloseStream`, `Finalize`, `KeepAlive`, close 1011 after
an idle timeout. Auth: `Token <any>` or a granted, unexpired `Bearer` token (header or subprotocol pair);
otherwise 401 on the handshake. VAD: 20 ms RMS > 300 (fixture noise ≈ 10); finals on endpoint
(`endpointing` ms of silence), after 8 s of speech, after 3 s of silence (empty, keeps results contiguous),
on `Finalize`/`CloseStream`; interims every 500 ms of speech. Words: own sentence corpus (one word per
400 ms of speech) or, with `mock_fixture`/`mock_channel`, the fixture ground truth spread over each segment
and released once its midpoint has been heard (`mock_offset_ms` maps socket time → fixture time after a
reconnect). Scenarios: `drop_after_ms` (+ `drop_times`, `mock_session`; keyed by the query minus
`mock_offset_ms`, so only the first connection drops), `latency_ms`, `reject_auth=1`,
`mock_idle_timeout_ms`. Generic additions to the mocks framework: optional `MockWebSocketRoute.verify()`
to refuse an upgrade with an HTTP status + JSON body; request log redacts `Sec-WebSocket-Protocol`
credentials. The ground-truth JSON is imported (esbuild inlines it); the Dockerfile copies
`fixtures/audio/*.segments.json` into the build stage, and `tools/mocks/turbo.json` adds them to test/build
inputs. The container only gets this after `pnpm dev:build` on main (not run here, per brief).

**Tests.** Shared contract (`contract.testsuite.ts`, `describeSttContract`) run by Fake (unit,
`fake.test.ts`) and Deepgram↔mock (int, `deepgram.int.test.ts`): both sources, statuses, source tags, final
text = ground truth (normalized), finals ordered/non-overlapping and on a ground-truth segment, interim
before final and none left at the end, slice at 8 s keeps recording-clock times, wrong source/rate throws,
`close()` silences, `finish()` without audio. Int extras: query/auth shape in the mock log (no `mock_*` by
default); realtime 5 s slice latency (measured 3–503 ms, limit 1.5 s); forced drop at 9 s → statuses
`connecting, open, reconnecting, open, closed`, exactly 2 dials per source, resume offset in (0, 9000],
text exact (no loss/dup); `replay_overflow` with a 1 s buffer; `reject_auth` → `auth` non-fatal then fatal,
status `error`; forged bearer → 401; KeepAlive keeps an idle stream open (control without it gets 1011 and
reconnects); stall redial. Unit: replay buffer/timeline math, result mapping + de-dup, env resolution, URL
params, grant source (cache/refresh/errors), backoff, token-failure give-up, close while connecting. Mock
unit tests (`stt.test.ts`): grant, handshake auth/validation (401/400), corpus interim→final contiguity,
Finalize, idle/KeepAlive, latency, drop-once, fixture text/offset mapping. Real Deepgram smoke test
(`deepgram.smoke.int.test.ts`, grant-token path) is skipped unless `DEEPGRAM_API_KEY` is set.

**Review round 1 fixes** (2026-11-14, after merging current `main`):
1. *Pause.* New `pauseFinalizeMs` (default 1000): after that long without a frame the stream sends
   `{"type":"Finalize"}` once (re-armed by the next frame), so the utterance before a pause becomes final.
   Stall detection only runs while audio flows (`< pauseFinalizeMs` since the last frame), and the reply
   wait restarts when audio resumes. The tick interval is derived from `keepAliveMs`/`pauseFinalizeMs`
   (≤ 250 ms, ≥ 10 ms). Mock: like Deepgram it now keeps talking while audio flows — an (often empty)
   interim every second of silence — so a flowing silent stream is never mistaken for a stall. Tests:
   scripted server that never answers (pause ≫ stall window → exactly one `Finalize`, no errors; resumed
   unanswered audio → `stall`); int realtime run with a 3 s pause and a 1.5 s stall window → no errors, no
   redial, the "Morning…" final arrives during the pause.
2. *Identity (D-19).* `SttSegment.id` (UUIDv7, `ids.ts`), assigned by `BaseSttStream.emitSegment`
   (adapters emit `SttSegmentData`): interims share the id of the final that closes them; the next segment
   gets a new id; ids survive reconnects. **Retraction = a final with the open interim's id and `text: ''`**
   (no words, `speechFinal: false`), emitted when a final maps to nothing (empty or fully de-duplicated)
   while an interim is open, and on `finish()` (normal close or `finish_timeout`) so no interim outlives the
   stream. Documented in `types.ts`. Tests: contract checks UUIDv7 ids, one open interim at a time, each
   interim closed later by a final/retraction with its id, final ids unique; scripted-server tests for
   shared ids and for retraction (and none without an open interim).
3. *Auth refresh.* `GetDeepgramToken(options?: { refresh?: boolean })`; after a 401/403 the next attempt
   calls `getToken({ refresh: true })`; `grantTokenSource` drops its cache then. Test: scripted server
   rejects `Bearer t1`, grant source (mocked fetch) yields t1 then t2 → calls `[undefined, {refresh:true}]`,
   second handshake carries t2, stream opens.
4. *KeepAlive test.* Mock idle timeout 1.5 s, pause 3.5 s, `keepAliveMs: 200` (control disables KeepAlive
   and the pause `Finalize`); both cases run in parallel.
Optional items done: mock honours `endpointing=false` (no endpoint finals; Finalize/periodic finals only);
new error code `quota` — 402 fatal, 429 retried `rateLimitRetries` (default 5) times then fatal (mock
`reject_status=<code>`; scripted tests); mock prunes expired grant tokens (and an expired-token test).
Not changed: `extraQuery`'s `offsetMs` is still computed at dial time (tests-only skew if eviction happens
between dial and open; documented here).
Checks after the fixes: `@oat/stt` test 47, test:int 14 + 1 skipped, `@oat/mocks` test 68; global
`typecheck`/`lint`/`test`/`test:int` (10/10) and `format:check` green; stt int ×6 (once concurrently

## Review
(reviewer, 2026-11-14) **Verdict: changes**

Checked and fine: listen query params (nova-3, linear16, sample_rate, channels=1, interim_results,
smart_format, endpointing, mip_opt_out, language, keyterm×n); `Results` fields (start/duration/is_final/
speech_final/from_finalize/words); KeepAlive at 3 s; CloseStream + wait for close 1000 (+ finish timeout);
`Authorization: Bearer` for `/v1/auth/grant` tokens (what Deepgram expects; subprotocol also accepted by the
mock and redacted in its log); replay buffer bounded by held audio, `SocketTimeline` anchors across gaps,
watermark de-dup; no `mock_*` in production paths, no credential logging; Dockerfile copies
`*.segments.json` into the build stage (bundle builds). Re-ran `@oat/stt` test (41), test:int (13 + 1 skipped),
`@oat/mocks` test (34): green.

1. **Pause → spurious `stall` + redial; pre-pause interim never finalizes.** `deepgram.ts:389-398` fires the
   stall check whenever audio sent after the last server message went unanswered, even though audio has
   stopped (pause/mute) — Deepgram (and the mock) say nothing without audio. Reproduced: 2.2 s of realtime
   speech, then 3.5 s pause, `stallTimeoutMs: 1000` → `stall` error, `reconnecting`, interims re-emitted.
   With the 30 s default every pause > 30 s shows an error in the UI and redials. Fix: only count a stall
   while audio is still flowing (`t - conn.lastAudioSentAt < keepAliveMs`), and when audio stops for
   `keepAliveMs` send `{"type":"Finalize"}` once (Deepgram flushes → final with `from_finalize`) so the
   utterance before the pause becomes final. Add an int test (realtime pause > stall timeout → no errors,
   final emitted).
2. **Interim→final identity (D-19) breaks on empty/de-duped finals.** Segments have no id; the "next segment
   supersedes the previous interim" rule fails when a final maps to `null` — an empty final after a
   non-empty interim (`deepgram-results.ts:87`, also full de-dup `:61-63`, `:83-84`) leaves a stale interim
   on screen, and at `finish()` contradicts `types.ts:99-100` ("every interim is superseded"). Fix: add a
   stable per-stream segment `id` (interims share the id of the final that closes them; new id after each
   final) and, when a final yields no segment while an interim is open, emit a final with that id and
   `text: ''` (or an explicit retraction) so consumers drop it. Cover in mapping/stream tests + contract.
3. **Auth retry reuses the rejected token.** `deepgram.ts:329-338` retries a 401/403 "with a fresh token",
   but `grantTokenSource` (`deepgram-config.ts:70-72`) returns the cached token until 5 s before expiry, so
   the single retry is pointless and the stream goes fatal. Fix: tell `getToken` to refresh after an auth
   rejection (e.g. `getToken({ refresh: true })`), drop the cache in `grantTokenSource`; unit-test it.
4. **Flaky timing in the KeepAlive int test.** `deepgram.int.test.ts:202-221` uses a 400 ms mock idle
   timeout while KeepAlive goes out from a 250 ms tick (`deepgram.ts:96`) — 150 ms margin; an event-loop
   stall under parallel `turbo test:int` fails the "kept" case. Fix: idle timeout ≈ 1500 ms, pause ≥ 3 s,
   `keepAliveMs: 100` (or derive the tick from `keepAliveMs`).

Optional: mock treats `endpointing=false` as 300 ms (`tools/mocks/src/providers/stt.ts:158-161`; Deepgram
disables it). 402/429 handshakes retry forever (non-fatal errors each) — consider fatal for 402.
`extraQuery`'s `offsetMs` is computed in `#connect` (`deepgram.ts:197`) but replay starts at `#onOpen`; an
eviction in between skews the mock's `mock_offset_ms` (tests only). Mock grant `tokens` map never prunes.
