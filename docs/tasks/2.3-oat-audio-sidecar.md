# 2.3 — `native/oat-audio` Swift sidecar
status: done
milestone: M2 · deps: — · branch: task/2.3-oat-audio-sidecar

## Goal
A small Swift CLI the Electron main process spawns to capture **mic** (AVAudioEngine) and **system audio**
(Core Audio process tap, macOS 14.4+) as two separate streams, emitting framed PCM over stdout. Crash-isolated
from Electron (D-8). Must be testable by agents without macOS permission prompts.

## Context
SPEC §3 (capture), §5 (sidecar), §6 (audio archive uses the same clock), §8 (never silently stop), D-8.
Research note `research/granola/audio-path.md` may appear while you work — reference only, optional.
Mid-task addition (orchestrator, from `research/granola/audio-path.md` §1 — reference app runs mic echo
cancellation against all system output, switchable off for headphones): enable Apple voice processing on the
mic path, on by default, `--no-aec` to disable, without unexpected ducking of other audio.
Toolchain: Xcode + Swift 6.2 on Apple Silicon, macOS 26. Use Swift Testing (`import Testing`); `swift test` works.

## Scope
In:
- SwiftPM package `native/oat-audio`: library target `OatAudioCore` (all testable logic) + executable `oat-audio`.
- CLI (use swift-argument-parser if you like; it's the only allowed dependency):
  - `oat-audio capture [--mic] [--system] [--sample-rate 16000] [--synthetic] [--duration <s>]`
    (default both sources). `--synthetic` generates deterministic test audio (e.g. different sine tones / speech-
    like bursts per source) through the *same* framing path, needs no permissions.
  - `oat-audio permissions` → JSON status for microphone + system-audio capture **without prompting**.
  - `oat-audio version` → JSON `{version, protocol}`.
- **Wire protocol** (document in `native/oat-audio/PROTOCOL.md`, versioned `protocol: 1`): stdout carries
  binary frames: `u8 kind (1=audio, 2=event)`, `u8 source (0=mic, 1=system, 255=none)`, `u64 LE t_us`
  (microseconds since capture start, one shared monotonic clock for both sources), `u32 LE payload_len`,
  payload (audio: PCM s16le mono at `--sample-rate`; event: UTF-8 JSON like `{"type":"started"|"stopped"|
  "paused"|"resumed"|"error"|"device_changed"|"level", ...}`). Frames ~20–100 ms. Logs → stderr only.
  Control on stdin: newline-delimited JSON `{"cmd":"pause"|"resume"|"stop"}`; EOF on stdin = stop.
  Graceful stop flushes and emits `stopped`. Errors (device lost, tap failure) emit `error` events and keep
  the other source running where possible.
- Mic: AVAudioEngine input → AVAudioConverter to target rate mono s16. System: process tap on all processes
  except self (CATapDescription / AudioHardwareCreateProcessTap + aggregate device), converted the same way.
  Handle default-device changes.
- Tests (`swift test`): frame encode/decode round-trip, converter/resampler output length & format, synthetic
  generator determinism, stdin command parsing, clock monotonicity.
- `native/oat-audio/README.md`: build, run, permission notes (needs `NSMicrophoneUsageDescription` /
  audio-capture usage strings when bundled in the Electron app — note for task 9.1).
- Add D-16 (proposed) in `docs/DECISIONS.md`: the wire protocol choice.
Out: TypeScript `SidecarSource` (2.4), Opus encoding (2.8 — done on the TS side), EventKit (7.1),
running real capture (human checkpoint — **do not run `capture` without `--synthetic`**, it would trigger
macOS permission prompts nobody can answer).

## Design notes
(implementer, 2026-11-14)

**Package.** SwiftPM, tools 6.0 / Swift 6 language mode (strict concurrency), platform floor macOS 14.4.
No dependencies — swift-argument-parser was allowed but a 100-line hand parser (`CLI.swift`, unit-tested)
avoids a network fetch at build time. All logic lives in `OatAudioCore`; `oat-audio/main.swift` only wires
sources, the stdout sink, signals and stdin.

**Pipeline (revised after review, item 1 — audio callbacks never block).**
`audio callback` → `SampleHandoff` → `SourcePipeline` queue → `CaptureSession` → `QueuedFrameSink` → writer thread → stdout.
- Callback (HAL IO block / AVAudioEngine tap): pick the buffer, down-mix to mono float (`MonoMix`) straight into
  a preallocated SPSC ring of 64 × 8192-frame slots (`SampleHandoff`; `OSAllocatedUnfairLock` only around the
  slot indices, no allocation, no conversion, no I/O), then `DispatchSourceUserDataAdd.add` to wake the queue.
  Ring full → audio dropped and counted exactly; the drop is attached to the next committed slot (or returned as
  trailing), so the pipeline reports it in stream order: audio before the gap (incl. converter tail) first, then
  `overrun` (`stage: "capture"`, `dropped_samples` = frames × target rate / device rate, exact), and the session
  closes that source's frame segment so audio after even a short gap keeps its real `t_us` (re-review g).
  Mic and tap use distinct one-off codes for skipped buffers: `mic_buffer_invalid` / `tap_buffer_invalid` (i).
- `SourcePipeline` (one serial queue per source): drain → `AVAudioConverter` → session (`didCapture`). The session
  lock now only covers in-memory work (assembler, meters, enqueue).
- `QueuedFrameSink`: `write` only enqueues into `BoundedFrameQueue` (≈ 5 s of audio for all sources, min 64 KiB);
  a dedicated writer thread does `write(2)`. Overflow drops the **oldest audio** (events are kept) and inserts an
  `overrun` event (`stage: "output"`, `dropped_samples`, `dropped_ms`, `t_us` of the first dropped frame) at that
  spot; adjacent markers merge. Delivered + dropped = captured, per source. EPIPE → `output_closed` stop.
  `stop` waits ≤ 3 s (`finishTimeout`) for the writer to get `stopped` out, so a dead reader can't hang exit.
- EAGAIN (non-blocking stdout) → `poll(POLLOUT)` on the writer thread, no spinning (`writeAll`).
`--synthetic` replaces only the source; session, assembler, events, writer and stdout are the same code as real
capture. Documented in PROTOCOL.md → *Backpressure*.

**Clock & timestamps.** `HostCaptureClock` = `mach_absolute_time`, origin at capture start. That is the Core
Audio host-time base, so mic (`AVAudioTime.hostTime`) and tap (`AudioTimeStamp.mHostTime`) buffers land on one
timeline without cross-clock conversion. `FrameAssembler` stamps frames from the sample count since an anchor
(no jitter, exactly frame-duration apart); it re-anchors (flushing the partial frame) when arrival time deviates
>100 ms from expectation (device switch, dropped buffers, long-term drift) and on pause/resume. Per-source
`t_us` is clamped strictly increasing.

**Frames/events.** 50 ms frames (configurable 20–100). Protocol per task brief, documented in `PROTOCOL.md`,
D-16 proposed. Extra pieces beyond the brief: `started` carries `protocol, version, sample_rate, frame_ms,
sources, synthetic, aec`; `stopped` carries `reason` + per-source sample counts; `level` events every 250 ms
(rms/peak dBFS) for meters; `invalid_command` error for bad stdin lines.

**stdin.** EOF = stop only when fd 0 is a pipe/socket (Electron) or a TTY. `/dev/null` (what agent/CI shells
give) is ignored, otherwise `capture --synthetic --duration 2` would stop instantly in automation. Regular-file
stdin is read for commands without EOF-stop. SIGINT/SIGTERM → graceful stop; SIGPIPE ignored.

**Errors (SPEC §8).** A source that fails to start emits `error` (`fatal: true` for that source) with its
specific code (`CodedError.code`: `tap_create_failed`, `mic_start_failed`, …; `start_failed` only as fallback) and
the others keep going; runtime failures (device lost / rebuild failed) the same. Only when no source is left does the
session stop with `reason: "error"`, exit 1.

**Converter.** `PCMConverter` wraps `AVAudioConverter` (downmix on, high-quality SRC) from whatever the device
delivers to mono Int16 at `--sample-rate`; rebuilt on input-format change; `flush()` drains SRC latency on stop
/ device switch so the tail is not lost. The tail is stamped as a continuation of the previous chunk
(`prev t + prev samples`), not `now`, so it doesn't trigger a spurious re-anchor. On an input-rate change the old
converter is drained before the new one is built — both in `PCMConverter.convert` and in the pipeline when the
chunk rate changes (re-review h). Within a segment the pipeline never stamps a chunk before the end of the previous
one when the overlap is ≤ 20 ms (converter latency); larger deviations pass through so real drift still re-anchors. Tested 48k stereo, 44.1k mono, 16k, 96k stereo → 16000 ±16 samples/s.

**System audio — Core Audio process tap** (`SystemAudioSource`):
1. Translate our PID (and any `--exclude-pid`) to process objects via
   `kAudioHardwarePropertyTranslatePIDToProcessObject`.
2. `CATapDescription(monoGlobalTapButExcludeProcesses:)` — mono mix of all other processes' output; `isPrivate`,
   `muteBehavior = .unmuted` (user still hears the call), fresh UUID = tap UID.
3. `AudioHardwareCreateProcessTap` → tap object.
4. `AudioHardwareCreateAggregateDevice` with: private, not stacked, main sub-device + sub-device list = the
   current default output device UID (clock source), tap list = `[{uid: tapUID, drift: true}]`,
   `tapautostart: true`.
5. **Before every `AudioDeviceStart`** (first start and each device switch — review item 3): re-read
   `kAudioTapPropertyFormat` (must be float32, mono or interleaved), the aggregate's
   `kAudioDevicePropertyNominalSampleRate` (rate of the drift-compensated tap stream; falls back to the tap
   format rate) and the output device's input-scope `kAudioDevicePropertyStreams` count. Stored as an immutable
   `Layout` (unfair lock) read by the IO block.
6. `AudioDeviceCreateIOProcIDWithBlock` on the aggregate (own serial IO queue), then `AudioDeviceStart`. The IO
   block selects the tap's buffer with `TapBufferSelection.index` (review item 2): the aggregate's input list is
   the sub-device's input streams first, then the tap, so the tap is at index `subDeviceInputStreams` (e.g. 1 when
   the output is a USB headset with a mic). It requires exactly `mNumberBuffers == index + 1` (one tap after the
   device's own inputs, re-review f — fails closed on unexpected layouts) and the buffer's channel count to
   equal the tap format's; otherwise the buffer is skipped (never guessed — picking buffer 0 would put the user's
   headset mic into "them") and a one-off non-fatal `tap_buffer_invalid` error is emitted. Time = `mHostTime`.
7. **Same-device rate/format changes** (re-review item 1 — Bluetooth headset dropping 48 → 16/24 kHz when its
   mic opens, without a default-device change): listeners on the aggregate's `kAudioDevicePropertyNominalSampleRate`
   and `kAudioDevicePropertyStreamConfiguration`, the output device's nominal rate and the tap's
   `kAudioTapPropertyFormat` (installed after `AudioDeviceStart`, removed in `stopAggregate`; unsupported ones are
   skipped). Notifications are debounced 100 ms, then the pure `FormatChange.evaluate(current:observed:)` decides
   (ignore unchanged / unreadable / transient rate 0; reconfigure on rate, channel or tap-index change). Reconfigure =
   `AudioDeviceStop` → layout invalid → `pipeline.flush()` (old-rate audio + converter tail out) → apply new layout →
   `AudioDeviceStart` → `format_changed` event (`device_sample_rate`, `previous_device_sample_rate`, `channels`).
   Restart failure → fatal error for system only. The mic gets `format_changed` too when an engine restart lands on
   the same device at a different rate.
8. Listener on `kAudioHardwarePropertyDefaultOutputDevice` → tear down aggregate + IO proc (tap kept; it is
   device-independent), flush converter, rebuild on the new device, emit `device_changed`; failure → fatal
   `error` for system only. Teardown order: `AudioDeviceStop` → `DestroyIOProcID` → `DestroyAggregateDevice`
   → `AudioHardwareDestroyProcessTap`. Setup/teardown run on a control queue, separate from the IO queue, so
   `AudioDeviceStop` never waits on its own queue.
   Note: a denied permission yields a silent tap, not an error (documented in README for the app).

**Mic** (`MicSource`): fresh `AVAudioEngine` per (re)start, tap on `inputNode` bus 0 (~100 ms buffers), time =
`AVAudioTime.hostTime`. `AVAudioEngineConfigurationChange` and `kAudioHardwarePropertyDefaultInputDevice`
changes → debounced engine rebuild bound to the new default input, rate-limited to one per second; `device_changed`
only when the default input device actually changed (review item e).

**Echo cancellation (mid-task addition).** `inputNode.setVoiceProcessingEnabled(true)` before start (VPIO;
on macOS its echo reference is the output device's playback, so the far side on speakers is removed from "me").
Ducking: `voiceProcessingOtherAudioDuckingConfiguration = {enableAdvancedDucking: false, duckingLevel: .min}`
(macOS 14+; the API has no "off", min is the least). `mainMixerNode.outputVolume = 0` so the output side of the
VPIO graph is configured but plays nothing. VPIO can expose a multi-channel input format; only channel 0
(processed signal) is taken (`MonoMix.planar(firstChannelOnly:)`, tested). Whether VP is active is captured by
value in each engine's tap closure, so the tap thread never reads mutable source state (review item d). If enabling fails →
non-fatal `aec_unavailable` event and capture continues raw. `--no-aec` (headphones) skips VPIO; `started.aec`
reports the requested state. AGC stays at VPIO's default (on) — fine for STT.
To confirm at the human checkpoint (can't be tested without hardware/permissions): echo removed on speakers;
call audio (heard + in the system stream) not noticeably ducked; channel 0 is the processed channel on the
built-in mic array; **no VPIO restart loop** — with AEC on, watch stderr for repeated "mic restarting: engine
configuration changed" lines (VPIO reconfiguring itself can post `AVAudioEngineConfigurationChange`); restarts are
rate-limited to 1/s and `device_changed` only fires on a real device change, but the loop itself can only be
ruled out on hardware (review item e). **Bluetooth headset (AirPods)**: AirPods as output with a call playing, then
open the mic (or use AirPods as input too) → the same device drops to 16/24 kHz: expect one `format_changed` per
affected source, no `error`, "them" with correct pitch/duration (`stopped.samples` vs wall-clock) and in sync with
"me" (re-review item 1). Also check the system stream after switching between outputs at different
rates (e.g. 48 kHz speakers ↔ 16/24 kHz Bluetooth headset): correct pitch/length, no repeated re-anchoring.

**Permissions** (`oat-audio permissions`): mic via `AVCaptureDevice.authorizationStatus(for: .audio)`; system
audio via TCC `TCCAccessPreflight("kTCCServiceAudioCapture")` resolved with `dlsym` (private, read-only, never
prompts; falls back to `"unknown"` if absent). Output includes `system_audio_method` so callers know which.

**Tests** (52, Swift Testing): frame header layout, round-trip, arbitrary chunking, garbage rejection; event
JSON; converter length/format/RMS across rates, mid-stream format change; generator
determinism (instances, chunking), source difference, bursts; control parsing + line splitter + stdin-mode
detection; CLI parsing incl. `--no-aec`; clock monotonic across threads + host-time mapping; assembler
timestamps / re-anchor / backwards input / reset, level meter; session end-to-end with synthetic sources
(exact sample counts and content, stop command, pause/resume gap, one source failing with its specific code,
all failing → exit 1). Added in review round 1: `BoundedFrameQueue` drop-oldest/keep-events/merge/accounting;
**slow reader** — `QueuedFrameSink` on a pipe nobody reads (400 writes return in < 0.5 s, overrun events, delivered
+ dropped = written, newest audio survives); `writeAll` on a non-blocking fd (EAGAIN path, 512 KB through a pipe);
session end-to-end with a reader stalled for 3.3 s on a 3 s capture (all 48000 samples/source generated on time,
delivered + dropped = 48000, `stopped` last); `SampleHandoff` order/splitting/overflow/invalid counters;
`MonoMix`; `TapBufferSelection` (speakers, USB headset, missing tap, channel mismatch); `SourcePipeline`
conversion off-thread + continuation-stamped tail + capture-stage overrun / one-off `tap_buffer_invalid`.
Added in re-review: `FormatChange.evaluate` (unchanged, float jitter, unreadable, transient 0 Hz, not configured →
none; rate / channels / tap index → changed); exactly-one-tap rule; pipeline rate switch 48 → 16 kHz without flush
(no samples lost, monotonic); converter format switch without explicit flush; exact capture-stage drop count +
ordering (audio before the drop) + `mic_buffer_invalid`; session: a 10 ms drop closes the segment and the next
frame keeps its real time (`a800@0, a200@50000, overrun, a800@72500, format_changed, stopped`).

**Not done / follow-ups.** Real capture not run (human checkpoint). Tap is global minus excluded PIDs (no
per-app filter). `--exclude-pid` lets 2.4 exclude the Electron app's own playback.

## Review
**Reviewer (2026-11-14) — verdict: `changes`.** Read task file + `git diff main...` only. Re-ran `swift build -c
release`, `swift test` (34 pass), `permissions`, and both synthetic `check-frames` commands — all OK. Teardown order
(Stop → DestroyIOProcID → DestroyAggregate → DestroyProcessTap), control/IO queue split, listener removal, session
stop/lock discipline (no deadlock paths found), stdin modes, TCC preflight (read-only via dlsym, `unknown` if
missing) and PROTOCOL.md framing are sound. Must fix:

1. **Backpressure blocks audio threads.** `CaptureSession.source(_:didCapture:)` (CaptureSession.swift:171-185)
   runs on the HAL IO queue (SystemAudioSource.swift:128-130) and the AVAudioEngine tap thread, takes the session
   lock and does a blocking `write(2)` to stdout (FrameWriter.swift:19-40, CaptureSession.swift:220-224). When the
   reader (Electron main) lags ~1 s (pipe buffer ≈ 64 KB at 64 KB/s), the HAL IO callback stalls (overloads /
   dropped tap data), the mic tap stalls, and pause/stop commands queue behind the lock. Conversion + Swift array/
   Data allocation also happen on the HAL IO block. Fix: in the IO/tap callbacks only copy the samples (or the raw
   buffer) and hand off to a non-real-time serial queue for convert → assemble; write frames from a dedicated
   writer thread with a bounded queue (e.g. ~5 s); on overflow drop audio and emit a non-fatal `error`
   (`code: "overrun"`, dropped sample count) so the gap is visible (SPEC §8) and the timeline re-anchors. Document
   the backpressure behaviour in PROTOCOL.md.
2. **Wrong buffer can be read as "them".** `process` (SystemAudioSource.swift:163-169) treats the aggregate's
   input `AudioBufferList` as if it held only the tap (`mBuffers` = first buffer, list wrapped with the mono tap
   format). The aggregate's input = sub-device input streams first, then taps. When the default output device
   also has input streams (common for USB headsets), buffer 0 is the headset mic → the user's voice ends up in the
   system stream. Fix: locate the tap's buffer (it is the last one; or count the aggregate's input streams via
   `kAudioDevicePropertyStreams` input scope at setup), check `mNumberBuffers`, and wrap a single-buffer
   `AudioBufferList` for that buffer only.
3. **Tap format never re-read after a device switch.** `tapFormat` is read once in `createTap`
   (SystemAudioSource.swift:89-93) but `defaultOutputChanged` rebuilds the aggregate on a device that may run at
   another rate (e.g. 48 kHz speakers → 24/16 kHz Bluetooth headset). Buffers would then be interpreted at the old
   rate (wrong pitch/length, constant re-anchoring, desync with mic). Fix: in `startAggregate`, after creating the
   aggregate and before `AudioDeviceStart`, read the actual input stream format (re-read `kAudioTapPropertyFormat`
   and/or the aggregate's input `kAudioStreamPropertyVirtualFormat` for the tap stream) and update `tapFormat`
   under `ioLock`; the converter already rebuilds on format change.

Optional (nits):
- a. Start failures always emit `code: "start_failed"` (CaptureSession.swift:86), dropping `CoreAudioError.code`
  (`tap_create_failed`, `mic_start_failed`, …) that PROTOCOL.md lists as emitted; pass the specific code through.
- b. `EAGAIN` on a non-blocking stdout busy-spins (FrameWriter.swift:30); `poll(POLLOUT)` before retrying.
- c. Converter tail on stop/device switch is stamped `clock.nowUs()` (MicSource.swift:120, SystemAudioSource.swift:158)
  rather than contiguous with the previous chunk; can cause a spurious re-anchor. Stamp it as "continuation".
- d. `voiceProcessingActive` is written on the control queue (MicSource.swift:66,76) and read on the tap thread
  (:129) without `ioLock`; set it under `ioLock`.
- e. Human checkpoint: watch for repeated `AVAudioEngineConfigurationChange` with VPIO causing a restart loop
  (MicSource.swift:92-96, 140-148); consider rate-limiting restarts and emitting `device_changed` only when the
  device actually changed.

**Review round 1 resolution** (implementer): 1 ✔ handoff + processing queue + bounded writer thread + `overrun`
event, PROTOCOL.md *Backpressure*. 2 ✔ `TapBufferSelection` (pure, tested), `mNumberBuffers` + channel validation.
3 ✔ tap format / aggregate rate / sub-device stream count re-read in `startAggregate` before `AudioDeviceStart`.
a ✔ specific codes via `CodedError`. b ✔ `poll(POLLOUT)` on EAGAIN, on the writer thread. c ✔ continuation
timestamps for converter tails. d ✔ VP flag captured immutably per engine. e — noted as human-checkpoint item

**Re-review (reviewer, 2026-11-14) — verdict: `changes` (one item).** Scope: `git diff ca2ee62..` against findings
1–3 and a–e. Re-ran release build, `swift test` (46 pass), both synthetic `check-frames` commands, and an 8 s stalled-reader
run (`| (sleep 8; cat)`): 6.9 s delivered + 2.1 s `overrun` (`stage: "output"`) per source = 9 s, `stopped` delivered,
rc 0. Verified: the IOProc and mic tap blocks only take an unfair lock for a few integer updates, copy into preallocated
`SampleHandoff` slots and call `DispatchSource.add` (no allocation, conversion, I/O or waiting). The SPSC slot protocol
is correct (slot written outside the lock, committed by `count += 1`; the consumer reads only the committed range
before freeing it). `BoundedFrameQueue` drops oldest audio, keeps events and merges markers per source; byte
accounting is right. `writeAll` uses `poll` instead of spinning. Teardown order (stop IO → flush pipeline → destroy
aggregate/tap) is right, and `finish` is bounded. No new deadlocks found (session lock is never held across `s.stop()`
or a blocking write). 1, 2, a–e resolved.

1. **Finding 3 is only half fixed: a sample-rate change on the same output device leaves `layout.sampleRate` stale.**
   `configureLayout` (SystemAudioSource.swift:159-175) runs only from `startAggregate`, i.e. at start and on a
   default-*device* change. A Bluetooth headset (e.g. AirPods) stays the same output device but drops 48 → 24/16 kHz
   when its mic is opened, which our own mic engine can trigger right after the system source starts. The aggregate
   then delivers at the new rate while `ioBlock` (:209) still labels buffers 48 kHz: wrong pitch and length, and the
   system timeline drifts from mic for the whole meeting. Fix: in `startAggregate`, also listen for
   `kAudioDevicePropertyNominalSampleRate` on the aggregate (and/or `kAudioTapPropertyFormat` on the tap). Remove that
   listener in `stopAggregate`. On change, either re-run `configureLayout` (after `pipeline.flush()`) or take the
   existing `defaultOutputChanged` rebuild path. Add this to the human-checkpoint list (Bluetooth headset).

Optional (nits):
- f. `TapBufferSelection.index` (SampleHandoff.swift:160-167) accepts `numberBuffers > idx`. Requiring
  `numberBuffers == subDeviceInputStreams + 1` (exactly one tap) would fail closed on unexpected layouts. As it stands, a
  mono sub-device stream in an unexpected order would pass the channel-count check.
- g. A capture-stage overrun under 100 ms leaves no timeline gap: the session does not re-anchor the assembler, so
  later frames are stamped early by the dropped amount. Reset that source's `FrameAssembler` in
  `source(_:didOverrunDroppingMs:)`. Also, `dropped_samples` is rebuilt from truncated ms (CaptureSession.swift:217),
  so PROTOCOL.md's "delivered + dropped = captured" is only approximate for `capture`. Pass
  `droppedFrames × targetRate / droppedRate` instead.
- h. `PCMConverter.converterFor` swaps converters on a rate change without draining the old one (a few ms lost). Flush
  first.
- i. The `tap_buffer_invalid` message is also used for mic buffers that are not float (MicSource.swift:128-130).
  Use a mic-specific message.
