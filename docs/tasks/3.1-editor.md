# 3.1 — `packages/editor`: TipTap block editor
status: done
milestone: M3 · deps: 1.3 · branch: task/3.1-editor

## Goal
A Notion-like block editor component reused by web and desktop, with TipTap/ProseMirror JSON as the canonical
format (D-4).

## Context
SPEC §4 Editor row, §7 (my text vs AI text marking), D-4. Tokens from `@oat/ui` (`--my-text`, `--ai-text`).
Research: Granola also uses TipTap/ProseMirror (bundle-map.md) — no code reuse, behaviour only.

## Scope
In:
- `packages/editor` (`@oat/editor`): `<OatEditor value onChange editable placeholder />` React component
  (TipTap v3 latest), schema/extension set exported separately (`createExtensions(options)`) so server code can
  use the same schema headlessly (`@tiptap/core` / `@tiptap/html` / generateJSON in Node).
- Blocks: paragraph, headings 1–3, bullet/ordered lists, task list (checklist), blockquote, code block,
  horizontal rule, callout (custom node with emoji/variant), link (autolink + paste), mention (`@person`,
  suggestion list fed by a prop callback), hard break. Marks: bold, italic, strike, code, highlight, link.
- Every block node carries a stable `id` attribute (unique-id extension) — needed for citations (6.x) and
  enhancement diffing. Custom attribute `origin: 'me' | 'ai'` on block nodes, rendered with `--my-text` /
  `--ai-text` styles (AI blocks visually distinct, per SPEC §3.5).
- Slash menu (`/` → filterable list of blocks, keyboard nav), Markdown input rules/shortcuts (`# `, `- `, `[] `,
  `> `, ``` ``` ```, `---`), bubble menu for marks + link editing. Placeholder text per empty block.
- Styles via `@oat/ui` tokens only (prose styles in `packages/editor/src/styles.css`).
- Tests: schema tests in Node (create doc JSON, validate, ids assigned), component tests (jsdom) for slash
  menu filtering and input rules where feasible. A gallery/playground route: add an "Editor" page to the
  `@oat/ui` gallery or a small Vite playground in this package; Playwright screenshot to
  `docs/tasks/evidence/3.1/`.
Out: Markdown conversion (3.2), persistence/sync (3.3/3.5), collaboration (non-goal).

- [x] Every block has a unique `id`; `origin` attribute round-trips through JSON.

## Design notes
(implementer + designer, 2026-11-14)

**TipTap version.** `pnpm view @tiptap/core version` → **3.34.0**; every `@tiptap/*` package pinned `^3.34.0`
in the pnpm catalog (plus `@floating-ui/dom` ^1.8.0 for menus, `happy-dom` ^21.0.4 dev-only for
`@tiptap/html/server` in Node tests).

**Package layout (`@oat/editor`, TS-source per D-15).**
```
src/index.ts          headless, Node-safe: createExtensions(), getEditorSchema(), validateDoc(),
                      ensureBlockIds(), collectBlockIds(), emptyDoc(), BLOCK_TYPES/ORIGINS,
                      Callout, OriginAttribute, SlashCommand, SLASH_ITEMS/filterSlashItems
src/react/index.ts    `@oat/editor/react`: <OatEditor>, BubbleToolbar, SlashMenu, MentionMenu, MenuList,
                      createSuggestionPopup
src/styles.css        `@oat/editor/styles.css` — prose styles, tokens only; has `@source './'` so the
                      consumer's Tailwind also scans the menu components
playground/           Vite playground on :5201 (?doc=empty|sample · ?theme=light|dark · ?readonly=1)
e2e/                  Playwright: editor.spec.ts (behaviour), screenshots.spec.ts (evidence, opt-in)
```
API: `<OatEditor value onChange editable placeholder onMentionQuery slashItems autoFocus onReady className
aria-label />`. Value is TipTap JSON; TipTap owns state, external `value` changes are applied with
`setContent(…, { emitUpdate: false })` only when they differ from what the editor last emitted (no echo).
`immediatelyRender: false` so it is SSR-safe under Next App Router.

**Schema decisions.**
- Blocks: StarterKit (paragraph, headings 1–3, bullet/ordered list, blockquote, code block, hr, hard break,
  bold/italic/strike/code/link) + TaskList/TaskItem (nested) + Highlight + Mention + custom `callout`.
  **Underline disabled** (not in scope, no Markdown equivalent for 3.2). StarterKit's TrailingNode stays on,
  so the editor keeps an empty paragraph after a trailing non-paragraph block.
- `callout`: `content: 'block+'`, attrs `emoji` (default 💡) and `variant`
  (`neutral|info|success|warning|danger`, default neutral). HTML `div[data-type=callout]` with a
  non-editable emoji span and a `[data-callout-content]` content hole; commands `setCallout`,
  `toggleCallout`, `unsetCallout`, `updateCallout`. No emoji/variant picker UI yet (follow-up).
- `id`: TipTap's MIT `UniqueID` extension on every block type in `BLOCK_TYPES` (incl. list containers and
  items), `generateBlockId()` (UUID v4: `crypto.randomUUID`, falling back to `getRandomValues` in
  non-secure contexts); split/paste/drop get fresh ids. Initial and external `value`s go through
  `ensureBlockIds()` (pure JSON, fills missing + replaces duplicates; also usable server-side, as is TipTap's
  `generateUniqueIds()`). `onChange` fires once after mount only if ids were repaired; opening a doc
  otherwise emits nothing (plugin-only updates such as TrailingNode's paragraph are not reported). A `value`
  equal to what the editor last emitted is ignored, so a parent re-reading its own save can't clobber
  newer typing.
- `validateDoc()` is the server gate: schema check + link hrefs must pass TipTap's `isAllowedUri`, `origin`
  ∈ `me|ai`, callout `variant` ∈ `CALLOUT_VARIANTS`, `emoji` = one grapheme ≤ 16 UTF-16 units
  (`normalizeCalloutEmoji`, also applied when parsing/rendering HTML).
- `origin: 'me' | 'ai'` (D-20) as a global attribute on the same block types, default `me`, rendered as
  `data-origin`, unknown values parse to `me`. Editing rules so my typing never looks AI-written:
  `keepOnSplit: false` (Enter after an AI line starts a `me` block) and an appendTransaction plugin turns
  an `ai` block whose text is emptied into `me` (skippable with the `oat:keepOrigin` meta); the same plugin
  marks a textblock `me` when a replace step merged two textblocks of different origin (Backspace/Delete at
  the boundary, deleting or typing over a cross-block selection). These origin changes join the same undo
  step as the edit. Editing words inside an AI block keeps it `ai` (D-23). Converters (4.4) should set
  origin on every block incl. inner paragraphs; CSS is "innermost block wins".

**Interaction design.**
- Slash menu: `/` at start of a word (not in code blocks), no spaces in the query (a space closes it, like
  Markdown typing). Ranking: title prefix → title word prefix → alias prefix → substring. Items show icon
  tile, title, one-line description and the equivalent Markdown shortcut. Keys: ↑/↓ (and Ctrl-N/P) wrap,
  Enter/Tab select, Esc closes and keeps the typed text. Empty state "No matching blocks".
- Menu a11y (combobox pattern): focus stays in the editor; while a menu is open the editor element gets
  `aria-expanded="true"`, `aria-autocomplete="list"`, `aria-controls=<listbox id>` and
  `aria-activedescendant=<active option id>` (removed on close); options have ids, `role=option`,
  `aria-selected`.
- Mentions: `@` → `onMentionQuery(query)` (sync or async; latest prop is used without recreating the editor),
  list shows initials avatar (`--me` tokens) + name + description; "Loading…"/"No people found" states.
  Stored as `{ type: 'mention', attrs: { id, label } }`, rendered `@Label` chip.
- Bubble menu over non-empty text selections (hidden in code blocks / node selections / read-only):
  bold, italic, strike, inline code, highlight | link, unlink. Link field opens from the button or ⌘K/Ctrl+K;
  Enter applies, Esc cancels, empty value removes; `normalizeHref` adds `https://` / `mailto:`. Link mark:
  autolink + linkOnPaste, `openOnClick: false` while editing, `rel=noopener noreferrer nofollow`.
- Markdown shortcuts (TipTap input rules): `# `/`## `/`### `, `- `, `1. `, `[] `, `> `, ```` ``` ````+space,
  `---`, `**b**`, `*i*`, `~~s~~`, `` `c` ``, `==h==`; Shift+Enter = hard break; ``` triple Enter ``` exits code.
- Placeholders: empty doc shows the `placeholder` prop (default "Write, or type '/' for commands…"); the
  current empty block shows "Type '/' for commands" / "Heading N" / "Code". Hidden when read-only.

**Visual design (tokens only).** Body `--type-base` sans in `--my-text`; AI blocks `--ai-text` (slate ink,
visibly softer — see screenshots); headings in the serif heading font at 2xl/xl/lg; block rhythm 8px, 12px
around boxed blocks, 24px above section headings. Code/inline code on `--muted` + `--border`, mono font.
Highlight = `--warning` at 32% (oklch mix); callout tint = variant token (`--muted-foreground`, `--primary`,
`--success`, `--warning`, `--destructive`) mixed into `--background` **in oklab** (oklch hue interpolation
turned the blue info tint green). Mentions reuse `--me`/`--me-foreground`. Menus reuse shadcn popover
surface classes (`bg-popover border shadow-md rounded-lg`, `aria-selected:bg-accent`).
@oat/ui components used: `Button` (ghost, icon-sm), `Input`, `Separator`, `cn`; playground also `Badge`,
`Switch`.

**Notes for @oat/ui (not changed here).**
1. Consider dedicated tokens `--highlight` and `--callout-*` instead of mixes of status colours.
2. Apps must `@import '@oat/editor/styles.css'` after `@oat/ui/styles.css` and add `@oat/editor` to Next
   `transpilePackages` (D-15). The ui components' self-imports (`@oat/ui/lib/utils`) resolved fine from the
   editor's Vite and tsc without the alias the ui gallery uses.
3. A `Kbd` component would be nice for the shortcut hints in menus (currently a styled `<kbd>`).

**Clean room.** No Granola code, strings or assets; research only informed the `origin` choice
(enhance-chat.md recommends a JSON attribute over Granola's line-text matching). Sample content is ours.

**Follow-ups (not in scope).** Callout emoji/variant picker; drag handles / block menu; input rule for
callouts; Markdown (3.2) — TipTap 3 extensions expose `parseMarkdown`/`renderMarkdown` hooks the callout
will need.

## Review
**Round 1 — 2026-11-14 — verdict: `changes`** (reviewer read task file + `git diff main...task/3.1-editor`,
3 screenshots, and probed behaviour with a throwaway jsdom test, not committed).

Checked and fine: schema names/attrs (StarterKit names, `callout{emoji,variant}`, `id`/`origin` on
`BLOCK_TYPES`) look stable; split mid-AI-block keeps `ai` on both halves, Enter at end gives `me`, undo after
"emptied → me" restores `ai`; paste with an existing `data-id` gets a fresh id; `setContent` dedupes ids;
pasted `javascript:` links, `<img onerror>`, `onclick` are dropped; `setLink({href:'javascript:…'})` and
JSON `javascript:` hrefs render `href=""`; mention/callout attrs are escaped in HTML; Escape and stale async
mention results handled by `@tiptap/suggestion`; no echo loop in `value`/`onChange`; `immediatelyRender:false`
+ `'use client'`; headless schema test runs in Node; styles are token-only. Clean room OK.

Findings (fix these):
1. **Join turns my text into AI text** — `src/origin.ts:54-77`. Backspace at the start of a non-empty `me`
   paragraph that follows an `ai` paragraph merges my words into the `ai` block (probe:
   `[ai:"AI text", me:"my text"]` + `joinBackward` → `[ai:"AI textmy text"]`), contradicting the module's own
   rule "what I type never looks AI-written". Fix: in the appendTransaction, when a step joins two textblocks
   whose old origins differ (compare `oldState.doc.resolve(step.from).parent` / `resolve(step.to).parent` for
   Replace steps spanning a block boundary), set the merged block to `me`; add tests for joinBackward,
   joinForward and a selection delete across an ai/me boundary. Orchestrator: add a one-line D-23 addendum
   ("mixed-origin join → `me`").
2. **Duplicate ids in initial content survive** — `src/react/oat-editor.tsx:96`. UniqueID's `onCreate` only
   fills `null` ids, so a `value` with two blocks `id:"x"` stays `["x","x"]` (the `setContent` path does
   dedupe). Fix: `content: value && ensureBlockIds(value)` at creation (and emit `onChange` once if that
   changed anything, like the missing-id case); test it.
3. **`validateDoc` accepts unsafe/invalid attrs** — `src/schema.ts:23-33`. `javascript:alert(1)` link hrefs
   validate `ok:true` (TipTap blanks them on render, but this is the server's gate for stored docs, and 3.2
   Markdown / share view / Notion export render outside TipTap); `origin:"banana"` also passes. Fix: walk
   marks/attrs and reject (or strip) link hrefs failing `isAllowedUri` from `@tiptap/extension-link`, and
   non-`ORIGINS` origins / non-`CALLOUT_VARIANTS` variants; tests for each.
4. **Slash/mention menus invisible to screen readers** — `src/react/suggestion-popup.tsx:39-57,124-150`. Focus
   stays in the `role=textbox` editor but nothing links it to the listbox (no `aria-expanded`,
   `aria-controls`, `aria-activedescendant`; options have no ids), so the active option is never announced.
   Fix: give the listbox/options ids and set `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`,
   `aria-activedescendant` on `editor.view.dom` in onStart/onUpdate/active change, remove in onExit; assert
   in the jsdom test.

Optional (nits, no re-review needed):
- `oat-editor.tsx:128-132`: a `value` with a new identity but *older* content (debounced save → re-read in
  3.3) replaces newer typing; also skip when it deep-equals `lastEmitted`, and document the contract.
- Link mark persists `target`/`rel` defaults into every stored link's attrs; consider render-only attrs.
- Callout `emoji` accepts any string from pasted HTML; clamp to one short grapheme.
- `crypto.randomUUID` needs a secure context — Electron's custom protocol must be registered `secure`.
- `@tiptap/html` is dev-only although the docs point server code at it; make it a dependency or say so.
- TrailingNode appends a paragraph to docs ending in a list/callout, so opening such a doc (even read-only)
  emits `onChange`; consider not emitting when `!editable`.

**Round 1 resolution (implementer, 2026-11-14)** — merged current `main` first (lockfile regenerated).
1. Fixed in `src/origin.ts`: replace steps that merge two textblocks of different origin mark the result
   `me`; origin fixes are now part of the undo step. Tests: Backspace, Delete, `joinBackward`/`joinForward`
   both orders, selection delete, typing over a cross-block selection, list-item join, ai+ai stays `ai`,
   undo restores `ai`/`me` (`react/oat-editor.test.tsx`).
2. Fixed: initial (and external) `value` → `ensureBlockIds`; one `onChange` when ids were repaired. Test with
   duplicate `id:"x"` blocks (ids unique, first `x` kept, one onChange, caller's object untouched).
3. Fixed: `validateDoc` rejects hrefs failing `isAllowedUri` (javascript:, data:, empty), unknown `origin`,
   unknown callout `variant`, multi-grapheme/over-long `emoji`; accepts http(s)/mailto/tel/relative/#.
   Tests in `schema.test.ts`. Added direct dep `@tiptap/extension-link`.
4. Fixed: combobox attributes on the editor element + option ids; asserted in jsdom (slash + mention) and
   in Playwright.
Optional items done: stale `value` equal to last emit is ignored (contract documented on the prop); callout
emoji clamped to one grapheme on parse/render; `generateBlockId` with a non-secure-context fallback (test);
no `onChange` on open for plugin-only updates (test). Not done: link `target`/`rel` stay as TipTap's default
stored attrs; `@tiptap/html` stays dev-only (doc comment says server code adds it + happy-dom).
