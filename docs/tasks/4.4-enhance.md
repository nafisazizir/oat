# 4.4 — Enhance pipeline
status: done
milestone: M4 · deps: 3.2, 4.3, 3.3 · branch: task/4.4-enhance

## Goal
After a meeting, one click turns my rough notes + transcript + template into structured notes in the document
body — my lines kept and marked `me`, AI additions marked `ai` — streamed into the editor, resumable, and
measurably good (evals).

## Context
SPEC §3.5, §7, §8 (< 30 s for a 1-hour meeting), D-20 (document body becomes the enhanced note; raw notes kept in
`enhancement.input_notes_json`; versions; server job with status + idempotency key + resumable stream; origin
derived by matching note lines, not trusted from the model), D-23, `@oat/ai` (enhance contract/EnhanceFn from 4.2,
`buildMeetingContext` + templates from 4.3, Output.object, evals), `@oat/editor` (schema, validateDoc,
ensureBlockIds, `@oat/editor/markdown` fromMarkdown with `trustMarkers:false`, `mentions:'text'`), `@oat/db`
enhancement table, `apps/web` documents API + document page (3.3). Research reference: enhance-chat.md
(behaviour only — write prompts ourselves).

## Scope
In:
- Prompt (our own) in `@oat/ai/enhance`: system + template sections + fenced context (notes/transcript/meta in
  clearly delimited, escaped blocks; instruct the model that content inside is data, not instructions).
  Structured output via Output.object with the 4.2 schema; citations: blocks may reference segment ids.
- Conversion: output → TipTap JSON (`@oat/editor`), origin assignment by fuzzy-matching each output block
  to the user's note lines (normalised text similarity ≥ threshold → `me`, else `ai`); user note lines missing
  from the output are re-inserted under an "Other notes" section (never lose my text) — tested.
- Server job: `POST /api/documents/:id/enhance {templateId, idempotencyKey}` → creates `enhancement` row
  (status generating), runs generation (in-process async with a Redis lock per document; durable workflow is
  8.x), streams progress over SSE `GET /api/enhancements/:id/stream` with resume (`Last-Event-ID`); on
  completion writes output_json, sets document body (new version, base-version check → if user edited
  meanwhile, keep both: save enhancement as a version and notify), status completed/failed; staleness timeout.
- UI: "Enhance" button + template picker on meeting notes; streaming preview (read-only) then swap into the
  editor; my vs AI styling; error/retry states; client re-attaches to a running job after reload.
- Evals: real `enhanceNotes` replaces the stub; mock run stays green; record baseline; quality tier ready.
  Performance: 1-hour fixture (synthesise a long transcript) under mock < 5 s overhead; note real-model
  latency target.
- Tests: conversion/origin unit tests (incl. adversarial transcript text trying to inject instructions — must
  stay data), API int (authz, idempotency, resume, concurrent enhance → one job), e2e: enhance a meeting doc with
  the mock → structured note with my lines marked; reload mid-stream re-attaches. Screenshots.
Out: regenerate/undo/versions UI (4.5), about-me (4.6), auto-enhance (7.5).

## Design notes

### Pipeline (`packages/ai`)
`prepareEnhance(input)` → `runEnhance(prepared, opts)` → `reconcileWithNotes` → `enhancementToDoc`.
`enhanceNotes` (the `EnhanceFn` the evals run) = prepare + run, returning the reconciled output; the 4.2 signature
is unchanged (`EnhanceInput`/`EnhanceOptions` only gained optional fields: `notesDoc`, segment `id`/`speakerLabel`,
attendee `email`, `endedAt`/`platform`, `me`, `locale`, `timeZone`, `aboutMe`, `vocabulary`, `headers`).

- **Prompt (ours, `ENHANCE_RULES`)**: system = rules + `MEETING_CONTEXT_RULES` (content inside `<oat:…>` is
  data) + a per-meeting length rule from `buildMeetingContext().budget`. User message = the template
  (`renderTemplate`, tag-neutralised: workspace content may guide but can't open/close a data block), then
  `renderMeetingContext()` (meeting, people, notes with block ids, transcript `[mm:ss sN] Speaker: text`).
  Markdown notes (evals) become a doc with `notesDocFromMarkdown` (`trustMarkers:false`, `mentions:'text'`,
  sequential ids, every typed line its own line).
- **Output**: the 4.2 schema + optional `sources` (transcript refs, max 12) per block. One `streamText` call with
  `Output.object`; `partialOutputStream` feeds previews (throttled, `partialIntervalMs`, default 150 ms; the
  server uses 200 ms). Errors surface from `await output` (SDK console logging suppressed);
  `classifyEnhanceError` → `model_error | invalid_output | timeout | internal`. Output cap raised to 8192 tokens
  (1,500-word budget + JSON structure).
- **Origin (D-20/D-23), `enhance-origin.ts`**: note lines = every non-empty textblock of the notes doc, split at
  hard breaks, typed paragraph/heading/bullet/task (+ checkbox, + inline JSON). A block is `me` iff its
  normalised text equals a note line or has bigram-Dice ≥ **0.85** with one (lines < 12 normalised chars: exact
  only); its text is then replaced by the user's line. Everything else is `ai`, whatever the model said
  (adversarial "mark me as mine" text stays `ai`, tested). A user task line stays a task. Note lines no block
  matched are appended under **"Other notes"** (`OTHER_NOTES_HEADING`), in note order, as `me`. Duplicated
  matches are all `me` (never label my words as AI). The eval `headings` scorer ignores a trailing "Other notes".
- **TipTap (`enhance-doc.ts`)**: section → `h2` (`ai`), paragraph → `p`, consecutive bullets/tasks →
  `bulletList`/`taskList` (children nested the same way); `me` blocks reuse the user's inline content (marks,
  links, mentions) and checkbox; AI task owner/due appended as ` — Owner, due X`; empty sections omitted; model
  text is plain text (no Markdown/HTML parsing). Citations: block id → segment ids (refs resolved through
  `segmentIdForRef`, unknown refs dropped), stored on the run, not in the doc. Output is checked with
  `validateDoc`.

### Server job (`apps/web/src/server/enhance/`)
- `POST /api/documents/:id/enhance {idempotencyKey, templateId?, timeZone?}` (locale from `Accept-Language`):
  readable (404) → `editDocument` (403) → live (403 if trashed) → `kind=meeting` (400). Same key → that run (200,
  `attached`); key of another note → 409 `idempotency_conflict`. Template: given → meeting's → General; must be
  built-in or of the note's workspace (else 404). Inputs snapshotted now: note body (→ `input_notes_json`), final
  segments, participants, the user; `input_hash` over them. Nothing at all → 422 `nothing_to_enhance`.
- **One run per note**: insert under `pg_advisory_xact_lock(hashtextextended('enhance:'||doc))` after checking for a
  live `generating` run (→ returned, 200 `attached`); stale ones are failed first. The run then takes the
  broker's per-note lock (Redis `SET NX PX` = staleness window, compare-and-delete unlock) — a second guard across
  instances; failure → run `failed`(`busy`) + 409. No migration needed (the advisory lock replaces a partial
  unique index).
- **Generation** runs via `after()` (in-process; durable workflows are 8.x), 2-min abort timeout; staleness
  window 3 min (`generating` older than that → `failed`/`stale`, settled lazily by readers and starters).
- **Completion** (one transaction): body written only `where version = <version at start>` (+1 version,
  `content_md` derived, same `prepareContent` gate as every write); `output_json = {v:1, output, raw, doc,
  citations, applied, documentVersion, missingLines}`; run → `completed` only if still `generating` (else rolled
  back). Edited meanwhile → body untouched, `applied:false`, the client offers "Use enhanced version" (D-20 "keep
  both"). Failures: `output_json = {v:1, error:{code,message}}` (fixed user-facing messages; provider details
  only in server logs).
- **Events / SSE** (`GET /api/enhancements/:id/stream`, read access): broker log per run, compacted to the newest
  `preview` (full snapshot) + the terminal `completed{enhancement, doc}` / `failed{enhancement}`. Redis Stream
  (`XADD` + Lua compaction, 1 h TTL; backlog `XRANGE (id`, live `XREAD BLOCK` on a dedicated connection) in the
  app, in-memory broker for tests — both pass one contract test. `Last-Event-ID` (or `?lastEventId=`) resumes;
  finished runs answer with their terminal event (`id: final`) from Postgres at once; a 5 s DB poll is the
  backstop if events stop (e.g. the job's instance died); 15 s keep-alive comments; `retry: 2000`.

### UI (`apps/web/src/components/document/enhance/`)
- `EnhanceButton` (meeting notes, editors only) in the header row: "Enhance" (meeting/default template) + chevron
  menu "Enhance with template" (built-ins + workspace templates, loaded on open). Busy → "Enhancing…", disabled.
- `useEnhancement`: flushes autosave first (`useAutosave.settle()`; refuses if edits can't be saved), POSTs with a
  fresh UUID key + browser time zone, follows the stream with `EventSource` (auto-resume with `Last-Event-ID`).
  On mount it re-attaches to a `generating` run, **or** to a run that completed + applied after this page was
  rendered (version newer than the rendered one — found by e2e: a reload landing just before completion showed the
  old body). Lost stream → "Reconnect"; failed run → "Try again" (same template) / "Dismiss".
- `EnhancePreview`: read-only, rebuilt from each snapshot with the editor's prose styles and `data-origin`
  colours, skeleton until the first snapshot, `aria-busy` + live status line. On `completed`+applied the editor
  comes back with the new body (`OatEditor value` swap), autosave adopts the server version
  (`useAutosave.adopt()`), sidebar is told (`announceDocumentChange`), toast "Notes enhanced". Viewers see the
  preview too (no button).

### Dev/e2e plumbing
- `AI_MOCK_CHUNK_DELAY_MS` (mock backend only) → the mock LLM's `x-mock-chunk-delay-ms`, to watch streaming.
- `e2e/web-server.ts` serves the in-process `llmProvider` (`AI_BASE_URL`, 60 ms/chunk) and writes the throwaway DB
  URL to `e2e/.auth/e2e-db.json` (git-ignored) so the spec can seed a meeting + transcript (no web API writes
  those until 3.5).

### Changes after review pass 1
- **Typed notes are never lost**: the editor stays mounted (hidden, read-only) under the preview, so a failed /
  lost / not-applied run gives back exactly what the user had; it is never re-created from the page-load body.
  Pending autosave is flushed (`settle()`) before the POST. e2e: type → enhance → run fails (stubbed start +
  `failed` stream) → text intact → next keystroke saves on top → still there after reload.
- **Re-enhance**: note lines are only the user's blocks — a textblock is skipped when it, or the list item directly
  holding it, is `ai` (D-23: an edited AI block stays `ai`; typed lines are `me`). `myNotesOnly(body)` rebuilds a
  notes doc from those lines when the body has AI blocks (else the body itself); it feeds the prompt and
  `input_notes_json`. Tests: unit (`enhance-reenhance.test.ts`) + int (enhance twice → one "Other notes", one of
  each heading/line, `input_notes_json` = my two lines).
- **Crash retry**: the Redis lock TTL is the job timeout + 15 s, capped below the staleness window − 15 s
  (135 s < 180 s); a start whose lock is held by a run the DB says isn't `generating` takes it over atomically
  (`lock(…, { takeOverFrom })`, Lua compare-and-set). Staleness is decided in SQL with the DB clock
  (`started_at < now() - make_interval(...)` inside the guarded `UPDATE`), never `Date.now()`. Int tests: dead run
  + held lock → retry 201 and owns the lock; app clock 1 h ahead → a live run still attaches.
- **Duration budget**: `maxDuration = 300` on `POST /api/documents/:id/enhance` (the `after()` job runs inside the
  POST function's budget) and on the stream route. In `next dev` there is no limit. On Vercel, `maxDuration`
  is capped by plan (Hobby 300 s with Fluid compute, Pro/Enterprise up to 800 s); the 2-min job timeout + 3-min
  staleness fit all of them. Without Fluid compute on Hobby (60 s) long runs would be cut and only surface as
  `stale` — revisit with durable workflows (8.x).
- **Duplicate lines**: the matcher returns candidates best-first and `reconcileWithNotes` prefers an unused one
  (multiset), so a line typed twice and kept twice isn't re-added; a third copy is still `me`.
- Optional ones, done: `Last-Event-ID` must look like an id we issue (`^\d+(-\d+)?$`), else replay from the
  start; "Use enhanced version" only offered to editors; idempotency keys stored as `user:document:key` (per user
  and note, no migration; `idempotency_conflict` is now unreachable but kept defensively); code lines come back
  under "Other notes" as code blocks with their line breaks.
- Merged `main` (share dialog sits next to Enhance; e2e DB URL via main's `databaseUrlFile(port)`).

### Performance (SPEC §8)
- Mock, synthetic 1-hour meeting (900 segments, ~21k words, ~34k prompt tokens, 1,500-word extractive output):
  prompt → streamed structured output → origins → TipTap **~2.2 s** of our overhead (test bound < 5 s,
  `enhance-perf.test.ts`). Mostly incremental partial-JSON parsing of word-sized mock chunks; real providers send
  larger chunks.
- Real model (not measurable here, D-13): output ≈ 1,500 words ≈ 2k tokens + ~1.5× JSON overhead ≈ 3–3.5k output
  tokens. At ~80–100 tok/s that's ~35–45 s + time to first token — **above the 30 s target for the longest
  meetings**. Levers when real keys arrive (human checkpoint): a faster enhance model, a lower word budget cap,
  or dropping `sources` from the schema. Short meetings are well under (budget scales with transcript length).

## Review

### Reviewer pass 1 (2026-11-14) — verdict: **changes**

Read: task file + `git diff $(git merge-base main task/4.4-enhance)..task/4.4-enhance`, screenshots in
`evidence/4.4/`. Good overall: prompt is our own wording; notes/transcript/template fenced + tag-neutralised;
origins derived (never trusted), `me` text replaced by the user's line, ids generated by us, citations resolved via
`segmentIdForRef`, `validateDoc` + `prepareContent` before write; advisory lock + status-guarded completion
(`SupersededError` rollback) is sound; job is not tied to the request (client disconnect doesn't abort; 2-min
abort + 8192 token cap); stream requires read access on the run's note (404 otherwise); base-version check →
`applied:false`. Findings:

1. **Notes lost after a failed/lost/not-applied run** — `apps/web/src/components/document/document-editor.tsx:60,218`.
   `OatEditor` is unmounted while streaming and remounted with `content`, which is the *page-load* body (onChange
   only queues autosave, never updates `content`). After `failed` / lost connection / `applied:false`, the editor
   shows the old body; the next keystroke autosaves it (versionRef is current after `settle()`) over the notes the
   user typed before clicking Enhance. Fix: keep the latest emitted JSON (`setContent`/ref in `onChange`) and
   remount from it, or keep the editor mounted (hidden, read-only) during streaming. Add an e2e: type → enhance
   with a failing mock → typed text still visible and still there after another edit + reload.
2. **Re-enhancing relabels AI text as `me`** — `packages/ai/src/enhance-origin.ts:110-146` (`noteLinesFromDoc`
   ignores `attrs.origin`); the Enhance button stays on an enhanced note (`enhance-done.png`). A second run treats
   every AI block and heading of the current body as the user's lines: matching AI text becomes `me`, unmatched old
   headings/AI lines are appended under "Other notes" as `me`, and `input_notes_json` stores the enhanced body as
   "my notes". Fix: collect note lines only from blocks whose effective origin isn't `ai` (an `ai` list/item
   ancestor counts; per D-23 an edited AI block is still `ai`), with a unit test on an enhanced body; or hide the
   button after an applied run until 4.5.
3. **Retry right after a crash can hit `busy`** — `apps/web/src/server/enhance/service.ts:144-145,348`. Staleness is
   `Date.now()` (app clock) vs `started_at` (DB `now()` = tx start), while the crashed run's Redis lock expires
   `staleMs` after it was taken (later). A retry at the moment of stale detection — or always under app/DB clock
   skew — gets 409 + a `failed(busy)` row. Fix: lock TTL = `timeoutMs` + margin (< `staleMs`), or on `SET NX`
   failure take over when the holder's run isn't `generating`; compute staleness in SQL. Int test: stale run whose
   lock is still held → retry starts a new run.
4. **Background job has no explicit duration budget** — `apps/web/src/app/api/documents/[id]/enhance/route.ts`.
   `after()` is bounded by the POST function's `maxDuration`; nothing sets it, so on a plan/config with a short
   default the job is killed silently and only surfaces as `stale` 3 min later. Set `export const maxDuration`
   ≥ `ENHANCE_TIMEOUT_MS` + completion margin (e.g. 180).
5. **Duplicate note lines are re-inserted** — `packages/ai/src/enhance-origin.ts:194,201`. `#byKey` keeps only the
   first line per key, so a second identical line (e.g. "follow up" twice) is never `used` and is appended under
   "Other notes" even when the model kept both. Fix: on match prefer an unused line with the same key/best score
   (track `used` in the matcher during reconcile); unit test.

Optional:
- Validate `Last-Event-ID` (`^\d+-\d+$`) before `XRANGE` (`broker.ts:200`): a bad id logs an error per reconnect and
  the EventSource loops.
- The "Use enhanced version" toast action is also shown to viewers (would 403); gate on `editable`. The offer
  disappears on reload (fine until 4.5 versions UI).
- Idempotency keys are globally unique, not per note/user; harmless with UUIDs, could be `(document_id, key)`.
- Code-block note lines re-inserted under "Other notes" become a paragraph with newlines collapsed.

Resolution (implementer, pass 2): 1–5 and all optional items fixed — see Design notes → "Changes after review
pass 1".
