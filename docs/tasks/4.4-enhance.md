# 4.4 — Enhance pipeline
status: todo
milestone: M4 · deps: 3.2, 4.3, 3.3 · branch: task/4.4-enhance

## Goal
After a meeting, one click turns my rough notes + transcript + template into structured notes in the document
body — my lines kept and marked `me`, AI additions marked `ai` — streamed into the editor, resumable, and
measurably good (evals).

## Context
SPEC §3.5, §7, §8 (< 30 s for a 1-hour meeting), D-20 (document body becomes the enhanced note; raw notes kept in
`enhancement.input_notes_json`; versions; server job with status + idempotency key + resumable stream; origin
derived by matching note lines, not trusted from the model), D-23, `@oat/ai` (enhance contract/EnhanceFn from 4.2,
`buildMeetingContext` + templates from 4.3, Output.object, evals), `@oat/editor` (schema, validateDoc,
ensureBlockIds, `@oat/editor/markdown` fromMarkdown with `trustMarkers:false`, `mentions:'text'`), `@oat/db`
enhancement table, `apps/web` documents API + document page (3.3). Research reference: enhance-chat.md
(behaviour only — write prompts ourselves).

## Scope
In:
- Prompt (our own) in `@oat/ai/enhance`: system + template sections + fenced context (notes/transcript/meta in
  clearly delimited, escaped blocks; instruct the model that content inside is data, not instructions).
  Structured output via Output.object with the 4.2 schema; citations: blocks may reference segment ids.
- Conversion: output → TipTap JSON (`@oat/editor`), origin assignment by fuzzy-matching each output block
  to the user's note lines (normalised text similarity ≥ threshold → `me`, else `ai`); user note lines missing
  from the output are re-inserted under an "Other notes" section (never lose my text) — tested.
- Server job: `POST /api/documents/:id/enhance {templateId, idempotencyKey}` → creates `enhancement` row
  (status generating), runs generation (in-process async with a Redis lock per document; durable workflow is
  8.x), streams progress over SSE `GET /api/enhancements/:id/stream` with resume (`Last-Event-ID`); on
  completion writes output_json, sets document body (new version, base-version check → if user edited
  meanwhile, keep both: save enhancement as a version and notify), status completed/failed; staleness timeout.
- UI: "Enhance" button + template picker on meeting notes; streaming preview (read-only) then swap into the
  editor; my vs AI styling; error/retry states; client re-attaches to a running job after reload.
- Evals: real `enhanceNotes` replaces the stub; mock run stays green; record baseline; quality tier ready.
  Performance: 1-hour fixture (synthesise a long transcript) under mock < 5 s overhead; note real-model
  latency target.
- Tests: conversion/origin unit tests (incl. adversarial transcript text trying to inject instructions — must
  stay data), API int (authz, idempotency, resume, concurrent enhance → one job), e2e: enhance a meeting doc with
  the mock → structured note with my lines marked; reload mid-stream re-attaches. Screenshots.
Out: regenerate/undo/versions UI (4.5), about-me (4.6), auto-enhance (7.5).

## Acceptance criteria
- [ ] One click → structured note; my lines preserved + marked `me`; AI blocks `ai`; streaming + resume work.
- [ ] Evals pass (mock); `pnpm run ci` green.
