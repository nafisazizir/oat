# 7.4 — Google Calendar (OAuth + events API, mocked in dev)
status: in-progress
milestone: M7 · deps: 1.6, 7.1 · branch: task/7.4-google-calendar

## Goal
Users without macOS Calendar (and the web app) get upcoming meetings from Google Calendar, normalised into the
same `CalendarEvent` (7.1). Dev/tests run against a Google Calendar API subset in `tools/mocks` (D-11).

## Context
D-11, D-21, `@oat/core` CalendarEvent + helpers, `@oat/calendar` (CalendarSource, CalendarCache),
`@oat/auth` (Google via genericOAuth pointed at OAUTH_GOOGLE_ISSUER; account linking rules), `tools/mocks`
(provider structure, `startMocks()`), `docker/oauth` mock config, SPEC §6 `integration` table.

## Scope
In:
- OAuth: request calendar read scope (`https://www.googleapis.com/auth/calendar.readonly`) as an incremental
  "Connect Google Calendar" flow (separate from sign-in, so sign-in scopes stay minimal); store tokens in
  Better Auth `account` (encrypted at rest if Better Auth supports it; else note) with refresh handling.
  Mock OAuth issues tokens with the requested scope.
- `tools/mocks` `gcal` provider: `GET /gcal/calendar/v3/users/me/calendarList`, `GET
  /gcal/calendar/v3/calendars/{id}/events` (timeMin/timeMax/singleEvents/orderBy/pageToken/syncToken subset,
  conferenceData, attendees with responseStatus/self/organizer), bearer validation against the mock OAuth
  token (or accept any non-empty bearer in dev — document), fixture data derived from
  `fixtures/calendar/week.json`; 410 on stale syncToken.
- `@oat/calendar` `GoogleCalendarSource` (server-side, Node): base URL from env (`GOOGLE_CALENDAR_BASE_URL`,
  default the mock), pagination, incremental sync tokens with 410 → full resync, normaliser → CalendarEvent
  (conference links from conferenceData/hangoutLink/location/description via shared detector), per-user cache.
- `apps/web`: `/settings/integrations` "Connect Google Calendar" + disconnect; `GET /api/calendar/upcoming`
  (session-auth) merging connected sources; Home shows "Upcoming" list (next 5, with join link + "Start
  notes" placeholder action).
- Tests: normaliser unit tests, mocks tests, int tests (connect flow against mock OAuth + gcal mock, 410
  resync), web e2e: connect → upcoming list renders fixture events. Screenshots.
Out: writing to calendars, push notifications/webhooks, desktop wiring (desktop uses EventKit + this API).

## Acceptance criteria
- [ ] Connect → upcoming events appear on Home (mock), normalised identically to EventKit fixtures (test
      compares the same fixture through both normalisers).
- [ ] No real Google calls in dev/tests; real Google works by env only.
- [ ] `pnpm run ci` green.
