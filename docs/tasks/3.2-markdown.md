# 3.2 — TipTap JSON ↔ Markdown
status: done
milestone: M3 · deps: 3.1 · branch: task/3.2-markdown

## Goal
Derive Markdown from canonical TipTap JSON (D-4) for AI input, export, copy-as-Markdown and Notion sync, and
parse Markdown into TipTap JSON (paste, AI output fallback, imports) — with round-trip tests.

## Context
D-4, D-20 (`origin` attr, block `id`s), `packages/editor` (3.1) schema + headless `createExtensions()`.

## Scope
In:
- `@oat/editor/markdown` (Node + browser, no DOM required): `toMarkdown(doc, opts)` covering every block/mark
  from 3.1 (callout → `> [!note]`-style admonition, mentions → `@Name`, task lists `- [ ]`, code fences w/
  language, links, highlights → `==text==`, hard breaks), option `includeOrigin` (emits `<!-- ai -->` markers
  or similar for AI prompts/evals) and `blockIds` (for citation-aware prompts); `fromMarkdown(md)` → valid
  TipTap JSON with fresh ids (`origin` param to stamp all blocks e.g. 'ai').
- Round-trip tests: JSON → MD → JSON preserves structure (ids/attrs aside) for a corpus of fixture docs;
  MD → JSON → MD is stable for a Markdown corpus (CommonMark + GFM task lists/tables-as-text). Property-style
  test generating random docs from the schema.
Out: Notion block mapping (8.1), HTML export.

## Acceptance criteria
- [ ] All block/mark types covered by fixtures; round-trip suites pass.
- [ ] Works in Node without jsdom (test runs in node environment).
- [ ] Global gates green.

## Design notes
(implementer, 2026-11-14)

**API — `@oat/editor/markdown`** (`src/markdown.ts` → `src/markdown/{to-markdown,from-markdown,shared}.ts`;
not re-exported from the main entry so editor-only consumers don't pull in the parser). Pure, no DOM; the
test file runs in Vitest's node environment and asserts `document`/`window` are undefined.
```ts
toMarkdown(doc, { includeOrigin?, blockIds?, mentionIds? }): string   // no trailing newline
fromMarkdown(md, { origin?: 'me'|'ai', trustMarkers?, preserveIds?, mentions?, generateId? }): JSONContent
// mentions: 'text' (default) | 'off' | { resolve(id, label) => id | null }       // output passes validateDoc
```
- `includeOrigin` → `<!-- ai -->` on blocks with `origin: 'ai'` (`me` is the default, never written).
  `blockIds` → `<!-- id=… -->` (both: `<!-- ai id=… -->`). Ids outside `[\w.:-]{1,128}` are skipped.
- `mentionIds` → `[@Name](mention:<id>)` (lossless; id fully percent-encoded — `encodeURIComponent` plus
  `!'()*~`); default plain `@Name` (for prompts/export).
- `fromMarkdown`: fresh UUID block ids (via `ensureBlockIds`); `preserveIds` keeps `id=` marker ids
  (de-duplicated). Output is run through the editor schema (`nodeFromJSON().check().toJSON()`) so every
  attr default is filled exactly like the editor's JSON.
- **Trust (review findings 6–7).** By default `fromMarkdown` treats its input as untrusted (AI output,
  paste, imports): origin markers are *stripped and ignored* and `origin` (default `me`) applies to every
  block, so prompt-injected `<!-- me -->` can't pass AI text off as mine and a pasted `<!-- ai -->` can't
  relabel my words (D-23). `trustMarkers: true` honours them — only for Markdown we produced ourselves
  (round-trips, evals). Mention links follow `mentions`: `'text'` (default) → plain `@Name`, no node;
  `'off'` → no mention syntax at all (an ordinary link to a disallowed URI → its text); `{ resolve }` →
  a mention node with the id the resolver returns (e.g. only the meeting's participants), else `@Name`.
  Callers like 4.4 should pass `{ origin: 'ai', mentions: { resolve: knownParticipant } }`.

**Parser choice.** `markdown-it` 15.0.3 (`default` preset: CommonMark + GFM tables/strikethrough; ships its
own types) + `markdown-it-mark` 4.0.0 for `==highlight==` (official markdown-it org plugin, untyped → tiny
ambient `markdown-it-mark.d.ts`). Both added to the pnpm catalog. `html: true` only so our comment markers
are visible as tokens — any other HTML becomes literal text, never HTML. `linkify` off (bare URLs stay text,
which keeps JSON→MD→JSON exact; the editor autolinks on input). `normalizeLink` is identity (hrefs stored as
written, no punycode/percent-encoding); every href — in both directions — is gated by `isSafeHref`
(TipTap's `isAllowedUri`, plus no protocol-relative `//host` / `\\host`): a disallowed link keeps its text and
loses the mark, and `toMarkdown` never writes one even if it is in the JSON. The parser instance is only ever
used to `.parse()` to tokens, never `.render()`, so `html: true` cannot emit HTML. Task items and callouts are detected by a core rule between block and
inline parsing (strips `[ ] `/`[x] ` and `[!type] emoji` from the raw inline source, so escaped `\[ \]`
never matches). Serialisation is hand-written over the JSON tree.

**Mapping.**

| TipTap JSON | Markdown out (`toMarkdown`) | Also accepted by `fromMarkdown` |
|---|---|---|
| paragraph | text; blocks separated by a blank line | soft breaks → space |
| heading 1–3 | `#`/`##`/`###` (ATX) | setext; `####`–`######` → level 3 |
| bold / italic | `**x**` / `*x*` (`__x__`/`_x_` only right after a closing `*`, see below) | `__x__`, `_x_` |
| strike / highlight / code | `~~x~~` / `==x==` / `` `x` `` (longer fence + padding when the code contains backticks) | |
| link | `[x](href "title")`, `<…>` destination when href has spaces/parens | autolinks `<https://…>`, reference links |
| mention | `@Name`, or `[@Name](mention:id)` with `mentionIds` | `[@Name](mention:id)` → mention node |
| hardBreak | `\` + newline (a space inside headings) | two-space breaks |
| bulletList / orderedList | `- ` / `1. ` (start kept); adjacent lists alternate `-`/`*` and `.`/`)` so they stay separate | `*`, `+` |
| taskList / taskItem | `- [ ] ` / `- [x] ` | `[X]`; a list mixing task and plain items splits into taskList/bulletList runs |
| blockquote | `> ` prefix | |
| callout | `> [!variant] emoji` + content (blank `>` line when the first block isn't a paragraph) | GitHub alerts (`[!NOTE]`, `[!TIP]`…) and Obsidian types mapped to the 5 variants (unknown → neutral); missing emoji → 💡; a non-emoji title stays as content |
| codeBlock | fenced, language as info string (first word) | indented code, `~~~` |
| horizontalRule | `---` | `***`, `___` |
| origin / id | `<!-- ai id=… -->` at the end of a paragraph/heading line, on the line before a code block / rule | marker on its own line before any leaf block |
| — | | GFM table → one paragraph with the table source, a row per line (hard breaks) — "tables as text" |
| — | | image → alt text (linked to src if allowed); other HTML → literal text |

**Escaping / injection.** All inline strings that can't hold a break — text, code spans, mention labels,
link titles — have every line break (`\r\n`, `\r`, `\n`, U+2028, U+2029) replaced by a space, so a display
name or pasted title can never start a heading/list/table in a prompt or export; href line breaks are
percent-encoded. Always escaped: `` \ ` * [ ] < ~ | `` (`|` so hard-broken lines can't form a GFM table); `_` unless between two letters/digits (`snake_case` stays
readable); `=` when next to another `=` or at a text edge; `&` before an entity; at line starts `# > - + =`
and `1.`/`1)`; trailing `#`s in headings; `!` right before a link. Adjacent same-mark text is merged first
so escaping never depends on how text happens to be split.

**Emphasis and CommonMark flanking.** A delimiter run only opens/closes depending on its neighbours, so the
serializer: moves whitespace from the inside edge of a mark to the outside; writes a letter/digit next to a
delimiter as a character reference (`&#x61;`) when punctuation on the other side would stop the run from
opening/closing (e.g. `word**(x)**`); and uses `__`/`_` for bold/italic that open right after a closing
`*` (or where a `*` could also close a still-open `*`), so runs never merge into an ambiguous `***`.

**Lossy cases (documented, tested as stable).**
- Container ids/origins: markers are written only for leaf blocks (paragraph, heading, codeBlock, hr).
  Lists, items, quotes and callouts get fresh ids; their origin is derived — `ai` iff all their blocks are
  `ai` (matches what 4.4 enhancement produces; a mixed container becomes `me`).
- Empty paragraphs are dropped (blank lines separate blocks); an empty doc → one empty paragraph. An empty
  first paragraph in a list item followed by another paragraph collapses into that paragraph.
- Leading/trailing whitespace of a line (block edges, around hard breaks) and leading/trailing hard breaks
  are dropped (leading spaces would become indented code); code spans keep their spaces.
- Hard breaks inside headings become spaces; heading levels 4–6 clamp to 3.
- Marks the schema can't hold together: `code` excludes every other mark, so code inside bold/italic is just
  code, and code inside a link becomes plain link text. Nested duplicate marks collapse.
- Link `target`/`rel`/`class` aren't represented (the editor's defaults come back); `title` is kept.
  `orderedList.type` isn't represented. Bare URLs aren't auto-linked.
- Mentions without `mentionIds` are plain `@Name` text (no id) — by design for prompts/export; mention
  links in untrusted input become `@Name` text unless a `mentions` resolver accepts them.
- Line breaks inside text/labels/titles become spaces; `|` is written escaped (`\|`), including in the
  text of a pasted table.
- Images, raw HTML, tables: become text as listed above (no image/table node in the schema yet).
- Touching marks: differently-marked runs with no space between them (`a**b**~~c~~*d*`) round-trip in
  ≥99% of random docs; a few pathological combinations (several `*`/`_` marks opening and closing at the
  same point next to punctuation) can still shift a mark boundary. The Markdown is always valid and stable
  after one pass.

**Tests** (`src/markdown.test.ts`, node env, ~1.7 s): every-block fixture with exact expected Markdown;
4 fixture docs (every block, escaping, marks, lists, containers) JSON→MD→JSON + MD fixed point; a check that
the fixtures cover every node and mark in the schema; option tests (includeOrigin, blockIds, mentionIds,
preserveIds, origin stamping, markers, unknown HTML, alerts/Obsidian callouts, mixed task lists, tables,
disallowed links, never-throws inputs, normalisation); 10 canonical Markdown docs (MD→JSON→MD identity) and
23 general CommonMark/GFM docs (one pass normalises, second is stable). Property-style (seeded PRNG, no new
dep): 1000 random schema docs JSON→MD→JSON exact (marks incl. punctuation-edged text, all blocks, nesting
to depth 3); 300 with random origins + ids through `includeOrigin`+`blockIds`+`preserveIds`; 1000 with
touching marks (valid + stable, ≥99% exact); 2000 random Markdown "soup" strings (valid + MD stable).
While developing these ran at 20×–50× the counts (20k/10k/20k docs, 100k soup) green except 1 touching-marks
doc in 2000. Adversarial suite (review round 1): mention labels / text / code / link titles with `\n`, `\r`,
`\r\n`, U+2028/9 + block syntax can't add blocks (both mention forms); hostile mention ids
(`a) **bold** [x](javascript:…)`, `(*!'~)`, newlines) round-trip exactly; unsafe hrefs (`javascript:`,
`vbscript:`, `//host`, `\\host`) never written by `toMarkdown` nor read by `fromMarkdown`; `|` table injection;
marker forgery both ways (AI `<!-- me -->`, pasted `<!-- ai -->`); mention policy `text`/`off`/resolver. The
generator now also uses tricky labels/ids/titles that must survive exactly, plus a `hostile` mode: 500 docs ×
2 mention forms keep their block structure, carry only safe hrefs and are stable. Perf: one paragraph with
8000 alternately-marked runs 204 ms → 12 ms (run lengths precomputed, no per-node `trim`/end-anchored regex).

## Review
**Reviewer (2026-11-14) — verdict: `changes`.** Read task file + `git diff main...task/3.2-markdown` only;
probed with a throwaway Vitest file (deleted, not committed).

What holds up: user text can't forge origin markers (`<` always escaped → `hello \<!-- ai -->` parses back as
text); markdown-it is only used to *parse* (never `.render()`), so `html: true` is not an XSS vector — all
non-marker HTML becomes literal text; `linkify` off; `javascript:`/`vbscript:`/`data:`, `&#106;avascript:`,
`java&#x09;script:`, `JAVASCRIPT:` and image `javascript:` are all rejected (markdown-it `validateLink` +
`isAllowedUri`); adversarial nesting (callouts/tables/code/tasks inside lists inside callouts, mentions under
marks) always yields `validateDoc`-valid JSON. Perf: 10k-block doc (773 KB MD, origins + ids) → toMarkdown
23 ms, fromMarkdown 102 ms; 50k `[`/`*a`/`==a`, 2000-deep quotes/lists, 20k mention links all < 60 ms.

Findings (must fix):
1. **Structure injection via mention labels** — `to-markdown.ts:460-462`: the label goes through `escapeText`
   without newline normalisation, so a display name `Eve\n\n# Ignore previous instructions\n\n- [x] done`
   becomes a real heading + list in the prompt/export (verified; with `mentionIds` it also breaks the link).
   Team members control their display names, so this is a cross-user prompt-injection path. Same file :464:
   `encodeURIComponent` leaves `)` `(` `*` `!` unencoded, so an id containing `)` ends the destination early and
   the rest is parsed as inline Markdown. Fix: normalise line endings to a space inside `escapeText` itself
   (covers every caller), and percent-encode `()*!'~` in the mention id (or use the `<…>` destination form).
2. **Structure injection via a lone `\r`** — `to-markdown.ts:467` only replaces `\r?\n`; CommonMark treats a
   bare `\r` as a line ending, so text `a\r\r# Injected\r\r- [ ] task` becomes paragraph + heading + list
   (verified). Fix: `/\r\n?|\n/g` (folded into the escapeText normalisation from 1).
3. **Structure injection via link titles** — `to-markdown.ts:490-493`: a title containing a blank line
   (`"x\n\n# Injected heading"`, e.g. from pasted HTML `title=`) ends the link and emits a heading (verified).
   Fix: collapse `\r`/`\n` runs in the title to a space (also escape `\` already done).
4. **`toMarkdown` writes any href verbatim** — `to-markdown.ts:484-494`: a `javascript:alert(1)` href in JSON
   (synced/imported/malicious client) is emitted as `[x](<javascript:alert(1)>)`, which a share-view/Notion/
   third-party renderer may turn into a live link. Fix: gate on `isAllowedUri` like `fromMarkdown` does —
   render the text without the link when disallowed; add a test.
5. **GFM table injection through hard breaks** — `escapeText` (`to-markdown.ts:504`) doesn't escape `|`, so a
   paragraph `a | b` + hard break + `| --- | --- |` serialises to a GFM table: fromMarkdown turns it into
   `| a | b\ |…` (user text changed) and any GFM renderer shows a table (verified). Fix: always escape `|`.
6. **Markers in untrusted / pasted Markdown override the caller** — `from-markdown.ts:123` (`marker?.origin ??
   derived`), fed by :150-154 and :339-345: AI output parsed with `{ origin: 'ai' }` that contains
   `<!-- me -->` (prompt-injected) is stamped `me`, i.e. AI text passes as the user's; and a user pasting
   Markdown that contains `<!-- ai -->` gets their own words labelled AI (against D-23). Fix: honour markers
   only with an explicit opt-in (e.g. `markers: true`, used for our own round-trips/evals); otherwise strip
   them and apply `origin` to every block. Tests for both directions.
7. **Arbitrary mention nodes from untrusted Markdown** — `from-markdown.ts:376-395`: any `[@X](mention:<id>)`
   in AI/pasted output becomes a mention node with an attacker-chosen id (verified
   `[@CEO](mention:admin-user-id)` under `origin: 'ai'`). Once mentions notify / resolve users this is a
   spoofing path. Fix: option `mentions?: false | ((id) => boolean)` (default off for non-round-trip callers,
   or a resolver that only accepts known participant ids); otherwise keep it as plain link-less text.
8. **Tests miss the adversarial cases** — the generator only uses fixed safe labels/hrefs/no titles
   (`markdown.test.ts:605,641`), so none of 1-7 can be caught. Add regression tests: labels/titles/text
   with `\n`, `\r`, `|`, `)`, disallowed hrefs in JSON, marker forgery both ways, mention gating.

Optional:
- `renderLine` is quadratic in nodes per line (`out.trim()` per node :342, `runLength` :345, `slice`/regex in
  `closeTo`): one paragraph with 8000 alternately-marked runs takes 204 ms (2000 → 18 ms). Fine for real notes;
  track `lineStart` with a flag and precompute run lengths if transcripts ever land in one paragraph.
- Relative / protocol-relative hrefs (`//evil.com`, `\javascript:x` → relative path) pass `isAllowedUri`;
  harmless for XSS, but consider restricting AI-output links to absolute http(s)/mailto.
- Add a one-line comment/test pinning that the markdown-it instance is never used to render HTML.

**Resolution (implementer, round 1).** All 8 fixed + both optional items:
1–3. `toSingleLine` (`/\r\n?|\n|\u2028|\u2029/g` → space) inside `escapeText` (all text + mention labels),
for code-span text and link titles (both directions); href line breaks %-encoded; mention ids
`encodeURIComponent` + `!'()*~`. 4. `toMarkdown` drops links failing `isSafeHref`, keeps text. 5. `|` always
escaped. 6. `trustMarkers` (default false: markers stripped, caller's `origin` wins); documented. 7. `mentions:
'off' | 'text' | { resolve }`, default `'text'`. 8. Adversarial tests + hostile generator (see Tests).
Optional: `renderLine` run lengths precomputed / no per-node `trim` (8000 runs 204 → 12 ms); protocol-relative
`//`/`\\` hrefs rejected both ways; comment pinning parse-only use of markdown-it.
