# 4.5 + 4.6 — Regenerate / switch template / versions & undo + "About me"
status: done
milestone: M4 · deps: 4.4 · branch: task/4.5-regenerate-versions

## Goal
Control over AI notes: regenerate (same or different template), see and restore earlier enhancement
versions, view my original notes, undo an enhancement — and an "About me" profile that enhancement and chat
use as context.

## Context
SPEC §4 Enhance, §7, D-20, D-26, `apps/web` enhance API/UI (4.4: enhancement rows with input_notes_json,
output_json, applied flag; "Use enhanced version"), `@oat/ai` (`buildMeetingContext` takes `aboutMe`; chat uses
it too), `@oat/db` (enhancement table; user profile — add `user_profile` table or column via migration,
renumber after main's latest).

## Scope
In:
- Versions: list enhancements for a document (time, template, applied); "View" read-only; "Restore" sets the
  document body to that version (new document version, baseVersion check); "Show my original notes" (from
  the latest input_notes_json); "Undo enhancement" = restore the body to the input notes of the last run.
- Regenerate: same template or pick another; warn (confirm dialog) when the current body differs from the
  last output (user edited AI notes) — D-20.
- About me: `/settings/profile` — name/role/team/what I care about/terms & names to spell correctly (max length,
  plain text); stored per user; passed into `buildMeetingContext` (fenced as data) for enhance and chat;
  vocabulary also offered to STT as keyterms (D-17) via the token route response (optional).
- Authz + deny markers for new routes; int tests (restore at stale version → 409, viewer can't restore, other
  user's profile inaccessible); e2e: enhance → edit → regenerate with warning → restore v1 → undo; profile
  saved and visible in the enhance prompt (mock echo). Screenshots.
Out: auto-enhance (7.5).

## Acceptance criteria
- [x] Versions/restore/undo/regenerate work; about-me flows into context; `pnpm run ci` + eval green.

## Design notes

### Data (`@oat/db`, migration `0009_user_profile`)
- `user_profile` (PK `user_id` → `user` cascade): `role`, `team`, `about` ("what I care about"), `vocabulary text[]`,
  timestamps; a check constraint enforces the limits (`PROFILE_LIMITS`: name/role/team 100, about 1000, ≤ 100 terms of
  ≤ 60 chars). The display name stays on `user.name` (Better Auth reads it on every session — no cookie cache — so the
  sidebar updates). Server-only: not synced, no change-log trigger.
- `getUserProfile`, `saveUserProfile` (normalises: one-line fields, collapsed blank lines, case-insensitive dedupe of
  terms; writes `user.name` + upserts the row in one transaction), `profileAboutMe` (labelled lines
  `Role:` / `Team:` / `What I care about:`, `null` when empty).
- Versions need no migration: `enhancement.input_notes_json` / `output_json.doc` (4.4) already keep everything.

### AI context (`@oat/ai`, wiring only)
- `buildMeetingContext` already took `aboutMe`/`vocabulary` (4.3); now actually fed. New `renderProfileContext()` renders
  just `<oat:about_me>` + `<oat:vocabulary>` with the same tag-neutralising/cleaning, and `renderMeetingContext` uses it
  (byte-identical output → evals unchanged).
- Chat: `loadDocumentContext` options gain `aboutMe`/`vocabulary`; `streamAssistant` gains `profile` for workspace
  chats (appended to the instructions as fenced data; `MEETING_CONTEXT_RULES` already names "the user's profile").

### Server (`apps/web`)
- `GET`/`PUT /api/profile` (`src/server/profile.ts`, contract `src/lib/profile.ts`): session user only — the API takes
  no user id; strict zod body (extra fields like `userId` → 400), limits → 400, PUT is CSRF-checked like every write.
  `aiProfile(db, userId)` → `{ me, aboutMe, vocabulary }` is what enhance and chat use.
- Enhance (`gatherInput`): `me` name/email + `aboutMe` + `vocabulary` from the profile; the profile is part of
  `input_hash`. Chat (`POST /api/chat`): same `aiProfile` for note and workspace chats.
- STT token (`POST /api/stt/token`): response gains `keyterms: string[]` (the session user's vocabulary; D-17 keyterms).
  Best effort: a profile lookup failure logs and returns `[]`, never costs the token. Desktop doesn't consume it yet
  (out of scope here; `DeepgramSttProvider` already accepts `keyterms` per stream).
- Versions (`src/server/enhance/versions.ts`, routes in `enhance/api.ts`):
  - `GET /api/documents/:id/enhancements` (read access) → completed runs newest first, numbered from the oldest
    (v1…), `templateName`, `current` (body `jsonEqual` that run's output), plus `body: { version, edited }` where
    **edited** (see "Changes after review pass 1" #2; originally: body has `origin: ai` blocks and equals no stored output) — i.e. the user changed notes that a
    regenerate/undo/restore would replace (D-20). A body that is only my lines (fresh, or after undo) never warns.
  - `GET /api/enhancements/:id` (read access) → `{ enhancement, doc (output), notes (input_notes_json) }`; only
    completed runs (else 404).
  - `POST /api/enhancements/:id/restore {baseVersion, target: 'output'|'notes'}` (editDocument → 403; trashed → 403;
    unreadable → 404): an ordinary body write — `prepareContent` gate, `version = baseVersion` in the UPDATE (stale →
    409 `stale_version` + server copy), +1 version, change_log → re-index. Taken under the same advisory lock as starting
    a run, and refused with 409 `enhance_busy` while a non-stale run is `generating`. `notes` of a transcript-only run
    (empty notes) → an empty paragraph. Undo = `notes` of the newest run; redo = its `output`.
- Every new handler has `denies(...)` markers (`versions.int.test.ts`, `profile.int.test.ts`).

### UI (Designer)
Header row of a meeting note (left → right): `[Enhance|Regenerate ▾] [History] [Send to Notion] [Share]`.
- **`EnhanceToolbar`** (`components/document/enhance/enhance-toolbar.tsx`, new) replaces the bare `EnhanceButton` in
  `document-editor.tsx` (the only edits there: render the toolbar, a `showServerBody()` helper shared by "enhancement
  applied" and "restored", `useNoteVersions`, "Undo" action on the "Notes enhanced" toast). The 6.4 chat panel can live
  beside it untouched.
- Button reads **Regenerate** (RefreshCw icon) once the note has a completed run; click repeats the newest version's
  template; the chevron menu "Regenerate with template" lists templates, then (separator) **Note history**, **Show my
  original notes**, **Undo enhancement**. Editors only (review #4): History button (outline, History icon).
- **D-20 warning**: before Regenerate / Undo / Restore the toolbar saves pending edits (`autosave.settle()`), re-reads
  `body.edited`, and if true shows a small confirm dialog ("Regenerate over your edits?" / "Undo over your edits?" /
  "Replace your edited note?", destructive action button, Cancel default). Not edited → runs at once.
- **Note history** (`note-history.tsx`, Dialog `sm:max-w-4xl`, two columns, stacks on mobile): left list of versions
  (Sparkles icon, "Version N", Current / Not applied badge, "template · local time"), separator, "My original notes —
  Before version N"; right a bordered read-only `OatEditor` preview (same prose + my/AI colours as the note), skeleton
  while loading, inline error. Footer: Close + primary "Restore this version" / "Restore my notes" (disabled with "This is
  the current note" when it already is). After a restore the dialog closes
  and a toast confirms ("Version 1 restored" / "Your original notes are back").
- **Undo** toast: "Enhancement undone — Your own notes are back…" with **Redo** (restores that run's output).
- Restores swap the editor value without remounting, `autosave.adopt()` the new version, announce to the sidebar —
  exactly as an applied enhancement does; pending edits are saved first, a 409 shows "This note changed elsewhere".
- **`/settings/profile`** ("About me", linked from a new first card on `/settings`): back link, header, one card with
  label/hint rows (same Field grid as workspace settings): Name, Role, Team or company, What I care about (textarea,
  counter after half the limit), Names and terms (one per line, mono textarea, counter, inline over-length error).
  Save disabled until dirty; "Last saved <day>"; toast "Profile saved — New enhancements and chats will use it";
  `router.refresh()` so the sidebar name updates. Tokens only (no new colours/spacing).

### Changes after review pass 1
1. **Never lose text** — new `document_snapshot` table (same migration, renumbered/regenerated as
   `0009_user_profile_snapshots`; server-only, not synced): `snapshotBeforeReplace(tx, doc, baseVersion, reason, user)`
   locks the row at `baseVersion` and, if its body equals (`jsonb =`) no stored output, input notes or snapshot of the
   note and has any text, inserts it. Called inside the restore/undo/redo transaction (after the advisory lock, before
   the version-checked UPDATE) and inside `runJob`'s apply transaction (exact body at `baseVersion`, so a regenerate
   keeps edited AI notes). Snapshots are listed in Note history ("Your edited note · Saved before regenerating /
   restoring", interleaved by time, Current badge), viewable via `GET /api/enhancements/:id` (`kind: 'snapshot'`) and
   restorable via the same restore route (`target: 'output'` only). `input_notes_json` now gets block ids
   (`ensureBlockIds`) so an undo writes exactly the stored notes and isn't mistaken for an edit.
2. **`edited`** = the note has a completed run, the body has text, and it equals no stored output, input notes or
   snapshot (computed in SQL) — covers my own lines (typed after an undo).
3. **Every replace is guarded** (`useNoteVersions.guard`): Regenerate, Undo (menu + "Notes enhanced" toast), Redo
   (toast), Restore. It saves pending edits, re-reads the list, and confirms when `edited` — or when the check failed
   (fail safe, "Replace the current note?"). Copy now says the current note is saved in Note history first; the
   confirm button is primary (nothing is lost).
4. **History is editors-only** (decision: earlier versions / raw notes can hold text an editor removed before sharing —
   like Docs/Notion): list and detail need `editDocument` (viewers 403, non-readers 404); the History button, menu and
   versions fetch are rendered/enabled only for editors.
5. **Profile name required**: `z.string().trim().min(1).max(100)` (same as update-user), `saveUserProfile` refuses a
   blank name, `required` on the input + Save disabled; int tests for `''` / `'   '`.
- Optional, done: `capKeyterms` in the token route (≤ 50 terms, ≤ 40 chars each, ≤ 2 KB of `&keyterm=` query);
  the list endpoint no longer loads `output_json` (applied/version/current computed in SQL); one toast slot per note
  (`noteToastId`) so a newer message replaces an older Undo, dismissed when a guarded replace starts or the user's
  edit saves.

### e2e plumbing
- `e2e/web-server.ts` also writes the in-process mocks URL to `e2e/.auth/mocks-url-<port>` (`mocksUrlFile`), so a spec
  can read the mock LLM's `/_requests` log and assert what the prompt contained (deterministic, unlike the echoed
  output).

### Not done / follow-ups

  `recording-setup.ts`).
- Versions list caps at the newest 50 runs (older runs stay restorable by id).
- `inputHash` now includes the profile; still nothing compares it (a "notes are outdated" hint could use it).

## Review

**Verdict: changes** (reviewer, 2026-11-14, diff `merge-base(main)..task/4.5-regenerate-versions` @ f28f3d7)

Authz, stale → 409, `enhance_busy`, trashed → 403, viewer restore → 403, own-profile-only API, prompt fencing
(`neutralizeTags` + `<oat:about_me>`/`<oat:vocabulary>` + DATA_RULES), keyterm URL encoding
(`URLSearchParams.append`, `packages/stt/src/deepgram-config.ts:138`) all look right and are tested.

1. **Edits to AI notes are destroyed, not kept** (orchestrator position: never lose user edits).
   `apps/web/src/server/enhance/versions.ts:196-206` (restore/undo/redo UPDATE) and
   `apps/web/src/server/enhance/service.ts:436` (regenerate's apply) overwrite the body; the replaced body is
   stored nowhere (`input_notes_json` keeps only `origin: me` lines, so edits inside AI blocks vanish). Fix:
   inside the same transaction (restore: under the advisory lock after the version check; regenerate: in
   runJob's apply transaction, i.e. the exact body at `baseVersion`), if the current body `jsonEqual`s no stored
   output/input notes of this note, save it as a snapshot (new `document_snapshot` row or a `kind: snapshot`
   enhancement row) shown in Note history as "Your edited note · <time>" and restorable via the same route.
   Int test: edit an AI block → regenerate / restore / undo → the snapshot restores the edit. Until then the
   history copy "nothing here is ever deleted" (`note-history.tsx:100`) is false.
2. **`edited` misses edits to my own lines** — `versions.ts:120` requires `hasAiBlocks`, so a body of only my
   lines that differs from every stored `input_notes_json` (lines typed after an Undo, or typed during a run
   that finished `applied: false`) is replaced by Restore / Undo / Redo with no warning. Fix: edited = body
   equals no stored output **and** no stored input notes (#1 makes this the snapshot condition too).
3. **Warning fails open / is bypassed** — `enhance-toolbar.tsx:72` (`latest` from a list that may not have
   loaded → runs unguarded, and the button even reads "Enhance"), `:77-79` (`refresh()` → `null` on error →
   action runs), `use-note-versions.ts:109` (toast **Redo**) and `document-editor.tsx` "Notes enhanced" toast
   **Undo** call restore/undo directly, never via `guarded`. Fix: route every replace through `guarded`;
   refresh when `latest` is unknown; on a failed refresh show the confirm (fail closed).
4. **Readers see past versions and raw notes** — `versions.ts:45-62,131-141` gate history on
   `canReadDocument`, so any viewer (and the History button, `enhance-toolbar.tsx:153`) can read lines an editor
   removed before sharing, and the raw "My original notes". Docs/Notion keep history to editors. Fix: require
   `editDocument` for `GET /api/enhancements/:id` (at minimum drop `notes` for non-editors) and the list, hide
   History for viewers; update the viewer int test. (If viewer access is intended, record it in DECISIONS.)
5. **Name rule diverges from 5.5** — `apps/web/src/server/profile.ts:19` + `packages/db/src/profile.ts:46`
   accept an empty (or all-whitespace) name and write `user.name = ''`, shown blank in teammates' member lists;
   `/update-user` requires trimmed 1–100 (`packages/auth/src/server.ts:197`). Fix: `z.string().trim().min(1)
   .max(100)` with a shared limit, `required` on the form input, int test for `''`/`'   '` → 400.

Optional:
- Keyterms: 100 terms × 60 chars can exceed Deepgram's keyterm budget (~500 tokens) once desktop wires it → the
  listen connection fails. Cap in `stt-token.ts` (e.g. first N terms within a char budget) or at the consumer.
- `completedRuns` (`versions.ts:72`) loads every run's full `output_json` on each list/detail/guard refresh;
  select `id`/`createdAt` plus a hash or compare in SQL.
- Stale "Notes enhanced · Undo" toast stays up over the confirm/history dialogs (screenshots); dismiss it when a
  newer run or a restore happens.
