# 6.1 — Chunking + embeddings (pgvector) + indexing queue
status: done
milestone: M6 · deps: 3.3, 4.1 · branch: task/6.1-embeddings

## Goal
Everything a user can read is retrievable by meaning: notes and transcripts chunked with stable references
(block ids, segment ids + start_ms), embedded, stored in pgvector, kept fresh incrementally via a Redis-backed
job queue.

## Context
SPEC §6 `chunk`, D-11 (Redis in compose), D-19/D-22 (change_log drives incremental indexing),
`@oat/ai` (getEmbeddingModel, EMBEDDING_DIMENSIONS, mock embeddings with similarity property), `@oat/db`
(chunk table + HNSW cosine index; note reviewer's tip: filtered HNSW + `iterative_scan` for small workspaces),
`@oat/editor/markdown`, `@oat/core` permissions.

## Scope
In:
- Chunkers: notes → chunks by heading/section with block-id ranges (~300–500 tokens, overlap); transcripts →
  windows of consecutive segments (by time ~60–90 s / token budget) with segment-id range + start/end ms + source.
- Queue: BullMQ (or a minimal Redis list/stream worker — justify) `index-document` / `index-meeting` jobs,
  debounced per document, retries with backoff, idempotent (content hash per chunk; unchanged chunks keep
  embeddings). Worker entry runnable in-process in dev (`apps/web` instrumentation or a `pnpm worker` script —
  and a compose `worker` service in the `app` profile).
- Triggers: on document/segment writes (from change_log polling or direct enqueue in write paths — pick, note).
  Backfill script `pnpm --filter @oat/db index:backfill`.
- `searchChunks(ctx, query, {k, scope: {documentId?|workspace}})` → permission-filtered (SQL) hybrid ranking
  (vector cosine + FTS rank from 3.6 if merged, else vector only) returning references for citations.
- Tests: chunker unit tests (boundaries, refs), queue int (enqueue → embedded rows; unchanged content not
  re-embedded; deletes remove chunks), retrieval int (permission-safe across users/workspaces; relevant
  fixture chunk ranks top-3 with mock embeddings).
Out: chat tools/API/UI (6.2–6.4).

## Design notes
(implementer, 2026-11-14)

**Package.** New `packages/indexing` (`@oat/indexing`): `chunk-notes.ts`, `chunk-transcript.ts`, `text.ts`
(token estimate ≈ chars/4, sentence splitter, `chunkHash`), `indexer.ts` (`indexDocument`, `indexMeeting`,
`draftChunks`, `embedTexts`), `queue.ts` (Redis queue + `connectRedis`), `changes.ts` (change log → jobs),
`worker.ts` (`createIndexWorker`), `backfill.ts`, `retrieval.ts` (`searchChunks`), `env.ts`, CLIs in
`src/cli/` (`worker.ts`, `backfill.ts`), `Dockerfile`. Deps: `@oat/{ai,core,db,editor}`, `ai`,
`@ai-sdk/provider`, `drizzle-orm`, `redis` (all already in the catalog; no new third-party package).

**Schema (migration `0007_chunk_indexing.sql`, after main's `0005_document_share_transcript` and
`0006_search`).** `chunk` gains `source chunk_source('notes'|'transcript')`,
`ordinal`, `ref_ids text[]` (block ids or segment ids, in order; GIN-indexed so a segment delete finds the
chunks citing it), `content_hash` (sha256 of `provider/modelId` + text), `token_count`; check
`source = transcript ⇔ segment range present`. All new columns have defaults (old rows/tests keep working; a
hand-added `UPDATE` marks pre-existing ranged rows as transcript before the check). Index
`chunk_document_id_idx` → `(document_id, source, ordinal)`. `change_log` gets `(txid, seq)` for the global
follower. `CHUNK_SOURCES`/`chunkSourceEnum` live in `@oat/db` enums (core doesn't need them yet).
`readAllChanges(db, cursor, {limit, tables})` in `@oat/db/sync.ts`: `readChanges` across every workspace,
same D-22 visibility rule and cursor format; server-side consumers only. **Merge note (FACTORY migration
rule):** `main` (with 5.3 and 3.6) was merged in and the migration regenerated as `0007` with drizzle-kit;
`db:generate` reports no drift. 3.6's `0006` rewrites `oat_log_change()` to read only key columns
(`oat_change_keys`); the `change_log` rows it writes (`table_name, row_id, workspace_id, op`) are unchanged,
and those four fields are all the follower uses, so nothing changed here (the int tests confirm it on the
merged schema). No API routes were added, so no `denies(...)` markers. 3.6's FTS indexes documents and segments,
not chunks; 6.2 can plug a rank into `searchChunks({ ftsRank })` by joining on `document`.

**Chunkers (pure, deterministic).**
- Notes: top-level blocks → Markdown units via `@oat/editor/markdown/to-markdown` (the serializer file only:
  the barrel also pulls the parser, which plain Node type stripping can't run), each with its block id.
  A block > `maxTokens` (500) splits into child blocks (list items keep list markup and cite the item id), a
  leaf still too long into sentence-packed pieces sharing its id. Packing: target 400, max 500; a heading
  starts a new chunk once the current one has ≥ 120 tokens (tiny sections merge); within a section the next
  chunk repeats trailing units ≤ 60 tokens (never across a heading). Text = `<title> › <heading path>`, a
  blank line, then the body (the path is what's *above* the chunk's first unit). `refIds` = block ids in order.
- Transcript: final segments ordered by `(start_ms, id)`, greedy windows closing at ≥ 75 s or ≥ 400 tokens,
  never > 90 s / 500 tokens; the next window repeats trailing segments that started ≤ 10 s before the end
  (≤ 60 tokens, never the whole window). Greedy-from-start ⇒ **prefix-stable**: appending segments (live
  meeting) only changes the last window, so earlier chunks keep hash + embedding. Lines `Me: …` (mic) /
  `<speaker_label|Them>: …`, consecutive same-speaker segments joined. Prefix `Transcript · <title>`. A single
  segment over the budget becomes several chunks citing it. `refIds` = segment ids; `segment_start/end_ms`.

**Indexer (idempotent, bounded).** Chunk (capped at `maxChunksPerDocument`) → hash → embed only hashes not
already stored for the document, in batches of 64, each batch inserted right away ("staged") → reconcile in
one transaction. Every write holds `pg_advisory_xact_lock(hashtextextended('chunk:'||doc))` and the document
row `FOR KEY SHARE`. Reconcile re-reads the document's `updated_at`/title (changed → start over, ≤ 3 rounds),
reuses rows by hash (updates ordinal/refs/range if they moved) and deletes leftovers (old chunks, staged rows of
an abandoned run). A deleted document returns `missing` (its chunks cascaded). Vector width is checked
against `EMBEDDING_DIMENSIONS`. The only job, `document:<id>`, indexes notes **and** transcript (the title
prefixes both, so a rename must refresh both; unchanged transcript windows cost one indexed query, no
embeddings). (Review round 1 changed the queue keys, staging and caps; see *Review → Resolution*.)

**Trigger: change-log polling (picked over enqueue-in-write-paths).** The worker follows `change_log`
(`readAllChanges`, unfiltered so the cursor also moves past other tables' rows; it keeps
document/meeting/transcript_segment) after a cursor stored in Redis, maps changes to jobs and enqueues them
*before* advancing the cursor (crash = re-read, never lost). Why: transcript
segments arrive through the desktop sync push (2.6/3.5, not built yet), and other writers (Better Auth,
seeds, cascades, future server jobs like 4.4 enhance) would each need a hook; the log already captures them
all (D-22), and if Redis or the worker is down nothing is lost — the follower catches up. Cost: latency =
poll (500 ms) + debounce (1.5 s), and one cheap indexed query per poll. Consequently **no `apps/web`
changes**. Mapping (always one `document:<id>` key per document): document upsert → itself; meeting upsert
→ its document; segment upsert → its meeting's document; segment delete (row gone) → the documents whose
chunks' `ref_ids` contain it;
document delete → nothing (cascade). Soft delete (trash) is an upsert; chunks are **kept** and search filters
trash at query time (restore is instant, no re-embed). Known gap: deleting a `meeting` row while its document
survives isn't mapped (no code path does that; the next document job removes the stale transcript chunks).
One follower at a time per queue (`SET NX PX` lock, renewed after every page); no stored cursor = from the beginning
(re-checks everything, cheap). If 3.5 prunes `change_log` past a stale cursor, run `index:backfill`.

**Queue: minimal Redis sorted-set queue, not BullMQ (justification).** Our jobs are "re-index X soon": they
must be deduplicated and debounced per document, retried, and survive worker crashes. That is one ZSET keyed
by job id with score = due time, plus five Lua scripts (`queue.ts`, ~300 lines) on the `redis` client
`@oat/auth` already uses. BullMQ would add ioredis (a second client), blocking connections (costly on
Upstash), and its dedup/delay options would still have to be bent into a trailing debounce. Semantics:
`enqueue` → due = min(now + debounce, first + maxWait) (1.5 s / 10 s), so a continuously edited doc still
indexes every 10 s; `claim` moves due jobs to `active` with a lease (2 min, extended by a worker heartbeat;
expired → back to pending, or to `failed` if that was the last attempt) and an owner token, and never claims
an active job (a change during a run → it runs again afterwards); `complete`/`fail`/`extend` only act for the
current token; `fail` → retry after 1 s·2^(n-1) (cap 5 min), after 5 attempts → `failed` hash with the last
error; a later change gives it a fresh start.

**Retrieval.** `searchChunks({ db, permissions, embeddingModel? }, query, { k=8 (≤50), scope?: {documentId}
| {workspaceId}, sources?, ftsRank? })` → `ChunkHit { chunkId, documentId, workspaceId, documentTitle,
documentKind, ordinal, text, ref: {source:'notes', blockIds} | {source:'transcript', segmentIds, startMs,
endMs}, similarity, score }`. Permission filter in SQL (`readableChunkFilter`): chunk workspace ∈ actor's
memberships (∩ scope), `document.workspace_id = chunk.workspace_id`, document `deleted_at is null`,
workspace `deleted_at is null` (soft-deleted workspaces from main, even if a caller's context still lists the
membership), owner = actor or visibility ≠ private — exactly `canReadDocument` for live docs without a share
token; every row is then
re-checked with `canReadDocument` (defence in depth). Share tokens never widen search (deliberate: a link
grants reading one page). Ranking: cosine on HNSW with `SET LOCAL hnsw.iterative_scan = relaxed_order` and
`ef_search` sized to the candidate count (the 1.5 reviewer tip for filtered HNSW on small workspaces),
re-sorted by exact distance; `score = similarity`. **FTS hook:** `ftsRank(query) → SQL<number>` adds a second
candidate list, fused by reciprocal rank fusion (k = 60). 3.6 isn't merged, so nothing depends on its
columns; `chunkTextFtsRank` (on-the-fly `ts_rank(to_tsvector('simple', text))`) is provided for tests and
small data. 6.2 should pass 3.6's indexed rank once it lands.

**Running it.** `pnpm dev` runs the worker (`@oat/indexing` `dev` script = `tsx watch src/cli/worker.ts`;
turbo's `dev` already passes DATABASE_URL/REDIS_URL/AI_*/MOCKS_URL/OAT_*). Alone:
`pnpm --filter @oat/indexing worker`. Compose: service `worker` (profile `app`, image `oat-worker:dev` from
`packages/indexing/Dockerfile`: prod deps of `@oat/indexing...`, Node's built-in TS like `migrate` but with
`--experimental-transform-types`, since `@oat/editor`'s parser uses parameter properties; no build step),
depends on migrate + postgres/redis/mocks; the indexing code imports `@oat/ai/provider`, not the `@oat/ai`
barrel (which now loads 4.3's context/prompt code); `pnpm dev:app` builds and starts it. Backfill:
`pnpm --filter @oat/db index:backfill` (delegates to `@oat/indexing backfill`: `--workspace`, `--enqueue`,
`--concurrency`). Env (in `.env.example` + DEV.md "Retrieval indexing"): `OAT_INDEX_QUEUE_PREFIX` (default
`oat:idx`), `OAT_INDEX_DEBOUNCE_MS` (1500), `OAT_INDEX_CONCURRENCY` (2).

**Tests.** Unit: `chunk-notes.test.ts`, `chunk-transcript.test.ts`, `text.test.ts`. Int (throwaway DB per
file; shared Redis with an `oat-test:idx:<uuid>` prefix per queue, cleared afterwards): `queue.int.test.ts`,
`indexing.int.test.ts` (running worker: write → indexed; stepped worker via `followOnce`/`processOnce`),

## Review
(reviewer, 2026-11-14) **Verdict: changes.**

Checked and fine: `readAllChanges` applies the D-22 rule (`txid < pg_snapshot_xmin`, `(txid, seq)` cursor,
only past returned rows) so out-of-order commits are deferred, never skipped; enqueue-before-cursor-advance
(crash = re-read); cursor-less start = full catch-up; Lua claim/enqueue are atomic (no double claim across
workers); debounce/maxWait math; content-hash reuse (model key in hash); trash/soft-deleted workspace filtered
at query time, hard delete cascades; `readableChunkFilter` is applied before LIMIT (no ranking side channel)
and matches `canReadDocument` for live docs; k clamped 1..50; `EMBEDDING_DIMENSIONS` checked on every embed;
`iterative_scan = relaxed_order` + `ef_search`; Dockerfile runs as `node`, no secrets baked in. Unit tests pass.

1. **Chunker stack overflow on one oversized list item** — `packages/indexing/src/chunk-notes.ts:68-78`. A
   single `listItem`/`taskItem` over `maxTokens` (≈ 2 000 chars, e.g. a pasted paragraph in a bullet) is
   re-wrapped as `{...list, content: [item]}`, which is still over budget with the same single child, so it
   recurses forever. Reproduced: `RangeError: Maximum call stack size exceeded`. The job fails 5× and the whole
   document is never indexed. Fix: when the node being split is already a one-item wrapper (or the child is
   the only block child), recurse into the item's own children (paragraphs / nested lists, citing the item
   id) or fall through to `splitLongText`; add a unit test.
2. **Queue lease recovery: poison jobs loop forever; stale owners can release a re-claimed job** —
   `packages/indexing/src/queue.ts:107-112` (CLAIM expiry loop) and `:128-151` (COMPLETE/FAIL). (a) A job that
   kills the process (OOM on a huge doc, crash) is put back on lease expiry and re-claimed indefinitely:
   `attempts` keeps growing but `maxAttempts` is only checked in FAIL, so it never reaches `failed`. Fix: in
   the expiry loop, if `attempts >= maxAttempts` move it to `failed` ("lease expired") instead of pending.
   (b) COMPLETE/FAIL don't check ownership: after a 5-min lease expires and worker B re-claims, slow worker A's
   `complete`/`fail` ZREMs B's `active` entry, so a third claim can run the same key concurrently with B (and
   combined with 3 below, stale content can win). Fix: return a claim token from CLAIM (e.g. store
   `token` in an `owner` hash) and make COMPLETE/FAIL no-ops on mismatch; ideally heartbeat-extend the lease
   while a job runs.
3. **Cross-key race leaves stale transcript chunks** — `packages/indexing/src/changes.ts:29-31` +
   `indexer.ts:129-140,161-170`. `document:X` and `meeting:M` (X's meeting) are different keys, so the queue
   lets them run at the same time; both rewrite X's transcript chunks from state read *before* the advisory
   lock, and the later committer wins even if it read older state. E.g. `meeting:M` reads title "Old", the
   user renames, `document:X` commits "Transcript · New" chunks, then `meeting:M` commits and replaces them
   with "Old" — nothing re-queues, stale until the next edit. Fix: resolve meeting/segment changes to
   `document:<documentId>` in `jobsForChanges` (one key per document ⇒ single-flight via `active`), or
   re-read `title`/`updated_at` inside the locked transaction and retry when they changed.
4. **No cost/size cap per document** — `packages/indexing/src/indexer.ts:140-158`. A multi-MB pasted page or
   a very long transcript produces an unbounded number of chunks, all embedded in one `embedMany` within one
   job (held in memory, racing the 5-min lease, re-paid in full on any retry). Add a `maxChunksPerDocument`
   (e.g. 1 000; truncate + log/metric) and embed in bounded batches.

Optional:
- `worker.ts:77-96`: `followPages` doesn't renew the follower lock between pages; a big backlog (first start,
  lost cursor) can outlast the 10 s TTL and start a second follower (duplicate enqueues, cursor may step
  back; nothing skipped). Renew per page.
- `queue.ts` ENQUEUE overrides a pending retry's backoff (plain `ZADD`): on a live meeting a failing job
  retries at debounce cadence, and after `failed` every change restarts it with fresh attempts — with a
  post-embedding failure (e.g. dimension mismatch) each run re-pays embeddings. Consider keeping the later
  of (debounce due, backoff due) while `attempts > 0`.
- `packages/db/src/sync.ts:84-116` duplicates `readChanges`' query; share one builder so the D-22 rule lives
  once, and add an in-flight-transaction case for `readAllChanges`.
- `retrieval.ts:180`: nothing checks the query model matches the model the chunks were hashed with; after a
  model switch (before backfill) scores are meaningless. Could warn/filter by model key.
- `.dockerignore` `.env*` matches the root only; `COPY packages/ packages/` would ship `packages/*/.env*`.
  Use `**/.env*` (pre-existing file).
- `worker.ts:133-157`: `processOnce` awaits the whole batch, so one slow job blocks the other slots.

**Resolution (implementer, round 1)** — all 4 fixed; optional follower-lock renewal done too.
1. `chunk-notes.ts` `unitsOf`: a multi-item list is re-wrapped one item per list; a one-item list (or an
   item, quote, callout) is only *descended into*, so every call is on a strictly smaller subtree; children
   without an id cite the nearest ancestor's; depth > 32 falls back to `splitLongText`. Tests: a single
   10 000+-char item in bullet/ordered/task lists (`it.each`), and a huge item with an id-less paragraph +
   nested list.
2. `queue.ts`: CLAIM's lease-expiry pass sends a job whose attempts reached `maxAttempts` to `failed`
   ("lease expired …") instead of back to pending. Each claim gets a token (`owner` hash); COMPLETE / FAIL /
   new EXTEND are no-ops unless the token still owns the job (`complete` → false, `fail` → `{stale: true}`).
   The worker heartbeats (`extend` every lease/3, lease now 2 min). Tests: poison job → `failed` after 3
   expiries; two queue instances on one prefix: A extends, hangs past its lease, B re-claims (attempt 2), A's
   complete/fail/extend change nothing, no third concurrent claim, B completes, the change made meanwhile runs.
3. `changes.ts`: meeting and segment changes resolve to `document:<documentId>` (one key per document ⇒
   single-flight through `active`). Also `indexer.ts` re-reads the document's `updated_at` + title under the
   advisory lock and starts over (≤ 3 rounds, then throws → retry) if they changed. Tests: rename + meeting +
   segment insert/delete map to exactly `[document:X]`; a rename landing mid-embed leaves only "New title"
   chunks (notes and transcript).
4. `maxChunksPerDocument` (`OAT_INDEX_MAX_CHUNKS`, default 1000; notes and transcript each keep ≥ half when
   both are long; dropped count returned as `truncated` and logged), embedding in batches of
   `embedBatchSize` (default 64). Each embedded batch is inserted right away ("staged", under the lock); the
   final reconcile matches rows by hash and deletes leftovers, so a run that fails halfway keeps its paid-for
   embeddings and the retry embeds only the rest. Tests: cap 5 / batch 2 → 5 chunks, calls `[2, 2, 1]`; second
   embed call throws → 1 staged row; retry embeds `n - 1` and keeps that row.
- Optional: the follower renews its lock after every change-log page and stops if it was lost.
- Not done (minor list): model-key check in retrieval, `.dockerignore` (pre-existing, outside scope),
  per-slot processing (batch waits for its slowest job; fine at concurrency 2).
