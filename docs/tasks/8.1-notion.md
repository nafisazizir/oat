# 8.1 — Notion integration (connect, choose target, push/update note)
status: done
milestone: M8 · deps: 3.2, 3.3, 7.4 · branch: task/8.1-notion

## Goal
Send a meeting note to Notion and keep it updated: connect a Notion workspace via OAuth, pick a target page or
database, push a note (create) and re-push (update the same Notion page). Dev uses a Notion API subset in
`tools/mocks` (D-11) — no real Notion calls.

## Context
SPEC §4 Integrations, §6 `integration` table, D-11, D-4 (TipTap JSON canonical → Notion blocks derived),
`@oat/editor` schema (+ `@oat/editor/markdown` for fallbacks), `@oat/auth` (7.4's encrypted token storage /
connect-only provider pattern — reuse its encryption helper), `apps/web` `/settings/integrations` (7.4),
documents API (3.3), `tools/mocks` provider structure.

## Scope
In:
- OAuth connect ("Connect Notion"): Notion's OAuth (authorize → token exchange with basic auth) against env
  `NOTION_BASE_URL`/`NOTION_OAUTH_*` (default: mocks `notion` provider implementing `/v1/oauth/token`, an
  authorize page that auto-approves in dev). Store the integration row (workspace_id, user_id, provider
  'notion', encrypted access token, bot id, workspace name/icon, settings_json {targetType, targetId}).
- `tools/mocks` `notion` provider subset: search (pages/databases the integration can see), retrieve
  database (properties schema), create page (parent page or database; properties title/date/people as rich
  text; children blocks ≤ 100 per request), append block children (paging), update page properties, archive
  blocks (for replace), request log. Validate payload shapes like Notion does (block types, rich_text limits:
  2000 chars per text object, 100 blocks per append) and return Notion-style errors.
- `packages/integrations-notion`: TipTap JSON → Notion blocks converter (paragraph, headings 1–3, bulleted/
  numbered lists with nesting ≤ 2 levels as Notion allows, to_do, quote, code w/ language, divider, callout
  w/ emoji, links/bold/italic/strike/code/highlight annotations, mentions → plain text), chunking long text
  into 2000-char rich_text pieces, batching ≤ 100 blocks; meeting properties (date, attendees as text,
  "Oat link"). Update strategy: store notion_page_id per document (new table `document_export` or
  settings JSON — migration), on re-push replace children (archive old blocks, append new) + update props.
- `apps/web`: settings — connect/disconnect, choose target (searchable picker from mock search);
  document page "Send to Notion" / "Update in Notion" action with status + link; API routes with authz
  (only users who can read the doc; integration owner's token) and rate limiting.
- Tests: converter unit tests (every block/mark, long text splitting, nesting limits), mocks tests (Notion
  validation), int (connect flow, push, re-push replaces content, token revoked → clear error), e2e
  (connect → choose target → send → mock request log shows created page). Screenshots.
Out: two-way sync, Notion → Oat import, scheduled pushes (8.3).

## Design notes
(implementer, 2026-11-14)

**Shape.**
```
Settings → Integrations (Notion card, active Oat workspace)
  form POST /api/integrations/notion/connect ──303──► ${NOTION_BASE_URL}/v1/oauth/authorize (mock: auto-approve)
        + signed state cookie (HttpOnly, Lax, 10 min, path /api/integrations/notion)
  GET /api/integrations/notion/callback?code&state ─► POST /v1/oauth/token (Basic) ─► integration row
        (secret_encrypted = @oat/auth encryptSecret(token); settings_json: Notion workspace, bot, target)
  target picker ─► GET …/targets?q (POST /v1/search) · PUT …/target (GET /v1/pages|databases/{id})
Document page "Send to Notion" / "Update in Notion"
  POST /api/documents/:id/notion ─► server/notion.ts sendToNotion ─► @oat/integrations-notion pushNote
        ─► POST /v1/pages (+ PATCH /v1/blocks/{page}/children batches)                    first time
        ─► GET page, PATCH page props, GET children, PATCH children, DELETE old blocks    re-push
        document_export (document_id, integration_id) → external_id/url, pushed_version, lease
```

**API version.** `Notion-Version: 2022-06-28` everywhere (client and mock): the long-stable version whose
database parent is `database_id` and whose search returns `database` objects. 2025-09-03's data sources would
change create-in-database and search; moving later is a client + mock change only (follow-up).

**`@oat/integrations-notion`** (fetch + zod, no Notion SDK; server-side):
- `convert.ts` `toNotionBlocks(doc, { baseUrl })`: paragraph, heading 1–3, bulleted/numbered list items, to_do
  (checked), quote, callout (emoji icon; variant → `gray|blue|green|yellow|red_background`), code (language mapped
  to Notion's enum with aliases, else `plain text`), divider. Containers (list item, quote, callout) use their
  first paragraph/heading as their own text, the rest as children. Marks: bold, italic, strike → strikethrough,
  code, highlight → `yellow_background`, link (absolute http(s)/mailto; relative links resolved against the app
  URL, unsafe ones dropped). Mentions → `@Name` plain text, hard breaks → `\n`; equal adjacent runs merged.
  Limits: text split into ≤ 2000-char items (never inside a surrogate pair); > 100 rich-text items continue in
  following paragraphs (code: more code blocks); **nesting ≤ 2 levels below the top**: deeper blocks are lifted
  to the deepest allowed level in document order (no follow-up requests); a children array over 100 lifts the
  rest after its parent; trailing empty paragraphs dropped. `batchBlocks`: ≤ 100 top-level blocks, ≤ 1000
  elements and a bounded JSON size per request. The converter tests run every request through the mock's own
  validator (`@oat/mocks/providers/notion/validate`), so "Notion-valid" is checked, not assumed.
- `properties.ts`: page parent → `title` only, plus a grey metadata line at the top of the body (date in the
  sender's zone, "Attendees: …", "Open in Oat" link) and a divider. Database parent → its title column, a `date`
  column (named like date/when, else the first), a `rich_text` column named like attendees/participants (people
  as text: Notion `people` need Notion user ids), a `url` column (oat/link/url…); whatever has no column goes into
  the metadata line. We never change a database's schema. Date = meeting `started_at`, else the note's creation.
- `client.ts` `NotionClient`: bearer + version, 15 s timeout, 429 → `Retry-After` (capped 10 s) and 502/503/504 →
  backoff, ≤ 3 retries; `NotionAuthError` (401) vs `NotionApiError` (`isNotFound()`); `listChildren` follows
  cursors. OAuth: `notionAuthorizeUrl` (`owner=user`), `exchangeNotionCode` (HTTP Basic), `revokeNotionToken`
  (best effort, never throws).
- `push.ts` `pushNote` (revised after review): Oat only removes what it wrote. The caller passes the top-level
  block ids an earlier push wrote (`ownedBlockIds`, stored in `document_export.block_ids`); a re-push archives
  only those, and never a `child_page`/`child_database` block (unknown ownership = legacy rows → everything but
  sub-pages/databases). Create = `POST /pages` (properties only) → `checkpoint` → content appended in batches.
  `checkpoint(state = { page, blockIds })` runs before/after every write (the caller renews its lease and
  records page + ids there); if it throws, the push stops and archives the batch it just appended. Re-push:
  page gone (404) or archived/in trash → a new page in the current target; else update properties against the
  page's *own* parent, append the new content, then archive the owned old blocks (3 in parallel). New before
  old: a failure leaves duplicates that are still owned, so the next push removes them. A not-found while
  creating in the target is `NotionTargetMissingError` (only that clears the chosen target).
- `config.ts` `resolveNotionConfig`: `NOTION_BASE_URL` → api.notion.com when `NOTION_OAUTH_CLIENT_ID` is set →
  `${MOCKS_URL}/notion` → (production: `null` = not configured; the card says "Not available") → localhost mock.
  Real Notion needs client id and secret; the mock defaults them to `oat-dev`.

**Data (migration `0008_notion_export`, regenerated on top of main's 0005–0007; `db:generate` shows no drift).**
New column `integration.secret_encrypted` (`credentials_ref` stays "a reference, never the secret") and table
`document_export (document_id → document cascade, integration_id → integration cascade, external_id,
external_url, block_ids jsonb, pushed_version, pushed_at, lease_until, lease_id, timestamps)`, unique per
(document, integration). Neither is synced (no change-log trigger). The `integration` row is per (Oat workspace,
user, provider) as SPEC §6 has it; `settings_json` = `{ notionWorkspaceId/Name/Icon, botId, targetType, targetId,
targetTitle, targetUrl, needsReconnect }`. Disconnect deletes the row and with it the mapping.

**`@oat/auth` `encryptSecret` / `decryptSecret`** (`secrets.ts`): Better Auth's `symmetricEncrypt` with the auth
instance's `secretConfig`, i.e. the same XChaCha20-Poly1305 key and `BETTER_AUTH_SECRETS` rotation 7.4 uses for
OAuth tokens on `account`. Notion can't live on `account` (not OIDC; the token belongs to a workspace bot, and
the connection is per Oat workspace).

**apps/web.**
- `server/notion.ts` (deps injected: db, auth, config, appUrl, state secret, rate limiter, fetch):
  `startNotionConnect` / `completeNotionConnect` (state = 18 random bytes; cookie `state.workspaceId.hmac`,
  HMAC-SHA256 over user id + state + workspace with the auth secret, compared in constant time; denied / bad
  state / failed exchange → `?notion_error=denied|state|exchange`; reconnecting the same Notion workspace keeps
  the target), `disconnectNotion` (revoke at Notion, delete), `searchNotionTargets` (25 most recent, no database
  rows), `setNotionTarget` (retrieves it first: unknown/unshared → 400), `getNotionDocumentStatus`, `sendToNotion`.
- **Authz:** connecting/searching needs membership of the workspace (`@oat/core` `roleIn`; non-member → 404).
  Sending needs read access to the note (`getDocument` → `canReadDocument`; unreadable → 404, so a viewer may send
  what they can read) and always uses the **sender's own** connection for the note's workspace; trashed → 400.
  Writes go through `apiRoute`'s CSRF check (connect is a form POST, so it is checked too).
- **Rate limits / concurrency:** sends 10/min/user, searches 60/min/user (`@oat/auth` Redis limiter; memory in
  tests) → 429 + `Retry-After`. A push takes a 2-minute lease on its `document_export` row (insert, or take over
  a free/expired lease); a concurrent push → 409 `notion_busy`.
- **Errors:** Notion 401 → `needsReconnect` stored + 409 `notion_reconnect` "Oat can no longer reach your Notion
  workspace. Reconnect Notion in Settings → Integrations." (settings shows "Reconnect needed" + Reconnect; the
  note's toast links there). Target gone (404 on create) → target cleared, 409 `notion_no_target`. Other Notion
  errors → 502 `notion_error` with Notion's message; unreachable → 502. A token that no longer decrypts (secret
  rotated away) → reconnect. Links from Notion are rendered only if http(s) (`safeUrl`).
- Routes: `POST /api/integrations/notion/connect`, `GET …/callback`, `GET|DELETE /api/integrations/notion`,
  `GET …/targets`, `PUT …/target`, `GET|POST /api/documents/:id/notion` (factory `server/api/notion.ts`, wired in
  `server/api/index.ts` next to the documents API).
- UI: Notion card under Google Calendar on `/settings/integrations` (status badge, connect form, Notion workspace
  + "For <workspace> · connected <date>", Disconnect, target picker = Popover + Command with server-side search
  (debounced, `shouldFilter=false`), "Open … in Notion" link, dev-mock note, success/error banners). Document
  page: `NotionExportButton` at the end of the header row (only when Notion is configured; hidden in the trash):
  "Send to Notion" / "Update in Notion", "In Notion · <day>" link, or "Notion copy is older" when the note
  changed since (version compare); flushes pending autosave first; toasts with "Open" / "Open settings" actions.

**Mock (`tools/mocks` `notion`).** See DEV.md "The notion provider". Page `url`s point at the mock's own HTML
viewer (`/notion/_mock/view/{id}`), so links work offline and the e2e can look at the Notion copy.

## Review
(reviewer, 2026-11-14) — task file + `git diff $(git merge-base main task/8.1-notion)..task/8.1-notion`.

**Verdict: changes**

Checked and fine: OAuth state (random state, HMAC over user+state+workspace, constant-time compare,
HttpOnly/Lax/path-scoped 10-min cookie cleared on callback, membership re-checked, `redirect_uri` fixed from
`appUrl`); connect POST through `apiRoute` CSRF; token encrypted at rest (`encryptSecret`), absent from
responses/UI/logs/sync, revoked on disconnect; send = `getDocument` read check + the sender's own
`integration` row only (no teammate token, no other user's target); no user-controlled URL fetched
(`NotionId` regex, ids path-encoded, base URL from env only); links limited to http(s)/mailto ≤ 2000,
`javascript:` dropped (tested); 2000-char split, 100 rich-text items, 100 children, nesting ≤ 2, ≤ 1000
elements/request; links rendered from Notion go through `safeUrl`; transcript is not sent.

1. **Migration number collides with main.** `packages/db/drizzle/0005_notion_export.sql` (+ `meta/0005_snapshot.json`,
   `_journal.json`): main now has `0005_document_share_transcript` and `0006_search`. Per FACTORY "Migrations in
   parallel branches": merge `main`, regenerate as `0007_…`, `db:generate` shows no drift, re-run `pnpm run ci`.
2. **Authz coverage (D-25) will fail after merging main.** Main's `apps/web/src/server/api/authz-coverage.test.ts`
   requires every route handler to have a `denies('<METHOD> <route>')` marker (or a reasoned PUBLIC/SELF_SCOPED
   entry). The 8 new handlers (`POST …/notion/connect`, `GET …/notion/callback`, `GET|DELETE /api/integrations/notion`,
   `GET …/targets`, `PUT …/target`, `GET|POST /api/documents/[id]/notion`) have none. The deny tests already exist in
   `notion.int.test.ts`; add the markers there (callback: marker for the foreign/missing-state cases, or a reasoned entry).
3. **Re-push archives the user's Notion sub-pages.** `packages/integrations-notion/src/push.ts:88-99` lists *all*
   top-level children and `DELETE`s each; `DELETE /blocks/{id}` on a `child_page`/`child_database` block trashes
   that page/database (e.g. a follow-up page the user nested under the exported note). Fix: skip
   `child_page`/`child_database` (and ideally only delete block ids Oat wrote, stored on `document_export`); add a
   push test with a nested child page that survives re-push.
4. **Lease can expire mid-push and is released unfenced.** `apps/web/src/server/notion.ts:527-545`: `LEASE_MS` = 2 min,
   but replacing a long note against real Notion (one DELETE per old block at ~3 req/s, 429 waits up to 10 s × 3,
   15 s timeouts) can exceed it; a second push then takes the lease and both append (duplicate content, or two
   pages on create), and the first push's `release()` (`where id = lease.id`) clears the second push's lease.
   Fix: fence writes/release on the lease value you took (`where id = … and lease_until = <yours>`), and renew the
   lease between batches (or size it to the function's max duration).
5. **Attendee emails leave Oat.** `apps/web/src/server/notion.ts:460` falls back to `participant.email` when there
   is no name, so third parties' addresses are written into the Notion page body / database column; the design
   says "people as text". Send names only (skip or use the local part for email-only participants), or record
   the choice in DECISIONS; add a test.

Optional:
- `notion.ts:579-596`: any 404/`restricted_resource` during a push clears the chosen target, including on re-push
  (e.g. `retrieveDatabase` of the existing page's *own* parent, which may not be the target). Limit to the create path.
- `notion.ts:288-291`: `signature.length` is UTF-16 length; a non-ASCII cookie makes `timingSafeEqual` throw → 500.
  Compare buffer lengths. Consider an issued-at in the signed state instead of relying on cookie `Max-Age` alone.
- Mock fidelity: `tools/mocks/src/providers/notion/validate.ts:161-166` accepts any scheme (`javascript:`) for
  `text.link.url`; real Notion rejects non-web URLs. Tighten so the e2e path would catch a converter regression.
- `disconnectNotion` requires membership: a user removed from the workspace can't revoke their stored token.
- `properties.ts:82`: the `url` column falls back to the first URL column of any name (may overwrite e.g. "Recording").
