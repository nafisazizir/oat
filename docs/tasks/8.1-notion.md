# 8.1 — Notion integration (connect, choose target, push/update note)
status: in-progress
milestone: M8 · deps: 3.2, 3.3, 7.4 · branch: task/8.1-notion

## Goal
Send a meeting note to Notion and keep it updated: connect a Notion workspace via OAuth, pick a target page or
database, push a note (create) and re-push (update the same Notion page). Dev uses a Notion API subset in
`tools/mocks` (D-11) — no real Notion calls.

## Context
SPEC §4 Integrations, §6 `integration` table, D-11, D-4 (TipTap JSON canonical → Notion blocks derived),
`@oat/editor` schema (+ `@oat/editor/markdown` for fallbacks), `@oat/auth` (7.4's encrypted token storage /
connect-only provider pattern — reuse its encryption helper), `apps/web` `/settings/integrations` (7.4),
documents API (3.3), `tools/mocks` provider structure.

## Scope
In:
- OAuth connect ("Connect Notion"): Notion's OAuth (authorize → token exchange with basic auth) against env
  `NOTION_BASE_URL`/`NOTION_OAUTH_*` (default: mocks `notion` provider implementing `/v1/oauth/token`, an
  authorize page that auto-approves in dev). Store the integration row (workspace_id, user_id, provider
  'notion', encrypted access token, bot id, workspace name/icon, settings_json {targetType, targetId}).
- `tools/mocks` `notion` provider subset: search (pages/databases the integration can see), retrieve
  database (properties schema), create page (parent page or database; properties title/date/people as rich
  text; children blocks ≤ 100 per request), append block children (paging), update page properties, archive
  blocks (for replace), request log. Validate payload shapes like Notion does (block types, rich_text limits:
  2000 chars per text object, 100 blocks per append) and return Notion-style errors.
- `packages/integrations-notion`: TipTap JSON → Notion blocks converter (paragraph, headings 1–3, bulleted/
  numbered lists with nesting ≤ 2 levels as Notion allows, to_do, quote, code w/ language, divider, callout
  w/ emoji, links/bold/italic/strike/code/highlight annotations, mentions → plain text), chunking long text
  into 2000-char rich_text pieces, batching ≤ 100 blocks; meeting properties (date, attendees as text,
  "Oat link"). Update strategy: store notion_page_id per document (new table `document_export` or
  settings JSON — migration), on re-push replace children (archive old blocks, append new) + update props.
- `apps/web`: settings — connect/disconnect, choose target (searchable picker from mock search);
  document page "Send to Notion" / "Update in Notion" action with status + link; API routes with authz
  (only users who can read the doc; integration owner's token) and rate limiting.
- Tests: converter unit tests (every block/mark, long text splitting, nesting limits), mocks tests (Notion
  validation), int (connect flow, push, re-push replaces content, token revoked → clear error), e2e
  (connect → choose target → send → mock request log shows created page). Screenshots.
Out: two-way sync, Notion → Oat import, scheduled pushes (8.3).

## Acceptance criteria
- [ ] Push + update work against the mock with Notion-valid payloads; no real Notion calls.
- [ ] `pnpm run ci` green.
