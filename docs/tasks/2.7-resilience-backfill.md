# 2.7 + 2.9 — Recording resilience + archive backfill
status: in-progress
milestone: M2 · deps: 2.5, 2.6, 2.8 · branch: task/2.7-resilience-backfill

## Goal
A recording never silently loses anything (SPEC §8): crash-left recordings are repaired at startup, long STT
outages are back-filled from the local Opus archive, and quit/crash mid-recording leaves a consistent meeting.

## Context
SPEC §8, D-10, D-17 (≥120 s replay buffer; longer gaps back-filled from the archive), D-24 (parts, meeting clock),
D-28 (audio index never wiped), D-30, `@oat/audio` (recoverRecordings/repairOpusFile, readMeetingRange),
`@oat/stt` (DeepgramProvider; a batch/pre-recorded transcription call — add `transcribeFile`/batch method to the
provider + mock: Deepgram pre-recorded API subset in tools/mocks), `apps/desktop` RecordingService (2.5),
meeting persistence (3.4), sync (2.6/3.5). Note from 3.8: `recoverRecordings` is never called at startup.

## Scope
In:
- Startup recovery: call `recoverRecordings` (signed-in account's recordings) at launch; repaired files marked
  partial/complete; meeting left "recording" by a crash is closed (`ended_at` = last segment/audio end) with an
  issue shown on the note ("Oat quit unexpectedly — recording saved up to 10:42").
- Gap detection: track STT coverage per source (finals' time ranges) vs audio captured; a gap > replay buffer
  (or any gap left after reconnect) becomes a backfill job.
- Backfill: after STT recovers (or after stop), read the gap range from the archive (`readMeetingRange`),
  send to the provider's batch API (mock in dev), merge returned segments as finals with stable ids on the
  meeting clock (dedupe against existing finals), mark them `backfilled`; progress + result visible in the
  transcript panel ("Filling in 2 min of transcript…"). Persisted job queue in local-store so it survives quit.
- Quit/crash mid-recording e2e: kill the Electron main process during a FileSource recording → relaunch →
  meeting closed, audio repaired, transcript up to the kill point present, no duplicate segments.
- Tests: unit (gap math, merge/dedupe), int (mock batch STT), desktop e2e (STT down for 3 min with fast
  FileSource → gap backfilled after recovery; kill-relaunch recovery). Never real capture.

## Acceptance criteria
- [ ] Startup recovery + backfill + crash e2e pass; nothing silently lost; `pnpm run ci` green.
