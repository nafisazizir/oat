# 2.7 + 2.9 — Recording resilience + archive backfill
status: done
milestone: M2 · deps: 2.5, 2.6, 2.8 · branch: task/2.7-resilience-backfill

## Goal
A recording never silently loses anything (SPEC §8): crash-left recordings are repaired at startup, long STT
outages are back-filled from the local Opus archive, and quit/crash mid-recording leaves a consistent meeting.

## Context
SPEC §8, D-10, D-17 (≥120 s replay buffer; longer gaps back-filled from the archive), D-24 (parts, meeting clock),
D-28 (audio index never wiped), D-30, `@oat/audio` (recoverRecordings/repairOpusFile, readMeetingRange),
`@oat/stt` (DeepgramProvider; a batch/pre-recorded transcription call — add `transcribeFile`/batch method to the
provider + mock: Deepgram pre-recorded API subset in tools/mocks), `apps/desktop` RecordingService (2.5),
meeting persistence (3.4), sync (2.6/3.5). Note from 3.8: `recoverRecordings` is never called at startup.

## Scope
In:
- Startup recovery: call `recoverRecordings` (signed-in account's recordings) at launch; repaired files marked
  partial/complete; meeting left "recording" by a crash is closed (`ended_at` = last segment/audio end) with an
  issue shown on the note ("Oat quit unexpectedly — recording saved up to 10:42").
- Gap detection: track STT coverage per source (finals' time ranges) vs audio captured; a gap > replay buffer
  (or any gap left after reconnect) becomes a backfill job.
- Backfill: after STT recovers (or after stop), read the gap range from the archive (`readMeetingRange`),
  send to the provider's batch API (mock in dev), merge returned segments as finals with stable ids on the
  meeting clock (dedupe against existing finals), mark them `backfilled`; progress + result visible in the
  transcript panel ("Filling in 2 min of transcript…"). Persisted job queue in local-store so it survives quit.
- Quit/crash mid-recording e2e: kill the Electron main process during a FileSource recording → relaunch →
  meeting closed, audio repaired, transcript up to the kill point present, no duplicate segments.
- Tests: unit (gap math, merge/dedupe), int (mock batch STT), desktop e2e (STT down for 3 min with fast
  FileSource → gap backfilled after recovery; kill-relaunch recovery). Never real capture.

## Design notes
(implementer, 2026-11-15)

**Gap detection (`RecordingService` + pure `transcript-gaps.ts`).** Each session has a `SessionCoverage` per
source on the recording clock: audio captured (every frame the STT pipe sees *and* frames dropped from its
queue — the controller's `onOverrun`), finals, and known-lost spans. Gaps come from explicit signals, not
from "no finals here" (silence has no finals, so finals-vs-audio would flag every pause):
- `replay_overflow` (outage longer than the 120 s replay buffer, D-17) → reported **at once** when the stream
  reconnects (= STT recovered), so it is back-filled mid-recording;
- frames dropped from the STT queue → lost;
- at session end, a stream that didn't end cleanly (offline at stop → closed, fatal error, `finish_timeout`)
  or never existed (no provider) loses `[watermark, audio end]`; watermark = new optional
  `SttStream.committedMs` (Deepgram: end of the last `is_final`, silence included), else the last final's
  end, else the first audio. Gaps < 500 ms are ignored. `onTranscriptGap` hands meeting-clock ranges
  (reason `stt_offline|stt_incomplete|stt_unavailable|stt_dropped`) to the queue.

**Batch STT (`@oat/stt`).** `SttProvider.transcribe?(request)` (optional; `SttBatchRequest {source, pcm,
sampleRate, offsetMs}` → `{segments (finals with words), durationMs}`, rejects with `SttBatchError {code,
retryable, status}`). `DeepgramProvider.transcribe` = Deepgram pre-recorded `POST /v1/listen` on the http(s)
twin of the live URL, WAV body (`Content-Type: audio/wav`), `model, smart_format, punctuate, utterances=true,
mip_opt_out, language, keyterm`, same short-lived bearer (401/403 retried once with a refreshed token);
`results.utterances[]` → one segment each (fallback: channel words split at ≥ 800 ms pauses); times =
`offsetMs` + s×1000. 5xx/network/timeout/429 retryable; 400/402/401-after-retry not. `extraQuery` gets
`attempt: 0` for batch (dev fixture params). `FakeSttProvider.transcribe` returns ground truth of the span
(+ `batchFails`, `batchRequests` for tests).

**Mock (`tools/mocks` stt).** `POST /stt/v1/listen` (WAV or raw linear16) → Deepgram pre-recorded JSON;
fixture mode by `mock_offset_ms`, corpus words over the energy VAD otherwise; `utterances`/`utt_split`.
`POST /stt/_mock/outage {down}` (503 for handshakes + batch, open sockets dropped; cleared by reset);
`sttProvider({acceptAnyBearer})`. Framework fix: the request-log middleware read bodies as text, which
mangled binary bodies for providers — now reads bytes and logs binary types as `<N bytes type>`.

**Queue (`@oat/local-store`, audio index migration 3).** `stt_backfill` jobs + `recording_recovery` rows live
in the never-wiped `audio-index.sqlite` (D-28; they refer to audio on this Mac and must survive quit, crash and
a cache rebuild), `AudioIndex implements TranscriptJobStore` (+ `InMemoryTranscriptJobStore`). Job = meeting,
user (D-30), source, meeting-clock range, `doneMs` cursor, reason, `pending|done|failed`, attempts, `nextAt`,
segment count, user-facing error. The per-user cache got migration 3: `transcript_segment.backfilled` (local
flag, stripped from sync pushes, kept on pulled echoes; exposed as optional `backfilled` on
`LiveSegment`/`StoredSegment`).

**Runner (`apps/desktop/src/main/transcript-backfill.ts`).** `enqueue` cuts a new gap against the meeting's
non-failed jobs of that source (overlapping reports never queue audio twice). One job at a time, only the
signed-in account's jobs with its database open. Chunks of 5 min: `readMeetingRange` (parts, silence
between sessions) through a view of the audio index that makes the **part being recorded readable up to
3 s behind live** (its row says 0 ms while open); all-zero audio skipped; `transcribe` → `mergeBackfill`
(drop words whose midpoint is outside the chunk or inside a stored final of that source; split utterances
there; id = deterministic UUID-v8 from meeting/source/start) → saved as `backfilled` finals in one
transaction (outbox → sync), pushed into the live transcript if that meeting is on screen → cursor advanced.
Re-running a chunk is a no-op (its words now overlap stored segments), so a crash between saving and the
cursor update can't duplicate. Failures: backoff 5 s → 5 min; refusals wait 5 min; after 10 attempts
`failed` (shown). Audio deleted → `failed` "no longer on this Mac". Kicks: new job, recording → idle,
account ready, and any STT stream turning `open` (also retries jobs in backoff: "after STT recovers").

**Crash recovery (`recording-recovery.ts` + runner).** At launch, before any recording can start
(`recording:start` awaits it; the 3.8 sweeper starts after it), `recoverRecordings` repairs every
`recording` row (all accounts — repair never removes audio) and a `recording_recovery` row per meeting
records the parts and `savedUntil` (wall clock of the repaired audio end). Once that account's database is
open, the runner applies it: `ended_at` = max(saved audio end, last stored final) if still open, and for each
part the tail after its source's last stored final is queued (`crash`); marked applied (a meeting not in the
cache yet waits). Not applied to a meeting that is being recorded again.

**UI (minimal, transcript panel).** New invoke `meeting:transcript-status {meetingId}` (`bridge-transcript.ts`)
→ `{pendingMs, doneMs, failedMs, segments, running, retrying, error, recoveredAt, savedUntil}`; reloaded on
`meetings:changed` (the runner announces progress). Pure `transcript-notices.ts` → notices above the list
(`data-testid=transcript-notice`, `data-kind`; tokens only, `role=status`): "Oat quit unexpectedly —
recording saved up to 10:42 AM." · "Filling in 2 min of transcript from the saved audio…" (spinner) · "2 min
of transcript is still missing (…). Oat will fill it in from the saved audio when it can." · "30 s of audio
couldn’t be transcribed: …" · "Part of this transcript (2 min) was filled in from the saved audio after
transcription was interrupted." Screenshots: `docs/tasks/evidence/2.7/`.

**Tests.** stt: 14 unit (`deepgram-batch.test.ts`: URL, mapping, auth retry, error classes, provider wiring,
fake) + 2 int against the in-process mock. mocks: 6 (`stt-batch.test.ts`). local-store: 5
(`transcript-jobs.test.ts`: both stores, migration from v2, flag never pushed). desktop: gap math 8,
back-fill service 8 (real FileSource → Opus archive → FakeSttProvider: mid-meeting fatal stream filled to
exact ground truth, no provider, batch down → retry → filled, give-up, account scoping, audio deleted,
enqueue dedupe, crash: truncated files repaired → meeting closed → tail filled, no duplicates), notices 4,
contract 3 (core). **Int** `transcript-backfill.int.test.ts`: 4½ min of fixture audio at 20× through
`DeepgramProvider` ↔ in-process mock, mock down for **3 minutes** of audio (default 120 s buffer) → both
sources report ≈60 s `stt_offline` on reconnect → back-filled via the mock's batch API → every spoken line of
every repetition has a stored final, no overlaps (≈14 s). **E2E** `backfill.spec.ts` (built app, in-process
mock via `OAT_STT_URL`): (1) STT down from a few seconds in until after the fixture ends → notice → back up →
stored transcript = ground truth word for word per side, live finals untouched, no duplicates, panel count;
(2) SIGKILL of the main process while recording → relaunch → `ended_at` set, storage status `partial`,
recovered notice, every pre-kill final present, no duplicates, tail back-filled, "Continue recording" offered.

**Deviations / notes.** (a) The e2e outage runs on the real-time 33 s fixture and spans the stop (the
"after stop" path); the 3-minute outage with a fast FileSource is the int test (fixtures are < 45 s and
FileSource has no loop; the desktop has no speed knob). (b) The e2e uses an in-process mock (`@oat/mocks` is
now a desktop devDependency) because the shared container gets the batch endpoint only after `pnpm dev:build`
on main. (c) Dev fixture replay: batch requests ask the mock for the configured `OAT_AUDIO_SOURCE` fixture
(`createBatchStt`); correct for one-part replays. (d) `backfilled` is local only — the server schema has no
column (follow-up if other devices should mark those lines). (e) The recovered note stays on the meeting
(no dismiss). (f) Live STT segments still use the recording clock → meeting clock mapping of 2.5.

**Out of scope touched.** `packages/core` (`bridge-transcript.ts` new, spread into `bridge.ts`;
`backfilled?` on `liveSegmentSchema`/`storedSegmentSchema`); `tools/mocks/src/app.ts` (binary body logging);
`apps/desktop/package.json` (+ `@oat/mocks` devDependency, lockfile); `docs/DEV.md` (mock routes).

## Review
(reviewer, 2026-11-15) **Verdict: changes.** Read the task file + `git diff main...` only; ran
`transcript-gaps.test.ts` + `transcript-backfill.test.ts` (16/16 pass). No real capture.

Checked and fine: gap math (recording clock throughout, mapped once to the meeting clock with the same
formula as live segments; gaps only from explicit signals, so no false gaps on silence; `replay_overflow` =
only audio evicted from the replay buffer; parts via `offsetMs`, pauses are silence in the file); merge
(midpoint dedupe vs stored finals of that source, deterministic v8 ids, sorted, re-run is a no-op, ints for
`syncSegmentRowSchema`); backfilled finals go through `saveSegment` → outbox → sync like any final, with the
local `backfilled` column stripped from pushes (needed: `strictObject`) and kept on pulled echoes — local-only
flag is acceptable (add an IDEAS follow-up); batch auth = the same short-lived token with one refreshed retry,
120 s timeout, 5-min chunks (~9.6 MB WAV), status classes sane; mock body-log fix (bytes, binary logged as
size); privacy (WAV only to the configured STT `listenUrl`, mock params only for loopback + unpackaged);
recovery can't close a meeting recording on another Mac (only this Mac's `recording` rows; `cannotContinue`
refuses meetings recorded elsewhere; `busyMeetingId` guards a local continue; only closes if `ended_at` null).

1. **Repair-before-recording is not enforced on the detection path.** `apps/desktop/src/main/index.ts:611-627`
   (`detection.startNotes`) calls `recording.start` without `await recovered` (only the `recording:start`
   handler at :563 waits). After a crash the user is typically still in the meeting, so the detection prompt
   is the likeliest way to restart; if it wins the race, the continued meeting's new part gets its offset from
   `#persistedEnd` (`recording-service.ts:359`) over rows that still say `recording`/0 ms → the new part
   overlaps the crashed part on the meeting clock (and the crash tail then dedupes against the wrong finals).
   Fix: `await recovered` in `startNotes` too (better: one gate both paths share, e.g. a `ready` promise
   `RecordingService.start` awaits).
2. **D-30: an account switch mid-job writes into the other account.** `transcript-backfill.ts:304-358`
   re-reads `this.#o.store()` in `#save` (:378) after `await provider.transcribe` and never re-checks the
   account inside `#runJob` (only between jobs, :270); the provider (:273) uses whoever's STT token is current.
   Switching A→B during a chunk: A's segments go into B's database/outbox if B has that meeting (a note A
   shared with B → pushed under B's session), otherwise the save throws and burns an attempt of A's job; B's
   STT grant transcribes A's audio. Fix: pin user + store at job start; before each chunk and before saving,
   require `currentUser() === job.userId && store() === pinned`, else return leaving the job pending without
   counting an attempt; create the provider per run/user. Add a unit test (switch during `transcribe`).

Optional: (a) `meeting:transcript-status` (`index.ts:458` → `status()`) isn't account-scoped — filter jobs and
recoveries by the signed-in user (D-30). (b) Recoveries with `userId` null (pre-D-30 audio rows) never match
`recoveries({userId})`, so such a meeting is never closed — fall back to the current account if it owns the
meeting. (c) `onChange` → `meetingsChanged()` on every job start/finish/10 s "not readable yet" retry reloads
every window's meeting lists; a narrower event would do. (d) `stt_dropped` spans are reported only at session
end, so a crash loses them (the crash tail starts after the last final) — note it or persist them as they occur.

**Round 1 — fixes (implementer, 2026-11-15).** Where the design notes say otherwise, this wins.
1. **One recovery gate.** `RecordingServiceOptions.ready` (index passes the crash-recovery promise); `#start`
   awaits it before anything else, so the UI, detection `startNotes`, the 7.3 calendar start and any future
   auto-start all wait (the handler-level `await` is gone). Test: crash-left rows + a stored transcript that
   lags the audio, then an immediate start of the same meeting (as detection does) → part 2's offset ≥ the
   repaired part 1 end (verified to fail without the gate: offset 4.3 s vs 22 s).
2. **Back-fill bound to the account.** A run pins `user` + that account's `LocalStore`; `owner()` (same user,
   same store object, not stopped) is checked before each job, before each chunk and after `transcribe`
   before saving; the save writes into the pinned store. On mismatch the job is left untouched (pending, no
   attempt, same cursor) and the run stops; an error seen after a switch counts no attempt either.
   `createProvider(userId)`: the desktop's batch provider fetches tokens only while that account is still
   signed in. Test: A→B switch during `transcribe` with B's database also holding the meeting → nothing in
   either database/outbox, B's provider never created, job unchanged; back as A → completes to ground truth.
Optional, done: (a) `status()` only counts the signed-in account's jobs/recoveries (signed out → empty).
(b) Recoveries with no account (pre-D-30 rows) are claimed by the account that owns the meeting's note
(`markRecoveryApplied(id, at, claimFor)` sets `user_id`); jobs get that account. (c) `onChange` is debounced
per meeting (500 ms) inside the service (on top of index's 250 ms `meetingsChanged` coalescing). (d) A run of
frames dropped from the STT queue is queued (`stt_dropped`) as soon as frames flow again (or at session end),
so a crash keeps it; test with a slow provider + tiny STT queue.

Round-1 checks: full `pnpm run ci` → `ci: ok` (every step pass; main @bb59103 merged, nothing new). A first run
had 2 back-fill unit tests racing the automatic kick under load; the harness now runs jobs only on `runNow()`
unless a test exercises automatic retries.
