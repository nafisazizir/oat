# 3.7 — Audio playback in the meeting view (desktop)
status: done
milestone: M3 · deps: 2.8, 3.4, 3.8 · branch: task/3.7-playback

## Goal
Listen back: play a meeting's local audio (mic, system or mixed) with the transcript in sync — click a segment to
jump there, the playing segment highlights — and clear states when audio isn't on this Mac.

## Context
SPEC §4 Audio archive, D-10, D-24 (multi-part, meeting clock offsets), `@oat/audio` (readMeetingRange,
locateMeetingTime/meetingSeek, Ogg Opus), `packages/meeting-ui` (shared transcript list), `apps/desktop` meeting
view (3.4) + storage status channel from 3.8 ("Audio deleted" / "Audio on another device"), web meeting view.

## Scope
In:
- Desktop main: serve audio to the renderer safely — a custom `oat-audio://<meetingId>/<part>/<source>` protocol
  (or a decode-to-PCM bridge stream) with path validation inside the audio root, range requests for seeking;
  mixed track = mic+system mixed on the fly (or decode both and mix in the renderer via WebAudio — pick, justify,
  measure CPU).
- Player UI in the meeting view: play/pause, scrubber across the whole meeting clock (parts + gaps rendered),
  speed 1×/1.25×/1.5×/2×, source toggle (Me / Them / Both), keyboard (space, ←/→ 5 s), current time.
- Sync: clicking a transcript segment seeks to its `startMs` (via meetingSeek across parts); the segment under
  the playhead highlights and auto-scrolls (respecting user scroll like the live panel).
- States: no audio ("Audio deleted" / "Audio is on <device>" from 3.8 status), partial recordings, loading/error.
- Web: transcript segments show "Audio on <device name>" hint (device name from sync metadata if available),
  no player.
- Tests: unit (seek mapping across parts and gaps, highlight logic), desktop e2e with a fixture recording (two
  parts): click segment → player time ≈ startMs ± 100 ms; playing advances highlight; deleted audio → state.
  Screenshots.

## Design notes
(implementer + designer, 2026-11-15)

**Decision: decode in main, serve one WAV on the meeting clock.** `playback:open {meetingId}` (new
`packages/core/src/bridge-playback.ts`, spread into `bridgeContract`) returns `{status, url, durationMs, parts[]}`;
`status` is 3.8's availability (`available | recording | deleted | other-device | none`), `url` is
`oat-audio://<128-bit token>/` (only when `available`). The `<audio>` element loads
`<url><mic|system|mix>.wav?v=<durationMs>`: a 16-bit mono WAV (the parts' rate, 16 kHz) of the **whole meeting
clock** — each part's Ogg Opus decoded at its `offsetMs`, holes silent, `mix` = mic + system summed and clipped.
So `currentTime × 1000` *is* the meeting time transcript segments use: click → `currentTime = startMs / 1000`,
highlight = `activeSegmentAt(segments, currentTime)`; no part mapping in the renderer. Why not serve the `.opus`
files or mix with WebAudio: a meeting has N parts × 2 sources; one element on one clock keeps seek, speed (native
`playbackRate`, pitch kept) and source switching trivial, nothing is decoded into renderer memory (WebAudio
`decodeAudioData` of an hour ≈ 230 MB per source), and no path reaches the renderer.
- Range requests (`stream: true` scheme privilege): `bytes=a-b` → only those samples are decoded, in 4 s chunks
  pulled by a `ReadableStream` (cancelled when the element seeks). Seeking inside a part = `decodeOggOpus` from
  the page index (`opusSeekPage`, 80 ms pre-roll) — the same mapping `meetingSeek`/`locateMeetingTime` use.
  Probed files are cached (8, keyed by size + mtime + inode). The 32-bit RIFF sizes cap the WAV at ~37 h of
  meeting clock at 16 kHz (`MAX_WAV_SAMPLES`; later parts are neither drawn nor played — D-24 offsets are
  back-to-back, so not expected).
- `?v=<durationMs>`: a resumed recording makes the timeline longer; the new URL makes the element reload (the
  e2e caught a stale 9 s duration without it). The server ignores `v`; any other query is refused.
- **CPU (measured in the e2e, Apple silicon):** main process 110 ms user + 17 ms sys over 3.6 s of 2× playback
  of `mix` (two Opus decodes) = **3.6 % of one core** for the whole main process (sync etc. included), i.e.
  ≲ 2 % at 1×. `evidence/3.7/playback.json` has it plus Electron's per-process metrics.

**Security (D-30, path validation).** `AudioStorage.playable(meetingId)` (new, in the 3.8 module) = `audioStatus`
+ the **signed-in account's** rows whose path is lexically `<userData>/audio/<meetingId>/(mic|system)[.n].opus`
(`archiveFilePath`), whose file `lstat`s as a regular file, in a meeting folder whose realpath is inside the
root's realpath. The reader opens each file with `O_NOFOLLOW` + `fstat` isFile. Every protocol request
re-checks: URL shape (`parsePlaybackUrl`: hex token host, `/mic|system|mix.wav`, no user/port/other query), token
known and < 12 h old, the token's account == the signed-in account (else 404), meeting still `available` (else
410: deleted mid-play, recording again, rows now another account's). Tokens are minted only through the IPC
bridge (trusted main frame), reused per meeting, at most 32, all revoked on account change; GET/HEAD only. CSP
gains `media-src oat-audio:` (nothing else can be played; `connect-src` unchanged, so renderer `fetch` can't
read the audio).

**UI (designer).** The player sits on top of the transcript panel (what it syncs with); `@oat/ui` + tokens only:
```
┌ Transcript 8 ───────────────────────────────[⇥]┐
│ (▶) 0:05 / 0:18  [Partial]   [Me|Them|Both]  2× │
│ ▬▬▬▬▬●──────── ╷ ─────────── ┄┄┄┄ ──────        │  parts as bars (3 px notch between sessions),
├─────────────────────────────────────────────────┤  holes dashed, thumb = playhead
│                          Me 0:00 ( bubble )     │
│            ( highlighted bubble: ring-2 primary )│  aria-current="time", data-active
│ Them 0:08 ( bubble )        [Back to playback]   │  (after the user scrolls away while playing)
```
- Play/pause (round primary icon button), `m:ss / m:ss` mono tabular figures, source = `radiogroup`
  (Me / Them / Both, ←/→ inside it), speed = a button cycling 1× → 1.25× → 1.5× → 2× (source and speed remembered
  per app), scrubber = `role=slider` (←/→ 5 s, PgUp/PgDn 30 s, Home/End, Space plays; pointer drag with capture;
  parts titled "Recording n: a–b" when there are several). Crash-repaired (partial) parts are hatched and a
  "Partial" badge explains.
- Keyboard over the panel (player + transcript): Space plays/pauses, ←/→ ±5 s; ignored in inputs/the editor and on
  the resize handle; Space on buttons and lines keeps their own meaning (Enter/Space on a line = seek there).
- Clicking a line seeks to its `startMs` (`seekTarget`: in a hole → the next part's start); the play state is
  kept (paused stays paused — so the e2e can assert the landing position exactly). While playing, holes ≥ 750 ms
  between parts are skipped (`skipGap`).
- Highlight + follow (`@oat/meeting-ui`): `activeSegmentAt(segments, ms)` (pure, binary search): the line that
  contains the playhead (latest start wins when the other side talks over me; a line without an end lasts until
  the next starts); in a pause ≤ 1.5 s the last line stays lit. `TranscriptList` gets `activeId` (ring +
  `data-active` + `aria-current="time"`, distinct from the deep-link focus ring) and `playheadKey`: the active line
  is scrolled into view while tracking; a wheel/touch/scrollbar/keyboard scroll by the user stops tracking and
  shows "Back to playback"; any seek re-arms tracking. The playhead lives in a tiny external store
  (`PlaybackClock`, rAF while playing) read through `useSyncExternalStore` selectors, so the meeting view
  re-renders only when the highlighted line changes (the bar at 10 Hz).
- States: loading ("Loading audio…"); `deleted` ("Audio deleted" — removed from this Mac, transcript and notes
  kept); `other-device` ("Audio is on another device" — audio stays on the Mac that recorded it); `none` ("No
  audio"); load/play error with Retry; while this note records there is no player (the recording bar owns that).
  The player reloads on `storage:changed` (recording ended, delete, sweep). Hiding the transcript pauses playback.
  The `<audio>` element is rendered (hidden) by the meeting view so it survives panel re-renders.
- **Web:** no player; the transcript panel shows "Audio is on the Mac that recorded this meeting" (laptop icon,
  tooltip explains). The device *name* isn't in sync metadata (no column on `meeting`; adding one needs a
  migration outside this task's scope) — follow-up.

**Tests.** Unit: `apps/desktop/src/main/audio-playback.test.ts` (16: WAV header; ranges incl. suffix/clamp/416/
multi-range; URL parser incl. traversal/query/user/bad token; timeline over two real Opus parts with a 1 s hole and
a failed source; decoding puts 440/1000/660 Hz tones at the right meeting times, silence in the hole, mix > one
source; a seeked range equals the same samples of a full decode; protocol HEAD/200/206, an odd-byte range across a
chunk boundary matches the full body and lands in part 2; chunked streaming; 404 for unknown token / another
account / signed out / revoked, 410 after delete; another account's rows never served; symlinked file and
out-of-folder row skipped; partial parts flagged). `src/renderer/src/meetings/playback.test.ts` (seek mapping
across parts and gaps, gap skipping, scrubber spans, speeds, notices, clock). `packages/meeting-ui`:
`activeSegmentAt` (5, incl. 20 000 lines perf), `TranscriptList` (active vs focused marking; user scroll → "Back to
playback", the highlight moving doesn't re-arm, a seek does). CSP test (`media-src oat-audio:`).
E2E `apps/desktop/e2e/playback.spec.ts` (~30 s): records `standup-short` (FileSource), stops, "Continue
recording" → 2 parts; both parts drawn; `HEAD` 200 via `net.fetch`; element muted; click a part-2 line and a
part-1 line → `currentTime` = `startMs` (measured error 0 ms; ≤ 100 ms asserted) and that line is `data-active`;
2× → the highlight moves to a later line and playback crosses into part 2; Them/Me/Both switch the stream keeping
the position; scrubber Home / → = 5 s; rows re-attributed to another account → "Audio is on another device" +
410; restored → player again; `storage:delete-audio` → "Audio deleted", no highlight, 410. Web `meeting.spec.ts`:
hint visible, no player.

**Out of scope touched (noted).** `apps/desktop/src/main/audio-storage.ts` (+`playable()`, read-only addition to
3.8's module), `apps/desktop/src/main/security.ts` (+`media-src`), `apps/desktop/src/renderer/src/recording/
transcript-panel.tsx` (passes `activeId`/`playheadKey`), `packages/core/src/bridge.ts` (spread + re-export),
`apps/web/e2e/meeting.spec.ts` (+hint assertion), `docs/DEV.md` (desktop playback paragraph).

**Follow-ups.** Device name for the web hint needs sync metadata (e.g. `meeting.recorded_on`). No waveform on the
scrubber. Clicking a line could optionally also start playback (kept paused for now).

## Review
(reviewer, 2026-11-15) — **changes**

Checked: `oat-audio://` security (128-bit `randomBytes` token minted only via the bridge, per-request re-check of
token/TTL/account/`available`, 404/410; scheme is `standard+secure+stream` without `corsEnabled`/`supportFetchAPI`/
`bypassCSP`, `connect-src` unchanged, no webviews/foreign navigation, so no other page can read it; lexical
`archiveFilePath` + real-folder check + `O_NOFOLLOW`/`fstat`; D-30 via `#scan().mine`; `revokeAll` on account
change/sign-out), WAV header (`MAX_WAV_SAMPLES` keeps `36+data` ≤ 2^32−1; timeline/parts clamped), ranges (suffix,
clamp, unsafe ints → 416, odd-byte start), memory (4 s chunks, pull-based stream; only probed Opus bytes cached, ≤8),
CPU evidence, slider/radiogroup keyboard + labels, screenshots (light/dark, all states). Solid work; two fixes:

1. **Playback fights the live-follow logic on a just-recorded note.** `meeting-view.tsx:175` passes
   `live={showsRecording || followLive}`; after a recording stops `live.meetingId` stays this meeting, so
   `TranscriptList` gets `follow=true` while the player is active. `revealActive` (`transcript-list.tsx:~178`)
   sets `scrollTop` without `programmatic.current`, so `onScroll` flips `following=false` → **"Jump to live"** shows
   for a finished recording and **"Back to playback" is suppressed** (`!(follow && !following)`, ~l.284); while
   `following` is still true the `useLayoutEffect` `scrollToEnd` (on any `segments` change) yanks the list away
   from the playhead. This is the common "stop, then listen back" path (the e2e is in it but the transcript fits
   on screen). Fix: don't follow the live end while playable — e.g. `live={showsRecording || (followLive && !playable)}`
   (or make `follow` and playhead tracking mutually exclusive inside `TranscriptList`), and mark `revealActive`'s
   scroll as programmatic. Add a unit test: `follow` + `activeId` with a long list → no "Jump to live",
   user scroll → "Back to playback".
2. **Tokens expire mid-playback.** `audio-playback.ts:391-403` `#grant` reuses a meeting's token with its original
   `expiresAt` (absolute 12 h from first mint). A note opened at 11 h 59 min after the first mint (or left open)
   gets a URL that 404s a minute later → the next range request fails → "Couldn't play the audio" mid-listen.
   Fix: slide the expiry on reuse (`g.expiresAt = now + TOKEN_TTL_MS`) or mint a fresh token when < 1 h is left;
   unit test with `now`.

Optional:
- `PROBE_CACHE = 8` (`audio-playback.ts:56`) thrashes for meetings with ≥ 5 parts (2 sources × parts > 8, probed in
  order → 100 % misses): every range request (each scrub `pointermove` seeks) re-reads and re-parses every file.
  Size the cache per meeting (e.g. keep the last meeting's probes) or throttle drag seeks to ~10 Hz.
- `parseRange`: `bytes=10-5` is syntactically invalid → RFC 9110 says ignore (200), not 416; 416 could carry
  `content-length: 0`.
- `TranscriptList` scroller `onPointerDown` with `target === currentTarget` also fires on the list padding, not only
  the scrollbar (stops tracking on a stray click).
- `#scan` (called by `playable()` on every protocol request) may write ownership attributions — a side effect in a
  hot read path; harmless today.

**Resolution (implementer, round 2; main merged incl. per-server rate-limit namespaces).**
1. Live follow vs playback: the meeting view passes `live={showsRecording || (followLive && !playable)}`; inside
   `TranscriptList` live follow and playhead tracking are now mutually exclusive (with an `activeId`, `onScroll`
   never flips "following", the segments effect never scrolls to the end, "Jump to live" is hidden, and "Back to
   playback" no longer depends on the live state); `revealActive`'s scroll is marked programmatic (reset next
   frame). Test `components.test.tsx` "a just-recorded note played back…": 300 lines, `follow` + `activeId`,
   our scroll + a new segment → neither button; padding press → still tracking; wheel → "Back to playback",
   never "Jump to live".
2. Tokens slide: reusing a meeting's token on `playback:open` and every served request renew it to now + 12 h;
   only a token idle for 12 h dies (then `open` mints a fresh one). Test with an injected `now`
   (reopen 1 min before expiry, use past the original expiry, idle 12 h → 404, fresh token → 200).
Optional, done: probe cache is an LRU by file bytes (256 MB ≈ 20 source-hours) instead of 8 entries — test:
6 parts × 2 sources stay cached across requests (`cachedFiles`); scrubber drags seek at most every 100 ms
(trailing seek + flush on pointer up/cancel); `bytes=10-5` → ignored (200, whole body), 416 carries
`content-length: 0` (tests); scroller presses only count as user scrolling right of the content box (the
scrollbar), not on the padding. Not changed: `#scan` attribution writes in `playable()` (harmless, noted).
Consequence for 2.5's `recording.spec.ts` (out of scope, adjusted): its "scroll up → Jump to live" check ran after
the fixture had ended, i.e. on a finished note — exactly what fix 1 changes. It now runs while recording (once the
transcript overflows), and after Stop the spec asserts the finished, playable note never offers "Jump to live".
