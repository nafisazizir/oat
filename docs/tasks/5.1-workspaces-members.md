# 5.1 + 5.2 — Team workspaces: settings, members, roles, invites
status: done
milestone: M5 · deps: 1.6, 1.7 · branch: task/5.1-workspaces-members

## Goal
Teams can work together: create a team workspace, manage its settings, invite people by email (Mailpit in dev),
accept invites, change roles, remove members, leave — every action enforced by `@oat/core` permissions.

## Context
SPEC §4 Workspace/Sharing, D-9, D-18 (only owners remove/demote admins), D-22 (no Better Auth hard delete —
soft-delete path of our own), `@oat/core` permissions (canInvite/canChangeRole/canRemoveMember/
canManageMembers/canDeleteWorkspace; last-owner protection needs the owner count with a row lock), `@oat/auth`
(organization plugin with our mapping, `requireEmailVerificationOnInvitation`, team-workspace cap,
beforeUpdateOrganization guards), `@oat/testkit` (Mailpit helpers), `apps/web` structure (settings route,
workspace switcher). Another implementer is building documents/sidebar (3.3) and `/settings/integrations` +
Home "Upcoming" (7.4) concurrently — stay within `/settings/workspace*`, `/invite/*`, and member APIs.

## Scope
In:
- `/settings/workspace` (team only; personal shows a short explanation): name, icon/emoji, slug read-only
  display; danger zone: leave workspace, delete workspace (owner only → soft delete: `workspace.deleted_at`
  + hidden everywhere; add column via migration if missing; restorable for 30 days — note), confirm dialogs.
- Members page: list with roles, invite dialog (email + role ≤ own role), pending invites (resend, revoke),
  role change dropdown, remove member — each button only when permitted, server re-checks via `assertCan`.
- Invite email (our template, plain + HTML, escaped), link to `/invite/[token]`: shows workspace + inviter,
  requires sign-in with the invited (verified) email, accept/decline; expired/revoked/used states.
- Route handlers or server actions wrapping Better Auth org endpoints where suitable, but authorization
  decisions from `@oat/core` (Better Auth's own checks are a second layer). Race-safe last-owner protection
  (transaction + `FOR UPDATE` on memberships).
- Tests: int tests for every action incl. deny cases (member invites admin, admin removes owner, viewer
  invites, last owner leaves/demotes, invite accepted by a different email, expired token, revoked invite),
  Playwright e2e: owner invites → Mailpit email → second user signs up via magic link → accepts → sees the
  team workspace in the switcher; owner changes role; removes member. Screenshots.
Out: document sharing dialog/visibility (5.3), public viewer (5.4).

## Acceptance criteria
- [x] Full invite → accept → role change → remove flow works in e2e with two users.
- [x] Every deny case tested; last-owner protection race-safe (concurrency test).
- [x] `pnpm run ci` green.

## Design notes
(implementer, 2026-11-14)

**Data (packages/db).** Migration `0004_workspace_soft_delete`: `workspace.deleted_at timestamptz` + check
`workspace_deleted_team_only_ck` (`deleted_at is null or kind = 'team'`: a personal workspace can never be
deleted, even by raw SQL). `auth-mapping.ts` declares `deletedAt` as an organization field with `input: false`
(Better Auth returns it, never accepts it). Restore window: data is kept; `WORKSPACE_RESTORE_DAYS = 30` is the
promise shown in the UI. Restore/purge jobs are **not** built (follow-up: a restore action + a purge job after
30 days; until then a restore is `update workspace set deleted_at = null`).

**Domain (packages/auth `members.ts`).** One write path for membership changes, each a single transaction:
`lockWorkspace` locks the workspace row `FOR UPDATE` (a per-workspace mutex), then selects every membership
row of the workspace `FOR UPDATE`; the actor's role, the target and `ownerCount` come from those locked rows;
`assertCan(changeRole | removeMember | deleteWorkspace)` from `@oat/core` decides; then the write.
- `changeMemberRole`, `removeMember` (also clears the removed user's sessions' `active_workspace_id`),
  `leaveWorkspace` (= remove self), `deleteWorkspace` (soft; clears every session that had it active).
- Unknown/deleted workspace or non-member actor → `NotFoundError` (no probing); permission → `ForbiddenError`.
- **Race-safety proof:** the three concurrency tests (two owners leaving at once, two owners demoting each
  other, demote+leave+remove racing; 5 rounds each) pass with the locks and **fail when the `FOR UPDATE`s are
  removed** (checked by temporarily deleting them: all 3 failed).
- Reads: `listMembers` (owners first), `listPendingInvites` (pending + expired-pending), `findInviteByToken`
  (unknown token, deleted or non-team workspace → undefined), `inviteState` (pending past expiry → `expired`),
  `findInvite`, `findLiveWorkspace`, `isLiveWorkspace`.
- `workspaces.ts`: `listUserWorkspaces` and `loadPermissionContext` skip soft-deleted workspaces, so a deleted
  workspace vanishes from the switcher and grants no role anywhere (documents included, via `@oat/core`).
  `UserWorkspace` gains `logo`.

**Better Auth wiring (packages/auth `server.ts`).**
- Invitations go **through Better Auth** (`createInvitation` incl. `resend`, `cancelInvitation`,
  `acceptInvitation`, `rejectInvitation`, `updateOrganization`): its checks (membership, AC, "already a
  member/invited", email must match, `requireEmailVerificationOnInvitation`, conditional pending→accepted
  update) are the second layer; our hooks are the policy layer (`beforeCreateInvitation` = `@oat/core
  canInvite` + live workspace; `beforeAcceptInvitation`/`beforeUpdateOrganization` refuse deleted workspaces).
- `invitationExpiresIn` 7 days. `sendInvitationEmail` looks up the invite's **own secret `token`** (column
  from 1.5) and mails `/invite/<token>`; Better Auth's invitation id never appears in the link.
- `hooks.before` refuses (404) Better Auth's `update-member-role`, `remove-member`, `leave` and `delete`
  (`BLOCKED_ORGANIZATION_PATHS`), over HTTP and in-process: they can't join our locked transaction, and
  `leave` has no hook at all. `set-active` refuses a soft-deleted workspace.
- Email `invitationEmail` (email.ts): plain text + HTML, inline styles, no remote assets; inviter and workspace
  names are flattened to one line (`emailSafeText`: no CR/LF → no header/line injection), capped, HTML-escaped.

**Web (apps/web).**
- Server actions `server/actions/members.ts`: session → zod → `@oat/core` `assertCan` on fresh rows →
  Better Auth call or `members.ts`. `updateWorkspace` (name + emoji icon in `logo`, gate `manageMembers` =
  team owner/admin, same as Better Auth's `organization:update`; core has no separate settings check),
  `inviteMember`, `resendInvite` (expired → Better Auth makes a new invite, we revoke the old one),
  `revokeInvite`, `changeRole`, `removeMember`, `leaveWorkspace`, `deleteWorkspace` (requires the typed name),
  `acceptInvite`/`declineInvite` (token → invite; email match + verified checked here and by Better Auth).
  Better Auth error codes are mapped to our copy. Leave/delete/accept `revalidatePath('/', 'layout')` +
  `redirect('/home')` so the shared shell (switcher) re-renders.
- Loader `server/workspace-settings.ts`: `buildWorkspaceSettings` (pure, unit-tested per role) turns rows +
  permission context into UI flags: `assignableRoles` per member, `canRemove`, `inviteRoles` (≤ own role),
  `canLeave` (false for the last owner), `canDelete`, invites only for managers. UI flags only; actions re-check.
- `proxy.ts` matcher `/settings` → `/settings/:path*` (nested settings routes; 7.4's `/settings/integrations`
  needs the same).

**Design (UI).** All from `@oat/ui` (Card, Button, Dialog, Select, Popover, Avatar, Badge, Input, Label) and
tokens; no new colours.

- Personal workspace: same header, no tabs, one "Just for you" card explaining it can't be shared/left/deleted +
  "Create a team workspace" (reuses the 1.6 dialog).
- Role picker = `Select` only when `assignableRoles` is non-empty, else a Badge; remove = icon button → confirm
  dialog; every action has a pending spinner, errors inline in dialogs or as a toast, success toasts.
- `/invite/[token]` lives in the `(auth)` group (centered card, wordmark): workspace tile + "Join <ws>" +
  "<inviter> invited you to join as a <role>". States: signed out → "Sign in to accept"
  (`/sign-in?next=/invite/<token>`; magic link brings you back); wrong account → explanation + "Sign in with a
  different account" (signs out first); already a member → "Open workspace"; match → Accept / Decline.
  Invalid / expired / revoked / declined / already used → a notice card. `referrer: same-origin`, `noindex`.
- Switcher: workspace tile shows the emoji icon; menu gains "Workspace settings", "Invite members"
  (owners/admins of a team), "Leave <workspace>" (team; same confirm dialog; the last owner gets the refusal
  inline). `Workspace` (lib/tree.ts) gains optional `icon` and `role`; `shell.ts` maps them.
- Settings page: the old disabled name/type rows became one row linking to `/settings/workspace`.
- Breadcrumbs for `/settings/workspace*` still show only the workspace (navigation.ts untouched; shared file).

**Out of scope / notes for the orchestrator.**

  `proxy.ts` (matcher). 3.3 / 7.4 may conflict there (small, mechanical).

## Review
(reviewer, 2026-11-14, `git diff $(git merge-base main HEAD)..task/5.1-workspaces-members`) — **changes**

Checked and fine: core rules (admin can't invite/grant owner, can't demote/remove admins or owners, last owner
protected); `lockWorkspace` (workspace `FOR UPDATE` then memberships; Better Auth's accept inserts a membership
whose FK takes `KEY SHARE` on the workspace row, so it waits on our lock — serialized, no deadlock order);
accept = token → id + email match + verified + conditional `pending→accepted` (no replay); invite token 192-bit,
never returned by Better Auth (undeclared field), no enumeration signal; array/comma roles fail `isRole`;
blocked member endpoints; `set-active`/`update`/create-invite/accept refuse deleted workspaces; server actions
re-check on fresh rows, CSRF via Next's Origin check + Better Auth `trustedOrigins`; email escaping/one-line.

1. **Invite authority isn't re-checked at accept** — `packages/auth/src/server.ts:285` (`beforeAcceptInvitation`).
   An admin/owner who is later removed or demoted keeps every pending invite they sent, incl. one to their own
   second address: they accept after removal and get the role back (admin, or owner if they were one). Fix: in
   `beforeAcceptInvitation` load the inviter's current membership in the live workspace and require
   `canInvite(ctx, ws, invitation.role)` (refuse otherwise); optionally also cancel those invites inside the
   `removeMember`/`changeMemberRole` transaction (`members.ts:108,130`). Add int tests (removed admin's invite,
   demoted owner's owner-invite).
2. **Invitation emails are unthrottled, and resend bypasses our hook** — `server.ts:209` (`sendInvitationEmail`).
   create→revoke→create, or `invite-member` with `resend: true` (Better Auth's resend branch returns before
   `beforeCreateInvitation`, so neither `canInvite` nor the live-workspace check runs), mails any address with
   attacker-chosen workspace/inviter text from Oat's domain, as fast as the per-IP limit allows (mail-bomb /
   phishing relay; magic link got a per-email cap for exactly this). Fix: in `sendInvitationEmail`, `isLiveWorkspace`
   check + `rateLimiter.hit` per recipient (e.g. 3/h) and per inviter (e.g. 30/h), throwing `TOO_MANY_REQUESTS`;
   map it in `AUTH_ERRORS`. Test the resend path for a deleted workspace and the cap.
3. **`/invite/<token>` uses `<meta referrer=same-origin>`, not `Referrer-Policy: no-referrer`** —
   `apps/web/src/app/(auth)/invite/[token]/page.tsx:22`. Same-origin still sends the token on every request the
   page makes to our origin (logs, prefetches), and a meta tag only applies once parsed. Fix: send the header
   `Referrer-Policy: no-referrer` (+ `Cache-Control: no-store`) for `/invite/:path*` (next.config `headers()` or
   proxy) and set the meta to `no-referrer`; assert the header in e2e.

Optional:
- Better Auth `list`, `get-full-organization`, `list-members`, `list-invitations`, `get-active-member` still serve
  soft-deleted workspaces to their former members (read-only; nothing actionable found beyond #2), and
  `list-invitations` shows invitee emails to viewers while our UI hides them. Consider refusing deleted
  workspaces (and non-managers for invitations) in `hooks.before`.
- Direct `/organization/update` skips the action's zod: no name length cap, admins can change the slug the UI
  calls read-only, arbitrary `metadata`. Narrow `UPDATABLE_WORKSPACE_FIELDS` to name/logo and cap name length in
  `beforeUpdateOrganization` (`server.ts:42,242`).
- `inviteMember` does `input.email.trim()` before validation (`apps/web/src/server/actions/members.ts:224`):
  non-string input → 500 instead of a validation error.
- Future data paths (sync pull, documents API) must use `loadPermissionContext` (deleted-aware), never raw
  `membership` rows — worth a line in the 3.3/sync task files.
- Email: workspace/inviter names can contain URL-looking text that clients auto-link; consider stripping
  `://` / domain-like tokens in `emailSafeText`.


**Resolution** (implementer, 2026-11-14, after merging `main` with 3.3 + 1.8; conflicts in app-sidebar, tree,
shell, shell.test, auth server resolved; `Workspace.role` is now required from 3.3, `icon` stays optional;
migration `0004_workspace_soft_delete` is still free):
1. Fixed. `inviterMayStillInvite` (members.ts): live workspace + the inviter's *current* membership +
   `@oat/core canInvite(role)`. `beforeAcceptInvitation` refuses otherwise (403). `changeMemberRole` /
   `removeMember` also revoke, in the same locked transaction, the target's pending invites they could no
   longer send (`revokeInvitesBeyondAuthority`). Int tests: demoted admin's admin-invite to their own second
   address (revoked + refused), removed admin (all revoked; owner's own invite untouched), demoted owner
   (owner-invites revoked, admin-invites kept), and accept refused when the inviter was demoted/removed by
   a path that doesn't revoke.
2. Fixed. `hooks.before` on `/organization/invite-member` (create **and** resend): `inviterMayStillInvite`
   first (Better Auth's resend branch skips `beforeCreateInvitation`), then the rate limiter
   (`INVITE_EMAIL_LIMITS`: 3/h per recipient, 30/h per inviter; Redis, fail-open like magic links) → 429 with
   `retry-after`. `sendInvitationEmail` repeats the authority check as a backstop (Better Auth logs, doesn't
   return, errors from it — so the real gate is the before-hook). Tests: resend by a demoted inviter and in a
   deleted workspace refused with no mail; recipient cap across inviters/workspaces; inviter cap.
3. Fixed. `proxy.ts` now also matches `/invite/:path*` (public, no redirect) and sets
   `Referrer-Policy: no-referrer` + `Cache-Control: no-store`; page meta `referrer: no-referrer`. Unit test on
   the proxy; e2e asserts both headers, and that Accept (server action) and "Sign in with a different
   account" (Better Auth sign-out POST) still work under no-referrer in Chromium.
Optional, all done: `organization/list` filters soft-deleted workspaces (after-hook);
`get-full-organization`, `list-members`, `list-invitations`, `get-active-member(-role)` → 404 for a deleted
workspace; `list-invitations` only for owners/admins (403 otherwise); `organization/update` accepts only
name/slug/logo, name 1–60 chars, logo ≤ 16 chars, slug changes owner-only and must be a valid slug (`metadata`
refused); `inviteMember` validates the email type in zod (no 500); invitation emails break URL-like text in
names with zero-width spaces (`unlinkable`: `://`, `a.b`, `@`; pre-existing zero-width chars stripped first).
Note for 3.x/sync: data paths must build permissions with `loadPermissionContext` (deleted-aware), never from
raw `membership` rows.
